## 一、nginx 反向代理（`deploy/nginx/*.conf`）

- [ ] 用仓库里的 `booking.conf`（HTTPS + 域名）或 `booking-ip.conf`（纯 IP 内测）**整份覆盖**，
      不要手工往上加——两份都已被 `npm run check:proxy` 守卫钉住，手工改必然漂移。
- [ ] `root` 指向 **dist 产物**（`/var/www/frontend`），不是 `frontend/` 源码。
- [ ] **课堂 17 个 location** 齐全：`classrooms / attendance / recordings / uploads / files / schedules / rtc /
      admin{classrooms,monitor,reports,reconcile,audit,contract,exports} + 1 条精确块`。
- [ ] ⚠️ **`location = /api/v1/admin/classrooms`（精确匹配）必须在**：这条路径**没有子段**，
      前缀块 `/api/v1/admin/classrooms/` 匹配不到它 → 落到兜底 8081 → 主服务无此映射 → **403「无权限访问该资源」**。
      2026-11-19 真实踩过（"建临时课堂"按钮 403，看着像权限问题）。
- [ ] `/ws/classrooms/` 必须带 `Upgrade` + `Connection "upgrade"`，`proxy_read_timeout 3600s`（少了进课堂一直重连）。
- [ ] `/api/v1/classroom-callback/` **显式钉 8081**（不钉会被通用规则抢走）。
- [ ] `/api/v1/eclassroom`（课堂**开关**）属主服务 8081 —— 不要误配到 8092。
- [ ] `include /etc/nginx/proxy_params` 的实体在服务器上**存在**
      （Debian 系自带；CentOS/Anolis/Rocky 需从 `deploy/nginx/proxy_params` 放一份）。
- [ ] `client_max_body_size` 三层：server 级 **40m** + `/api/v1/uploads/` **40m** +
      `/api/v1/app-package/` **450m**（2026-11-27 起；旧文档的"≥105m"已作废）。
- [ ] **云托管模板安全/限流增强已同步（2026-11-27）**：
      - `/api/v1/files/` 块内整套重发 6 个安全头，`X-Frame-Options` 降为 **SAMEORIGIN**，
        否则讲稿 PDF / 回放录制无法 iframe 同源内联（nginx `add_header` 是覆盖式继承，
        块内写了头就会丢掉 server 级的，必须整套重发）。
      - 静态资源用 `expires 7d`（**不用 add_header**，避免丢安全头）；
        `.html` / `/build-info.json` / `/app-config.json` 用 `expires -1` 强制回源校验。
      - 4 个 `limit_req_zone`（login/sms/public/api）在 `conf.d/00-limit-req-zone.conf`，
        与云托管模板参数一致；限流点带 `limit_req_status 429`。
- [ ] `nginx -t` 通过后再 reload。
- [ ] 三个易错前缀（**别凭名字猜**）：`/api/v1/messages*`（复数，消息）≠ `/api/v1/user`（单数，主服务）；
      `/api/v1/schedules/`（复数，课堂）≠ `/api/v1/schedule`（单数，主服务）。

## 二、后端白名单与鉴权（最易漏，随 jar 生效）

- [ ] 新增公开端点必须**四处同时登记**，缺一处即整体失效：
      `SecurityConfig.permitAll` / `JwtAuthenticationFilter.WHITELIST_PATHS` /
      `WebMvcConfig.EXCLUDE_PATTERNS` / `tools/check-authz-declarative.mjs` 的 PERMIT_ALL。
- [ ] 兜底规则是 `anyRequest().denyAll()`：**漏声明 = 403**（不会静默放行，比反过来安全）。
- [ ] 确认服务器上的 jar 是含本次改动的构建（`java -jar` 必须重新 `mvn package`，`compile` 不更新 jar）。
- [ ] **不要在服务运行中覆盖 jar**：进程的 `BOOT-INF` 索引仍指向旧文件偏移，之后再加载的框架资源会读不到
      （2026-11-20 实测出现过 `ResourceBundle [...] not found` 这类怪错）。先 stop，再换 jar，再 start。

## 三、前端产物（`frontend/dist` → `/var/www/frontend`）

- [ ] 构建用 `CODEBUDDY_SAFE_DELETE_ENABLED=0 node frontend/build.js`（默认会先 `rmSync(dist)`，
      本机安全删除闸会拦）。构建后产物自动收口到 `deploy/dist/`。
- [ ] 传的是 dist 的**内容**（`scp -r frontend/dist/* $SERVER:/var/www/frontend/`），不是 `dist` 这一层。
- [ ] `vendor/` 一并上传（axios / fullcalendar / html2canvas / font-awesome 含 8 个 webfonts）。
      漏 vendor 的典型症状：`auth.js 依赖 utility_request.js`（axios 未定义）——这是**本地化之前的旧症**，
      现在仓库已全部自托管，只要不手工裁剪就不会复发。
- [ ] 上线后浏览器 **Ctrl+F5**（`dist` 里的 js 文件名不带 hash，缓存会继续用旧文件）。

## 五、数据库（**本章最容易出错，按顺序做**）

- [ ] **第 0 步**：`sudo mysql -uroot -p < /opt/lesson/sql/00-create-databases.sql`
      —— 建三库 + 建 `lesson` 账号（`127.0.0.1` 与 `localhost` **两个 host**）+ 删 root 远程 host
      + 断言 `root@localhost` 仍存在。执行前把 `CHANGE_ME` 换成真实密码，且与三份 env 的 `DB_PASSWORD` 一致。
- [ ] ⚠️ 若镜像**只有** `root@'%'`、没有 `root@localhost`：先
      `RENAME USER 'root'@'%' TO 'root'@'localhost';` 再跑，否则会一个 root 都不剩。
- [ ] 三个库的 collation **逐库不同**（`unicode_ci` / `general_ci` / `0900_ai_ci`）——不要统一，
      课堂要跨库只读主库的 `sys_tenant_eclassroom`。
- [ ] 表结构：基线 dump（2 个文件）+ **11 张手写表**（6 个文件：legal-doc / auth-guard / work-language /
      eclassroom-tenant / lesson-attendance / student-lesson-ledger）+ 种子（3 个文件）+ 课堂库 schema。
      **`20261025-1500-teaching-lang-duration.sql` 新库跳过**（基线已含目标列，再跑报 Duplicate column）。
- [ ] patch 里**只有两条必跑**：`20261029-1300-eclassroom-default-instance.sql`（课堂实例种子）
      与 `20261113-1200-eclassroom-education-tenant-bind.sql`（把种歪的 `ws_base_path='/ws'` 归一回 `''`）。
      其余 patch 是历史增量，绝大多数已并入 schema，重复执行会报 Duplicate。
- [ ] 校验口径：`45 / 8 / 13` 张表；`sys_eclassroom_instance` ≥1 行且 `ws_base_path=''`；
      `sys_term` 317 行；`msg_category` 14 行（含三个业务分类编码，缺了消息一律被拒收）。
- [ ] **备份覆盖三库 + 课堂文件**：`deploy/backup.sh` 已备 4 类产物（三个库各一个 .sql.gz + `oss_*.tar.gz`），
      库留 14 天、oss 留 3 天（录制体积大，14 份全量会撑爆盘）；失败不留半截文件且 exit 1。
      上线后确认 `/opt/backup` 下当天有 **4 个**文件、`oss_*.tar.gz` 非空——只回库不回文件 = 记录都在、点开全 404。

完整的命令与幂等性说明见 `deploy/sql/README.md`（权威），落地版见《维护手册》第 5 章 / 《腾讯云手册》3.3。

## 六、环境变量与密钥（三份 env）

- [ ] 共用密钥统一放 `/etc/lesson/keys.env`：`JWT_SECRET`（≥64 字符）、`AES_KEY` / `HMAC_KEY`（Base64 解码 32 字节）。
- [ ] 三个 unit 都含 `EnvironmentFile=/etc/lesson/keys.env`，且**排在各自 `xxx.env` 之前**。
- [ ] 三份 `xxx.env` 里**不得**再出现这三个键（2026-11-21 已迁出，残留会按「后加载覆盖」把 keys.env 冲掉）。
- [ ] 校验三进程取值一致（看进程不看文件）：用《维护手册》3.5.0b 的 `len + sha16` 脚本，三行必须相同。
- [ ] 变量名就是 **`AES_KEY` / `HMAC_KEY`**：写成 `CRYPTO_AESKEY` **不生效且不报错**，会静默沿用仓库公开的默认密钥。
- [ ] `DB_USERNAME=lesson` / `DB_PASSWORD=…`（勿用 root）**写在 `/etc/lesson/keys.env`**（2026-11-22 起，见维护手册 3.5.0b），三份 `xxx.env` 里不得再有生效值；`SPRING_DATASOURCE_URL` 仍留在各自 env，指向 127.0.0.1 的三个库。
      > 注意 host 形态：MySQL 把 127.0.0.1 反解成 `localhost`，命中 `'lesson'@'localhost'`；与 `'lesson'@'127.0.0.1'` 是两个独立账号、各有各的密码。
- [ ] **`SERVER_ADDRESS=127.0.0.1`（三份都要）**：不设则监听 `0.0.0.0`，安全组稍松即可绕过 nginx 直连 8081/8090/8092。
- [ ] **`SERVER_PORT`（三份都要，8081/8090/8092）**：防止外部残留环境变量把进程顶到别的端口（booking 这项 2026-11-20 才补）。
- [ ] 课堂额外：`REDIS_HOST/PORT`（db 2）、`STORAGE_LOCAL_ROOT`（绝对路径 `/opt/lesson/data/oss`）、
      `BOOKING_API_URL=http://127.0.0.1:8081`、`RTC_PROVIDER`（默认 native-mesh）、
      **`INSTANCE_CODE=default-local`**（容量准入开关，留空 = 不启用且启动打 WARN）。
- [ ] `LOG_PATH` 三份**各一个子目录**（`/var/log/lesson/{api,message,classroom}`）：
      logback 与 logrotate 管同一文件会互相踩（fd 指向已重命名的 inode，"当前文件"永远为空）。
- [ ] `WECHAT_SECRET` / `WECHAT_OPEN_SECRET` 填真实值（占位时服务启动 WARN、接口静默降级 1001）。
- [ ] 三份 env `chmod 600` + `chown lesson:lesson`。

## 八、提交前自检（本地，改代码的人做）

```bash
npm run check:proxy        # 端点 ↔ nginx ↔ dev 清单三向一致（改了接口或 nginx 必跑）
npm run check:props        # properties/env 的值里没有 # 与中文（值吞注释/乱码，启动才炸）
# 其余 17 道由 pre-commit 全跑；回归测试用 node tests/check_*.js 单独跑
# （没有 `npm test`：package.json 里 test 仍是占位脚本，别照着旧文档敲）
```

> `check:props` 是 2026-11-20 新增的守卫（第 19 道 `check:*`，插在 pre-commit 最后一步），起因是一次真实事故：
> 编辑 `application.properties` 时把下一行注释粘进了值里 →
> `classroom.rollcall-timeout-minutes=2# 过期数据保留（天）` → 8092 **启动即失败**
> （`Failed to convert value of type 'java.lang.String' to int`，且报错里中文是乱码、指向 `@Value` 注入点）。

## 附录 A：2026-10-13 那次修复（历史归档）

> 背景：本地 8080 开发代理伺服 `frontend/` 源码，从未暴露问题；一旦部署到云服务器（尤其国内），
> 所有走境外 CDN 的前端依赖全部加载失败，表现为「auth.js 依赖 utility_request.js，请先引入
> utility_request.js」（axios 未定义 → utility_request.js 崩溃 → `window.request` 没挂上）。
> **根因**：前端 4 类库此前全走 CDN（jsdelivr / cdnjs / bootcdn），云服务器访问境外 CDN 不稳定/被墙。
> 那次已把全部依赖本地化到 `frontend/js/public/vendor/` 并修正构建脚本（`copyAssets` 补 vendor CSS、
> `check-origin.js` 的 SKIP_REL 改匹配任意层级 `/vendor/`）。该结论至今有效，日常只需保证
> **vendor 随 dist 一起上线**（见第三章）。

那次清单里已过期的项（保留说明，避免有人照旧文档操作）：

| 旧说法 | 现在的事实 |
|---|---|
| 「主服务新增接口基本无需改路由」 | **不成立**。三服务分流，课堂端点必须逐个精确前缀（17 个 location），且有 1 条精确匹配块 |
| 「课堂 14 个前缀」 | 已是 **17 个 location / 24 个端点**（含 `admin/classrooms` 精确块） |
| 「业务库 40 张表」 | **45 张**（补进课堂实例、出勤、课时台账共 5 张） |
| 「新环境不需要执行 patch」 | **两条必跑**（课堂实例种子 + ws_base_path 修正） |
| 「先建两个库」 | **建三库**，且 collation 逐库对齐，统一用 `00-create-databases.sql` |
