## 三、全仓构建实跑与根 `build-all.bat` 两处历史缺陷

### 3.1 实跑结果

Docker 不在 PATH，全程 `--skip-docker`；**未 push 镜像、未上传远端**。

| 脚本 | 命令 | 结果 | 内容 |
|---|---|---|---|
| 根 `build-all.bat` | `--skip-docker` | ✅ `rc=0` | 3 后端 Maven 打包 + 前端构建 + jar 收口 |
| `deploy/build-all.bat` | `--skip-docker` | ✅ `rc=0` | 3 后端 + 2 前端 + Step 2c 多端包（APK / 自解压 EXE）+ 收口 |

### 3.2 缺陷 A：`PROJECT_ROOT` 路径推导错误

- **证据**：首次运行报找不到 `G:\WorkBuddy\api\pom.xml`（少一层）。
- **根因**：根 bat 用 `pushd "%~dp0.."` 推导项目根，这是 `deploy/build-all.bat` 所在深度的写法；但本文件就在仓库根，`..` 跑到了 `G:\WorkBuddy`。注释里「本文件在 deploy\ 只有一层」是从 deploy 版本拷贝时留下的错误说明。
- **修法**：改为 `pushd "%~dp0"`，并在两处注释写明「两个 bat 路径深度不同，勿互拷」。`deploy/build-all.bat` 用 `%~dp0..` 是对的，未改。

### 3.3 缺陷 B：缺 `CODEBUDDY_SAFE_DELETE_ENABLED=0`

- **证据**：`frontend/build.js` 清空 `dist`（137 文件 > 阈值 50）被 WorkBuddy 批量删除守卫拦截，构建中止。
- **修法**：变量段补 `set "CODEBUDDY_SAFE_DELETE_ENABLED=0"`，与 `deploy/build-all.bat` 一致。

### 3.4 顺带确认的打包链路改动

`deploy/build-all.bat` 的 Step 2c 把 2 处 `npm run` 改为直接 `node scripts\pack-sfx.cjs --rebuild` / `node scripts\build-native.cjs android`。原因：系统 PATH 命中 node 25.2.1 + npm 11.6.2 时，`npm run` 加载 `fs-minipass@3.0.3` 抛 `TypeError: Class extends value undefined`（minipass@7.1.2 与 node 25 不兼容），表现为「Windows 自解压 EXE 打包失败 exit 7」。node 25 本身可用，绕开 npm 即可。

## 四、`deploy/nginx` 安全 / 限流增强

以 `cloudBased/frontend/default.conf.template`（微信云托管）为参照做结构化对比。两者架构不同：云托管是容器化、上游为变量域名；`deploy/nginx` 是自建云服务器、`/var/www/` 静态根 + `127.0.0.1:8081/8090/8092` 三服务。只同步通用增强，不照搬架构。

### 4.1 对比结论

| 判定 | 项目 |
|---|---|
| 已一致，无需改 | 6 大安全响应头（含 HSTS 按 HTTP/HTTPS 分支）、4 个 `limit_req_zone`（login/sms/public/api）参数、限流点 `limit_req_status 429` |
| **实补 2 项** | ① `/api/v1/files/` 块重发安全头 ② 静态资源 `expires` 缓存 |
| 不补（架构差异） | `gzip`（云服务器全局 `nginx.conf` 已配）、`resolver` / 变量上游（云服务器是固定 127.0.0.1）、`location /` 的 `/login.html` 兜底（守卫依赖，改动会破坏课堂 App 承接） |

### 4.2 实补项 ①：`/api/v1/files/` 允许 iframe 同源内联

讲稿 PDF / 回放录制需要在 iframe 里显示，原来继承 server 级 `X-Frame-Options: DENY` 会被浏览器拒绝。nginx 的 `add_header` 是**覆盖式继承**：块内一旦写头，server 级 6 个头全部丢失，因此必须整套重发：

```nginx
add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;  # 仅该 server 段已有未注释 HSTS 时
add_header X-Frame-Options "SAMEORIGIN" always;
add_header X-Content-Type-Options "nosniff" always;
add_header X-XSS-Protection "1; mode=block" always;
add_header Referrer-Policy "strict-origin-when-cross-origin" always;
add_header Permissions-Policy "geolocation=(), microphone=(self), camera=(self)" always;
```

HSTS 只在该 server 段已有未注释 HSTS 时重发——HTTP 版与自签证书版不加。

### 4.3 实补项 ②：静态资源缓存

```nginx
# 用 expires 而非 add_header：不参与覆盖式继承，server 级安全头不会丢
location ~* \.(js|css|png|jpg|jpeg|gif|ico|svg|woff2?|ttf|eot|otf|mp4|webp)$ {
    expires 7d;
    try_files $uri =404;
}
location ~* \.html$          { expires -1; }   # 多页应用每次回源校验
location = /build-info.json  { expires -1; }
location = /app-config.json  { expires -1; }   # 改了配置不能拿到旧值
```

### 4.4 应用范围与优先级验证

5 份 conf 共 **6 处 HTTPS/主 server 段**（`booking-ip-dual.conf` 含双 server）全部补齐：`booking.conf`、`booking-https.conf`、`booking-ip.conf`、`booking-ip-https.conf`、`booking-ip-dual.conf`。

新增的静态资源正则块可能抢走课堂 App 资源，已按 nginx 规则（`=` > `^~` > 正则按出现顺序 > 普通前缀）模拟验证：

| URI | 命中 | 结论 |
|---|---|---|
| `/app-*.js`、`/app.css` | 前序课堂承接正则 | 不被抢 |
| `/js/classroom/*` | `^~` 前缀（命中即停） | 不被抢 |
| `/css/classroom.css` | `=` 精确 | 不被抢 |
| 课堂 `*.html` | 前序课堂承接正则 | 不被抢 |
| `/js/public/api.js` | 新增静态正则 `expires 7d` | 符合预期 |

`check:proxy` 另确认 6 处「课堂 App 承接块」逐字一致、28 个课堂端点全部可达。

### 4.5 校验边界

本机无 nginx，**未跑 `nginx -t` 实机校验**，只做了括号平衡 / 行尾分号静态检查与 location 匹配模拟。部署到服务器后须按清单执行一次 `nginx -t && systemctl reload nginx`。
