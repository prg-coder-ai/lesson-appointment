# 纯 IP 环境启用 HTTPS（自签证书）配置清单

> 适用：云服务器**没有域名、只有公网 IP**（当前 `152.136.254.127`）时的 HTTPS 落地。
> 有域名请走另一套：`deploy/nginx/booking-https.conf` + Let's Encrypt，见维护手册 **§3.8**。
> 本文是**可勾选的操作清单**：从上到下逐条执行，每步都有验证方式与失败判据。
>
> 配套文件：`deploy/nginx/gen-selfsigned-cert.sh`、`booking-ip-https.conf`、`booking-ip-dual.conf`

---

## 0. 先选形态（三选一，只启用一份）

| 形态 | 站点文件 | 80 端口 | 443 端口 | 适用 |
|---|---|---|---|---|
| **纯 HTTP** | `booking-ip.conf` | 完整站点 | 无 | 现状；课堂用不了（无安全上下文，摄像头被禁） |
| **纯 HTTPS** | `booking-ip-https.conf` | **301 跳转**到 https | 完整站点 | 只想要 https；curl/脚本探测需改 `-k https` |
| **双栈** | `booking-ip-dual.conf` | 完整站点 | 完整站点 | **同时要 http 和 https**：兼容老客户端、脚本探测、排查 TLS 时分诊 |

三份文件的**分流 location 逐字一致**（`npm run check:proxy` 会五份一起比对，漏一处即判红），差别只在 server 级。

> 🔴 **`booking-https.conf`（域名版）在没有域名、没有证书时绝对不能启用。**
> 它引用 `/etc/letsencrypt/live/your.domain.com/fullchain.pem`，证书不存在时 `nginx -t` 直接报
> `cannot load certificate ".../your.domain.com/fullchain.pem": BIO_new_file() failed`，
> 整份配置校验失败。**纯 IP 环境只允许用 `http` / `https-ip` / `dual` 三种。**

> ⚠️ 同一时间**只能启用一份**。这里的"启用"指的是 `/etc/nginx/sites-enabled/` 里的软链 ——
> `sites-available/` 下放多少份都不影响运行，nginx 只 `include sites-enabled/*`。
> 所以**不需要删除文件，只需摘链接**（保留文件才能在形态间秒切、也才能回滚）。

## 0.1 🔥 如果 `nginx -t` 已经失败（救火，3 分钟）

典型报错：`cannot load certificate "/etc/letsencrypt/live/your.domain.com/fullchain.pem"` ——
说明**启用了域名版 `booking-https` 而它没有证书**（2026-11-22 实际发生）。

**先确认线上没挂**：`nginx -t` 失败时 `reload` 根本没执行，nginx 仍在跑内存里的旧配置，站点是活的。
**此时绝对不要 `sudo systemctl restart nginx`** —— 那会真的起不来。

```bash
# ① 找出谁在引用 letsencrypt（预期只有 booking-https）
sudo grep -rln "letsencrypt" /etc/nginx/sites-enabled/ /etc/nginx/sites-available/
ls -l /etc/nginx/sites-enabled/

# ② 摘掉域名版的链接（只删链接，sites-available 里的文件保留）
sudo rm -f /etc/nginx/sites-enabled/booking-https

# ③ 确认自签证书是否已生成；没有就先生成
ls -l /etc/nginx/ssl/selfsigned/
sudo bash /opt/lesson/nginx/gen-selfsigned-cert.sh 152.136.254.127

# ④ 启用正确的形态（双栈 / 纯 HTTPS 二选一）
sudo ln -sfn /etc/nginx/sites-available/booking-ip-dual /etc/nginx/sites-enabled/booking-ip-dual
#   sudo ln -sfn /etc/nginx/sites-available/booking-ip-https /etc/nginx/sites-enabled/booking-ip-https

# ⑤ 再校验（必须看到 test is successful 才 reload）
sudo nginx -t && sudo systemctl reload nginx
```

**更稳的做法**：用切换脚本，它会先把上面所有前置条件验一遍，`nginx -t` 失败还会自动回滚：

```bash
sudo bash /opt/lesson/nginx/switch-site.sh          # 先看现状（启用了什么、证书在不在、SAN 覆盖不覆盖）
sudo bash /opt/lesson/nginx/switch-site.sh dual     # 再切
```

## 1. 事前检查（5 分钟，缺一项后面都会白跑）

- [ ] **443 已在安全组放通**（腾讯云控制台 → 安全组 → 入站规则）。80 视所选形态保留。
      若开了 ufw：`sudo ufw allow 443/tcp`
- [ ] **zone 定义在位**（三份站点都引用 `limit_req zone=api_zone`，缺定义会 `zero size shared memory zone`）：
      ```bash
      ls -l /etc/nginx/conf.d/00-limit-req-zone.conf
      sudo nginx -T 2>/dev/null | grep -c limit_req_zone      # 期望 4
      ```
- [ ] **nginx 版本确认**（决定 `http2` 写法）：
      ```bash
      nginx -v      # 1.24 → 必须用 listen 443 ssl http2;   1.25.1+ 才可用 http2 on;
      ```
      本套模板按 **1.24** 写：`listen 443 ssl http2;`。**1.24 上写 `http2 on;` 会 unknown directive，整站起不来。**
- [ ] **备份现有配置**：
      ```bash
      sudo cp -a /etc/nginx /root/nginx.bak.$(date +%F-%H%M%S)
      ```
- [ ] **先 `nginx -t` 通过再动手**（若当前 `-t` 就失败，先修它，否则分不清是谁弄坏的）：
      ```bash
      sudo nginx -t
      ```

## 2. 生成自签证书

- [ ] **执行脚本**（root 执行，因为要写 `/etc/nginx/ssl` 并把私钥设 600）：
      ```bash
      sudo bash deploy/nginx/gen-selfsigned-cert.sh 152.136.254.127
      ```
      多个地址（公网 + 内网）就都传：
      ```bash
      sudo bash deploy/nginx/gen-selfsigned-cert.sh 152.136.254.127 10.0.0.8
      ```
      > 不传 IP 时会自动探测 `hostname -I`，但**云服务器的公网 IP 走 NAT、不在网卡上**，
      > 所以一定要显式传公网 IP，否则 SAN 里没有它，浏览器会「连不上」而不是「点继续」。

- [ ] **确认 SAN 里有你访问用的 IP**（这一步没过就别往下走）：
      ```bash
      openssl x509 -in /etc/nginx/ssl/selfsigned/server.crt -noout -ext subjectAltName
      # 期望：DNS:localhost, IP Address:127.0.0.1, IP Address:152.136.254.127
      ```
      脚本自己也会打印并做链校验（`✓ 由本 CA 签发，链完整`）。

- [ ] **产物与权限核对**：
      ```bash
      ls -l /etc/nginx/ssl/selfsigned/
      # ca.key / server.key → 600 root；ca.crt / server.crt → 644
      ```

**为什么是两层（CA + 服务器证书）**：浏览器校验的是 `server.crt`，而它由 `ca.crt` 签发。
客户端只要**导入一次 `ca.crt`**，以后重签叶子证书都不会再报警告。只签一张自签证书的话，
每次换 IP / 到期重签，所有机器都要重新点一次「继续前往」。

| 文件 | 用途 | 可否分发 |
|---|---|---|
| `ca.crt` | 根证书，导入「受信任的根证书颁发机构」后免警告 | **可**（脚本会放一份到 `/var/www/frontend/ca.crt` 供下载） |
| `ca.key` | 根私钥 | **绝不外发** |
| `server.crt` | 服务器证书（浏览器校验的就是它） | 可 |
| `server.key` | 服务器私钥 | **绝不外发** |

## 3. 启用站点

- [ ] **看清 `sites-enabled` 现状**（软链才有 `->`；若发现是真实文件，说明当初是 `cp` 进去的，摘掉也不会丢内容）：
      ```bash
      ls -l /etc/nginx/sites-enabled/
      ```

- [ ] **摘掉其它形态的链接**（**不删 `sites-available` 里的文件**）：
      ```bash
      sudo rm -f /etc/nginx/sites-enabled/{booking,booking-ip,booking-https,booking-ip-https,booking-ip-dual,default}
      ```
      > `default` 是 Ubuntu 自带的，它同样写 `listen 80 default_server`，留着必定抢默认站点，
      > 表现为 `nginx -t` 报 **`a duplicate default server for 0.0.0.0:80`**。

- [ ] **拷入并启用目标形态**（以双栈为例；纯 HTTPS 把文件名换掉即可）：
      ```bash
      sudo cp deploy/nginx/booking-ip-dual.conf /etc/nginx/sites-available/booking-ip-dual
      sudo ln -sfn /etc/nginx/sites-available/booking-ip-dual /etc/nginx/sites-enabled/booking-ip-dual
      ```
      纯 HTTPS：
      ```bash
      sudo cp deploy/nginx/booking-ip-https.conf /etc/nginx/sites-available/booking-ip-https
      sudo ln -sfn /etc/nginx/sites-available/booking-ip-https /etc/nginx/sites-enabled/booking-ip-https
      ```

- [ ] **改 IP（当前模板已写死 `152.136.254.127`）** —— 换服务器时才需要：
      ```bash
      sudo sed -i 's/152\.136\.254\.127/新IP/g' /etc/nginx/sites-available/booking-ip-dual
      ```
      ⚠️ 改完必须**重跑第 2 步的证书脚本**，否则 SAN 里还是旧 IP → 浏览器「连不上」。

- [ ] **校验并 reload**（`-t` 不过就别 reload）：
      ```bash
      sudo nginx -t && sudo systemctl reload nginx
      ```
      必须看到 **`test is successful`**，只有 `syntax is ok` 不算通过。

### 3.5 更省事：用 `switch-site.sh` 切换（推荐）

手工 `ln -sfn` 已经出过一次事故（错启域名版 → `nginx -t` 报证书不存在）。脚本把「前置校验 → 切换 → 校验 → 失败自动回滚」串起来：

```bash
sudo bash /opt/lesson/nginx/switch-site.sh              # 只看现状：启用了什么、证书在不在、SAN 覆盖不覆盖
sudo bash /opt/lesson/nginx/switch-site.sh http         # 纯 HTTP
sudo bash /opt/lesson/nginx/switch-site.sh https-ip     # 纯 HTTPS + 80 跳转（自签）
sudo bash /opt/lesson/nginx/switch-site.sh dual         # HTTP + HTTPS 双栈（自签）
sudo bash /opt/lesson/nginx/switch-site.sh https-domain # 域名 + 受信任证书
```

它会在动手前拦下这四类错误：

| 脚本会拦 | 手工操作时的后果 |
|---|---|
| 目标文件不存在 | `ln -s` 建出悬空链接，`nginx -t` 报 No such file |
| 文件里还有 `your.domain.com` 占位符 | `cannot load certificate .../your.domain.com/fullchain.pem` |
| 证书/私钥文件不存在 | 同上 |
| 证书 SAN 不含 `server_name` 里的地址 | 浏览器 `ERR_CERT_COMMON_NAME_INVALID` 且点不进「继续」 |

`nginx -t` 失败时，脚本会**把 `sites-enabled` 恢复到切换前的状态**并返回 1 —— 也就是说"切错了"不会让你停在半坏的状态。

## 4. 验证

- [ ] **TLS 能握手、证书链自检**（本机回环，绕开安全组）：
      ```bash
      openssl s_client -connect 127.0.0.1:443 -servername 152.136.254.127 </dev/null 2>/dev/null \
        | grep -E "subject=|Verify return code"
      # 自签必然是 Verify return code: 18 (self-signed certificate)  ← 正常
      # 用 CA 校验才是 0：
      openssl s_client -connect 127.0.0.1:443 -CAfile /etc/nginx/ssl/selfsigned/ca.crt </dev/null 2>/dev/null \
        | grep "Verify return code"      # 期望 0 (ok)
      ```

- [ ] **站点可访问**：
      ```bash
      curl -kI https://127.0.0.1/ -H "Host: 152.136.254.127"     # 期望 200/302
      curl -kI https://152.136.254.127/                          # 经安全组，期望 200
      ```

- [ ] **纯 HTTPS 形态额外确认 301**：
      ```bash
      curl -I http://152.136.254.127/     # 期望 301 → https://...
      ```

- [ ] **双栈形态额外确认 80 不再跳转**：
      ```bash
      curl -I http://152.136.254.127/     # 期望 200，不是 301
      ```

- [ ] **浏览器实测**：首次会拦「您的连接不是私密连接」→「高级」→「继续前往（不安全）」。
      进去后地址栏仍显示"不安全"，这是自签的必然结果，不影响功能。

- [ ] **课堂 WebSocket 必须是 101**（进课堂后看 Network）：
      `wss://152.136.254.127/ws/classrooms/...` → **101 Switching Protocols**。
      若 failed，先查实例的 `ws_host`（见第 6 节倒数第二条）。

- [ ] **四项回归**（少测一项就会在事后才炸）：
      1. 登录 → 平台首页正常
      2. 进课堂 → `wss://` 101、白板/心跳可用
      3. 上传 >20MB 讲稿成功（`client_max_body_size`）
      4. 消息中心实时收到（SSE 不被缓冲、不 60s 断）

- [ ] **客户端免警告（可选，逐台做）**：
      | 系统 | 做法 |
      |---|---|
      | Windows | 双击 `ca.crt` → 安装证书 → 本地计算机 → 受信任的根证书颁发机构 |
      | macOS | 双击 → 钥匙串「系统」→ 始终信任 |
      | Linux | `sudo cp ca.crt /usr/local/share/ca-certificates/lesson-ca.crt && sudo update-ca-certificates` |
      | Android | 设置 → 安全 → 加密与凭据 → 安装证书 → CA 证书 |
      | iOS | 安装描述文件 → 设置 → 通用 → 关于本机 → 证书信任设置 → 打开「完全信任」（iOS 必须走这一步，光装描述文件不算信任，这点和 Android 不同） |

      下载入口：`https://152.136.254.127/ca.crt`（双栈时 `http://152.136.254.127/ca.crt` 也能下）。

## 5. 双栈专属注意（选了 `booking-ip-dual.conf` 才需要看）

- [ ] **知道 http 与 https 是不同 origin**：`scheme` 参与同源判定，所以 `localStorage` / `sessionStorage` 不共享。
      用户在 http 登录后切到 https 会显示「未登录」，反之亦然。**这是浏览器行为，不是 bug**，别当故障查。
- [ ] **知道 http 段不是安全上下文**：`getUserMedia` 在 `http://<IP>` 下被直接禁用（只有 `localhost` 例外）。
      表现是：**进课堂能看到白板和文字消息，但摄像头/麦克风开关点了没反应**。要音视频必须走 https。
- [ ] **知道明文段 token 可被中间人截获**：双栈只适合内测/内网过渡；正式对外仍应尽快上域名 + 受信任证书。
- [ ] **服务端脚本的探测地址要跟着改**：`deploy/upload-to-server.sh` 用 `curl http://127.0.0.1/...`；
      在**纯 HTTPS** 形态下会拿到 301。双栈形态不用改；纯 HTTPS 要改成 `curl -k https://127.0.0.1/...`。
- [ ] **两个 server 块的 location 必须同步**：本文件由脚本从 `booking-ip-https.conf` 派生，
      新增课堂端点时改一份就要重生成。`npm run check:proxy` 会把五份站点一起校验，漏同步即判红，提交前跑一次。

## 6. 坑位对照表（症状 → 真因 → 处置）

| 症状 | 真因 | 处置 |
|---|---|---|
| **`cannot load certificate "/etc/letsencrypt/live/your.domain.com/fullchain.pem": BIO_new_file() failed`** | **启用的是域名版 `booking-https.conf`**，且证书（和域名占位符）都没有 | 摘掉 `sites-enabled/booking-https`，改用 `booking-ip-dual` 或 `booking-ip-https`（见 §0.1）。**不能 restart，只能改完再 `-t` 通过后 reload** |
| `nginx -t` 报 `a duplicate default server for 0.0.0.0:80` | `sites-enabled` 里还有另一份带 `default_server` 的站点（`booking-ip` 或 `default`） | 摘掉多余链接（第 3 节第二步） |
| `nginx -t` 报 `unknown directive "http2"` | nginx 1.24 不支持 `http2 on;` | 用 `listen 443 ssl http2;`（模板已如此） |
| `nginx -t` 报 `cannot load certificate ... No such file` | 证书没生成，或路径与 `ssl_certificate` 不一致 | 重跑 `gen-selfsigned-cert.sh`，核对 `/etc/nginx/ssl/selfsigned/` |
| 浏览器 **「无法访问此网站 / ERR_CERT_COMMON_NAME_INVALID」**，点不进「继续」 | 证书 SAN 里**没有**你访问的那个 IP（浏览器只看 SAN，不看 CN） | 重跑脚本并显式传该 IP，再 `reload` |
| 浏览器 **ERR_CERT_AUTHORITY_INVALID**，**有**「继续前往」 | 自签且未导入 `ca.crt` —— 正常现象 | 点「继续前往」，或按第 4 节导入根证书 |
| 点过「继续」后**再也进不去**，连警告页都不给 | 曾发出 HSTS 头，浏览器记住了 max-age | `chrome://net-internals/#hsts` → Delete domain security policies 清掉该 IP；**模板已默认注释掉 HSTS**，勿打开 |
| 页面能开但**摄像头/麦克风被禁** | 走的是 `http://`，不是安全上下文 | 用 `https://` 访问；双栈时确认没被浏览器自动补成 http |
| 课堂 Network 里 `ws://`（不是 wss）或连接失败 | 页面本身是 http；或实例 `ws_host` 填了公网 IP，后端 `buildWsUrl` 恒输出 `ws://` | **实例 `api_host`/`ws_host` 保持 `127.0.0.1`**，前端判定回环后自动改用同源 `wss://` |
| 切入 https 后用户「被登出」 | http 与 https 是不同 origin，localStorage 不共享 | 正常行为；双栈过渡期的已知代价 |
| `curl` 探测全变 301 | 纯 HTTPS 形态的 80 段只做跳转 | 改 `-k https://`，或改用双栈形态 |
| 上传 >20MB 报 413 | `client_max_body_size 20m` | 要 100MB 就**把 `/api/v1/uploads/` 那处改成 `105m`，且纯 HTTPS 与双栈两份同时改** |
| 后台报 `zero size shared memory zone "api_zone"` | 缺 `conf.d/00-limit-req-zone.conf` | 补回后 `nginx -t && reload`；**reload 失败仍跑旧配置，别用 restart** |

## 8. 三种形态之间如何切换

| 从 → 到 | 操作 |
|---|---|
| 纯 HTTP → 双栈 | 按第 2、3 节走一遍，启用 `booking-ip-dual.conf` |
| 纯 HTTP → 纯 HTTPS | 同上，启用 `booking-ip-https.conf`；注意脚本探测要改 `-k https` |
| 纯 HTTPS ⇄ 双栈 | 只换软链，证书不动（两份用同一套证书路径） |
| 任一 → 有域名 HTTPS | 走 `booking-https.conf` + certbot，见维护手册 §3.8；`gen-selfsigned-cert.sh` 与 `ssl/selfsigned/` 可保留备用 |

## 11. 自签证书的硬边界（做不到的事，别浪费时间去调）

| 场景 | 能否用自签 | 说明 |
|---|---|---|
| 电脑浏览器（Chrome/Edge/Firefox/Safari） | ✅ 可，需点「继续前往」或导入 CA | 功能完整，地址栏显示"不安全" |
| **微信内置浏览器** | ❌ **打不开** | 微信没有"继续前往"入口，直接拦死 |
| **微信小程序** | ❌ 不可用 | 小程序要求受信任证书，且**合法域名必须是域名、不能填 IP** |
| 手机 App / 第三方回调 | ⚠️ 视实现 | 多数需在代码里信任该 CA |
| 服务器内 curl / 监控 | ✅ 可 | 加 `-k` 跳过校验 |

**所以**：如果课堂需要在小程序端或微信里使用，**必须拿域名 + 受信任证书**（Let's Encrypt 免费），
自签只能覆盖"电脑浏览器内测"这一档。境内服务器还需完成 **ICP 备案**，否则 80/443 会被云厂商拦截
（IP 直连不受备案影响，这也是当前只能用 IP 的原因之一）。
