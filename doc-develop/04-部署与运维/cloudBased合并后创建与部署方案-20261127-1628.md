> 生成时间：2026-11-27 16:28
> 适用分支：`student-crossplatform`　适用版本：**2.2.1**
> 状态：**方案已确认，P0 收口已执行；P1/P2 需在有 Docker / 有权限的机器上执行**
> 关联：上一轮「cloudBased 深度合并进 deploy」的落地后续；`版本2.2.1与部署配置变更说明-20261127-1449.md`

## 一、达到的效果（目标态）

| 维度 | 合并前 | 合并后（本方案目标） |
|---|---|---|
| 目录 | `cloudBased/`（微信云托管）与 `deploy/`（自建服务器）两套并列，同名文件 5 类内容不同 | `deploy/` 单一入口，`deploy/docker/` 一个构建上下文，`deploy/scripts/` 一个脚本目录 |
| 重复文件 | 5 份 `.dockerignore`、占位 `Dockerfile`(182B)、重复的 `deploy-keys.txt`（含密钥） | 合并为 1 份 `.dockerignore`；删除占位文件与重复密钥副本 |
| 镜像构建 | 4 个服务各自 `cd 目录 && docker build .`，4 套上下文 | `docker build -f Dockerfile.cloudbase-* deploy/docker/`，**1 套上下文**，4 个 Dockerfile 的 `COPY` 一行未改 |
| 脚本 | `CLOUD_API/MSG/CLS/WEB` 四个变量、路径深耦合 | 单一 `DOCKER_DIR`，4 份构建脚本（2 bat + sh + ps1）口径一致 |
| 创建/部署 | 三套链路各自散落、无统一说明 | 本文档给出三套链路的**创建 → 部署 → 验证 → 回滚**完整路径 |
| 外推安全 | `--docker-push` / `scp` 可能误触发 | 默认 `DOCKER_PUSH=0`、`SERVER` 未设即 die；**默认不 push、不上传远端** |
| 版本库 | jar / dist / EXE 解包目录可能泄漏 | `.gitignore` 通配收敛 + 运行时产物整目录忽略 |

## 二、方案总览（P0 → P1 → P2）

```
P0 收口（本机，已完成）        P1 创建（需 Docker）         P2 部署（需权限/远端）
├ 修 3 处 -f 悬空引用          ├ 3 个 jar + frontend/dist   ├ 链路A 微信云托管
├ 同步 4 份 dockerfilePath     ├ 云环境 env（幂等生成）      ├ 链路B 自建服务器 systemd+nginx
├ 修 .dockerignore 过时注释    └ 4 个镜像（tag 带 sha）     └ 链路C 本地 Docker 单机
└ 提交（不 push）                                            （灰度→验证→可回滚）
```

**核心原则**：P0 不动业务逻辑、不改 Dockerfile 的 `COPY`；P1/P2 只给命令，**不在本机实机执行镜像构建与远端部署**（本机无 Docker、无远端授权）。

│   ├── resolver-entrypoint.sh       （00-resolver.sh，注入上游域名）
│   ├── container.config.{api,message,classroom,frontend}.json
│   ├── application-cloud.{api,message,classroom}.properties
│   ├── README.cloudbase-{frontend,db}.md

│   ├── env/                         （gen-cloud-env.ps1 生成，gitignore）
│   └── booking-api-*.jar 等 3 个 jar  （运行时由构建脚本复制，gitignore）
├── scripts/                         ★ 云托管构建/环境脚本（原 cloudBased/scripts/）

## 四、P0：必须先修的收口项（已随本方案执行）

合并后勘察发现 2 个会直接让「创建」失败的阻断缺陷 + 1 个过时注释：

| 编号 | 缺陷 | 位置 | 修复 |
|---|---|---|---|
| B1 | `-f` 引用 `Dockerfile.cloudbase-web`，实际文件叫 `Dockerfile.cloudbase-frontend` | `build-all.bat:268`、`deploy/build-all.bat:498`、`deploy/scripts/build-all.sh:150` | 3 处统一改为 `-frontend`（ps1 原本正确） |
| B2 | 云托管流水线 `container.config.json` 的 `dockerfilePath` 仍是 `"Dockerfile"` | 4 份 `container.config.*.json` | 分别改为 `Dockerfile.cloudbase-{api,message,classroom,frontend}` |
| B3 | 根 `.dockerignore` 注释仍写「上下文 deploy/docker/api」（该目录已不存在） | `.dockerignore:6,24` | 改为「云托管统一上下文 deploy/docker/」 |

**B1 的后果**：不修则 `docker build -f` 必定报 "failed to read dockerfile"，4 个镜像里前端镜像一定失败。
**B2 的后果**：不修则微信云托管控制台/流水线按 `"Dockerfile"` 找文件（会命中本地 Docker 那套 6948B 的 `Dockerfile`），构建出错误的镜像。

## 五、P1：创建（本地产物 + 镜像）

> 前置：JDK 21、Maven 3.9.x、Node 18+、**Docker 可用**。
> 本机当前 Docker 不在 PATH → 以下步骤需在构建机/服务器上执行。

### 5.1 创建后端 jar 与前端 dist

| 入口 | 命令 | 产出 |
|---|---|---|
| 根 `build-all.bat`（云托管版，3 后端 + 前端） | `build-all.bat --skip-docker` | `api/target/booking-api-2.2.1.jar`、`api/message-service/target/message-service-1.1.0.jar`、`frontend/dist` |
| `deploy/build-all.bat`（本地多服务版，3 后端 + 2 前端 + 多端包） | `build-all.bat --skip-docker`（在 `deploy/` 下） | 上述 + `api/classroom-service/target/classroom-service-1.0.0.jar` + `classroom-app/www` |
| Linux 云托管脚本 | `bash deploy/scripts/build-all.sh` | 同上，自动 `cp` 到 `deploy/docker/` |

构建脚本会自动把 jar / dist 复制到 `deploy/docker/`，与 4 个 Dockerfile 的 `COPY` 对齐：

| Dockerfile | COPY 源（相对 `deploy/docker/`） | 脚本复制目标 |
|---|---|---|
| `cloudbase-api` | `booking-api-2.2.1.jar` | `deploy/docker/booking-api-2.2.1.jar` |
| `cloudbase-message` | `target/message-service-1.1.0.jar` | `deploy/docker/target/message-service-1.1.0.jar` |
| `cloudbase-classroom` | `classroom-service-1.0.0.jar` | `deploy/docker/classroom-service-1.0.0.jar` |
| `cloudbase-frontend` | `dist`、`default.conf.template`、`resolver-entrypoint.sh` | `deploy/docker/dist/` + 顶层 |

> ★ 三个 jar 的落点**不一致是刻意保留**的：api / classroom 读上下文根，message 读 `target/`。改动脚本时勿「统一」成同一目录。

### 5.2 创建云环境变量（链路 A 必需，幂等）

```powershell
./deploy/scripts/gen-cloud-env.ps1 `
    -MySqlHost mysql.<envid>.<region>.tcloudbase.com `
    -DbUser lesson -DbPassword '<真实库密码>' `
    -CorsOrigins "https://www.yourdomain.com,https://*.tcloudbase.com"
```

产物落在 `deploy/docker/env/`（已 gitignore，不入库）：`cloud.env.api`、`cloud.env.message`、`container.config.*.env.json`。
**幂等**：已存在的 `JWT_SECRET / AES_KEY / HMAC_KEY` 原样复用，绝不重新生成（换密钥会导致全员 token 失效、库里加密字段解不开）。仅轮换用 `-Force`，且必须在维护窗口。

### 5.3 创建 4 个镜像

统一上下文 = `deploy/docker/`，用 `-f` 指定 Dockerfile：

```bash
docker build -f deploy/docker/Dockerfile.cloudbase-api        -t booking-api:2.2.1          deploy/docker/
docker build -f deploy/docker/Dockerfile.cloudbase-message    -t booking-message-service:1.1.0 deploy/docker/
docker build -f deploy/docker/Dockerfile.cloudbase-classroom  -t booking-classroom-service:1.0.0 deploy/docker/
docker build -f deploy/docker/Dockerfile.cloudbase-frontend   -t booking-web:latest          deploy/docker/
```

或用构建脚本一次性完成（`--docker-push` 才会外推，默认关闭）：

```bat
build-all.bat                :: 根，3 个 -f（api/message/web）
deploy\build-all.bat         :: 4 个 -f（api/message/classroom/web）
```

| 镜像 | 基础镜像 | 端口 | 启动 profile |
|---|---|---|---|
| `booking-api:2.2.1` | eclipse-temurin:17-jre-jammy | 8081 | 默认 |
| `booking-message-service:1.1.0` | 同上 | 8090 | `cloud` |
| `booking-classroom-service:1.0.0` | 同上 | 8092 | `cloud` |
| `booking-web:latest` | nginx:alpine | 8080 | nginx（非 root 不能监听 80） |

> ★ `deploy/docker/.dockerignore` 刻意**不忽略** `*.jar` / `dist/` / `*.template` / `*.sh`——这些是 `COPY` 源，忽略会让构建静默失败。

### 5.4 镜像 tag 规范（链路 C 回滚的地基）

`deploy/docker/build-images.sh` 用 `<pom版本>-<git short sha>[-dirty]`，例如 `lesson/booking-api:2.2.1-a1b2c3d`。同一个 2.2.1 改三次也能分清是哪次；工作区有未提交改动会带 `-dirty`，**正式发布必须先提交再构建**。

## 六、P2 链路 A：微信云托管部署

### 6.1 前置

- 云托管环境已创建，MySQL / Redis 就绪；三库 `lesson_appointment` / `message_center` / `classroom` 结构已导入。
- `deploy/docker/env/` 已生成（5.2），`envParams` 已粘进 `container.config.*.json`。
- `resolver-entrypoint.sh` 启动时**强校验** `API_UPSTREAM` / `MSG_UPSTREAM`（`CLASSROOM_UPSTREAM`）非空，缺一个容器直接起不来。

### 6.2 创建服务 / 版本

| 服务 | `container.config` 规格 | 端口 | 最小/最大实例 | CPU/内存 |
|---|---|---|---|---|
| api | `container.config.api.json` | 8081 | 1 / 10 | 0.5 / 1G |
| message-service | `container.config.message.json` | 8090 | 1 / 10 | 0.3 / 1G |
| classroom-service | `container.config.classroom.json` | 8092 | 1 / 10 | 0.5 / 2G |
| frontend | `container.config.frontend.json` | 8080 | 1 / 10 | 0.25 / 0.5G |

**方式 A：控制台「新建服务 → 新建版本」**（推荐首次）
- 上传方式选「**上传镜像**」（最稳，构建可控）；或「上传代码包/Dockerfile」时 `dockerfilePath` 用 B2 修好的新名。
- 端口/规格按上表填；环境变量注入 `envParams`。
- `API_UPSTREAM` 等必须用云托管「服务设置 → 内网访问」复制的域名，**带端口且端口 = 该服务发布时填的容器端口**：
  `http://api-xxxxxxxx.<region>.internal-run.tcloudbase.com:8081`
  ★ 绝不可用 `*.svc.cluster.local`（云托管无此 DNS，实测 NXDOMAIN）。

**方式 B：CLI**（适合 CI/CD）

```bash
npm install -g @wxcloud/cli && wxcloud login
wxcloud deploy --env prod-1g0xxxxx --serviceName booking-api      --containerPort 8081
wxcloud deploy --env prod-1g0xxxxx --serviceName message-service  --containerPort 8090
```

### 6.3 发布 / 灰度 / 验证 / 回滚

- 新建版本时可设灰度比例，观察正常再全量；保留最近 2–3 个版本。
- 默认域名 `https://<service>-<envid>.sh.run.tcloudbase.com` 已带 HTTPS，可直接加入小程序 request 合法域名。
- 验证：`GET /api/v1/system/info` 返回 2.2.1；消息 `/api/v1/message/system/info`；课堂 `/api/v1/rtc/providers`。
- 回滚：控制台「版本列表 → 回滚到上一版本」，一键退回。

## 七、P2 链路 B：自建云服务器（systemd + nginx）

### 7.1 前置

- 服务器：`/opt/lesson`（jar/env/脚本）、`/var/www/frontend`（dist）、`/var/www/classroom-app`（课堂 App www）。
- 三服务 systemd：`booking` 8081 / `message-service` 8090 / `classroom-service` 8092；nginx 在前端。
- 共用密钥文件 `/etc/lesson/keys.env`（`JWT_SECRET / AES_KEY / HMAC_KEY`）——**唯一密钥源**，三份 `xxx.env` 里不得重复这三个键（会冲掉共用密钥，表现为「登录成功后立刻 401」）。
- Redis 必须跑（课堂在线状态的唯一真相源）；**不要配 allkeys-lru**（key 被逐出会把在课学生判成掉线）。

### 7.2 创建产物并一键上传

```bash
# 本地：先构建（产物收口到 deploy/jars 与 deploy/dist）
build-all.bat --skip-docker        # 或 deploy/build-all.bat --skip-docker
node deploy/collect-artifacts.js   # 收口快照（若脚本存在）

# 一键上传（9 步）
SERVER=root@1.2.3.4 bash deploy/upload-to-server.sh
```

9 步依次为：① 3 个 jar → ② 前端 dist → ③ 课堂 App www → ④ SQL 初始化脚本（三库）→ ⑤ systemd 单元 + env 模板 → ⑥ Nginx 配置 + 备份脚本 + logrotate → ⑦ 日志/课堂存储目录 + logrotate 校验 → ⑧ 启用软链并平滑 `reload nginx` → ⑨ 分流自检（三端口）。

> 默认只启用纯 HTTP 的 `booking-ip`；**无域名/无证书切勿启用 443 SSL 块**，否则 `nginx -t` 直接失败整站起不来。

### 7.3 服务器侧收尾（脚本打印的清单）

```bash
sudo cp /opt/lesson/keys.env.template      /etc/lesson/keys.env        # ★ 先填真实密钥
sudo cp /opt/lesson/booking.env.template   /etc/lesson/booking.env
sudo cp /opt/lesson/message.env.template   /etc/lesson/message.env
sudo cp /opt/lesson/classroom.env.template /etc/lesson/classroom.env
sudo chmod 600 /etc/lesson/*.env
cd /opt/lesson && mv -f booking_api.jar.new booking_api.jar \
  && mv -f message-service.jar.new message-service.jar \
  && mv -f classroom-service.jar.new classroom-service.jar
sudo systemctl daemon-reload && sudo systemctl restart booking message-service classroom-service
sudo nginx -t && sudo systemctl reload nginx
```

### 7.4 验证 / 巡检 / 回滚

- `sudo bash /opt/lesson/healthcheck.sh`（cron 每 5 分钟）：磁盘/日志体积、上课提醒应发却 0 条、message-service 不可达。
- 一次性配置：每日备份 `backup.sh`（库留 14 天、oss 留 3 天）；告警巡检 cron。
- **恢复必须库 + 文件目录一起**（只回库不回文件 = 记录都在、点开全 404）。
- 回滚：systemd 单元未删，可退回上一版 jar；`deploy/backup.sh` 提供库与 oss 的回退源。

## 八、P2 链路 C：本地 Docker 单机（save/load + 前后版本切换）

> 这套是 `deploy/docker/` 里**另一套**本地 Docker 方案（`Dockerfile`、`docker-compose.yml`、`network_mode: host`），与云托管的 `Dockerfile.cloudbase-*` 互不影响，勿混用。

### 8.1 前置

- 服务器按 `deploy/docker/README.md` 第四节装好 Docker、建 `lesson` 账号与目录、`keys.env` 就位。
- 本地 `deploy/jars/` 已有 3 个 jar（先跑 `build-all.bat --skip-docker` + 产物收口）。

### 8.2 创建镜像（tag 带 sha）

```bash
bash deploy/docker/build-images.sh                 # 全部三个
bash deploy/docker/build-images.sh booking         # 只构建一个
# → lesson/booking-api:2.2.1-a1b2c3d 等，产物 tag 写入 /tmp/lesson-image-tags.txt
```

### 8.3 一键发布（6 步，失败自动回滚）

```bash
SERVER=root@1.2.3.4 bash deploy/docker/release.sh
SERVER=root@1.2.3.4 bash deploy/docker/release.sh --only booking
SERVER=root@1.2.3.4 bash deploy/docker/release.sh --skip-build     # 镜像已构建
SERVER=root@1.2.3.4 bash deploy/docker/release.sh --frontend-only
```

流程：连通性检查 → `docker save | gzip` → `scp` → 远端 `docker load` → `switch.sh` 切版本（**healthcheck 通过才算成功，失败自动回滚**）→ 前端 `/var/www/releases/<bundle>` 切换。
用 save/load 而非推 registry：单机、发布频率低，少一个要打补丁的组件。

### 8.4 验证 / 回滚

```bash
# 服务器上
sudo bash switch.sh status                          # 看当前版本与容器状态
sudo bash rollback.sh booking                       # 回到上一成功版本
sudo bash rollback.sh booking 2.2.1-a1b2c3d         # 回到指定版本
```

- ★ `docker compose up -d` 返回 0 ≠ 部署成功，**必须走 `switch.sh`**（切换 + 健康检查 + 失败自动回滚）。
- 发布脚本从不 `docker rmi` 旧镜像，保证回滚随时可用；清理只清 30 天前的 tag。
- compose 里 `keys.env` 必须排在前、`xxx.env` 在后（后加载覆盖先加载）。

## 九、三套链路对照

| | 链路 A 微信云托管 | 链路 B 自建服务器 | 链路 C 本地 Docker 单机 |
|---|---|---|---|
| 入口 | `container.config.*.json` + `wxcloud deploy` / 控制台 | `deploy/upload-to-server.sh` | `deploy/docker/release.sh` |
| 产物形态 | 4 个镜像（`Dockerfile.cloudbase-*`） | 3 jar + 2 个前端目录 + nginx conf | 3 个镜像（`Dockerfile`） + 前端 bundle |
| 分流 | 云托管内网域名 + `resolver-entrypoint.sh` | nginx 站点配置（5 份 conf） | `network_mode: host` + nginx |
| 密钥 | `envParams` / `cloud.env.*`（gen-cloud-env.ps1） | `/etc/lesson/keys.env`（唯一密钥源） | `keys.env` + `xxx.env`（compose 顺序敏感） |
| 切换/回滚 | 控制台版本列表回滚 | systemd 退回 jar + `backup.sh` | `switch.sh` / `rollback.sh`（健康检查门禁） |
| 适用 | 微信生态、弹性扩缩、免运维 | 已有云服务器、要完全掌控 | 单机、低频发布、要版本可追溯 |
