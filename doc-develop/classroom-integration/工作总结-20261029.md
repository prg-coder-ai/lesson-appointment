## 二、包2·P1 教学闭环（`aeb16151`）

### 根因
原 WS 是**透明转发**：`ClassroomSignalHandler` 把报文原样 broadcast 给同房间的人，服务端不理解任何语义。于是：
- 教师关摄像头，学生端无感知（`cam-state` 只是前端自说自话）；
- 全员禁言只在本地静音，刷新即失效；
- 点名只有记录、没有强提示；
- 白板刷新即丢，`saveWhiteboardSnapshot` 零调用；
- 迟进/重连的人收不到任何当前状态。

### 解法的三层地基
| 组件 | 职责 |
|---|---|
| `WsRoomRegistry` | 把 signal / whiteboard 两通道 session 收口到一张注册表，让 **REST 控制器与定时任务也能向房间广播** |
| `ClassroomLiveState` | 内存权威态（muteAll / handRaised / cameraOff / wbGrants / wbSnapshot）；仅 `mute_all` 落库 `classroom_runtime_state` |
| `ClassroomSignalService` | 信令子类型路由（`hand` / `hand:approve` / `mute-all` / `cam-state` / `chat` / `wb:grant`）：改状态 → 权威广播 → 写教学事件流水 |

进房即 `pushInitialState`，把当前禁言/摄像头/举手/白板授权推给新连上的人——这一条同时修掉了「迟到者状态错乱」。

### 同时补齐
随机点名（`RollCallService.pickRandomStudent`）+ `rollcall:start` 强提示广播、白板持久化与 2s 节流落盘 / 重连重放、学生举手→教师批准开麦、聊天服务端禁言拦截（回 `chat:rejected`）、学生上传与教师点评 UI、`SubmissionReq` 校验。
F3-03/04 的 **IDLE 宽限**：`OnlineStateManager` 记最后心跳时间戳，掉线判定三级（ONLINE ≤30s / IDLE 30~60s / OFFLINE >60s），闪断不再被误判离开。

## 三、包3·P2 媒体与录制（三个子包）

### 3A RTC 抽象模型（你点名要的那块，`f7e174b4`）

设计目标：**前端只认一份契约，换服务商后端换实现、前端一行不动**。

```
RtcProvider (SPI)  ←→  RtcProviderRegistry (选型 + 降级)  ←→  MediaService (薄门面)
                                    ↓
                         RtcJoinInfo (统一下发结构)
```

`RtcJoinInfo` 的关键字段各有明确分工：`topology` 决定前端用 mesh 还是 SFU 引擎、`sdkType` 决定加载哪份 SDK、`token` 是厂商凭证（mesh 为空）、`iceServers` 只对 mesh 有意义。

四个 provider：

| provider | 拓扑 | 凭证实现 | 状态 |
|---|---|---|---|
| `native-mesh`（默认/兜底） | MESH | STUN + **coturn REST 临时凭证**（HMAC-SHA1，不落固定账密）；`maxPeers` 硬上限 | 零依赖，永远可用 |
| `livekit` | SFU | HS256 JWT **纯 JDK 签发**，`video` claim 承载 `canPublish`/`room` | 配 url+apiKey+secret 即用，可自建 |
| `trtc` | SFU | UserSig v2 = `base64(zlib(json))`，CRC32 派生数字房号 | 配 sdkAppId+secretKey 即用 |
| `agora` | SFU | **反射**官方 `io.agora:authentication` | 未引入依赖 → `available=false`，自动跳过 |

三条设计纪律：
1. **房间号由 scheduleId 派生**，客户端传不进来（拿到 token 也进不了别人的课堂）；
2. **权限写在凭证里**（LiveKit 的 `video.claim`），学生即使解出 token 也改不了推流权限；
3. **缺配置自动降级 mesh 并打 WARN**，`GET /api/v1/rtc/providers` 暴露 `configured / active / degraded`——「配了 livekit 却一直跑 mesh」这种事故不留痕是查不出来的。

前端拆成 `js/classroom/rtc/{rtc-engine,engine-mesh,engine-sdk}.js`：工厂按 topology 选引擎，SDK 加载或进房任何一步失败**自动回落 mesh**，`classroom-rtc.js` 退化为门面，controls/teacher/main 三个模块零改动。

生命周期接线：`startClass` 建房、`endClass` **先释放房间再做收尾**（房间按时间计费，不能等出勤那串 DB 操作跑完）。

### 3B 对象存储真实化（`a306bbd2`）

修复前的真相：`OssClient` 四个方法全是 stub，`generateSignedUrl` 拼的是假地址 `?expire=2h`；讲稿/作品只接一个客户端传来的 `ossKey`——**服务端既不存文件也不校验**，前端也没有任何能产出 `ossKey` 的入口。

现在：
- `ObjectStorage` SPI + `LocalFsObjectStorage`：原子写（`tmp → ATOMIC_MOVE`，进程被 kill 不留半截文件）、key 白名单 + 规范化后必须仍在 root 内（防目录穿越）；
- `StorageService`：分片上传（meta.json 存 `.uploads/<id>/`）、**断点续传**（`GET /uploads/{id}` 回传已传分片）、合并缺片**明确报缺哪几片**（不静默拼出坏文件）、`complete` 幂等（只清 `.part` 保留 meta）；
- 签名 URL：`base64url(key) + exp + hex(HMAC-SHA256(key\n exp))`，默认 2h；
- `GET /api/v1/files/{token}` 从 `AuthInterceptor` **exclude**（`<video>/<iframe>/<img>` 带不了 Authorization 头），实现**单区间 Range 206**——这是回放拖动/倍速的前提；
- 讲稿 `POST /materials/file` 直传 ≤100MB + `GET /materials/current`，翻页落库后广播 `page:state`（**此前「学生跟随翻页」完全没实现**）；PDF 用 `#page` 翻页不重下整份文件。

### 3C 录制闭环与回放（`1e40e3bf`）

修复前 `startRecording/stopRecording` 零调用，`classroom_recording` 永远空表。

- `RecordingBackend` SPI：`CLIENT`（教师端 MediaRecorder 录本地上行，录完 5MB 分片上传）为真实现；`CLOUD` 需要厂商云录制 REST + 回调验签，**没实现就不写假实现**，配了也降级并 WARN；
- `RecordingService`：`start` 幂等（复用进行中记录，防「幽灵录制」）、`finish` 校验 ossKey 已落盘、下课 `markOrphansFailed`（教师直接关页面时不留永远"录制中"的记录）、`purgeExpired` **先删对象再删记录**（只删记录会留下没人认领的文件，磁盘只涨不降）；
- 权限与合规：只有教师/管理员能开录，开停录都广播 `record:state`，**学员端有「老师正在录制本堂课」横幅**（合规底线，不能偷偷录）；
- `replay.html` + `replay.js`：录制列表（时间/时长/状态）+ 签名 URL 播放，Range 已支持，拖动与倍速是原生能力。

## 七、遗留与待拍板

### 需要你拍板（技术路线，不是缺陷）
1. **云录制**：要让「学生画面也进录制文件」必须接厂商云录制 REST + 回调验签（LiveKit Egress / 声网云录制 / TRTC 云端录制）。当前只有 CLIENT（只录教师本地上行）。

3. **限流阈值**：enter 30 / upload 30 / rollcall 10 / submit 20 是拍的初值，需要按真实课堂并发压一遍再定。

### 明确的坑位
- `GET /api/v1/admin/*` 全部走 `AuthContext.isManager()`，**没有单独的运营角色**；旁听（F8-02）仍无独立权限模型。
- 聊天不落库（设计如此），所以 F8-03 的「聊天查阅」只能记「谁看了」，看不到内容本身。
- 多课次精确进入（`scheduleId~N` 的 classIndex 透传）仍未做，入口只到排期级首课次。
- 过期清理是物理删除，无归档（F8-05 范畴）。
- `RecordingService.purgeExpired` 依赖 `expire_at`；历史遗留的 `expire_at IS NULL` 记录按 `created_at + retentionDays` 兜底。
