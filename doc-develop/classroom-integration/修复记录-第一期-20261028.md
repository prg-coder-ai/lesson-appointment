## 二、逐项改动

### P0-A1 统一 base_path 契约

**问题**：`sys_eclassroom_instance.api_base_path` 默认写的是 `/api/v1/classroom`，而 classroom-service 的路由是 `/api/v1/schedules/events`、`/api/v1/classrooms/**`。拼接后 404，且推送是 best-effort，线上只看到"课堂状态不动"。

| 文件 | 改动 |
|------|------|
| `api/sql/schema/20261027-0900-eclassroom-tenant.sql` | `api_base_path` 默认 → `/api/v1`；`ws_base_path` 默认 → `''` |
| `api/sql/patch/20261028-1700-classroom-integration-fix.sql` | 新增：修正存量脏值（`/api/v1/classroom`、`/ws`），幂等 |
| `EclassroomService` | 常量 `DEFAULT_API_BASE_PATH=/api/v1`、`DEFAULT_WS_BASE_PATH=''`；`normalizeBasePath` 去尾斜杠；**存量脏值 `/api/v1/classroom` 显式回退并 WARN**，避免等运维改库才能用 |

**语义定稿**：`api_base_path` = API 根（含版本前缀、不含业务段）；`ws_base_path` = WS 根（空串=host:port）。拼接方负责补 `/schedules/events`、`/ws/classrooms/{sid}/*`。

### P0-A2 出勤回流 DTO 两侧归一

两侧原本是两套命名，只有 `scheduleId` 能对上：

| 旧（booking） | 新（= classroom 侧，按需求 8.3） |
|---|---|
| `classroomId` | `courseId` + `classroomStatus` |
| `startTime` / `endTime` | `actualStart` / `actualEnd` |
| `durationMinutes` | （无，由课堂侧按实际时长给 `effectiveMinutes`） |
| `items[].status` | `items[].attendanceStatus` |
| `items[].joinTime/leaveTime` | `items[].checkInAt/checkOutAt` |
| `items[].onlineMinutes` | `items[].effectiveMinutes` |
| — | `consumptionVersion` |

同批把 `AlertCallbackReq` 也对齐（旧：`alertId/classroomId/level/alertTime`；新：`courseId/severity/occurredAt`）。

### P0-A3 回调改为原文验签

`ClassroomCallbackController` 四个端点全部改为 `@RequestBody String rawBody` → 对原文 `verify` → 再反序列化。
旧实现「反序列化 → 重新序列化 → 验签」，两侧字段集/顺序任何差异都会 403。

单测 `ClassroomCallbackControllerTest` 新增一条**键序打乱也必须验签通过**的回归用例，钉住这个坑。

### P0-A4 出勤与课时消耗落库

新增 `lesson_attendance`（DDL 见 `sql/schema/20261028-1700-lesson-attendance.sql`）+ `LessonAttendance` / `LessonAttendanceMapper` / `LessonAttendanceService`。

- 幂等键 `(schedule_id, user_id)`，重复回调 upsert；
- `consumption_version` 小于库内值整条丢弃（`stale`）；
- **租户由 `course_schedule.tenant_id` 反查**，不采信回调载荷（免登录通道，载荷可伪造）；
- 回调线程无租户上下文，插件会兜底拼 `tenant_id = -1`，故 Mapper 方法全部 `@InterceptorIgnore(tenantLine="true")` + 显式 tenantId；
- 响应体返回 `inserted/updated/stale/invalid`，便于对端对账。

**有意不做**：不改 `appointment.status`、不扣 `student_balance`。课时扣减要和请假/退费档位（`refund_snapshot`）统一口径，否则会「课堂扣一次、退费又退一次」。本表先把「课上成什么样」钉死。

### P0-A5 回调前缀与前端路由解耦

nginx 的 `location /api/v1/classrooms/ → 8092` 会抢走 booking 的回调（同前缀）。回调改为独占前缀：

- 后端：`/api/v1/classroom-callback/{attendance|events|alerts|reconcile}`
- 同步四处白名单：`SecurityConfig` / `JwtAuthenticationFilter` / `WebMvcConfig`（双路径形态）/ `tools/check-authz-declarative.mjs` 的 `PERMIT_ALL`
- nginx 两个 conf 各加一条显式 `location /api/v1/classroom-callback/ → 8081`
- classroom-service 的 `CallbackService` 三个 URL 同步改

顺带修掉 `check:endpoints` 的两处硬编码（`/api/v1/eclassroom/config` 改取 `ApiPaths.ENDPOINTS.ECLASSROOM_CONFIG`），该守卫由红转绿。

### P0-A 附带：回调重试与死信

`CallbackService` 原样只打日志（注释自承"M1 阶段降级"）。现：

- 独立调度器 `callbackRetryScheduler`（不占用 `@Scheduled` 的对账线程）；
- 退避 1/5/15 分钟，共 3 次；
- **必须检查响应体 `code`**：本项目契约是 HTTP 200 + Result.code，验签失败也回 200，只看 HTTP 会记成"投递成功"；
- `400/401/403/404` 判永久失败 → 直接死信（`[DLQ]` ERROR 日志含完整报文）；
- 连接/读取超时 3s/8s（默认无超时会挂死回调线程池）。

### P0-B1 排期事件接口鉴权

`/api/v1/schedules/events` 改为原文 HMAC 验签（与出向回调同一把 `crypto.hmac-key`），并补 `Validator` 显式校验（手工反序列化后 `@Valid` 不生效）。booking 侧推送改为「序列化一次 → 同一字符串既签名又发送」。

`HmacSigner.verify` 改用 `MessageDigest.isEqual` 恒定时间比较，空签名一律失败。

### P0-B2 课堂访问守卫

新增 `ClassroomAccessGuard`，判定顺序：课堂不存在(40401) → 管理员/平台管理员放行 → system 放行 → 教师须为 `teacherId` 或名单内教师(40302) → 学生须在名单且未被移出(40402/40301) → 跨租户拒（`tenant_id>0` 时才生效，等 P0-C 修完自动激活）。

接入 6 个 Controller 共 17 个端点：status/enter/leave/start/end/kick、attendance(2)、materials(3)、rollcall(3)、submissions(3)、recordings(2)。

### P0-B3 WebSocket 握手鉴权 + 房间隔离

- 新增 `WsHandshakeAuthInterceptor`：校验 `access_token`（或 `Authorization: Bearer`）→ 解析 `scheduleId` → `assertAccess` → 写入 session 属性；
- 三条通道全部 `addInterceptors`；
- `WhiteboardHandler` / `ClassroomSignalHandler` 由「全局 sessions 广播」改为 `Map<scheduleId, Set<session>>` 房间广播，并对 `sendMessage` 加锁（`WebSocketSession` 非线程安全）；
- `HeartbeatHandler`：scheduleId 从 session 属性取（原来取 `parts[4]`，实际拿到的是通道名 `heartbeat`，在线状态全写进一个假 key）；心跳报文里的 `userId` 不再参与身份判定（防"替别人刷心跳"）。

## 三、修复过程中新发现的 5 个缺陷（原分析报告未覆盖）

| # | 缺陷 | 证据 | 处置 |
|---|------|------|------|
| N1 | **两服务 JWT 密钥不一致**（差 1 个字符：`...Duw06Zs...` vs `...Duw062Zs...`）。主系统签发的 token 在课堂服务**一律 401**——原报告"共享 JWT 密钥域 ✅"是错的 | 冒烟 T1b 报"登录状态无效"，逐字节比对 882 vs 883 | 已对齐（882==882）；aes/hmac 两把本来就一致 |
| N2 | `Result.fail` 白名单只有 HTTP 码，而 `GlobalExceptionHandler` 直接下发 5 位业务码 → 在异常处理器内部抛 `IllegalStateException`（日志 `Failure in @ExceptionHandler`）→ **所有业务错误变 500** | 冒烟 T9/T10/T12/T13 全 500 | classroom-service 的 `ALLOWED_CODES` 补入 16 个 `ErrorCodes`（该文件不在 `check:result-contract` 扫描范围内，主系统契约不受影响） |
| N3 | `reconcile_log` 重复写会撞主键 → catch 里再写一次 → 再次撞键 → 500；且 `fail_reason` varchar(500) 装不下 SQL 异常全文（`MysqlDataTruncation`） | 冒烟 T2 首次跑出 500 + 建表报错栈 | `logEvent` 容错（吞 DuplicateKey/截断 50/500 字符），审计旁路不再拖垮主线 |
| N4 | 推送的时间字段是 `yyyy-MM-dd HH:mm:ss`，对端 `LocalDateTime` 默认只认 ISO → **400 请求体格式错误**（且推送失败只记 warn） | api 日志 `err=400 : {"code":400,"message":"请求体格式错误"}` | 发送侧归一为 ISO；接收侧加宽松反序列化（两种格式都收）；顺便补上原本漏发的 `duration`，`version` 由硬编码 1 改为 epoch 秒（否则"按 version 丢弃旧事件"永远不生效） |
| N5 | **eclassroom 两张表在库里根本不存在**（`sys_eclassroom_instance` / `sys_tenant_eclassroom`），课堂功能在该环境完全不可用；`classroom` 库也未建 | 查 `information_schema` 返回空 | 已建（schema 脚本 + 8 张表），DDL 无数据损失 |

### 6.2 需要拍板的 2 件事
