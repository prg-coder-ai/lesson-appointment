## 1. 背景与根因

第三期结束后，课堂生命周期仍**完全依赖人工**调 `/start`、`/end`：到点不会自动开课、超时不会自动下课、掉线不会自动判离线、点名不会超时、过期历史数据永不清理。
已有的定时任务只有 `DailyReconcileTask` / `WeeklyFullCheckTask`（对账）和 booking 侧 `LessonSettlementTask`（账务兜底），
**课堂侧的 7 个生命周期扫描器是空的**，属于"功能缺失"而非"不完善"。

补充后，课堂才具备无人值守的自愈能力。

## 3. 七个扫描器逐一说明

| # | 扫描器 | 频率 | 选行（SQL/Mapper） | 动作 | 容错/幂等 |
|---|---|---|---|---|---|
| 1 | 就绪提醒 | `0/30 * * * * ?` | `listReadyToRemind(readyBeforeStartMinutes)`：SCHEDULED 且 `start_time ≤ now+10min` | `markReady`（SCHEDULED→READY）+ 推 `READY_REMINDER` 告警（回调 booking `/alerts`） | `markReady` 仅在真翻成功时返回 true→才发提醒；非 SCHEDULED 直接跳过，每轮可重跑 |
| 2 | 自动开课 | `0/30 * * * * ?` | `listDueToStart`：SCHEDULED/READY 且 `start_time≤now` 且 `end_time≥now` | `startClass`（→LIVE，写 `actual_start`） | 全局 `classroom.auto-start=false` 整轮跳过；单课堂 `auto_start=false` 跳过该课堂 |
| 3 | 自动下课 | `0/30 * * * * ?` | `listOverdueLive(autoEndGraceMinutes)`：LIVE 且 `end_time ≤ now - 5min` | `endClass`（→CLOSED，触发 `closeAfterEnd` 收尾：出勤核算 + 课时回流） | 复用 `endClass`，与人工下课同口径；状态非 LIVE 抛异常被单条 catch |
| 4 | 学生掉线判定 | `0/20 * * * * ?` | `listByStatus("LIVE")` → `listOnline`（DB `online_state=ONLINE`） | 对每条：Redis key 消失 → `leave(...,"timeout")` 置 OFFLINE | 以 Redis 在线 key 为唯一真相源；是 WS 断连事件丢失时的安全兜底 |
| 5 | 点名超时 | `0/30 * * * * ?` | `listExpiredPending(now - 2min)`：PENDING 且 `initiated_at` 早于阈值 | `updateById` 置 `TIMEOUT` + `answered_at=now` | 仅改 PENDING；已应答/已超时的不在此列 |
| 6 | 教师掉线结课 | `0/40 * * * * ?` | `listByStatus("LIVE")` → `getTeacher` | 教师 `OFFLINE` 且 `leave_time` 距现已超 `teacher-drop-grace-seconds(120)` → `endClass` | 只消费"教师已离线 + 离开时刻"结论；宽限内/无教师记录→不动，避免误杀 |
| 7 | 过期数据清理 | `0 30 3 * * ?`（每日 03:30） | 各表 `deleteBefore(created/received/end/initiated_at ≤ now - 保留天数)` | 删 `presence_segment` / `rollcall` / `reconcile_log` / `session_record` / `submission` / `recording` | 各表独立删除，互不阻塞；日志打出各类删除条数 |

> 频率设计：掉线判定(20s) 早于教师掉线结课(40s)，且教师宽限(120s) ≫ 两者间隔，即使顺序抖动也能在下一轮补齐，不会误杀。

## 4. 关键设计决定

1. **状态流转一律复用 `ClassroomService` 的 `markReady/startClass/endClass`**，与教师手动"开始/结束"同口径。
   特别是自动下课走 `endClass` → `closeAfterEnd`，保证"自动"和"人工"都做完整的出勤核算 + 课时回流，不会出现两条口径。
2. **每个扫描器自包含 `try/catch`**：单条课堂/记录处理失败只记 ERROR，绝不污染整轮或别的课堂（单测 `scanReadyReminder_resilientToItemError` 钉住）。
3. **掉线判定的真相源是 Redis 在线 key**，不是 DB 的 `online_state`（DB 只是展示态）。`OnlineStateManager.refresh` 的 TTL 改为可配，与 `classroom.offline-timeout-seconds` 对齐，避免"健康客户端因 TTL 过短被误判掉线"。
4. **教师掉线结课不直接判断"教师是否刚掉线"**，而是消费扫描器 4（或 WS 断连处理器）写下的"教师 OFFLINE + `leave_time`"结论，再叠加宽限。这样扫描器之间职责清晰、可独立重跑。
5. **自动开课双闸**：全局开关 + 单课堂 `auto_start=false`，给"想手动掌控开课"的租户留出口。

## 5. 配置项（新增/调整）

```
classroom.ready-before-start-minutes=10     # 就绪提醒窗口
classroom.auto-start=true                    # 自动开课全局开关
classroom.auto-end-grace-minutes=5           # 自动下课宽限（分钟）
classroom.offline-timeout-seconds=60         # 在线 key TTL / 掉线判定宽限（秒），≥心跳间隔
classroom.teacher-drop-grace-seconds=120     # 教师掉线结课宽限（秒）
classroom.rollcall-timeout-minutes=2         # 点名超时（分钟）
classroom.presence-retention-days=180
classroom.rollcall-retention-days=90
classroom.reconcile-retention-days=365
classroom.session-retention-days=180
classroom.submission-retention-days=730
classroom.recording-retention-days=90
classroom.retention.cron=0 30 3 * * ?        # 过期清理时刻
spring.task.scheduling.pool.size=8           # 2→8（9 个常驻扫描器）
```

## 6. 待确认 / 遗留

- 扫描器已接 `CallbackService.sendAlert`，但就绪提醒告警的**前端展示/触达渠道**（站内信/短信/推送）尚未建设——目前只回流到 booking 的 `/alerts` 落库。
- 教师掉线结课：若教师**从未进入过课堂**（无 membership 记录）则不会自动结课——这是有意的安全保守（避免"教师迟到"被误杀）；若业务要求"开课后 N 分钟教师未入场即结课"，需另加一条"教师未入场超时"扫描。
- 过期清理目前是物理删除；若需审计留存，应改为归档表或软删（F8-05 范畴，未纳入本期）。
- 历史遗留守卫 `check:cascade` / `check:secret-env` 仍红（非本期引入，见第三期记录），提交沿用 `SKIP_CASCADE=1 SKIP_SECRET_ENV=1`。
