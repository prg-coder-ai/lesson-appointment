# 多租户特性开关与上课/预约页面分离方案

> 日期：2026-10-27
> 背景：部分租户不需要线上课堂模块，前端需按租户隐藏课堂相关界面；上课页面与预约页面需架构级分离。

---

## 一、需求分析

### 1.1 核心诉求

| # | 需求 | 说明 |
|---|------|------|
| 1 | 租户级模块开关 | 平台管理员可为每个租户启用/禁用"线上课堂"模块 |
| 2 | 前端按租户隐藏 | 未启用课堂的租户，前端不显示任何课堂相关 UI（菜单、按钮、页面） |
| 3 | 上课页面与预约页面分离 | 课堂页面（RTC/白板/聊天）与预约页面（CRUD 管理）架构解耦 |
| 4 | 向后兼容 | 现有租户默认行为不变；新租户按需配置 |

### 1.2 约束条件

- 前端为纯 MPA（多页应用），无框架、无路由库，vanilla JS + axios
- 后端为微服务架构：booking-api(8081) + message-service(8090) + classroom-service(8092)
- 多租户隔离已成熟：JWT claims 携带 tenantId → TenantInterceptor → TenantContext(ThreadLocal) → MyBatisPlus 插件自动拼 SQL
- **当前不存在任何特性开关机制**（无表、无字段、无注解、无前端代码）

## 二、现状分析

### 2.1 租户模型现状

**租户主表** `sys_tenant`（`api/sql/schema/20261013-0400-lesson_appointment-schema.sql:684-709`）：

```

industry_id, expire_time, offline_time, remark, referred_by,
trial_status, trial_expire_time, creator_account, deleted,

```

- **无** `features` / `capabilities` / `modules` / `enabled_modules` 字段
- 关联表 `sys_tenant_package` 是**资源配额**（course/teacher/student 的 limit+current），非功能开关
- `sys_system_config` 是**平台级全局配置**（监控参数），非租户级

### 2.2 tenantId 流转链路

```
登录 → JwtUtil.generateToken(tenantId, userId, role)
     → JWT claims: {sub: userId, role, tenantId}
     → 请求携带 Authorization: Bearer <token>
     → TenantInterceptor.preHandle(): 解析 tenantId → TenantContext.setTenantId()
     → MyBatisPlusConfig: TenantLineInnerInterceptor 自动拼 tenant_id = ?
     → 平台管理员 tenantId=0: 跳过租户隔离（ignoreTable 返回 true）
```

- 三服务（booking-api / message-service / classroom-service）共享同一 `jwt.secret`，token 跨服务通用
- `TenantController`（`api/.../controller/TenantController.java`）提供租户 CRUD，但无模块配置接口

### 2.3 前端导航现状

**四端入口**：`admin.html` / `teacher.html` / `student.html` / `platform_admin.html`

统一布局骨架：

导航切换：`menu-item click` → `loadAdminPageContent(key)` → `switch(key)` → 调用 `renderXxx()` 或 `window.location.href` 跳转

## 三、特性开关方案设计

### 3.1 方案选型

| 方案 | 描述 | 优点 | 缺点 | 评价 |
|------|------|------|------|------|
| A. sys_tenant 加 JSON 列 | `ALTER TABLE sys_tenant ADD COLUMN enabled_modules JSON` | 最简单，单表查询 | JSON 列难索引，语义不清晰 | ★★★ |
| B. 新建 sys_tenant_module 表 | `(tenant_id, module_key, enabled, config)` | 规范化，可扩展，易查询 | 多一张表，需 JOIN | ★★★ |
| C. 复用 sys_package_template | 在套餐模板上挂模块定义 | 复用现有套餐模型 | 套餐是资源配额语义，非功能开关；租户无法单独覆盖 | ★★ |
| D. 复用 sys_system_config | 加 tenant_id 列做租户级配置 | 复用配置基础设施 | sys_system_config 是平台级，改动语义混乱 | ★★ |
| **E. eclassroom 实例表 + 租户关系表** | `sys_eclassroom_instance`（实例地址/端口）+ `sys_tenant_eclassroom`（租户-实例关系） | **同时解决特性开关 + 服务发现**，支持多实例部署，语义最清晰 | 两张表 | ★★★★★ **推荐** |

**选定方案 E**：eclassroom 实例表 + 租户关系表。

理由：
1. **一表多用**：租户在 `sys_tenant_eclassroom` 中有记录 = 启用课堂；JOIN 实例表即可拿到 API 地址和端口，同时解决特性开关和服务发现两个问题
2. **支持多实例部署**：不同租户可关联不同的 classroom-service 实例（大型 SaaS 场景按区域/负载分配课堂服务器）
3. **服务间通信不再硬编码**：booking-api 需要调用 classroom-service 时，从表中查地址，不再依赖 nginx 硬编码或配置文件
4. **运维灵活**：可动态切换课堂服务器地址（如故障迁移），不需要改配置文件重启
5. **语义清晰**：`sys_eclassroom_instance` = 课堂服务实例注册表；`sys_tenant_eclassroom` = 租户使用了哪个课堂实例
6. **向后兼容**：租户在 `sys_tenant_eclassroom` 中无记录 = 未启用课堂（默认不启用，与现有行为一致——当前没有租户使用课堂）

> 与方案 B 的区别：方案 B 是通用模块开关（`module_key` + `enabled`），但不包含服务地址信息。方案 E 专为 eclassroom 设计，额外携带 API 地址/端口，解决了微服务动态路由问题。如果未来其他微服务（如 message-service）也需要按租户开关 + 动态地址，可参照此模式建类似的表。

### 3.2 数据库设计

在 `lesson_appointment` 数据库中新建两张表：

#### 3.2.1 eclassroom 实例表 `sys_eclassroom_instance`

课堂服务实例注册表。一行 = 一个 classroom-service 部署实例。

```sql
-- ============================================================
-- eclassroom 实例表（课堂服务实例注册）
-- ============================================================
CREATE TABLE `sys_eclassroom_instance` (
    `id`              BIGINT       NOT NULL AUTO_INCREMENT  COMMENT '主键',
    `instance_code`   VARCHAR(64)  NOT NULL                 COMMENT '实例编码（唯一标识，如 classroom-svc-1）',
    `instance_name`   VARCHAR(128) NOT NULL                 COMMENT '实例名称（展示用，如 华东课堂服务-1）',
    `api_host`        VARCHAR(255) NOT NULL                 COMMENT 'API服务地址（IP或域名，如 127.0.0.1 或 classroom-svc-1.internal）',
    `api_port`        INT          NOT NULL DEFAULT 8092    COMMENT 'API服务端口号',
    `api_base_path`   VARCHAR(128)          DEFAULT '/api/v1/classroom' COMMENT 'API基础路径',
    `ws_host`         VARCHAR(255)          DEFAULT NULL     COMMENT 'WebSocket服务地址（如与API同址可留空）',
    `ws_port`         INT                   DEFAULT NULL     COMMENT 'WebSocket端口号（如与API同端口可留空）',
    `ws_base_path`    VARCHAR(128)          DEFAULT '/ws'    COMMENT 'WebSocket基础路径',
    `status`          TINYINT      NOT NULL DEFAULT 1       COMMENT '实例状态：1=正常 0=停用 2=维护中',
    `region`          VARCHAR(64)           DEFAULT NULL     COMMENT '部署区域（如 cn-east-1），用于就近路由',
    `max_capacity`    INT                   DEFAULT NULL     COMMENT '最大并发课堂数（用于负载均衡选择）',
    `current_load`    INT                   DEFAULT 0        COMMENT '当前负载（并发课堂数，定期更新）',
    `remark`          VARCHAR(255)          DEFAULT NULL     COMMENT '备注',
    `creator_account` VARCHAR(255)          DEFAULT NULL     COMMENT '创建者账号',
    `deleted`         TINYINT      NOT NULL DEFAULT 0       COMMENT '软删除：0正常 1已删除',
    `create_time`     DATETIME              DEFAULT CURRENT_TIMESTAMP     COMMENT '创建时间',
    `update_time`     DATETIME              DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_instance_code` (`instance_code`),
    KEY `idx_status` (`status`),
    KEY `idx_region` (`region`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT='eclassroom课堂服务实例注册表';
```

#### 3.2.2 租户-eclassroom 关系表 `sys_tenant_eclassroom`

租户与课堂实例的关联表。一行 = 一个租户启用了课堂并关联到某个实例。

```sql
-- ============================================================
-- 租户-eclassroom 关系表（租户课堂开关 + 实例绑定）
-- ============================================================
CREATE TABLE `sys_tenant_eclassroom` (
    `id`              BIGINT       NOT NULL AUTO_INCREMENT  COMMENT '主键',
    `tenant_id`       BIGINT       NOT NULL                 COMMENT '租户ID（对应 sys_tenant.id）',
    `instance_id`     BIGINT       NOT NULL                 COMMENT 'eclassroom实例ID（对应 sys_eclassroom_instance.id）',
    `enabled`         TINYINT      NOT NULL DEFAULT 1       COMMENT '是否启用：1=启用 0=临时禁用（保留关联但关闭入口）',
    `config`          JSON                  DEFAULT NULL     COMMENT '租户级课堂配置（JSON，如录制开关、人数上限、白板只读等）',
    `remark`          VARCHAR(255)          DEFAULT NULL     COMMENT '备注',
    `creator_account` VARCHAR(255)          DEFAULT NULL     COMMENT '操作人账号',
    `create_time`     DATETIME              DEFAULT CURRENT_TIMESTAMP     COMMENT '创建时间',
    `update_time`     DATETIME              DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_tenant_id` (`tenant_id`)  COMMENT '一个租户最多关联一个课堂实例',
    KEY `idx_instance_id` (`instance_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT='租户-eclassroom课堂关系表';
```

#### 3.2.3 判断逻辑

```
租户是否有 eclassroom：
  SELECT 1 FROM sys_tenant_eclassroom WHERE tenant_id = ? AND enabled = 1
  → 有记录 = 有课堂；无记录 = 无课堂

获取租户的课堂服务地址：
  SELECT i.api_host, i.api_port, i.api_base_path, i.ws_host, i.ws_port, i.ws_base_path
  FROM sys_tenant_eclassroom t
  JOIN sys_eclassroom_instance i ON t.instance_id = i.id
  WHERE t.tenant_id = ? AND t.enabled = 1 AND i.status = 1 AND i.deleted = 0
  → 返回实例的 API 地址和端口
```

> **默认行为约定**：`sys_tenant_eclassroom` 中**无记录** = 该租户**未启用**课堂（与方案 B 的"无记录=启用"相反）。因为课堂是新功能，现有租户默认不应自动启用，需平台管理员显式分配实例后才启用。`enabled = 0` 表示临时禁用（保留关联关系，后续可快速恢复）。

**核心查询逻辑**：
```java
public EclassroomConfig getTenantClassroomConfig(Long tenantId) {
    if (tenantId == null || tenantId == 0L) return null; // 平台管理员无租户课堂

    TenantEclassroom te = tenantEclassroomMapper.selectOne(
        Wrappers.<TenantEclassroom>lambdaQuery()
            .eq(TenantEclassroom::getTenantId, tenantId)
            .eq(TenantEclassroom::getEnabled, 1)
    );
    if (te == null) return null; // 未启用课堂

    EclassroomInstance instance = eclassroomInstanceMapper.selectById(te.getInstanceId());
    if (instance == null || instance.getStatus() != 1 || instance.getDeleted() == 1) {
        return null; // 实例不可用
    }

    // 组装配置
    EclassroomConfig config = new EclassroomConfig();
    config.setEnabled(true);
    config.setApiBaseUrl(buildUrl(instance.getApiHost(), instance.getApiPort(), instance.getApiBasePath()));
    config.setWsBaseUrl(buildUrl(instance.getWsHost(), instance.getWsPort(), instance.getWsBasePath()));
    config.setTenantConfig(te.getConfig()); // 租户级 JSON 配置
    return config;
}

private String buildUrl(String host, Integer port, String basePath) {
    if (host == null) return null;
    String scheme = "http";
    // 简单判断：443端口用https，否则http
    if (port != null && port == 443) scheme = "https";
    return scheme + "://" + host + (port != null && port != 80 && port != 443 ? ":" + port : "") + basePath;
}
```

#### 3.3.4 登录响应增强

在 `AuthController` / `UserService` 的登录方法中，登录成功后额外返回 `eclassroom` 配置：

```json
{
  "code": 200,
  "data": {
    "token": "xxx",
    "refreshToken": "xxx",
    "userId": "xxx",
    "role": "teacher",
    "tenantId": 1001,
    "tenantCode": "T1001",
    "eclassroom": {
      "enabled": true,
      "apiBaseUrl": "http://127.0.0.1:8092/api/v1/classroom",
      "wsBaseUrl": "ws://127.0.0.1:8092/ws"
    }
  }
}
```

这样前端在登录时即可获得课堂开关和服务地址，无需额外请求。`eclassroom` 配置不放入 JWT token（避免 token 膨胀），仅放在登录响应体中。前端存入 `localStorage`，token 刷新时不重复获取（课堂配置变更频率极低）。

#### 3.3.5 服务间通信（booking-api → classroom-service）

booking-api 需要向 classroom-service 推送排期事件（如排期发布/改期/取消）。此前设计是硬编码 classroom-service 地址，现在改为从 `sys_tenant_eclassroom` 表动态查询：

```java
// 在 MessageNotifyService 模式基础上改造
// 排期事件推送 → classroom-service
public void notifyClassroomScheduleEvent(Long tenantId, String eventType, Object payload) {
    String classroomApiUrl = eclassroomService.getTenantClassroomApiBaseUrl(tenantId);
    if (classroomApiUrl == null) {
        log.debug("租户{}未启用课堂，跳过事件推送", tenantId);
        return; // 未启用课堂，直接跳过
    }
    try {
        String eventUrl = classroomApiUrl + "/schedules/events";
        // 使用 RestTemplate + 共享 JWT（现签令牌）调用 classroom-service
        restTemplate.postForEntity(eventUrl, payload, Void.class);
    } catch (Exception e) {
        log.warn("推送课堂事件失败: tenant={}, type={}, err={}", tenantId, eventType, e.getMessage());
    }
}
```

#### 3.3.6 classroom-service 侧守卫

classroom-service 需要校验请求所属租户是否确实启用了课堂。由于 classroom-service 是独立微服务，有两种方案：

> - **方案①（推荐）**：classroom-service 直连 `lesson_appointment` schema 的 `sys_tenant_eclassroom` + `sys_eclassroom_instance` 表（只读 Mapper），加本地缓存（Caffeine，TTL 5min）
> - **方案②**：classroom-service 启动时调用 booking-api 的 `GET /api/v1/eclassroom/config` 接口（REST 调用，有网络开销）

```java
// classroom-service 的 JwtAuthenticationFilter 中
Long tenantId = AuthContext.currentTenantId();
if (tenantId != null && tenantId != 0L) {
    if (!tenantEclassroomService.hasClassroomEnabled(tenantId)) {
        response.setStatus(403);
        response.getWriter().write("{\"code\":403,\"message\":\"课堂未启用\"}");
        return;
    }
}
```

#### 3.3.7 nginx 路由可选部署

对于完全不需要课堂的部署环境，可不部署 classroom-service，nginx 中不配置 `/api/v1/classroom` 路由。此时前端"进入课堂"按钮因 `eclassroom.enabled === false` 不显示，用户不会触发课堂 API 调用。

```nginx
# 可选：仅当部署了 classroom-service 时才添加此段
location /api/v1/classroom/ {
    proxy_pass http://127.0.0.1:8092;
    include /etc/nginx/proxy_common.conf;
}
```

> 注意：前端课堂 API 调用使用的是 `eclassroom.apiBaseUrl`（从登录响应获得），而非固定的 nginx 路由。nginx 路由仅作为后端代理层兜底。在单实例部署场景下，`apiBaseUrl` 指向 nginx，nginx 再代理到 classroom-service；在多实例场景下，`apiBaseUrl` 可直接指向具体实例。

## 四、前端特性开关机制

### 4.1 feature-flags.js 工具模块

新建 `frontend/js/public/feature-flags.js`：

```javascript
(function() {
    const STORAGE_KEY = 'eclassroomConfig';

    function getConfig() {
        try {
            return JSON.parse(localStorage.getItem(STORAGE_KEY) || 'null');
        } catch (e) {
            return null;
        }
    }

    function setConfig(config) {
        localStorage.setItem(STORAGE_KEY, JSON.stringify(config || null));
    }

    // 判断当前租户是否启用了课堂
    function hasClassroom() {
        var config = getConfig();
        return config !== null && config.enabled === true;
    }

    // 获取课堂 API 基础地址
    function getClassroomApiBaseUrl() {
        var config = getConfig();
        return config ? config.apiBaseUrl : null;
    }

    // 获取课堂 WebSocket 基础地址
    function getClassroomWsBaseUrl() {
        var config = getConfig();
        return config ? config.wsBaseUrl : null;
    }

    // 批量隐藏未启用模块的菜单项
    function applyMenuVisibility() {
        // 课堂相关菜单项
        if (!hasClassroom()) {
            document.querySelectorAll('.menu-item[data-module="classroom"]').forEach(function(item) {
                item.style.display = 'none';
            });
        }
    }

    // 课堂页面守卫：未启用课堂则跳回角色首页
    function guardClassroom() {
        if (!hasClassroom()) {
            var role = (JSON.parse(localStorage.getItem('userInfo') || '{}')).role;
            var pageMap = {
                admin: 'admin.html',
                teacher: 'teacher.html',
                student: 'student.html',
                platform_admin: 'platform_admin.html'
            };
            window.location.href = pageMap[role] || 'login.html';
            return false;
        }
        return true;
    }

    window.hasClassroom = hasClassroom;
    window.getClassroomApiBaseUrl = getClassroomApiBaseUrl;
    window.getClassroomWsBaseUrl = getClassroomWsBaseUrl;
    window.setEclassroomConfig = setConfig;
    window.applyMenuVisibility = applyMenuVisibility;
    window.guardClassroom = guardClassroom;
})();
```

## 五、上课页面与预约页面分离方案

### 5.1 分离原则

| 维度 | 预约页面（现有） | 课堂页面（新增） |
|------|-----------------|-----------------|
| 交互模式 | CRUD 管理（表单/表格/卡片） | 实时交互（RTC/白板/聊天） |
| 布局 | sidebar + content 管理布局 | 全屏沉浸式布局 |
| 技术 | vanilla JS + axios + template | WebRTC + WebSocket + Canvas 白板 |
| 生命周期 | 随时访问，无状态 | 有状态（课堂进行中/已结束） |
| 数据源 | booking-api (8081) | classroom-service (8092) |
| 更新频率 | 用户操作触发 | 实时流（音视频/白板/聊天） |

**结论**：课堂页面与预约页面在交互模式、布局、技术栈上完全不同，**必须是独立 HTML 页面**，不能混入现有 admin/teacher/student.html 的 sidebar 布局中。

```javascript
// classroom-main.js
window.onload = function() {
    // 1. 课堂守卫：未启用课堂则跳回
    if (!window.guardClassroom()) return;

    // 2. 登录态守卫
    var userInfo = JSON.parse(localStorage.getItem('userInfo') || '{}');
    if (!userInfo.role) { window.location.href = 'login.html'; return; }

    // 3. 解析参数
    var params = new URLSearchParams(window.location.search);
    var scheduleId = params.get('scheduleId');
    if (!scheduleId) { window.location.href = pageUrl(roleHome(userInfo.role)); return; }

    // 4. 获取课堂 API 地址（从 localStorage，登录时已存入）
    var apiBaseUrl = window.getClassroomApiBaseUrl();
    var wsBaseUrl = window.getClassroomWsBaseUrl();

    // 5. 调用进入课堂接口（直连 classroom-service）
    ClassroomAPI.enter(apiBaseUrl, scheduleId).then(function(res) {
        if (res.code !== 200) { alert(res.message); goBack(); return; }
        var classroomData = res.data;
        classroomData.wsBaseUrl = wsBaseUrl; // 传递 WS 地址

        // 6. 初始化各模块
        ClassroomRTC.init(classroomData.rtcConfig);
        ClassroomWhiteboard.init(classroomData.whiteboardConfig);
        ClassroomChat.init(classroomData.chatConfig);

        // 7. 按角色加载专属功能
        if (userInfo.role === 'teacher') ClassroomTeacher.init(classroomData);
        else if (userInfo.role === 'student') ClassroomStudent.init(classroomData);
        else if (userInfo.role === 'admin') ClassroomAdmin.init(classroomData);

        // 8. 初始化控制栏
        ClassroomControls.init(userInfo.role);
    });
};
```

#### 5.5.2 JS 完全独立

`frontend/js/classroom/` 下的 JS 不依赖任何现有 `admin-*.js` / `teacher-*.js` / `student-*.js`。仅依赖 `public/` 下的公共工具（`api.js` / `utility_request.js` / `feature-flags.js`）。

#### 5.5.3 API 路由分离

| 功能 | API 前缀 | 后端服务 | 端口 |
|------|---------|---------|------|
| 预约/排期/课程 | `/api/v1/schedule/*`, `/api/v1/course/*` | booking-api | 8081 |
| 消息中心 | `/api/v1/message/*` | message-service | 8090 |
| **课堂** | `/api/v1/classroom/*` | **classroom-service** | **8092** |

nginx 按前缀分流，课堂 API 独立路由到 classroom-service。

#### 5.5.4 部署独立

classroom-service 是独立 Spring Boot 应用，独立 Docker 容器，独立端口。不部署 classroom-service 时：
- nginx 不配置 `/api/v1/classroom` 路由
- 前端"进入课堂"按钮因 `hasClassroom() === false` 不显示
- 即使误访问 `classroom.html`，`guardClassroom()` 会跳回角色首页

#### 5.5.5 数据库 schema 独立

classroom-service 使用独立的 `classroom` schema（`classroom-schema.sql` 中定义的 9 张表），与预约系统的 `lesson_appointment` schema 分离。仅通过 `schedule_id` 关联排期数据，通过共享 JWT 实现身份互通。

## 八、关键设计决策总结

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 特性开关存储 | `sys_eclassroom_instance` + `sys_tenant_eclassroom` 两张表 | 同时解决特性开关 + 服务发现，支持多实例部署 |
| 默认行为 | `sys_tenant_eclassroom` 无记录 = 未启用 | 课堂是新功能，现有租户默认不启用，需显式绑定实例 |
| 课堂服务地址 | 存储在 `sys_eclassroom_instance` 表中 | 动态路由，不硬编码，支持故障迁移和多实例 |
| 配置传递 | 登录响应体含 eclassroom 配置（非 JWT） | 避免 token 膨胀，前端 localStorage 存储 apiBaseUrl/wsBaseUrl |
| 课堂页面形式 | 独立 `classroom.html`（全屏） | 课堂交互模式与预约 CRUD 完全不同 |
| 课堂页面角色适配 | 单页面 + JS 按角色加载 | 课堂 UI 三角色高度相似，避免重复 |
| 课堂入口 | 预约页面就地嵌入按钮 | 符合用户操作动线（看到课→进入课堂） |
| 课堂 API 调用 | 前端使用 apiBaseUrl 直连 classroom-service | 支持多实例场景，不依赖 nginx 固定路由 |
| classroom-service 守卫 | 跨 schema 只读查询 + 本地缓存 | 避免服务间调用开销，课堂开关低频变更 |
| 服务间通信 | booking-api 动态查表获取 classroom 地址 | 不硬编码，未启用课堂的租户跳过推送 |
| 未部署 classroom-service | nginx 不配路由 + 前端不显示按钮 + 表中无实例 | 三重保险 |
