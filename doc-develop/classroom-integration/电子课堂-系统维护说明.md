# 电子课堂系统 · 系统维护说明

> 适用版本：2026-10-29（包 1~4 全部交付后）
> 面向对象：运维、后端开发、值班同学
> 配套文档：《电子课堂-操作说明.md》（角色与功能操作）

## 一、系统构成

### 1.1 服务拓扑

```
浏览器 ──HTTPS──> nginx ──┬─ /api/v1/classrooms|uploads|files|recordings|attendance|schedules|rtc
                          │  /api/v1/admin/{classrooms,monitor,reports,reconcile,audit,contract,exports}
                          │  /ws/classrooms/*            ──> classroom-service :8092
                          │
                          ├─ /api/v1/classroom-callback/ ──> booking-api :8081（课堂回调落点）
                          ├─ 其余 /api/v1/               ──> booking-api :8081
                          └─ /api/v1/users|message|sse   ──> message-service :8090
```

| 服务 | 端口 | 数据库 | 职责 |
|---|---|---|---|
| classroom-service | 8092 | `classroom`（独立库） | 课堂全生命周期、信令、白板、上传、录制、报表、运营台 |
| booking-api | 8081 | `lesson_appointment` | 预约/排期/课时账务；接收课堂回调 |
| message-service | 8090 | `message_center` | 消息中心 |

### 1.2 外部依赖

| 依赖 | 用途 | 缺失后果 |
|---|---|---|
| MySQL 8.x | 课堂库 + 跨库只读 `lesson_appointment.sys_tenant_eclassroom` | 启动失败（readiness 探针 503） |
| Redis db=2 | 在线状态（心跳 TTL）、限流计数、事件幂等 | 在线判定失效、限流降级放行（不阻断业务） |
| 对象存储目录 | 讲稿/作品/录制文件 | 上传失败；`local` 类型需保证磁盘与备份 |
| STUN/TURN | WebRTC 打洞 | **只有 STUN 时约 2~3 成用户建连失败**，见第八节 |
| 浏览器麦克风/摄像头权限 | 音视频 | 只能看不能听/说 |

### 1.3 关键共享密钥

三个服务必须**逐字符一致**，否则跨服务调用全部 401：

```
JWT_SECRET   —— 与 booking-api 共享，用于校验登录令牌
AES_KEY      —— 服务间报文加解密
HMAC_KEY     —— 回调报文签名（X-Hmac-Signature）
```

## 二、部署

### 2.1 方式一：单机 jar + nginx（推荐生产）

```bash
# 1) 构建（本机 mvn 可能损坏，用 Maven launcher JAR 直调）
cd api/classroom-service
unset CLASSPATH
export JAVA_HOME="/path/to/jdk-17"        # 注意：本模块是 Java 17，不是 21
export PATH="$JAVA_HOME/bin:$PATH"
mvn -o -q clean package -DskipTests

# 2) 产物
ls target/classroom-service-1.0.0.jar

# 3) 启动（profile 与线上一致时用 cloud）
java $JAVA_OPTS -jar target/classroom-service-1.0.0.jar --spring.profiles.active=cloud

# 4) 验证
curl -s http://127.0.0.1:8092/actuator/health/liveness    # 期望 {"status":"UP"}
curl -s http://127.0.0.1:8092/actuator/health/readiness   # 含 db，DB 不通则为 DOWN
```

### 2.2 方式二：Dockerfile（CI / 独立镜像）

```bash
cd api/classroom-service
docker build -t classroom-service:1.0.0 .
docker run -d --name classroom \
  -p 8092:8092 \
  -e JWT_SECRET=... -e AES_KEY=... -e HMAC_KEY=... \
  -e REDIS_HOST=redis -e DB_USERNAME=... -e DB_PASSWORD=... \
  -e BOOKING_API_URL=http://booking:8081 \
  -v /data/classroom/logs:/app/logs -v /data/classroom/oss:/app/data \
  classroom-service:1.0.0
```

镜像特性：多阶段构建、非 root 运行、`HEALTHCHECK` 探 `/actuator/health/liveness`、`MaxRAMPercentage=75`、`ExitOnOutOfMemoryError`。日志与对象存储必须挂载卷，否则重建容器即丢数据。

### 2.3 方式三：微信云托管

目录 `cloudBased/classroom-service/`（Dockerfile + `container.config.json` + `application-cloud.properties`）。

- `containerPort` / `EXPOSE` / `server.port` 三者必须都是 **8092**。
- 该目录是「本机构建 jar → 拷进 `target/` → 打包」流程，不做多阶段构建。
- 云托管按 `initialDelaySeconds` 自行探活，镜像内未加 HEALTHCHECK。

### 2.4 nginx 路由（**上线必查**）

课堂服务的前缀必须显式代理到 8092，漏一个就是该功能整片 404。当前应包含：

| location | 归属功能 | 漏配后果 |
|---|---|---|
| `/api/v1/classrooms/` | 课堂主接口、白板、点名、讲稿、作品、录制控制 | 进不去课堂 |
| `/api/v1/attendance/` | 学生历史出勤 | 「我的出勤」空白 |
| `/api/v1/recordings/` | 录制列表与回放地址 | 回放页无数据 |
| `/api/v1/uploads/` | 分片上传（init/parts/complete） | 讲稿/作品/录制上传全失败 |
| `/api/v1/files/` | 签名 URL 访问（`<video>`/`<iframe>` 直连） | 回放打不开、讲稿显示不出来 |
| `/api/v1/schedules/` | 排期事件接收（`POST /events`） | 排期变更不下发到课堂 |
| `/api/v1/rtc/` | RTC 选型诊断 | 运营台「部署健康」缺一块 |
| `/api/v1/admin/classrooms/` | 巡课/远程结束 | 管理员无法干预 |
| `/api/v1/admin/monitor/` | 实时监控 | 运营台监控 tab 空 |
| `/api/v1/admin/reports/` | 学情报表 | 报表 tab 空 |
| `/api/v1/admin/reconcile/` | 对账差异 | 对账 tab 空 |
| `/api/v1/admin/audit/` | 内容审核 | 审核 tab 空 |
| `/api/v1/admin/contract/` | 契约联调 | 联调 tab 空 |
| `/api/v1/admin/exports/` | CSV 导出 | 导出按钮报错 |
| `/ws/classrooms/` | 信令/白板/心跳三条 WS | 课堂只能看静态页，状态全不同步 |
| `/api/v1/classroom-callback/` → **8081** | 课堂回调预约系统 | 反向代理写错会 404（该前缀必须归 8081） |

**两个必须遵守的写法**：

1. `/api/v1/admin/` **不能通配**到 8092 —— 主服务也有 `/api/v1/admin` 语义的接口，通配会把主业务整片抢走。必须逐个精确前缀。
2. `/ws/classrooms/` 必须带 `Upgrade`/`Connection` 头且 `proxy_read_timeout` ≥ 3600s，否则心跳连接被 60s 掐断，表现为「每分钟抖一次」。

> 历史教训：包 3/4 新增的 9 个前缀一度全部缺失。单机直连 8092 一切正常，走 nginx 则全 404 —— 因为 `/api/v1/` 兜底规则把它们送到了 8081。

### 2.5 本地联调

```bash
# 一条命令起前端同源代理（8080），三端都转发：
#   booking :8081 / message-service :8090 / classroom :8092（含 /ws/* 的 WebSocket 升级）
node doc-develop/dev-frontend-local.js

# 浏览器访问
http://localhost:8080/classroom.html?scheduleId=<课次ID>
http://localhost:8080/classroom-ops.html      # 运营台
```

代理的分派规则与生产 nginx 保持一致（前缀清单见 `dev-proxy.js` 的 `toClassroomService`）：
课堂前缀优先于 booking 兜底，`/ws/*` 走原始 TCP 双向 pipe 转发升级后的帧。

常用环境变量：

| 变量 | 默认 | 用途 |
|---|---|---|
| `DEV_PORT` | 8080 | 换端口（8080 被占用时用这个） |
| `FRONTEND_ROOT` | `../frontend` | 改静态根目录 |
| `DIST=1` | 关 | 伺服 `frontend/dist` 构建产物而非源码 |
| `CLASSROOM_PORT` | 8092 | 设为 `0` 可关闭课堂路由（只调预约/消息时用） |
| `NO_PROBE=1` | 关 | 跳过启动前的连通性检查 |

**两个常见坑**：

1. **端口被历史进程占用**：报 `EADDRINUSE` 说明 8080 已被占。先查是谁占的：

   ```powershell
   Get-CimInstance Win32_Process -Filter "ProcessId=<netstat 查到的 PID>" | Select-Object CommandLine
   ```

   如果它指向**另一个目录的旧副本**（不是当前工作空间），务必先停掉再起，否则你打开的是旧代码。

2. **只起前端不启后端也能跑**：代理会打印 `❌ 不可达`，静态页面照常打开，只是接口报错。课堂服务单独缺失时只影响课堂页，不影响预约/后台。

```bash
# 前端改动后重建 dist（dist 被 gitignore，线上伺服的是它）
cd frontend && CODEBUDDY_SAFE_DELETE_ENABLED=0 node build.js
```

`CODEBUDDY_SAFE_DELETE_ENABLED=0` 不能省：构建脚本会先删 dist（>50 文件），会被安全删除闸拦住并静默不构建。

## 三、配置项

配置文件：`api/classroom-service/src/main/resources/application.properties`。所有值均可用环境变量覆盖。

### 3.1 媒体选型（RTC）

| 配置 | 默认 | 说明 |
|---|---|---|
| `classroom.rtc.provider` | `native-mesh` | `native-mesh` / `livekit` / `trtc` / `agora` |
| `classroom.rtc.student-publish-video` | `false` | 学生是否推视频（省上行；音频始终可发） |
| `classroom.rtc.mesh.turn-urls` | 空 | **生产必配**，逗号分隔 |
| `classroom.rtc.mesh.turn-secret` | 空 | coturn `static-auth-secret`，走 REST 临时凭证 |
| `classroom.rtc.mesh.max-peers` | `6` | 超过只收不发 |
| `classroom.rtc.livekit.{url,api-key,api-secret}` | 空 | 三项齐备才启用 |
| `classroom.rtc.trtc.{sdk-app-id,secret-key}` | 0/空 | `sdk-app-id` 为 0 视为未配 |
| `classroom.rtc.agora.{app-id,app-certificate}` | 空 | 需项目引入 `io.agora:authentication` |

**降级规则**：任一 provider 的关键配置缺失 → 启动时自动降级为 `native-mesh` 并打 WARN。实际生效值查：

```bash
curl -s -H "Authorization: Bearer <管理员token>" http://127.0.0.1:8092/api/v1/rtc/providers
# {"configured":"trtc","active":"native-mesh","degraded":true,...}
```

**看到 `degraded:true` 就是配置没生效**，去查配置，不要查代码。

| 配置 | 默认 | 影响 |

| `classroom.reconcile.cron` | `0 0 1 * * ?` | 日终对账 |
| `classroom.reconcile.fullcheck.cron` | `0 0 2 ? * MON` | 周全量校验 |

### 3.5 数据保留期

| 配置 | 默认 | 数据 |
|---|---|---|
| `classroom.presence-retention-days` | 180 | 在线区间明细 |
| `classroom.rollcall-retention-days` | 90 | 点名记录 |
| `classroom.reconcile-retention-days` | 365 | 对账日志 |
| `classroom.session-retention-days` | 180 | 课堂会话/事件流水 |
| `classroom.submission-retention-days` | 730 | 学生作品 |
| `classroom.recording-retention-days` | 90 | 录制文件 |

### 3.6 限流

| 配置 | 默认 | 说明 |
|---|---|---|
| `classroom.rate-limit.enabled` | `true` | 总开关 |
| `classroom.rate-limit.enter-per-minute` | 30 | 进课堂（刷新/重连都算，不要调太小） |
| `classroom.rate-limit.upload-per-minute` | 30 | 上传会话初始化 |
| `classroom.rate-limit.rollcall-per-minute` | 10 | 发起点名 |

### 3.7 日志与健康

```

```

日志：`./logs/classroom-service.log`，按天 + 50MB 滚动，**保留 90 天**，总量上限 10GB，落盘 `logs/archived/*.gz`。

## 四、数据库

### 4.1 表清单（13 张，独立库 `classroom`）

| 表 | 用途 | 增长量级 |
|---|---|---|
| `classroom` | 课堂主表（状态机、计划/实际起止、课时回流版本） | 每课次 1 行 |
| `classroom_membership` | 成员与在线展示态 | 每课次 × 人数 |
| `classroom_attendance` | 出勤结果（到课/迟到/缺勤 + 有效时长） | 每课次 × 人数 |
| `classroom_presence_segment` | 在线区间明细（进入/离开时间片） | 每人在线次数，最大 |
| `classroom_session_record` | 课堂会话 + 教学事件流水 `event_log` | 高频，按课次 |
| `classroom_runtime_state` | 服务端权威态（当前只有 `mute_all`） | 每课次 1 行 |
| `classroom_material` | 讲稿元数据 + 当前页码 | 每课次 N 份 |
| `classroom_rollcall` | 点名记录与应答状态 | 每课次 N 次 |
| `classroom_submission` | 学生作品 + 评语评分 | 每课次 × 人数 |
| `classroom_recording` | 录制记录（ossKey、时长、保留期） | 每课次 1~N 条 |
| `classroom_reconcile_log` | 对账执行日志 | 每天 1 行 |
| `classroom_reconcile_diff` | 对账差异（可处置） | 异常时增长 |
| `classroom_audit_log` | 内容审核/查阅留痕 | 审核动作，长期保留 |

文件本身**不在库内**：只存 `oss_key`，实体类里 `url` 字段标了 `@TableField(exist=false)`，由接口按需签名。

### 4.2 初始化与迁移

```bash
# 新建库：直接跑全量 schema（已自洽，含 13 张表）
mysql -uroot -p classroom < api/classroom-service/sql/classroom-schema.sql

# 存量库：按时间顺序跑 patch（全部幂等，可重复执行）
mysql -uroot -p classroom < api/sql/patch/20261029-1430-classroom-runtime-state.sql
mysql -uroot -p classroom < api/sql/patch/20261029-2000-classroom-reconcile-diff.sql
mysql -uroot -p classroom < api/sql/patch/20261029-2010-classroom-audit-log.sql
```

> 建表语句在 `schema` 与 `patch` 各留一份是有意的：新建库跑 schema 即完整；存量库只跑 patch。**改表结构时两处必须同步**，否则新环境会缺表（`classroom_audit_log` 曾只在 patch 里，新人建库后审核功能直接 500）。

### 4.3 跨库只读

课堂服务需要读 `lesson_appointment.sys_tenant_eclassroom` 判断机构是否开通课堂。要求：

1. 两个服务连**同一个 MySQL 实例**；
2. 课堂服务的数据库账号对 `lesson_appointment` 有 `SELECT` 权限；
3. 主库名不是 `lesson_appointment` 时改 `classroom.cross-schema.tenant-schema`，并同步实体/Mapper 里硬编码的全限定表名。

### 4.4 备份与恢复

```bash
# 备份（必须用 --result-file，重定向到文件在 Windows/特殊字符下会损坏）
mysqldump -uroot -p --single-transaction --routines \
  --result-file=/backup/classroom_$(date +%F).sql classroom

# 文件存储同样要备（对象存储是 local 模式时，文件不在库里）
tar czf /backup/oss_$(date +%F).tar.gz -C /data/classroom oss

# 恢复
mysql -uroot -p classroom < /backup/classroom_2026-10-29.sql
```

**恢复顺序**：先库后文件。只恢复库会导致「记录在、文件不在」，回放页显示有录制但播不了。

## 五、定时任务

全部在 `ClassroomScheduler` 与 `reconcile` 包，共 9 个。线程池 `spring.task.scheduling.pool.size=8`。

| 任务 | 频率 | 做什么 | 停摆症状 |
|---|---|---|---|
| `scanReadyReminder` | 每 30s | 开课前 10 分钟 `SCHEDULED→READY` 并发提醒 | 学生收不到上课提醒，到点点进去还是未开始 |
| `scanAutoStart` | 每 30s | 到点 `READY→LIVE` | 课堂不自动开始，必须教师手动进 |
| `scanAutoEnd` | 每 30s | 超结束 5 分钟 `→CLOSED` + 收尾 | 课堂永远 LIVE，课时不回流 |
| `scanStudentDrop` | 每 20s | 按最后心跳判 ONLINE/IDLE/OFFLINE | 掉线的人一直显示在线，出勤时长虚高 |
| `scanRollCallTimeout` | 每 30s | 点名 2 分钟未答判超时 | 点名永远挂 PENDING |
| `scanTeacherDrop` | 每 40s | 教师掉线 2 分钟自动结课 | 教师断网后课堂一直挂着占资源 |
| `scanRetentionCleanup` | 每日 03:30 | 按保留期清过期数据；录制**先删对象再删记录** | 磁盘只涨不降 |
| `DailyReconcileTask` | 每日 01:00 | 四规则真对账 + 推汇总给预约侧 | 差异发现不了，账对不上 |
| `WeeklyFullCheckTask` | 每周一 02:00 | 全量校验 | 历史偏差积累 |

**为什么掉线判定要 20s 一次**：心跳间隔 15s、Redis TTL 60s、IDLE 宽限 30s。扫描太慢会让「已离开」的人在这段时间里继续累计有效时长。

## 六、监控

### 6.1 健康探针

```bash
curl -s http://127.0.0.1:8092/actuator/health/liveness    # 进程活着
curl -s http://127.0.0.1:8092/actuator/health/readiness   # 含 DB，能接流量
```

`deploy/healthcheck.sh` 已覆盖 booking / message / **classroom** 三个服务，cron 每 5 分钟：

```bash
*/5 * * * * /opt/lesson/healthcheck.sh >> /var/log/lesson/healthcheck.log 2>&1
```

退出码 0=全绿，1=有告警（供监控采集）。

### 6.2 业务指标（Prometheus）

```bash
curl -s -H "Authorization: Bearer <管理员token>" \
  http://127.0.0.1:8092/api/v1/admin/monitor/prometheus
```

端点走**业务鉴权**（仅管理员），不是匿名的 `/actuator/prometheus` —— 课堂服务常直接对公网，不为此单独开匿名口子。抓取方用服务账号 token 即可。

| 指标 | 类型 | 含义 | 异常判断 |
|---|---|---|---|
| `classroom_online_users` | Gauge | 当前在线人数 | 与实际人数长期不符 → 心跳链路断 |
| `classroom_live_classrooms` | Gauge | 进行中课堂数 | 深夜不归零 → 自动下课失效 |
| `classroom_signal_total{type}` | Counter | 各类信令次数 | `chat:rejected` 突增 → 误开全员静音 |
| `classroom_ws_connect_total{channel}` | Counter | 三通道建连数 | heartbeat 远高于 signal → 页面反复重连 |
| `classroom_callback_total{result}` | Counter | 回流投递结果 | `failed`/`permanent_fail` > 0 → 课时没回流 |
| `classroom_upload_bytes_total{purpose}` | Counter | 上传字节（按用途） | RECORDING 异常放大 → 录制没按预期压缩 |
| `classroom_whiteboard_denied_total` | Counter | 未授权白板改动被拒 | 持续增长 → 有人在试探权限 |

**Gauge 由 `/admin/monitor/overview` 顺手回写**，Prometheus 抓取不会打 DB —— 15s 一次的全表统计在生产上是显著负载。

### 6.3 运维台

`/classroom-ops.html`（管理员）五个 tab，其中「实时监控 → 部署健康」会显示 RTC/录制/存储的**实际选型**，与配置不一致即说明降级。

### 6.4 需要配的告警（建议）

| 告警 | 阈值 | 理由 |
|---|---|---|
| readiness 探针非 200 | 连续 2 次 | DB/进程问题 |
| `classroom_callback_total{result="failed"}` | 5 分钟内 > 0 | 课时没回流，账会错 |
| `classroom_live_classrooms` | 非教学时段 > 0 | 课堂没收尾 |
| 对账 OPEN 差异数 | > 10 | 系统性问题 |
| 磁盘使用率 | > 85% | 录制与日志会写满 |
| 日志目录体积 | > 20GB | 同上的前置信号 |

## 七、日志与排障

### 7.1 日志位置与格式

```
./logs/classroom-service.log            当前
./logs/archived/classroom-service.*.gz  归档（90 天）
```

格式：

```
2026-10-29T20:31:02.114+08:00  INFO  [http-nio-8092-exec-3] [a3f9c1d2e4b5...] c.c.service.ClassroomService : 开课成功: scheduleId=...
                              ────┬───  ─────────┬──────────  ──────┬──────
                                级别          线程              traceId
```

### 7.2 用 traceId 串一条链路

同一次用户操作贯穿四段，**这四段默认在不同线程**：

| 段 | 线程前缀 | 是否自动带 traceId |
|---|---|---|
| HTTP 入口（进课堂、上传、运营台接口） | `http-nio-*` | 是（过滤器建立） |
| 异步回流 / 退避重试 | `callback-` | 是（`TaskDecorator` 传播） |
| 调度任务 | `sched-` / `cb-retry-` | 否（各自独立链路，按 scheduleId 查） |
| WebSocket（信令/白板/心跳） | `http-nio-*` | 是（握手时从 `?traceId=` 绑定，三通道共用一个） |

排查示例：

```bash
# 1) 前端报障时，响应头里就有链路 id（浏览器 F12 → Network → 任一请求 → X-Trace-Id）
# 2) 一条命令拉全链路
grep "a3f9c1d2e4b5" logs/classroom-service.log

# 3) 只看某个课次
grep "scheduleId=<课次ID>" logs/classroom-service.log | tail -100
```

**入站 `X-Trace-Id` 会被校验**（只接受 `[A-Za-z0-9._-]{8,64}`），不合法的值会被重新生成 —— 这是防日志注入，不是 bug。

### 7.3 日志级别临时调整

```bash
# 未暴露 loggers 端点（安全考虑），改级别需改配置重启
# 或临时在服务启动参数上覆盖：
java -jar app.jar --logging.level.com.classroom.ws=DEBUG
```

## 八、故障处置手册

### 8.1 学生进不去课堂

```bash
# 1) 看服务是否活着
curl -s http://127.0.0.1:8092/actuator/health/readiness

# 2) 看机构是否开通课堂
mysql -uroot -p -e "SELECT * FROM lesson_appointment.sys_tenant_eclassroom WHERE tenant_id=<租户ID>"

# 3) 看课堂状态与成员
mysql -uroot -p classroom -e "SELECT schedule_id,status FROM classroom WHERE schedule_id='<ID>'"
mysql -uroot -p classroom -e "SELECT user_id,role FROM classroom_membership WHERE schedule_id='<ID>'"

# 4) 看 nginx 是否代理
grep -n "8092" /etc/nginx/conf.d/*.conf
```

常见结论：

| 现象 | 根因 |
|---|---|
| 403「本机构未开通在线课堂」 | `sys_tenant_eclassroom` 无记录或未启用 |
| 403「无权进入该课堂」 | 不在 `classroom_membership` |
| 401 | token 过期或 `JWT_SECRET` 与 booking 不一致 |
| 404 | nginx 漏配前缀（尤其 `/api/v1/classrooms/`） |
| 429 | 进课堂限流（30 次/分），多人共用账号或疯狂刷新 |

### 8.2 课堂里听不到 / 看不到

| 现象 | 先查 | 处置 |
|---|---|---|
| 全部人都听不到 | 是否开了全员静音（红色横幅 / `classroom_runtime_state.mute_all`） | 教师解除；卡住时可 `UPDATE classroom_runtime_state SET mute_all=0 WHERE schedule_id=...` 后让学员刷新 |
| 个别人听不到 | 该学员是否被点名禁言 / 浏览器未授权麦克风 | 让其点地址栏图标恢复权限 |
| 看不到画面 | 对方未开摄像头；或 mesh 人数超 `max-peers` | 超 6 人必须切 SFU（LiveKit/TRTC） |
| 全员频繁掉线重连 | `classroom_ws_connect_total` 突增 | nginx WS 超时太短（须 ≥3600s）或后端重启 |

**mesh 模式的硬限制**：浏览器上行随人数线性增长，超过 `max-peers` 的成员只收不发。课堂超过 6 人且需要互相看画面，必须切 SFU，改配置即可：

```properties
classroom.rtc.provider=livekit
classroom.rtc.livekit.url=wss://...
classroom.rtc.livekit.api-key=...
classroom.rtc.livekit.api-secret=...
```

改完重启，用 `/api/v1/rtc/providers` 确认 `active=livekit`（不是 `degraded`）。

### 8.3 上课高峰 WebRTC 建连失败率高

**九成是没配 TURN**。只有 STUN 时，对称型 NAT 与企业防火墙下约 2~3 成用户连不上。

```properties
classroom.rtc.mesh.turn-urls=turn:turn.example.com:3478?transport=udp,turn:turn.example.com:3478?transport=tcp
classroom.rtc.mesh.turn-secret=<coturn static-auth-secret>
```

`turn-secret` 走后端 HMAC-SHA1 签发临时凭证，**不要**在代码或前端放固定账号密码。验证：

```bash
# 用证书里的临时凭证手工测中继（把 <user>/<cred> 换成接口返回的）
turnutils_uclient -u <user> -w <cred> -p 3478 turn.example.com
```

### 8.4 上传失败

| 现象 | 根因 | 处置 |
|---|---|---|
| `init` 返回 404 | nginx 漏配 `/api/v1/uploads/` | 补 location |
| 上传到 100% 报「分片缺失，无法合并: [n]` | 某个分片没传成功（网络抖动） | 客户端重传该分片；服务端不会静默拼坏文件 |
| 上传成功但打不开 | nginx 漏配 `/api/v1/files/` | 补 location；确认支持 Range |
| 报「文件大小不符」 | 客户端少传/多传字节 | 服务端已自动删坏对象，重传 |
| 磁盘满 | `local` 存储写满 | 清 `data/oss` 过期文件（先跑清理任务），扩盘 |

检查残留分片会话：

```bash
ls -la ./data/uploads/        # 未完成的会话目录
# 长时间未完成的可直接删（对应 DB 无记录，仅临时态）
```

### 8.5 录制没有文件 / 回放打不开

```bash
# 看录制记录状态
mysql -uroot -p classroom -e \
 "SELECT recording_id,status,oss_key,start_time,expire_at FROM classroom_recording WHERE schedule_id='<ID>'"

# 看文件是否真在
ls -la ./data/oss/<oss_key 对应路径>
```

| 状态 | 含义 | 处置 |
|---|---|---|
| `RECORDING` | 录制中或上传中断 | 若课堂已 CLOSED 仍为此态，是被下课任务标记前的窗口，等一轮或人工置 `FAILED` |
| `COMPLETED` 但文件不在 | 文件被手工删/盘丢 | 标记 `FAILED`，无法恢复 |
| `FAILED` | 录制中断 | 学员/教师重新录 |

回放打不开最常见原因是**签名地址过期**（2h）或 nginx 未代理 `/api/v1/files/`。

### 8.6 课时没回流 / 账对不上

```bash
# 1) 看课堂状态与回流版本
mysql -uroot -p classroom -e \
 "SELECT schedule_id,status,actual_end,consumption_version FROM classroom WHERE schedule_id='<ID>'"

# 2) 看差异列表（运营台「对账差异」同源）
mysql -uroot -p classroom -e \
 "SELECT * FROM classroom_reconcile_diff WHERE status='OPEN' ORDER BY created_at DESC LIMIT 20"

# 3) 看回调投递结果
grep -E "DLQ|投递失败|permanent" logs/classroom-service.log | tail -50
```

- `status=CLOSED` 但 `consumption_version=0` → 回流没发出去。在运营台「契约联调」对该课次**重放**，幂等保护不会重复扣课时。
- `status=LIVE` 且超过结束时间很久 → 自动下课没生效，查 `scanAutoEnd` 是否在跑（看日志有无 `[自动下课]`），或手工结束。
- `actual_end` 为空但 CLOSED → 收尾异常，需人工补时间后重放。

### 8.7 白板不同步 / 刷新后笔迹丢失

| 现象 | 查 |
|---|---|
| 刷新后空白 | `classroom_session_record.event_log` 是否有 wb 快照；`WhiteboardHandler` 的 `flush` 是否报错 |
| 学生画不上 | 是否被授权（名单里「授权白板」）；`classroom_whiteboard_denied_total` 会持续增长 |
| 只自己看得到 | WS 白板通道断了（`/ws/classrooms/*/whiteboard`），看 nginx WS 配置 |

### 8.8 服务启动失败

```bash
# 看第一条错误，不要从底部往上翻
grep -m5 -E "ERROR|Caused by" logs/classroom-service.log

# 最常见三种
# 1) DB 连不上 → readiness DOWN，查 datasource 与网络
# 2) 跨库权限不足 → "SELECT command denied ... lesson_appointment.sys_tenant_eclassroom"
# 3) 端口占用 → Windows 用 PowerShell: Get-NetTCPConnection -LocalPort 8092
```

## 十、容量与扩容

### 10.1 单实例能撑多少

| 维度 | 参考上限 | 瓶颈 |
|---|---|---|
| 并发课堂（mesh） | 数十节 | 主要是信令广播与 DB 写入 |
| 单节课人数（mesh） | 6（`max-peers`） | 浏览器上行 |
| 单节课人数（SFU） | 数百 | 取决于 SFU 与带宽 |
| 录制文件 | 90 分钟 720p ≈ 400~800MB | 磁盘 |

### 10.2 扩容顺序

1. **课堂人数上不去** → 先切 SFU（LiveKit 自建最省），不是加实例。
2. **信令延迟高** → `WsRoomRegistry` 是**单实例内存态**，多实例部署会导致跨实例广播失败。这一层若要水平扩容，必须引入 Redis Pub/Sub 做房间广播中继（当前未实现，见第十一节）。
3. **DB 写入压力** → `classroom_presence_segment` 是最大表，先确认保留期生效。
4. **磁盘** → 对象存储切 `s3`/`oss`（实现 `ObjectStorage` 接口，业务代码不动）。

### 10.3 存储估算

```
每课次占用 ≈ 录制(0.5GB) + 讲稿(5MB × N) + 作品(5MB × 人数)
100 节课/月 × 90 天保留 ≈ 150GB 录制 + 少量附件
```

建议对象存储单独挂盘，不要与日志同盘 —— 录制写满会连带把日志挤掉，出问题时既没空间也没日志。

## 十一、当前已知限制（上线前必读）

这些是**设计边界**，不是 bug。要么接受，要么按右列改造：

| 限制 | 影响 | 改造方向 |
|---|---|---|
| `WsRoomRegistry` 为单实例内存态 | **不能水平扩多实例**（跨实例收不到广播） | 引入 Redis Pub/Sub 做房间广播中继 |
| `ClassroomLiveState` 内存权威态 | 重启后禁言/举手/白板授权丢失（`mute_all` 已落库，其余未落） | 关键态补落库或启动时回放事件流水 |
| 白板笔迹只在内存 + 定期快照 | 重启后可能丢最后 2 秒笔迹 | 缩短 flush 间隔或改增量落库 |
| 云录制未接入厂商 REST | 录制里只有教师画面 | 接 LiveKit Egress / 声网云录制 / TRTC 云端录制 |
| 云对象存储未内置 | 只有 `local` | 实现一个 `ObjectStorage` 即可切换 |
| 点名按 `targetUserId` 单发 | 只支持点单人，不支持批量/分组 | 扩展 `RollCallService` |
| 聊天不落库 | 只能实时看，事后仅能查审计日志 | 落 `chat_message` 表（注意保留期与合规） |
| 学员端无「不被录」开关 | 当前 CLIENT 录制不含学生画面，开关无意义 | 改云录制混流后必须补，并在录制文件做遮挡 |
| 未成年人「默认不公开」未实现 | 回放链接知晓即可看（有成员校验） | 定「公开」载体后加默认值与家长授权 |

## 十二、升级与回滚

```bash
# 1) 升级前
mysqldump ... --result-file=/backup/classroom_pre_upgrade.sql classroom
cp -r ./data/oss /backup/oss_pre_upgrade

# 2) 停服务（先摘流量再停，避免请求打到半停机实例）
#    nginx: 注释 8092 相关 location 并 reload
systemctl stop classroom-service

# 3) 跑 patch（幂等，可重复）
mysql classroom < api/sql/patch/<新 patch>.sql

# 4) 换 jar 启动
systemctl start classroom-service
curl -s http://127.0.0.1:8092/actuator/health/readiness

# 5) 回滚：换回旧 jar；DB 变更按「只加不删」原则设计，旧版本通常可兼容新表
```

**DB 变更纪律**：只加表/加列/加索引，不删不改类型。旧版本对新字段是「不认识但忽略」，可直接回滚；一旦删列，回滚就必然失败。
