## 一、连接方案概述

### 1.1 架构定位

预约系统（booking-api, port 8081）是主系统，classroom-service（port 8092）是课堂业务域微服务。两者通过 **REST 同步调用 + HMAC 签名** 对接，与 message-service 的对接模式完全一致：

```
┌──────────────────────────────────────────────────────────────┐
│                      微信云托管 / Nginx                        │
│                                                              │
│  ┌────────────┐   排期事件(REST)    ┌──────────────────┐     │
│  │            │ ──────────────────▶ │                  │     │
│  │ booking    │   POST /schedules/  │ classroom-service│     │
│  │   -api     │       events        │  (port 8092)     │     │
│  │ (port 8081)│ ◀────────────────── │                  │     │
│  │            │   出勤回流/告警/对账  │                  │     │
│  └────────────┘   POST /classrooms/ └──────────────────┘     │
│       │                                      │               │
│       │  前端同源访问                         │ Redis(在线状态)│
│       │  /api/v1/classroom/* → 8092          │ OSS(讲稿/作品) │
│       │  /api/v1/recordings/* → 8092         │ WebSocket(信令)│
│  ┌────────────┐                              │               │
│  │  frontend  │  /ws/classrooms/* → 8092     │               │
│  │  (nginx)   │                              │               │
│  └────────────┘                              │               │
│  ┌────────────┐                              │               │
│  │  message   │  (port 8090)                                │
│  │  -service  │                                              │
│  └────────────┘                                              │
└──────────────────────────────────────────────────────────────┘
```

### 1.2 对接模式对比

| 维度 | message-service 对接 | classroom-service 对接 |
|------|---------------------|----------------------|
| 调用方向 | booking-api → message-service（单向） | **双向**（排期事件下行 + 出勤回流上行） |
| 通信方式 | RestTemplate + 共享 JWT | RestTemplate + 共享 JWT + HMAC 签名 |
| 失败策略 | best-effort（失败仅日志） | **重试 3 次**（1/5/15 分钟）+ 死信队列 |
| 幂等保证 | 无 | eventId Redis SETNX + DB 唯一索引 |
| 触发时机 | 预约成功/候补/上课提醒 | 排期创建/更新/取消 + 课堂关闭后回流 |
| 前端访问 | nginx 前缀分流 `/api/v1/message` | nginx 前缀分流 `/api/v1/classroom` + `/api/v1/recordings` |

## 二、服务间通信设计

### 2.1 下行：booking-api → classroom-service（排期事件推送）

**触发时机**：排期创建/更新/取消时，同步推送事件到 classroom-service。

**实现方式**：在 `ScheduleController` 的 `create`/`update`/`updateStatus` 方法中，排期落库后异步调用 `ClassroomEventPushService.push()`。

**新增类**：`api/src/main/java/com/reservation/service/ClassroomEventPushService.java`

```java
@Service
public class ClassroomEventPushService {

    @Value("${classroom.service.base-url:http://localhost:8092}")
    private String baseUrl;

    private final RestTemplate restTemplate;
    private final JwtUtil jwtUtil;

    /**
     * 推送排期事件到 classroom-service（best-effort + 重试）。
     * eventId = "evt-" + scheduleId + "-" + eventType + "-" + System.currentTimeMillis()
     */
    @Async("classroomPushExecutor")
    public void push(String eventId, String eventType, Schedule schedule,
                     String courseName, String teacherName, List<Booking> bookings) {
        String url = baseUrl + "/api/v1/schedules/events";
        Map<String, Object> body = buildEventBody(eventId, eventType, schedule,
                courseName, teacherName, bookings);
        HttpHeaders headers = new HttpHeaders();
        headers.setContentType(MediaType.APPLICATION_JSON);
        headers.setBearerAuth(jwtUtil.generateToken(0L, "system", "system"));
        HttpEntity<Map<String, Object>> entity = new HttpEntity<>(body, headers);
        try {
            restTemplate.postForEntity(url, entity, Map.class);
        } catch (Exception e) {
            log.warn("排期事件推送失败(已忽略): eventId={}, scheduleId={}", eventId, schedule.getId(), e);
        }
    }
}
```

**事件载荷**（与 classroom-service `ScheduleEventReq` 对齐）：

```json
{
  "eventId": "evt-sch-123-created-1730000000",
  "eventType": "created",
  "scheduleId": "sch-123",
  "courseId": "crs-456",
  "courseName": "英语口语入门",
  "teacher": {"userId": "u1", "name": "王老师"},
  "students": [{"userId": "s1", "name": "张三"}, {"userId": "s2", "name": "李四"}],
  "startTime": "2026-10-28T10:00:00",
  "endTime": "2026-10-28T11:00:00",
  "duration": 60,
  "version": 1
}
```

**触发点**（在现有 Controller 中埋点）：

| Controller 方法 | 事件类型 | 触发条件 |
|----------------|---------|---------|
| `ScheduleController.create` | `created` | 排期创建成功后 |
| `ScheduleController.update` | `updated` | 排期更新成功后 |
| `ScheduleController.updateStatus` | `cancelled` | 状态改为 CANCELLED 时 |
| `ScheduleController.delete` | `cancelled` | 排期删除时 |

### 2.2 上行：classroom-service → booking-api（出勤回流/告警/对账）

**实现方式**：classroom-service 的 `CallbackService` 通过 RestTemplate + HMAC 签名回调 booking-api。

**新增接口**（在 booking-api 中接收回调）：

| 接口 | 方法 | 说明 | 对应需求 |
|------|------|------|---------|
| `/api/v1/classrooms/attendance` | POST | 出勤与课时消耗明细 | F2-06, F7-02 |
| `/api/v1/classrooms/events` | POST | 课堂事件（签到/退出/迟到） | F7-03 |
| `/api/v1/classrooms/alerts` | POST | 异常告警 | F7-03 |
| `/api/v1/classrooms/reconcile` | POST | 日终对账报告 | F7-05 |

**新增 Controller**：`api/src/main/java/com/reservation/controller/ClassroomCallbackController.java`

```java
@RestController
@RequestMapping("/api/v1/classrooms")
public class ClassroomCallbackController {

    private final HmacSigner hmacSigner;
    private final AppointmentService appointmentService;

    /**
     * 接收 classroom-service 的出勤回流。
     * 验证 HMAC 签名 → 更新预约系统的课次记录（出勤状态/有效时长/课时消耗）。
     */
    @PostMapping("/attendance")
    public Result<Void> receiveAttendance(
            @RequestBody AttendanceCallbackReq req,
            @RequestHeader("X-Hmac-Signature") String signature) {
        // 验签
        if (!hmacSigner.verify(objectMapper.writeValueAsString(req), signature)) {
            return Result.fail(403, "签名验证失败");
        }
        // 更新课次出勤记录
        for (AttendanceCallbackReq.AttendanceItem item : req.getItems()) {
            appointmentService.updateAttendance(req.getScheduleId(), item);
        }
        return Result.success();
    }
}
```

### 2.3 通信时序

```
排期创建：
  前端 → POST /api/v1/schedule/create → booking-api 落库
    └─→ ClassroomEventPushService.push("created") ──→ classroom-service
                                                        └─→ 写 classroom 表 + membership 表
                                                        └─→ 写 reconcile_log（SUCCESS）

课堂运行：
  前端 → POST /api/v1/classrooms/{scheduleId}/enter → classroom-service（nginx 直连 8092）
    └─→ 签到记录 + 在线状态

课堂关闭：
  教师 → POST /api/v1/classrooms/{scheduleId}/end → classroom-service
    └─→ 状态流转 LIVE → CLOSED
    └─→ CallbackService.sendAttendanceCallback() ──→ booking-api
        POST /api/v1/classrooms/attendance（HMAC 签名）
          └─→ 更新课次出勤 + 课时消耗
```

## 三、前端接入方案

### 3.1 Nginx 路由扩展

在现有 nginx 配置中增加 classroom-service 的分流规则：

```nginx
# ---- classroom-service 分流（新增） ----
location /api/v1/schedules/events { proxy_pass http://127.0.0.1:8092; }
location /api/v1/schedules/sync   { proxy_pass http://127.0.0.1:8092; }
location /api/v1/classrooms/      { proxy_pass http://127.0.0.1:8092;
                                    proxy_read_timeout 120s; }
location /api/v1/recordings/      { proxy_pass http://127.0.0.1:8092; }
location /ws/classrooms/          { proxy_pass http://127.0.0.1:8092;
                                    proxy_http_version 1.1;
                                    proxy_set_header Upgrade $http_upgrade;
                                    proxy_set_header Connection "upgrade";
                                    proxy_read_timeout 3600s; }

# ---- 现有规则保持不变 ----
location /api/v1/sensitive  { proxy_pass http://127.0.0.1:8090; }
location /api/v1/message    { proxy_pass http://127.0.0.1:8090; }
location /api/v1/sse        { proxy_pass http://127.0.0.1:8090; proxy_buffering off; }
location /api/v1/users/     { proxy_pass http://127.0.0.1:8090; }
location /api/v1/           { proxy_pass http://127.0.0.1:8081; }
```

**关键点**：
- `/api/v1/classrooms/` 注意末尾斜杠，避免与 booking-api 的 `/api/v1/classroom`（如有）冲突
- `/ws/classrooms/` 需要 WebSocket 升级头
- `/api/v1/schedules/events` 和 `/api/v1/schedules/sync` 是 classroom-service 的入向接口，需路由到 8092
- `/api/v1/schedule/`（单数，无 events）仍路由到 8081（booking-api 的排期管理）

### 3.3 WebSocket 连接封装

在 `frontend/js/public/` 下新增 `classroom-ws.js`：

```javascript
/**
 * classroom-service WebSocket 封装。
 * 三条通道：白板/心跳/信令。
 */
const ClassroomWS = {
    _sessions: {},

    connect(scheduleId, token, handlers) {
        const base = `${location.protocol === 'https:' ? 'wss' : 'ws'}://${location.host}/ws/classrooms/${scheduleId}`;
        const tokenQuery = `?access_token=${token}`;

        // 心跳通道
        const heartbeat = new WebSocket(`${base}/heartbeat${tokenQuery}`);
        heartbeat.onmessage = (e) => {
            const msg = JSON.parse(e.data);
            if (msg.type === 'heartbeat' && handlers.onHeartbeat) handlers.onHeartbeat(msg);
        };
        // 每 15 秒发心跳
        const hbTimer = setInterval(() => {
            if (heartbeat.readyState === WebSocket.OPEN) {
                heartbeat.send(JSON.stringify({ type: 'heartbeat', userId: handlers.userId, ts: Date.now() }));
            }
        }, 15000);

        // 信令通道（点名/成员状态/上下课通知）
        const signal = new WebSocket(`${base}/signal${tokenQuery}`);
        signal.onmessage = (e) => {
            const msg = JSON.parse(e.data);
            if (handlers.onSignal) handlers.onSignal(msg);
        };

        // 白板通道
        const whiteboard = new WebSocket(`${base}/whiteboard${tokenQuery}`);
        whiteboard.onmessage = (e) => {
            const msg = JSON.parse(e.data);
            if (handlers.onWhiteboard) handlers.onWhiteboard(msg);
        };

        this._sessions[scheduleId] = { heartbeat, signal, whiteboard, hbTimer };
    },

    disconnect(scheduleId) {
        const s = this._sessions[scheduleId];
        if (!s) return;
        clearInterval(s.hbTimer);
        s.heartbeat.close(); s.signal.close(); s.whiteboard.close();
        delete this._sessions[scheduleId];
    },

    sendWhiteboard(scheduleId, data) {
        const s = this._sessions[scheduleId];
        if (s && s.whiteboard.readyState === WebSocket.OPEN) {
            s.whiteboard.send(JSON.stringify({ type: 'whiteboard', ...data }));
        }
    },

    sendSignal(scheduleId, data) {
        const s = this._sessions[scheduleId];
        if (s && s.signal.readyState === WebSocket.OPEN) {
            s.signal.send(JSON.stringify(data));
        }
    }
};

window.ClassroomWS = ClassroomWS;
```

## 六、实施计划

### 阶段一：后端对接（1-2 周）

1. booking-api 新增 `ClassroomEventPushService`，在 `ScheduleController` 埋点
2. booking-api 新增 `ClassroomCallbackController`，接收出勤回流
3. booking-api `application.properties` 新增 classroom.service.base-url 配置
4. 联调：创建排期 → classroom-service 收到事件 → 课堂状态查询

### 阶段二：前端基础（2-3 周）

1. 新增 `classroom-api.js` 和 `classroom-ws.js` 公共封装
2. 教师端 `teacher-classroom.html` + `teacher-classroom.js`（开课/下课/成员/讲稿）
3. 学生端 `student-classroom.html` + `student-classroom.js`（进入/签到/讲稿同步）
4. nginx 路由配置更新

### 阶段三：功能完善（3-4 周）

1. 教师端点名/作品批阅/录制管理
2. 学生端作品提交/点名响应/录制回放
3. 管理员端课堂监控台
4. WebSocket 白板协作
5. 端到端测试
