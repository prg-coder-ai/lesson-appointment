# 前后端分离 L1 路线实施总结（2026-09-07）

> 路线：Nginx 同域反代。前端静态由 Nginx `:8080` 托管，`/api/v1/` 反代到后端 `:8081`；API 路径统一为 `/api/v1/`。platform-admin 套件继续留在后端 `api` 模块。

> ⚠️ **本文档为 2026-09-07 的 L1 阶段历史记录，部分结论已被后续阶段覆盖。请以最新状态为准：**
> - **Phase 2**：租户管理端 `admin.html` 套件迁至前端 `frontend/`。
> - **Phase 3（2026-09-09）**：平台管理端 `platform_admin.html` 套件**也已迁至前端** `frontend/`，与业务前端统一构建成 `dist/` 由 Nginx 伺服。
> - 后端 `api` 模块自此为**纯后台服务**：`src/main/resources/static/` 已整体删除，`booking_api-1.0.0.jar` 不含任何页面；`api/build-platform.js`、`api/package.json`、`node_modules` 已删，`api/pom.xml` 的 `frontend-maven-plugin` 已移除（**api 不再跑 Node**），仅保留一个缺省自我标识页 `/`。
> - message-service 同样新增缺省自我标识页 `/`（程序名 / 版本 / 构建时间 / 服务器时间 / 时区 / 已运行时长）。
> - 前端登录分发：`platform_admin` 角色由 `ADMIN_ORIGIN`（`:8081`）改为 `FRONTEND_ORIGIN`（`:8080`）；`api.js` 现仅 `frontend/js/public/api.js` 一份，无双份同步问题。
> - 因此，本文中出现「`platform_admin.html` 由 `:8081` 提供」「后端保留静态页」「双份 api.js 须同步」等表述**均已失效**。

## 1. 为什么走 L1

| 路线 | 做法 | 结论 |
|------|------|------|
| L0 | 仅把 static 移出、不动前缀 | 改动小但前端仍耦合后端端口，灰度价值低 |
| **L1（采用）** | Nginx 同域：`8080` 静态 + `8080/api/v1/` → `8081` | 最小改动、同域无 CORS、可平滑演进到独立部署 |
| L2 | 前端独立域名 + 独立构建流水线 | 工作量过大，本期不做 |

L1 同时满足「统一 `/api/v1/` 前缀」「新前端 vanilla 移植全部业务界面」「后端保留 platform-admin 套件」三项用户要求。

- 在 `const API_BASE_URL = window.API_BASE_URL || '';` 后新增 `normalizeUrl(url)`：
  - 绝对 http(s) 原样返回；
  - 已以 `/api/v1` 开头原样返回；
  - 以 `/api/` 开头 → 换成 `/api/v1` + 余下；
  - 以 `/` 开头 → 补 `/api/v1`；
  - 其余原样。
- `service` 实例与 `refreshTokenAxios` 独立实例的请求拦截器首行均 `config.url = normalizeUrl(config.url);`。

## 9. L1 后续修复：安全白名单补齐 `/api/v1` 前缀（2026-09-07）

### 9.1 问题
本地 8081 起后端、前端 8080 经 Nginx 反代，teacher/student（及所有角色）登录返回 401。

### 9.2 根因
L1 把 20 个控制器类级前缀统一为 `/api/v1`，但三处「公开路径白名单」仍写旧裸路径、未含 `/api/v1` 前缀：
- `SecurityConfig` 的 `permitAll` 匹配项（登录/注册/公开接口）
- `JwtAuthenticationFilter` 的 `WHITELIST_PATHS`
- `WebMvcConfig` 的 `EXCLUDE_PATTERNS`（TenantInterceptor 租户拦截器）

导致 `/api/v1/auth/login` 等公开接口落到 `anyRequest().authenticated()`，无 token 即被 `AuthenticationEntryPoint` 返回 401；即便 Security 放行，`TenantInterceptor.preHandle` 对无 `Authorization` 头也直接返回 `{"code":401,"msg":"未登录，请先登录"}`。三道拦截均在到达 `AuthController` 之前，故登录永远进不去（交叉验证：`/api/v1/tenant/name`、`/api/v1/schedule/getAvailableSchedule` 同样 401）。

### 9.3 修复
三处白名单均补 `/api/v1` 前缀的对应条目（旧裸路径保留以兼容遗留调用）。涉及文件：
- `api/src/main/java/com/reservation/config/SecurityConfig.java`
- `api/src/main/java/com/reservation/config/JwtAuthenticationFilter.java`
- `api/src/main/java/com/reservation/config/WebMvcConfig.java`

### 9.4 生效条件
须**重新编译并重启后端**（Spring Security 与 MVC 拦截器配置为启动时加载，devtools 热重载不生效）。`cd api && bash run.sh` 重启后，登录与所有公开接口即恢复正常。
