## 第一步：开通云托管环境

```
微信开发者工具 → 工具栏「云开发」→ 开通「云托管」
  或直接访问 https://cloud.weixin.qq.com/ → 云托管
```

1. **选择地域**：建议选离用户最近的（如广州 ap-guangzhou / 上海 ap-shanghai）
2. **创建环境**：命名如 `lesson-appointment`，会分配一个环境 ID（`envId`，后续 CLI 用）
3. **计费模式**：首次开通有免费额度（通常 1 个月），之后选**按量计费**（小项目比包月省）

> 开通后获得一个 **环境 ID**（形如 `prod-1g0xxxxx`），记下来。

---

## 第二步：创建云托管 MySQL

```
云托管控制台 → 云资源 → MySQL → 新建
```

| 配置项 | 推荐值 | 说明 |
|--------|--------|------|
| 实例规格 | 1C1G 基础版 | 小规模够用，后续可升配 |
| 数据库版本 | MySQL 8.0 | 与项目一致 |
| 计费方式 | 包月（比按量便宜约 40%） | ~50-80 元/月 |
| 账号密码 | 自定义 root 密码 | 记录下来，后续作为环境变量 |

创建后获得：
- **内网地址**（形如 `10.0.0.xxx:3306`，仅同环境内网可访问）
- **外网地址**（需手动开启，用于本地调试导入数据）

### 导入数据

```bash
# 开启外网访问后，用本地 mysql 客户端连接
mysql -h <外网地址> -P 3306 -u root -p

# 导入两个 schema
source api/sql/schema/20261011-0105-lesson_appointment-schema.sql;
source api/message-service/src/main/resources/schema.sql;
# 再导入 seed 数据（如有）
```

导入完成后**关闭外网访问**（安全收口）。

## 第三步：为两个服务编写 Dockerfile

项目当前无 Dockerfile，需新建两份。

### 3.1 业务服务 `api/Dockerfile`

```dockerfile
# ---- 构建阶段 ----
FROM maven:3.9-eclipse-temurin-17 AS builder
WORKDIR /build
COPY pom.xml .
COPY src/ src/
RUN mvn package -DskipTests -q

# ---- 运行阶段 ----
FROM eclipse-temurin:17-jre-alpine
WORKDIR /app
COPY --from=builder /build/target/booking-api-*.jar app.jar

# 云托管要求：监听端口由环境变量 PORT 注入
ENV SERVER_PORT=8081
EXPOSE 8081

# 健康检查（云托管自动探测 /actuator/health/readiness）
ENTRYPOINT ["java", "-jar", "app.jar", \
  "--server.port=${PORT:8081}", \
  "--spring.profiles.active=prod"]
```

### 3.2 消息服务 `api/message-service/Dockerfile`

```dockerfile
FROM maven:3.9-eclipse-temurin-17 AS builder
WORKDIR /build
COPY pom.xml .
COPY src/ src/
RUN mvn package -DskipTests -q

FROM eclipse-temurin:17-jre-alpine
WORKDIR /app
COPY --from=builder /build/target/message-service-*.jar app.jar

ENV SERVER_PORT=8090
EXPOSE 8090

ENTRYPOINT ["java", "-jar", "app.jar", \
  "--server.port=${PORT:8090}", \
  "--spring.profiles.active=prod"]
```

> **优化提示**：若本地已 `mvn package` 出 jar，可跳过构建阶段，直接 `COPY target/xxx.jar app.jar`，推送更快。

## 第四步：部署两个服务

### 方式 A：控制台可视化部署（推荐首次使用）

```
云托管控制台 → 服务列表 → 新建服务
```

**服务 1：booking-api**

| 配置项 | 值 |
|--------|-----|
| 服务名称 | `booking-api` |
| 服务端口 | `8081` |
| 上传方式 | 本地代码（选 `api/` 目录，含 Dockerfile） |
| CPU/内存 | 0.5 核 / 1G（最小规格） |
| 最小实例数 | 0（缩容到 0 省钱，有请求自动拉起） |
| 最大实例数 | 2 |
| 冷启动超时 | 30s（Java 启动较慢） |

**服务 2：message-service**

| 配项同上，端口改 `8090`，上传目录选 `api/message-service/` |

### 方式 B：CLI 部署（适合 CI/CD）

```bash
# 安装云托管 CLI
npm install -g @wxcloud/cli

# 登录
wxcloud login

# 部署 booking-api
wxcloud deploy \
  --env prod-1g0xxxxx \
  --serviceName booking-api \
  --localDir ./api \
  --containerPort 8081

# 部署 message-service
wxcloud deploy \
  --env prod-1g0xxxxx \
  --serviceName message-service \
  --localDir ./api/message-service \
  --containerPort 8090
```

部署成功后，每个服务会获得一个 **HTTPS 域名**：

```
booking-api:      https://booking-api-prod-1g0xxxxx-xxxx.run.tcloudbase.com
message-service:  https://message-service-prod-1g0xxxxx-xxxx.run.tcloudbase.com
```

> 这些域名**已备案、已 HTTPS**，可直接加入小程序白名单。

## 第五步：配置环境变量（密钥注入）

```
云托管控制台 → 服务详情 → 环境变量 → 编辑
```

**两个服务都配以下变量**（值从 `application.properties` 的 `${VAR:default}` 对应）：

| 变量名 | 值 | 说明 |
|--------|-----|------|
| `DB_USERNAME` | `root` | 云托管 MySQL 账号 |
| `DB_PASSWORD` | （第二步设的密码） | 云托管 MySQL 密码 |
| `JWT_SECRET` | （重新生成的 Base64 密钥） | **勿用仓库里的明文默认值** |
| `AES_KEY` | （重新生成的 32 字节 Base64） | **换密钥需同步重加密历史数据** |
| `HMAC_KEY` | （重新生成的 32 字节 Base64） | - |
| `WECHAT_APPID` | `wxc4f96c9bd2351015` | 小程序 appid |
| `WECHAT_SECRET` | （微信公众平台获取） | 小程序 appsecret |

### 修改数据库连接地址

两个服务的 `application.properties` 需把 `localhost:3306` 改为云托管 MySQL 内网地址。有两种方式：

**方式 1（推荐）：环境变量注入**

```properties
# application.properties 改为
spring.datasource.url=jdbc:mysql://${DB_HOST:localhost}:3306/lesson_appointment?useUnicode=true&characterEncoding=utf8&serverTimezone=UTC&allowPublicKeyRetrieval=true
```

环境变量加 `DB_HOST=10.0.0.xxx`（云托管 MySQL 内网 IP）。

**方式 2：新增 `application-prod.properties`**

```properties
# application-prod.properties（不进版本库，加入 .gitignore）
spring.datasource.url=jdbc:mysql://10.0.0.xxx:3306/lesson_appointment?...
```

Dockerfile 中已加 `--spring.profiles.active=prod`，会自动加载。

## 成本估算（小规模）

| 资源 | 规格 | 月费 |
|------|------|------|
| 云托管 MySQL | 1C1G 基础版 | ~50-80 元 |
| booking-api 容器 | 0.5C1G，最小实例 0 | ~30-60 元（按量） |
| message-service 容器 | 0.5C1G，最小实例 0 | ~20-40 元（按量） |
| **合计** | | **~100-180 元/月** |

> 最小实例数设为 0 时，无请求不计费，但有**冷启动延迟**（Java 约 5-15 秒）。若对延迟敏感，设最小实例 1，月费约 +60 元/服务。

---

## 注意事项

| 项 | 说明 |
|---|------|
| **冷启动** | Java JVM 启动慢，最小实例 0 时首次请求延迟 5-15s。建议 booking-api 设最小实例 1，message-service 可设 0 |
| **AES 密钥** | 若用新密钥，历史加密数据（phone/email/name）不可解，需先在旧库导出明文再重新加密导入 |
| **日志** | 云托管自动收集容器 stdout，现有 logback 配置仍生效，但 `./logs/` 落盘文件不可持久（容器重启即丢），需改用云托管日志 |
| **SSE** | message-service 的 SSE 长连接在云托管中**可能被网关超时断开**（通常 60s），小程序端用轮询不受影响，Web 端需加断线重连 |
| **文件存储** | 当前无文件上传，若后续加头像/图片，用云托管的**对象存储 COS**，不要放容器本地 |
