# 平台与租户 / 租户与用户的协议及隐私政策 —— 合规设计方案

> 文档版本：v1.0（设计稿）　起草日期：2026-10-14
> 适用范围：多租户预约系统（lesson_appointment，SaaS 架构）
> 协议 / 隐私政策**文本草案**已独立为《协议与隐私政策文本草案.md》；本文聚焦数据模型、管理方案、签署方案与落地计划。

---

## 〇、重要声明（使用前置）

1. 协议与隐私政策**文本草案**（场景 A 平台↔租户、场景 B 租户↔用户，各含用户协议 + 隐私政策）已独立成文件《协议与隐私政策文本草案.md》。文本为**产品级模板草案**，用于确定条款结构、覆盖范围与可配置字段。**正式上线前必须经执业律师 / 法务按适用法域（中国大陆《个人信息保护法》《网络安全法》《数据安全法》《民法典》及行业监管）逐条审阅修订**，本草案不构成法律意见。
2. 文本中所有【方括号】内容为**占位变量**，需由管理方在后台维护时填充（运营主体名称、联系方式、备案号、行业专属条款等）。
3. 系统设计的核心目标：**同一套文档模型，平台与租户两个层级各自可维护、可版本化、可追溯签署**，前端公开可读、未登录亦可访问。

---

## 一、需求分析

### 1.1 两个合规场景的本质差异

| 维度 | 场景 A：平台 ↔ 租户 | 场景 B：租户 ↔ 注册用户 |
|---|---|---|
| 签署双方 | 平台运营方（SaaS 提供方） ⇄ 入驻租户（B 端商家，如律所） | 某租户 ⇄ 其 C 端用户（学员 / 咨询者 / 教师） |
| 文档归属 | **平台单向制定**，租户只能"签"不能"改" | 默认继承平台，**租户可覆盖**本租户版本 |
| 签署时机 | 租户自助建租户（推广路径 1）末步确认 | 用户在 web / 小程序注册或首次登录时确认 |
| 数据角色 | 平台是租户数据的**处理者**（受托） | 租户是用户个人信息的**控制者**，平台是受托处理者 |
| 作用域解析 | 平台级（tenant_id = 0） | 平台级 → 租户级覆盖（tenant_id = 该租户） |

### 1.2 当前缺口（已查证）

- 系统**无任何**协议 / 政策存储表与同意钩子：登录 / 注册流程无勾选框，`sys_system_config` 仅存 ≤500 字符短参数，`sys_term.term_name` 仅 varchar(64)，均不适合存长文档。
- 现状可复用的基建：
  - **`sys_term` 三级作用域模型**（`industry_id` + `tenant_id` + `language` + `status` 停用回退 + 唯一键）——可直接照抄其"平台 / 行业 / 租户优先级 + 多语言 + 停用回退"思路做协议文档解析。
  - **`/api/v1/sys/config/update` 已带 `checkPlatformAdmin`** 平台管理员改配置入口；web 端「系统设置」页（`platform-admin-config.js`）已有 行业管理 / 行业词汇 / 系统参数 三个 tab，**加「协议与政策」tab 最自然**。
  - **`免登录白名单`有四处处处同步点**（SecurityConfig.permitAll / JwtFilter.WHITELIST_PATHS / check-authz 的 PERMIT_ALL / WebMvcConfig.EXCLUDE_PATTERNS）——协议阅读页必须免登录可读，新端点四处都要加，缺一即运行时裸 401。

## 二、数据模型设计（新建两张表）

### 2.1 `sys_legal_doc`（法律文档主表）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | bigint PK | 自增 |
| doc_type | varchar(32) | `user_agreement` / `privacy_policy` |
| tenant_id | bigint | **0 = 平台级**；>0 = 租户覆盖级 |
| industry_id | bigint | 行业 id（预留行业级微调，当前可默认 0） |
| language | varchar(16) | `zh` / `en` / `fr` … 默认 `zh` |
| title | varchar(255) | 文档标题 |
| content | longtext | 正文（**HTML 或 Markdown**，前端渲染） |
| version | int | 每次保存 +1，从 1 起 |
| status | tinyint | 1=启用 0=停用（停用回退上级） |
| effective_time | datetime | 生效时间 |
| create_time / update_time | datetime | 审计 |

**唯一约束建议**：`uk_doc (doc_type, tenant_id, industry_id, language, version)` —— 保留所有历史版本，可版本对比 / 强制重签。
**读取解析**（复用 term 优先级）：`按 (doc_type, 当前租户 tenant_id, language, status=1, 最大 version)` 优先；命中为空 **回退 (doc_type, 0, language, status=1, 最大 version)**（平台级兜底）。

### 2.2 `sys_legal_accept`（签署留痕）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | bigint PK | 自增 |
| subject_type | tinyint | 1=租户(场景A) 2=用户(场景B) |
| subject_id | bigint | 租户 id 或 用户 id |
| doc_type | varchar(32) | 同主表 |
| version | int | 签署时所读版本（留痕关键） |
| accept_time | datetime | 签署时间 |
| channel | varchar(16) | `web` / `miniprogram` |
| ip | varchar(64) | 来源 IP（审计） |

> 唯一约束建议：`uk_subject_doc (subject_type, subject_id, doc_type)` —— 同一主体同一文档仅保留最新一次签署记录（含版本与时刻），重签即更新。

### 2.3 多语言与多行业

- 文档正文与 `sys_term` 同源走 `language` 字段；前端按 `lang` 请求对应语言版本。
- 行业级微调（如律师咨询行业对"咨询记录保密"的特殊条款）通过 `industry_id` 维度扩展，默认与平台级共用。

## 四、管理方"更换 / 修改"落地方案

### 4.1 平台管理员（场景 A 文档维护）
- 入口：`platform_admin.html` → 系统配置 → 系统设置 → **新增「协议与政策」tab**（与现有 行业管理 / 行业词汇 / 系统参数 并列）。
- 能力：对 `doc_type ∈ {user_agreement, privacy_policy}` 且 `tenant_id = 0` 的文档进行**富文本 / Markdown 编辑**；保存即 `version + 1`、置 `status=1`、记录 `effective_time`。
- 历史版本保留，支持「查看历史 / 恢复 / 版本对比」。

### 4.2 租户管理员（场景 B 文档覆盖）
- 入口：`admin.html` → 系统设置 → 协议与政策。
- 能力：
  - **平台协议（场景 A）仅展示不可编辑**（租户只能"签"不能"改"）。
  - **本租户的用户协议 / 隐私政策可编辑覆盖**（写 `tenant_id = 本租户`），保存即升版本。

### 4.3 强制重签开关
- 管理端提供"**发布后强制未签署 / 旧版本用户重新确认**"开关；开启后，凡 `sys_legal_accept.version` 低于当前启用版本者，下次登录强制弹窗确认。

## 五、用户"阅读 + 签署"落地方案

### 5.1 公开阅读页（免登录）
- 端点：`GET /api/v1/legal/doc?type=privacy_policy&tenant={tenantCode}&lang=zh`
  - 返回解析后的启用版本正文（HTML/Markdown）+ `version`。
  - **必须加入四处处处白名单**：SecurityConfig.permitAll / JwtFilter.WHITELIST_PATHS / check-authz 的 PERMIT_ALL / WebMvcConfig.EXCLUDE_PATTERNS。
- 前端：web 用独立页 `legal.html`；小程序用 `web-view` 打开同款 H5（复用，避免双端维护）。

### 5.2 签署钩子（当前缺失，需新增）
- **场景 B（注册 / 登录确认）**：
  - web `login.html`、小程序 `login.js` 注册 / 登录处加「已阅读并同意《用户协议》《隐私政策》」勾选框，未勾不能过。
  - 提交时把当前 `version` 写入 `sys_legal_accept`（subject_type=2）。
- **场景 A（租户入驻末步）**：
  - 推广自助建租户（路径 1）末步加同类确认，version 写入 `sys_legal_accept`（subject_type=1，subject_id=租户 id）。

### 5.3 重签校验
- 登录 / 进入关键流程前，比对 `sys_legal_accept` 中该主体该文档的 `version` 与当前启用版本；低于则触发强制确认弹窗。

## 六、落地实施计划（分阶段）

### Phase 1 —— 最小可用（建表 + 平台级维护 + 公开阅读 + web 签署）
1. 新建 `sys_legal_doc` / `sys_legal_accept` 表（DDL，落 `api/sql/schema/`，重 dump）。
2. 实体 + Mapper + Service：`LegalDocService.resolve(tenantId, docType, lang)`（平台级回退）、`saveVersion()`、`accept()`。
3. 管理接口：`GET /api/v1/sys/legal-doc/*`（平台 / 租户读取）、`POST /api/v1/sys/legal-doc/update`（平台改，带 `checkPlatformAdmin`；租户改带 `checkTenantAdmin` 且 `tenant_id` 锁定自身）。
4. 公开接口 `GET /api/v1/legal/doc`（**四处白名单全加**）。
5. `platform_admin.html` 系统设置加「协议与政策」tab，富文本编辑平台级两份文档。
6. `legal.html` 公开阅读页（web）。
7. web `login.html` 加勾选框 + 写入 `sys_legal_accept`。

### Phase 2 —— 小程序与场景 A 签署
1. 小程序 `login.js` 加勾选框 + 写入签署记录。
2. 推广自助建租户（路径 1）末步加场景 A 确认 + 写入签署记录。
3. 小程序 `web-view` 接通 `legal.html`（或独立小程序阅读页）。

### Phase 3 —— 租户级覆盖 + 重签治理
1. 租户管理员后台可覆盖本租户文档（场景 B，写 `tenant_id`）。
2. "强制重新确认"开关 + 登录时版本比对触发重签。
3. 历史版本查看 / 恢复 / 版本对比。
4. 多语言（en / fr）文档维护与前端切换。

## 七、风险与注意事项

1. **法律文本身非技术产物**：协议文本（见《协议与隐私政策文本草案.md》）必须经法务审定，本文仅定结构与系统方案。
2. **白名单四处同步**：公开阅读端点漏加任一处即裸 401，落地时纳入守卫核对（双路径形态）。
3. **数据安全角色分离**：场景 A 平台是处理者、场景 B 租户是控制者 —— 隐私政策文案与告知义务主体必须对应，平台不可越俎代庖替租户做对终端用户的告知决策。
4. **版本与回退**：停用回退机制须与 `sys_term` 一致保证"平台级兜底"始终可读，避免租户误删致公开页空白。
5. **免登录可读 ≠ 免鉴权滥用**：公开接口仅返回"当前启用版本正文"，不暴露历史版本 / 管理接口。
6. **多租户数据隔离**：`sys_legal_doc` 的 `tenant_id` 维度需纳入 TenantLineInnerInterceptor 忽略表策略（平台级表不参与租户拦截），同 `sys_term` 处理。
