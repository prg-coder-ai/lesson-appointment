# 网页自动操作与录制方案

> 适用对象：本项目的培训演示视频画面素材制作。目标是让智能体用脚本驱动本机浏览器，按分镜镜号自动完成"打开页面 → 登录 → 点击 → 填表 → 弹窗确认"，并逐镜输出视频文件，替代人工录屏。
>
> 配套资产：`培训演示脚本-五集合集-分镜版.md`、`录制清单/第N集-录制清单.md`、`音频/第N集-配音轨.wav`、`字幕/第N集.srt`、`出片验收表.md`。

## 一、结论与边界

| 项目 | 结论 |
|---|---|
| 是否可行 | 可行，需安装 Python 自动化框架，驱动本机已安装的 Edge |
| 内置浏览器工具 | 只能打开页面，**不能操作、不能录制**，不能作为录制方案 |
| 可自动完成 | 导航、点击、输入、下拉、页签切换、弹窗确认、滚动、截图、录屏 |
| 不可自动完成 | 微信扫码、短信验证码、动态图形验证码、真实用户隐私数据 |
| 需要额外处理 | 鼠标指针与点击高亮（自动录屏默认没有光标，需注入模拟光标） |
| 依赖前置 | 服务已启动、演示账号可用、演示数据（待审核/满额/候补等状态）已就绪 |

## 二、软件与依赖

| 软件/库 | 建议版本 | 用途 | 获取方式 |
|---|---|---|---|
| Python | 3.11（本机已具备） | 运行自动化脚本 | — |
| Playwright（Python 包） | ≥ 1.40 | 浏览器自动化、上下文隔离、视频录制 | `pip install playwright -i https://pypi.tuna.tsinghua.edu.cn/simple` |
| Microsoft Edge | 本机已装（111.x） | 被驱动的浏览器，`channel="msedge"`，无需再下载 Chromium | 系统已安装 |
| imageio-ffmpeg | ≥ 0.4 | 自带 ffmpeg 二进制，用于 webm→mp4、补帧、混音 | `pip install imageio-ffmpeg -i https://pypi.tuna.tsinghua.edu.cn/simple` |
| numpy / soundfile | 已安装 | 读配音轨、校验时长与采样格式 | 已具备 |
| 可选：opencv-python | 任意 | 抽帧质检、空白帧检测 | 视需要安装 |

> 不推荐 Selenium：需要与本机 Edge 版本严格匹配的 `msedgedriver`，版本漂移就会启动失败。
> 不推荐 Puppeteer：Node 侧需另行下载 Chromium，本机网络下载不稳定。

## 四、处理流程

### 第 1 步：环境与服务确认

1. 启动主业务服务（8081）与消息中心（8090）
2. 浏览器手工打开登录页，确认页面能正常渲染
3. 安装 Playwright 与 imageio-ffmpeg（使用国内镜像）
4. 不需要执行 `playwright install`，直接复用本机 Edge

### 第 2 步：账号与演示数据准备

1. 按集准备账号：平台管理员、租户管理员、教师、学生
2. 按 `录制清单` 准备状态数据：待审核账号、待审核课程、满额课程、候补队列、待确认预约、取消申请
3. 演示数据集中放在一个专用租户，避免污染真实数据
4. 逐条确认登录方式为**账号 + 密码**，不触发扫码或短信

### 第 3 步：注入录制增强（关键）

自动录屏默认没有鼠标指针，观众会看不出点了哪里。录制前注入 `overlay.js`：

```js
// 伪代码：在页面加载前注入
const dot = document.createElement('div');
dot.style.cssText = 'position:fixed;width:22px;height:22px;border-radius:50%;'
  + 'background:rgba(255,80,80,.85);border:2px solid #fff;z-index:2147483647;'
  + 'pointer-events:none;transition:transform .12s;transform:translate(-50%,-50%)';
document.documentElement.appendChild(dot);

// 跟随鼠标
addEventListener('mousemove', e => dot.style.transform =
  `translate(${e.clientX - 11}px,${e.clientY - 11}px)`);

// 点击涟漪
addEventListener('mousedown', () => dot.style.transform += ' scale(.8)');
addEventListener('mouseup', () => dot.style.transform = dot.style.transform.replace(' scale(.8)', ''));
```

补充要求：

- 关闭页面内动画与过渡（`*{animation:none!important;transition:none!important}`），避免录制抖动
- 右下角固定显示镜号角标，便于后期核对，例如 `E02_S01`
- 光标移动要插值，避免"瞬移"：`page.mouse.move(x, y, steps=25)`

### 第 4 步：按镜号录制

1. 每个镜号建立一个独立 `browser_context`，保证登录态、滚动位置、弹窗状态互不污染
2. 上下文参数：`viewport=1920×1080`、`record_video_dir=原始/`、`record_video_size=1920×1080`
3. 动作表按镜号描述：`goto → wait → click → fill → select → press → wait`
4. 定位优先用**可见文本或角色**（`get_by_role("button", name="新增租户")`），不要用坐标，改版后仍可复用
5. 每步之间显式等待目标元素可见，再补固定停顿，避免录到加载空白
6. 每个镜头录到"镜头秒数"再关闭上下文，防止素材过短
7. 每个镜头结束写一条日志：镜号、开始时间、动作列表、实际时长

### 第 5 步：转码

1. webm → mp4（H.264、25fps、1920×1080、CRF 20、yuv420p）
2. 通过 `imageio_ffmpeg.get_ffmpeg_exe()` 获取 ffmpeg 路径后调用，无需系统级安装
3. 输出到 `成品/`，命名 `E02_S01.mp4`，与素材规范一致

### 第 6 步：时长校准

1. 读取每个成品时长，与分镜"镜头秒"比对
2. 不足：末尾冻结最后一帧（`tpad=stop_mode=clone`）补齐
3. 超出：截断，或回到脚本减少停顿后重录
4. 校准结果写入日志，超差超过 1 秒的镜头标记重录

### 第 7 步：与配音、字幕合成

1. 配音轨 `音频/第N集-配音轨.wav` 已是 24kHz / 16bit / 单声道，且按入点对齐
2. ffmpeg 合成：画面轨 + 配音轨 + `字幕/第N集.srt`
3. 响度统一到 -16 LUFS，片头片尾各 3 秒
4. 输出 `第N集-成片.mp4`

### 第 8 步：质检

1. 每个镜头抽 3 帧，检查是否空白、加载中、弹窗遮挡
2. 核对时长、命名、字幕入点
3. 按 `出片验收表.md` 逐镜勾选，异常进入返工记录

## 五、脚本骨架

```python
# 脚本/record.py（骨架）
import asyncio
from pathlib import Path
from playwright.async_api import async_playwright

RAW = Path("原始"); RAW.mkdir(exist_ok=True)

async def record_shot(shot: dict):
    async with async_playwright() as p:
        browser = await p.chromium.launch(channel="msedge", headless=False)
        ctx = await browser.new_context(
            viewport={"width": 1920, "height": 1080},
            record_video_dir=str(RAW),
            record_video_size={"width": 1920, "height": 1080},
        )
        page = await ctx.new_page()
        await page.add_init_script(path="脚本/overlay.js")
        await page.goto(shot["url"], wait_until="networkidle")

        for step in shot["steps"]:
            await page.wait_for_selector(step["target"], state="visible")
            if step["action"] == "click":
                await page.get_by_role("button", name=step["target"]).click()
            elif step["action"] == "fill":
                await page.get_by_label(step["target"]).fill(step["value"])
            await page.wait_for_timeout(step.get("pause", 600))

        # 录满镜头时长
        await page.wait_for_timeout(int(shot["seconds"] * 1000))
        await ctx.close()
        await browser.close()
```

## 六、风险与人工介入点

| 风险 | 影响 | 处置 |
|---|---|---|
| 扫码/短信登录 | 脚本中断，录到登录页卡住 | 统一走账号密码；确需扫码的镜头人工补录 |
| 异步加载慢 | 录到空白或半渲染页面 | 每步 `wait_for_selector`；必要处等待接口完成 |
| 弹窗层级或遮挡 | 点击落空 | 按文本/角色定位，加 `scroll_into_view_if_needed` |
| 状态数据被消耗 | 后续镜头无可用数据 | 每镜录制前重置；或准备多条同状态记录 |
| 自动光标生硬 | 观感差、不可用 | 调整光标尺寸与移动插值步数，录制后试看 |
| 分辨率与缩放 | 文字模糊 | 系统缩放 100%，视口固定 1920×1080，禁用设备模拟缩放 |
| 页面改版 | 脚本失效 | 用语义选择器；改版后只改动作表 |

## 七、试点方案

先做 1 个镜头（第 2 集 2-1，登录页）：

| 项目 | 内容 |
|---|---|
| 输入 | 动作表 1 份、overlay.js、演示账号 |
| 产出 | `E02_S01.mp4`、3 张抽帧、1 份日志 |
| 验收 | 分辨率 1920×1080；光标可见且移动自然；无加载空白；时长 14.5s ±0.5；文字无模糊 |

试点通过后再批量，否则回退人工录屏，仅保留自动转码与合成。

## 九、决策建议

| 情形 | 建议 |
|---|---|
| 页面稳定、操作路径固定、以列表和表单为主 | 批量自动化，收益最高 |
| 含扫码登录、页面频繁改版、强依赖实时数据 | 人工录屏，自动只做转码、合成与校验 |
| 折中 | 静态页面与表单自动录，关键交互人工补录，统一走自动合成与验收 |
