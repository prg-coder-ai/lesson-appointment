## 二、数据模型（v2 修订）

### 2.1 `wx_userid`（微信 openid 关联表）

与原稿一致，但补充租户插件处理说明。

```sql
CREATE TABLE `wx_userid` (
  `id`          bigint       NOT NULL AUTO_INCREMENT COMMENT '自增主键',
  `wx_openid`   varchar(64)  NOT NULL COMMENT '微信 openid（全局唯一，不随租户隔离）',
  `user_id`     varchar(36)  NOT NULL COMMENT '关联 user.user_id',
  `tenant_id`   bigint       NOT NULL COMMENT '用户所属租户（冗余，便于按租户统计）',
  `bind_source` varchar(20)  NOT NULL DEFAULT 'manual' COMMENT 'manual=已有账号绑定 / auto_register=微信直接注册',
  `create_time` datetime     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `update_time` datetime     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_wx_openid` (`wx_openid`) COMMENT '一个微信最多关联一个账号',
  KEY `idx_user_id` (`user_id`),
  KEY `idx_tenant_id` (`tenant_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='微信 openid 与用户 ID 关联表';
```

> **租户隔离**：本表**有** `tenant_id` 列，但语义是"冗余统计"，隔离应当被**显式跳过**（一个微信全局只绑一个账号，跨租户统一）。  
> 做法二选一（推荐前者，集中可查）：
>
> 1. `WxUseridMapper` 全类加 `@InterceptorIgnore(tenantLine = "true")`
> 2. 把 `wx_userid` 加入 `IGNORE_TABLES`
>
> 若**两者都不做**，插件会追加 `tenant_id = 当前租户`，导致跨租户场景（平台管理员）查不到绑定 → 静默失败。这是必须显式处理的点。

## 三、8 字符 tenantCode —— **D3 修订**

### 3.1 生成规则（不变）

```java
public class TenantCodeGenerator {
    // 去除易混淆字符：0/O、1/I/l
    private static final char[] CHARS =
        "23456789abcdefghjkmnpqrstuvwxyzABCDEFGHJKMNPQRSTUVWXYZ".toCharArray();
    private static final int DEFAULT_LENGTH = 8;
    private static final SecureRandom RANDOM = new SecureRandom();

    public static String generate() { return generate(DEFAULT_LENGTH); }

    public static String generate(int length) {
        StringBuilder sb = new StringBuilder(length);
        for (int i = 0; i < length; i++) sb.append(CHARS[RANDOM.nextInt(CHARS.length)]);
        return sb.toString();
    }
}
```

### 3.2 组合数修正

库是 **`utf8mb4_general_ci`（大小写不敏感）**，`K` 与 `k` 视为同一字符。  
字符集 54 个 → 大小写等价后有效字符 = 8 个数字 + 21 个字母 = **29 个**

```
有效组合 = 29^8 ≈ 5.0×10^11   （原稿写 54^8 ≈ 7.2×10^13，高估约 144 倍）
1 万租户时碰撞概率 ≈ n²/(2N) ≈ 1×10^-4；重试 10 次后失败概率可忽略
```

**结论不变（可行），但文档数字要按 29^8 写。**

### 3.3 唯一性保证

```java
public String generateUniqueTenantCode() {
    int maxRetry = sysConfigService.getInt("tenant.code.max.retry", 10);
    for (int i = 0; i < maxRetry; i++) {
        String code = TenantCodeGenerator.generate();
        if (getByCode(code) == null) return code;   // 走 sys_tenant.uk_tenant_code
    }
    throw new BusinessException("租户编码生成失败，请重试");
}
```

> 因大小写不敏感，同一个码的大小写变体也会撞唯一键 —— 这只会**增加**重试概率，不会造成错绑，可接受。

### 3.4 硬约束：`platform` 行不得改写 —— **D3 关键**

`UserService.fillOrgName` 依赖 **`tenant_code = 'platform'`** 定位平台自身行（真库 `id=11`），用于：

- 平台管理员的「所属公司」显示
- `/user/briefs` 回 `orgName` 时，`tenant_id <= 0` 的兜底（`v2 昨夜刚落地的功能`）

**约束**：

1. `TenantCodeGenerator` **只用于新建租户**，不得对已存在行做批量重编
2. 若将来必须重编历史数据，**显式排除 `tenant_code = 'platform'`**
3. 新建租户时校验生成结果不与保留字冲突：

```java
private static final Set<String> RESERVED_TENANT_CODES = Set.of("platform", "default");

public String generateUniqueTenantCode() {
    for (int i = 0; i < maxRetry; i++) {
        String code = TenantCodeGenerator.generate();
        if (RESERVED_TENANT_CODES.contains(code.toLowerCase())) continue;  // 撞保留字则换
        if (getByCode(code) == null) return code;
    }
    throw new BusinessException("租户编码生成失败，请重试");
}
```

### 3.5 与账号关联（不变）

注册租户时把创建者 `account` 写入 `sys_tenant.creator_account`，提供：

- `GET /api/v1/tenant/code-by-account?account=xxx` → `{ tenantCode, orgName }`
- `TenantService.getByCreatorAccount(account)`

> **权限提醒**：该接口回租户编码 + 机构名，属于可被枚举的信息。原稿标 `permitAll`。  
> **v2 建议**：收敛为「**本人账号** 或 **管理员**」才可查（否则任意账号可反查其所属租户）。若必须 permitAll，至少加限频。

### 4.1 场景 A：静默登录（已绑定）

```
小程序启动 → 无本地会话 → wechatSilentLogin()
  ① wx.login() → code（静默）
  ② POST /api/v1/auth/wechat-login { code }（不带 Bearer）
  ③ WeChatService.code2Session(code) → openid
  ④ WxUseridService.findByOpenid(openid)
     ├─ 命中 → 状态校验 → 发 token → { token, role, tenantCode } → 进首页
     └─ 未命中 → Result.fail(1001, ...) → 前端静默降级（密码登录 / 微信注册）
```

> **必须用 1001 而非 401**：401 会触发小程序 `request.js` 的 `onAuthFail` 重定向把用户踢回登录页；此处只是"未绑定"，应静默降级。该约定在原屏蔽代码注释里已写明，**解除屏蔽时不要改**。

### 4.2 场景 B：已有账号绑定

```
密码登录成功 → 勾选"允许微信登录" → bindWechat()
  ① wx.login() → code
  ② POST /api/v1/auth/bind-wechat { code }（带 Bearer）
  ③ code2Session → openid
  ④ 校验 openid 未被其他账号占用（uk_wx_openid）
  ⑤ INSERT wx_userid { wxOpenid, userId, tenantId, bindSource:'manual' }
```

> 失败用 **400 而非 401**（401 会把已登录用户踢出），该约定同样在原注释里，保留。

### 4.3 场景 C：微信直接注册（**新增**）

```
扫码进入（带 ref / tcode）
  → wechatSilentLogin() 返回 1001（未绑定）
  → 检测到 tenantCode → POST /api/v1/auth/wechat-register { code, tenantCode, role }
  → 后端：
     ① code2Session → openid
     ② 查 wx_userid 未命中（防重复）
     ③ getByCode(tenantCode) → tenant，校验 status 正常
     ④ 事务内：
        ├─ 创建 User { account: openid, password: 随机UUID密文, role: student, status: pending }
        ├─ TenantQuotaService.acquire(tenantId, USER)      ← 原稿笔误 acquire8 已修
        ├─ 若 role=student 再 acquire(tenantId, STUDENT)
        ├─ INSERT wx_userid { openid, userId, tenantId, bindSource:'auto_register' }
        └─ 发 token
     ⑤ 返回 { token, userId, role, tenantCode, status:'pending' }
```


**要点**：

- `account = openid`：`user.account` 唯一键是 `uk_user_account_tenant`（含租户维度），openid 全局唯一 → 不冲突 ✅
- `status = pending`：与 `applyRoleAdmission` 的既有语义一致（student/teacher 一律 pending，须管理员审批）
- **不能密码登录**：password 设为随机 UUID 密文，用户无从得知 → 只能走微信

export function captureAttribution(options) {
  if (!options) return;
  const next = {};
  if (options.ref)     next.ref     = String(options.ref);      // v2 新增
  if (options.inviter) next.inviter = String(options.inviter);
  if (options.source)  next.source  = String(options.source);
  if (options.scene) { /* 原有 scene 解析，再加 ref */ }
  if (!next.ref && !next.inviter && !next.source) return;
  const prev = storage.get(ATTR_KEY) || {};
  storage.set(ATTR_KEY, {
    ref:         prev.ref         || next.ref         || '',
    inviter:     prev.inviter     || next.inviter     || '',
    source:      prev.source      || next.source      || '',

## 九、安全要点（v2 增补）

### 9.1 沿用原稿正确的部分

openid 不落前端（仅 `wx.login()` 临时 code）；`uk_wx_openid` 全局唯一；appsecret 走环境变量；推广码与目标租户匹配校验；tenantCode 碰撞重试。

### 9.2 环境变量

`WECHAT_APPID` + `WECHAT_SECRET` —— **原稿只提了 secret，漏了 appid**。  
当前代码读的是 `wechat.miniapp.appid` / `wechat.miniapp.secret`（`WeChatService:25/28`），需与密钥注入守卫口径对齐。

### 9.3 解绑保护（**D1**）

```java
public Result<Boolean> unbindWechat(String userId) {
    WxUserid binding = wxUseridMapper.getByUserId(userId);
    if (binding == null) return Result.fail(404, "未绑定微信");
    if ("auto_register".equals(binding.getBindSource())) {
        // 微信直接注册的账号：account=openid、password=随机 → 解绑后永久无法登录
        return Result.fail(400, "微信注册的账号需先设置登录密码，方可解绑");
    }
    wxUseridMapper.deleteByUserId(userId);
    return Result.success(true, "已解绑");
}
```

### 9.4 路径1 防刷（**D4**）

`POST /promo/register-tenant` 是 permitAll 且会创建租户 + 自动 active 的 admin + 占用套餐额度，必须加闸：

1. **限频**：同 IP 每小时 ≤ `promotion.register.period.limit`（默认 3）
2. **手机号校验**：表单收 phone，后端校验格式并做同号码建租户次数限制
3. **全局上限**：试用租户总数 ≤ `promotion.trial.global.limit`（默认 200），超出直接拒绝并告警
4. 推广码本身也要校验：`status='active'` 且未过期，且 `path_type=1`
