# 预约系统腾讯云部署流程与维护手册

> 适用项目：lesson-appointment（api-1.0.0.jar，Spring Boot 3.3.5 / Java 17 / MySQL 8）
> 云平台：腾讯云（轻量应用服务器或 CVM 均适用，本文以轻量应用服务器 + Ubuntu 22.04 为例）
> 读者假设：有基本计算机知识，会用命令行复制粘贴命令即可
>
> **阅读指引**：第一章做一次就完；第二章是上线流程，按顺序执行；第三章是日常维护，建议打印备查；第四章是故障速查表。

---

## 一、部署前准备（一次性）

### 1.1 购买服务器

登录腾讯云控制台 → 轻量应用服务器 → 新建：

| 配置项 | 推荐选择 | 说明 |
|--------|----------|------|
| 地域 | 就近（如上海/广州） | 面向国内用户 |
| 镜像 | **Ubuntu 22.04 LTS** | 本文所有命令基于此系统 |
| 套餐 | 2核4G 起步 | 单实例跑应用+MySQL 够用；客户多后升配 |
| 登录方式 | 密钥对（推荐）或 root 密码 | 密码至少 16 位随机字符串 |

> **采购纪律**：优先选"续费同价款"套餐或直接 3 年付锁价。轻量服务器新购促销价续费会涨 3–25 倍，做成本测算一律按续费价。

### 1.2 域名与备案（如需 HTTPS 和正式访问）

1. 腾讯云注册域名（.com 约 ¥60–80/年）
2. **域名解析到中国大陆服务器必须完成 ICP 备案**（腾讯云控制台 → 备案，全程线上，通常 1–2 周）
3. 备案期间可先用 `http://服务器IP:端口` 调试

### 1.3 本地打包

在开发机项目根目录执行：

```bash
cd H:/2026/lesson-appointment/api
mvn clean package -DskipTests
```

成功后产物在 `target/api-1.0.0.jar`（约几十 MB，含全部前端静态页面）。

### 1.4 准备好 4 个 SQL 文件（按执行顺序）

| 顺序 | 文件 | 作用 |
|------|------|------|
| 1 | `api/database.sql` | 基础建库建表（含 CREATE DATABASE lesson_appointment） |
| 2 | `api/migration-20260814-teacher-professional.sql` | 教师职业信息 3 张表 |
| 3 | `api/migration-20260815-teacher-published-profile.sql` | 教师发布信息表 |
| 4 | `api/migration-20260822-audit-log.sql` | 审计日志表 |

> 新环境必须按 1→2→3→4 顺序全部执行；老环境升级只需执行新增的迁移脚本。

## 二、服务器部署流程（按顺序执行）

### 2.1 登录服务器

Windows 用系统自带终端或 PowerShell：

```bash
ssh root@你的服务器IP
```

首次连接输入 yes 确认指纹，然后输入密码（或配置了密钥则免密）。

### 2.2 安装基础软件

```bash
apt update && apt upgrade -y
apt install -y nginx mysql-server openjdk-17-jdk-headless
```

验证安装：

```bash
java -version     # 应显示 openjdk version "17.x"
mysql --version   # 应显示 8.x
nginx -v          # 应显示 1.18+
```

### 2.3 配置 MySQL 并导入 4 个 SQL 文件

**第一步：初始化 MySQL 安全设置**

```bash
mysql_secure_installation
```

按提示：设置 root 强密码 → 一路选 Y（移除匿名用户、禁止 root 远程登录、删除测试库）。

**第二步：上传 SQL 文件到服务器**

在**本地电脑**新开一个终端执行（注意是在本地，不是服务器上）：

```bash
cd H:/2026/lesson-appointment/api
scp database.sql migration-20260814-teacher-professional.sql migration-20260815-teacher-published-profile.sql migration-20260822-audit-log.sql root@你的服务器IP:/root/
```

**第三步：回到服务器终端，按顺序导入**

```bash
mysql -u root -p < /root/database.sql
mysql -u root -p lesson_appointment < /root/migration-20260814-teacher-professional.sql
mysql -u root -p lesson_appointment < /root/migration-20260815-teacher-published-profile.sql
mysql -u root -p lesson_appointment < /root/migration-20260822-audit-log.sql
```

（第 1 条不用指定库名，脚本自带 CREATE DATABASE；后 3 条必须指定库名。每条都会提示输入 root 密码。）

**第四步：验证导入结果**

```bash
mysql -u root -p -e "USE lesson_appointment; SHOW TABLES;"
```

应能看到 user、course_template、course、teacher_professional、teacher_published_profile、audit_log 等全部表。

**第五步：创建应用专用数据库账号（不用 root 跑应用）**

```bash
mysql -u root -p
```

进入后执行（把 `换成你的强密码` 替换为真实密码）：

```sql
CREATE USER 'lesson'@'localhost' IDENTIFIED BY '换成你的强密码';
GRANT SELECT, INSERT, UPDATE, DELETE ON lesson_appointment.* TO 'lesson'@'localhost';
FLUSH PRIVILEGES;
EXIT;
```

> 只授权 localhost、只授权增删改查——应用账号没有 DROP/ALTER 权限，误操作和注入攻击都删不了表结构。

### 2.4 上传 jar 并配置生产参数

**第一步：上传（本地终端执行）**

```bash
cd H:/2026/lesson-appointment/api/target
scp api-1.0.0.jar root@你的服务器IP:/opt/
```

**第二步：服务器上创建工作目录与生产配置**

```bash
mkdir -p /opt/lesson
mv /opt/api-1.0.0.jar /opt/lesson/
```

创建生产配置文件 `/opt/lesson/application.properties`（与 jar 同目录，Spring Boot 会自动优先加载它，覆盖 jar 内的开发配置）：

```bash
cat > /opt/lesson/application.properties << 'EOF'
server.port=8081
spring.datasource.url=jdbc:mysql://localhost:3306/lesson_appointment?useUnicode=true&characterEncoding=utf8&useSSL=false&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true
spring.datasource.username=lesson
spring.datasource.password=换成你的强密码
spring.datasource.driver-class-name=com.mysql.cj.jdbc.Driver
mybatis-plus.mapper-locations=classpath:mybatis/mapper/*.xml,classpath:com/reservation/mapper/*.xml
mybatis-plus.configuration.map-underscore-to-camel-case=true
spring.thymeleaf.cache=true
logging.file.name=/opt/lesson/logs/app.log
logging.level.com.reservation.mapper=ERROR
EOF
```

> 三个关键差异：① 数据库账号换成专用账号；② 时区从 UTC 改为 Asia/Shanghai（排期时间不再错 8 小时）；③ 日志写文件便于排查。**生产配置文件不要提交进代码仓库。**

### 2.5 注册为系统服务（开机自启 + 崩溃自动拉起）

创建 systemd 服务：

```bash
cat > /etc/systemd/system/lesson-api.service << 'EOF'
[Unit]
Description=Lesson Appointment API
After=network.target mysql.service

[Service]
Type=simple
WorkingDirectory=/opt/lesson
ExecStart=/usr/bin/java -Xms512m -Xmx1024m -jar /opt/lesson/api-1.0.0.jar
Restart=on-failure
RestartSec=10
User=root

[Install]
WantedBy=multi-user.target
EOF

systemctl daemon-reload
systemctl enable lesson-api
systemctl start lesson-api
```

验证运行状态：

```bash
systemctl status lesson-api        # 应显示 active (running)
curl http://localhost:8081/        # 应返回页面 HTML
```

> `Restart=on-failure` 的意义：程序崩溃后 10 秒自动重启，凌晨挂了也会自己爬起来。

### 2.6 配置 Nginx 反向代理（80/443 → 8081）

```bash
cat > /etc/nginx/sites-available/lesson << 'EOF'
server {
    listen 80;
    server_name _;              # 有域名后改成你的域名，如 booking.example.com

    client_max_body_size 20m;   # 允许上传资质图片等

    location / {
        proxy_pass http://127.0.0.1:8081;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
EOF

ln -s /etc/nginx/sites-available/lesson /etc/nginx/sites-enabled/
rm -f /etc/nginx/sites-enabled/default
nginx -t && systemctl reload nginx
```

浏览器访问 `http://你的服务器IP/` 验证能看到登录页。

### 2.7 配置防火墙（安全组）

腾讯云控制台 → 轻量应用服务器 → 防火墙，只保留：

| 端口 | 协议 | 来源 | 用途 |
|------|------|------|------|
| 22 | TCP | 你的常用 IP（建议） | SSH 管理 |
| 80 | TCP | 0.0.0.0/0 | HTTP |
| 443 | TCP | 0.0.0.0/0 | HTTPS |

**确认不开放**：8081（由 Nginx 内部转发）、3306（MySQL 只允许本机访问）。可在服务器上自查：

```bash
ss -tlnp | grep -E '8081|3306'   # 都应只绑定在 127.0.0.1 或 [::] 本地回环
```

### 2.8 配置 HTTPS（备案完成后）

1. 腾讯云控制台 → SSL 证书 → **申请免费 DV 证书**（绑定你的域名，免费，有效期以申请页为准，到期需重新申请）
2. 证书签发后下载 Nginx 格式，得到 `.crt` 和 `.key` 两个文件
3. 上传并在 Nginx 配置中启用：

```bash
scp 你的域名.crt 你的域名.key root@你的服务器IP:/etc/nginx/ssl/
```

```bash
cat > /etc/nginx/sites-available/lesson << 'EOF'
server {
    listen 80;
    server_name booking.example.com;
    return 301 https://$host$request_uri;    # HTTP 全部跳转 HTTPS
}
server {
    listen 443 ssl;
    server_name booking.example.com;

    ssl_certificate     /etc/nginx/ssl/你的域名.crt;
    ssl_certificate_key /etc/nginx/ssl/你的域名.key;

    client_max_body_size 20m;

    location / {
        proxy_pass http://127.0.0.1:8081;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
EOF

nginx -t && systemctl reload nginx
```

至此部署完成。整条链路：**用户 → HTTPS(443) → Nginx → 127.0.0.1:8081 (jar) → localhost:3306 (MySQL)**。

## 三、日常维护方法

### 3.1 服务的启停与状态（最常用）

```bash
systemctl status lesson-api     # 看状态
systemctl restart lesson-api    # 重启应用
systemctl stop lesson-api       # 停止
journalctl -u lesson-api -n 100 # 看最近 100 行启动/运行日志
```

### 3.2 数据库备份（最重要的一项维护）

**每日自动备份到本机 + 腾讯云 COS**

```bash
mkdir -p /opt/backup
mysql_config_editor set --login-path=backup --host=localhost --user=root --password
# 输入 root 密码（凭据加密存储，脚本里不用写明文密码）
```

创建备份脚本 `/opt/backup/backup.sh`：

```bash
cat > /opt/backup/backup.sh << 'EOF'
#!/bin/bash
DATE=$(date +%Y%m%d)
mysqldump --login-path=backup --single-transaction --routines lesson_appointment \
  | gzip > /opt/backup/lesson_appointment_${DATE}.sql.gz
find /opt/backup -name "*.sql.gz" -mtime +14 -delete
EOF
chmod +x /opt/backup/backup.sh
```

设置每天凌晨 3 点执行：

```bash
crontab -e
# 在文件末尾添加一行：
0 3 * * * /opt/backup/backup.sh
```

> 本机备份保留 14 天。**强烈建议再加一层**：在腾讯云控制台为服务器设置**每日自动快照**（轻量应用服务器 → 快照 → 定期快照），或把 `/opt/backup` 目录定期同步到腾讯云 COS 对象存储。本机备份防误删，异地备份防机器报废。

**恢复演练**（每季度做一次）：

```bash
gunzip < /opt/backup/lesson_appointment_20260825.sql.gz | mysql -u root -p lesson_appointment
```

> 备份只有在恢复成功过才算数。

### 3.3 版本升级流程（发新版）

在本地打包新版本后：

```bash
# ① 本地：上传新 jar（先传到临时名，验证后再替换）
cd H:/2026/lesson-appointment/api/target
scp api-1.0.1.jar root@你的服务器IP:/opt/lesson/api-1.0.1.jar.new
```

服务器上：

```bash
# ② 备份当前版本（回滚保险）
cp /opt/lesson/api-1.0.0.jar /opt/lesson/rollback.jar

# ③ 如果新版带了新的 migration SQL，先导库（新库表向后兼容旧程序，先库后程）
mysql -u root -p lesson_appointment < /root/migration-新的.sql

# ④ 替换并重启
systemctl stop lesson-api
cd /opt/lesson && mv api-1.0.1.jar.new api-1.0.1.jar
sed -i 's/api-1.0.0.jar/api-1.0.1.jar/' /etc/systemd/system/lesson-api.service
systemctl daemon-reload && systemctl start lesson-api

# ⑤ 验证
systemctl status lesson-api
curl -s http://localhost:8081/ | head -5
```

**回滚**（新版有问题时 30 秒恢复）：

```bash
systemctl stop lesson-api
cd /opt/lesson && mv rollback.jar api-1.0.0.jar   # 若文件名不同则按实际调整
sed -i 's/api-1.0.1.jar/api-1.0.0.jar/' /etc/systemd/system/lesson-api.service
systemctl daemon-reload && systemctl start lesson-api
```

> 数据库迁移脚本能回滚程序、回滚不了数据。所以迁移脚本必须写"只增不改"（加表加列），破坏性变更（删列改类型）要单独评估。

### 3.4 日常巡检（每周 5 分钟）

```bash
# 磁盘是否快满（Use% 超过 85% 就要清理）
df -h

# 内存是否吃紧
free -h

# 应用是否存活
systemctl is-active lesson-api

# 近期有没有报错
grep -iE "error|exception" /opt/lesson/logs/app.log | tail -20
```

### 3.5 系统更新（每月）

```bash
apt update && apt upgrade -y      # 补安全漏洞
reboot                             # 内核更新后需要重启一次
```

> reboot 前确认 lesson-api 已 enable（开机自启），重启后应用会自动恢复。

### 3.6 安全清单（上线后立即做 + 定期复查）

- [ ] MySQL root 已设强密码，应用使用 lesson 专用账号（本手册 2.3 已做）
- [ ] 安全组只开 22/80/443（本手册 2.7 已做）
- [ ] SSH 改用密钥登录、禁用密码：编辑 `/etc/ssh/sshd_config` 设 `PasswordAuthentication no`，然后 `systemctl restart sshd`
- [ ] `application.properties` 中的 `jwt.secret` 生产环境换成新随机值（**换新后所有用户需重新登录**，选夜间执行）
- [ ] 数据库密码、jwt 密钥不提交到代码仓库
- [ ] 每季度恢复演练一次备份

## 四、故障速查表

| 症状 | 排查命令 | 常见原因与解法 |
|------|----------|----------------|
| 网页打不开 | `systemctl status lesson-api` | 服务挂了 → `systemctl restart lesson-api`；起不来 → `journalctl -u lesson-api -n 50` 看报错 |
| 服务活着但 502 | `ss -tlnp \| grep 8081` | Nginx 转发目标没监听；检查应用是否真的起了 |
| 起动报数据库连不上 | `grep -A3 "datasource" /opt/lesson/logs/app.log` | 密码错/MySQL 没起（`systemctl status mysql`）/库名不对 |
| 中文乱码 | `mysql -u root -p -e "SHOW VARIABLES LIKE 'character%';"` | 库是 utf8mb4 没问题则查连接串是否带 `characterEncoding=utf8`（2.4 配置已带） |
| 排期时间差 8 小时 | 检查连接串 `serverTimezone` | 开发配置是 UTC，生产配置已改 Asia/Shanghai；确认 jar 加载的是外置配置 |
| 磁盘满 | `df -h` 然后 `du -sh /opt/lesson/logs/*` | 日志暴涨：按 3.4 清理或加日志轮转 |
| 端口被占用 | `ss -tlnp \| grep 8081` | 旧进程没退：`kill -9 旧的PID` 再启动 |
| 服务器整体卡死 | 控制台 VNC 登录 | 内存耗尽：`free -h` 查看，考虑升配或调小 `-Xmx` |

**万能三板斧**（顺序执行，解决 80% 问题）：

```bash
systemctl restart mysql
systemctl restart lesson-api
nginx -t && systemctl reload nginx
```

## 五、架构总览（一图记住）

```
用户浏览器
   │  https://booking.example.com (443)
   ▼
腾讯云安全组（只放行 22 / 80 / 443）
   ▼
Nginx（反向代理 + SSL 证书）
   │  127.0.0.1:8081
   ▼
systemd → java -jar api-1.0.0.jar（/opt/lesson，崩溃自动重启）
   │  localhost:3306（lesson 专用账号）
   ▼
MySQL 8 / lesson_appointment（database.sql + 3 个迁移脚本）
   │
   └→ 每日 3:00 mysqldump 备份（/opt/backup，保留 14 天 + 云端快照）
```

## 附：多客户部署提示

按《部署模式对比》的结论，验证期采用"每客户一实例"时，本手册对应调整：
- 每个客户一个数据库（`lesson_appointment_a`、`lesson_appointment_b`……）+ 一个 jar 实例（8081、8082……端口错开）
- Nginx 用子域名区分：`firm-a.example.com → 127.0.0.1:8081`，`firm-b.example.com → 127.0.0.1:8082`
- systemd 服务名错开：`lesson-a.service`、`lesson-b.service`
- 备份脚本循环导出所有库
- 客户数超过 15 家后启动多租户改造，把新客户收进共享池
