## 第 1 章 本地调试环境（一次性搭建）

### 1.1 软件清单

| 软件 | 版本要求 | 验证命令 | 说明 |
|------|---------|---------|------|
| JDK | **17**（必须） | `java -version` | 三个模块 `pom.xml` 都是 `<release>17</release>`，用 21 会编译失败 |
| Maven | 3.9+ | `mvn -v` | 本机 `mvn` 损坏见 1.4 绕过法 |
| Node.js | 20+（可选） | `node -v` | 用 Maven 构建前端时会**自动下载** Node v20.11.1 到 `frontend/target/`，本机可不装 |
| MySQL | 8.0+ | `mysql --version` | 本地库账号默认 `root / 123456`（源码配置） |
| Git | 任意 | `git --version` | — |

> 后端构建**不需要** Node（api 已移除前端插件）；只有构建 `frontend` 才需要。

### 1.2 本地数据库初始化（两个库）

本地需要两个库：`lesson_appointment`（业务）和 `message_center`（消息中心）。

SQL 脚本都在 `api/beforeRun/sql/`：

| 顺序 | 文件 | 作用 | 是否自带建库 |
|------|------|------|-------------|
| 1 | `lesson_appointment_schema_fixed.sql` | 业务库全量表结构 | ✅ 自带 `CREATE DATABASE` + `USE` |
| 2 | `lesson_appointment_sys_seed.sql` | 行业、套餐模板、租户等种子数据 | ❌ 需指定库名 |
| 3 | `sys_term_upsert_to_target.sql` | 术语表 317 行数据 | ❌ **文件内有 3 处 `<目标数据库名>` 占位符，需先替换成 `lesson_appointment`** |
| 4 | `messagecenter-schema.sql` | 消息中心建库建表 | ✅ 自带 `CREATE DATABASE` + `USE` |
| — | `lesson_appointment_cleanup.sql` | （可选）清空业务库数据、保留结构 | ❌ 需指定库名 |

**Windows（Git Bash 或 PowerShell，在项目根目录执行）**：

```bash
cd api/beforeRun/sql

# 1) 业务库结构
mysql -uroot -p123456 < lesson_appointment_schema_fixed.sql

# 2) 种子数据
mysql -uroot -p123456 lesson_appointment < lesson_appointment_sys_seed.sql

# 3) 术语数据：先把占位符替换掉（PowerShell 用下面这行，Git Bash 见下方 sed 版本）
# PowerShell:
#   (Get-Content sys_term_upsert_to_target.sql) -replace '<目标数据库名>','lesson_appointment' | Set-Content sys_term_target.sql -Encoding UTF8
sed 's/<目标数据库名>/lesson_appointment/g' sys_term_upsert_to_target.sql > sys_term_target.sql
mysql -uroot -p123456 lesson_appointment < sys_term_target.sql

# 4) 消息中心库
mysql -uroot -p123456 < messagecenter-schema.sql
```

**Linux / macOS / 服务器**：

```bash
mysql -uroot -p < /opt/lesson/sql/lesson_appointment_schema_fixed.sql
mysql -uroot -p lesson_appointment < /opt/lesson/sql/lesson_appointment_sys_seed.sql
sed 's/<目标数据库名>/lesson_appointment/g' /opt/lesson/sql/sys_term_upsert_to_target.sql > /tmp/sys_term_target.sql
mysql -uroot -p lesson_appointment < /tmp/sys_term_target.sql
mysql -uroot -p < /opt/lesson/sql/messagecenter-schema.sql
```

**验证**：

```bash
mysql -uroot -p123456 -e "SHOW TABLES FROM lesson_appointment;" | head -20
mysql -uroot -p123456 -e "SHOW TABLES FROM message_center;"
# 业务库应能看到 sys_industry / sys_term / sys_package_template / user / course ...
# 消息库应能看到 msg_category / msg_message / msg_template ...
```

> 提示：message-service 的 JDBC URL 带 `createDatabaseIfNotExist=true`，即使不导 `messagecenter-schema.sql`，服务启动也会建库（但**不会建表**），所以脚本必须导。

### 1.3 本地配置文件在哪、怎么改（不改源码的三种方法）

**源码配置位置（不要在这里写生产密钥）**：

| 文件 | 关键项 |
|------|--------|
| `api/src/main/resources/application.properties` | `server.port=8081`、DB `lesson_appointment`、`jwt.secret`、`crypto.aes-key`、`crypto.hmac-key`、`DB_USERNAME/DB_PASSWORD` 占位 |
| `api/message-service/src/main/resources/application.properties` | `server.port=8090`、DB `message_center`、三个密钥（必须与 booking 相同） |

**三种不改源码的覆盖方式（推荐程度从高到低）**：

1. **命令行参数**（最省事，适合临时调试）

   ```bash
   java -jar api/target/booking_api-2.0.0.jar \
        --server.port=8081 \
        --spring.datasource.url="jdbc:mysql://localhost:3306/lesson_appointment?useUnicode=true&characterEncoding=utf8&useSSL=false&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true" \
        --spring.datasource.username=root --spring.datasource.password=123456
   ```

2. **外置 `application.properties`**（适合长期固定一套本地配置）

   Spring Boot 启动时会读 **当前工作目录** 下的 `./config/application.properties` 和 `./application.properties`，优先级高于 jar 内配置。
   在 `api/target/` 下新建文件 **`application.properties`**（与 jar 同目录）：

   ```properties
   # ===== 本地开发环境覆盖配置：api/target/application.properties =====
   # 只在本地生效，不会被打进 jar（target/ 已 gitignore）
   server.port=8081
   spring.datasource.url=jdbc:mysql://127.0.0.1:3306/lesson_appointment?useUnicode=true&characterEncoding=utf8&useSSL=false&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true
   spring.datasource.username=root
   spring.datasource.password=123456
   # 本地日志：打印 SQL 便于调试（生产不要开）
   logging.level.com.reservation.mapper=DEBUG
   ```

   同理，`api/message-service/target/application.properties`：

   ```properties
   # ===== 本地开发环境覆盖配置：api/message-service/target/application.properties =====
   server.port=8090
   spring.datasource.url=jdbc:mysql://127.0.0.1:3306/message_center?useUnicode=true&characterEncoding=utf8&useSSL=false&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true
   spring.datasource.username=root
   spring.datasource.password=123456
   logging.level.com.messagecenter.mapper=DEBUG
   ```

   > ⚠️ 注意坑：本机沙箱环境若导出了 `SERVER__PORT` / `SERVER_PORT` 环境变量，Spring Boot 宽松绑定会把它映射成 `server.port`，**覆盖** 配置里的端口。所以本地启动命令里**显式带 `--server.port=xxxx`** 最保险。

3. **环境变量**（与服务器部署方式一致）

   ```bash
   export DB_USERNAME=root DB_PASSWORD=123456
   export SPRING_DATASOURCE_URL="jdbc:mysql://127.0.0.1:3306/lesson_appointment?...&serverTimezone=Asia/Shanghai"
   java -jar api/target/booking_api-2.0.0.jar
   ```

### 1.4 本地构建三份产物

**正常构建**：

```bash
cd api              && mvn clean package -DskipTests && cd ..
cd api/message-service && mvn clean package -DskipTests && cd ../..
cd frontend         && npm install && npm run build   && cd ..
# frontend 也可用 Maven：mvn clean package -DskipTests（会自动下载 Node v20.11.1）
```

**本机 Windows `mvn` 命令损坏时的绕过法**（用 Maven Launcher JAR 直启，Git Bash 执行）：

```bash
unset CLASSPATH
MVN_HOME="C:/Program Files/apache-maven-3.9.11"
LAUNCHER="$MVN_HOME/boot/plexus-classworlds-2.9.0.jar"

cd api && java -classpath "$LAUNCHER" -Dmaven.home="$MVN_HOME" -Dmaven.multiModuleProjectDirectory=. \
  org.codehaus.plexus.classworlds.launcher.Launcher -B clean package -DskipTests && cd ..

cd api/message-service && java -classpath "$LAUNCHER" -Dmaven.home="$MVN_HOME" -Dmaven.multiModuleProjectDirectory=. \

```

**构建完成必须核对产物名**（这是最容易翻车的一步）：

```bash
ls api/target/*.jar api/message-service/target/*.jar
# 期望：api/target/booking_api-2.0.0.jar
#      api/message-service/target/message-service-1.0.0.jar

# 期望：index.html admin.html platform_admin.html student.html teacher.html booking.html auditLog.html logBrowser.html
```

## 第 2 章 本地启动与联调（每天用）

### 2.1 启动两个后端

**方式一：一键脚本（推荐）**

- Windows：双击 `deploy/local/start-backend-local.cmd`
- Linux / macOS / Git Bash：`bash deploy/local/start-backend-local.sh`

**方式二：手工起（两个独立终端）**

```bash
# 终端 1：预约主系统 :8081
java -jar api/target/booking_api-2.0.0.jar --server.port=8081

# 终端 2：消息中心 :8090（必须显式带端口）
java -jar api/message-service/target/message-service-1.0.0.jar --server.port=8090
```

**验证**：

```bash
curl -s -o /dev/null -w "booking  %{http_code}\n" http://127.0.0.1:8081/
curl -s -o /dev/null -w "message  %{http_code}\n" http://127.0.0.1:8090/
curl -s http://127.0.0.1:8081/api/v1/system/info          | head -c 200; echo
curl -s http://127.0.0.1:8090/api/v1/message/system/info  | head -c 200; echo
```

> 两个 jar 的 `/` 是**缺省页**（自我标识：程序名、版本、构建时间、服务器时间、已运行时长）。
> 访问 `http://127.0.0.1:8081/index.html` 应返回 **HTTP 200 + body `{"code":404,...}`**（"静默 404"）——这说明 jar 里确实没有页面，**属正常现象**。

### 2.2 启动前端（三种模式，按场景选）

所有前端脚本都在 `doc-develop/` 目录，**监听 8080**，并自动把 `/api/v1` 按规则分流：

| 分流规则 | 目标 |
|---------|------|
| `/api/v1/message/**`、`/api/v1/sse/**`、`/api/v1/users/**` | message-service **8090** |
| 其余 `/api/v1/**` | booking **8081** |

| 脚本 | 静态根目录 | 后端指向 | 适用场景 | Windows 双击 |
|------|-----------|---------|---------|-------------|
| `dev-frontend-local-src.js` | `frontend/`（**源码直出，不打包**） | 本机 8081 + 8090 | **日常开发首选**：改完 js/html/css 直接刷新浏览器 | `start-frontend-local-src.cmd` |
| `dev-frontend-local.js` | `frontend/dist`（`DIST=1`）或 `frontend/` | 本机 8081 + 8090 | 验证构建产物是否正确 | `start-frontend-local.cmd` |
| `dev-frontend-remote.js` | `frontend/` 或 dist（`DIST=1`） | **远程服务器** 8081 + 8090 | 本地页面连线上接口排障 | `start-frontend-remote.cmd` |

```bash
cd doc-develop
node dev-frontend-local-src.js          # 源码直出 + 本地后端  ← 最常用

# 其他用法
node dev-frontend-local.js              # 本地后端 + 可选 DIST=1
DIST=1 node dev-frontend-local.js       # 伺服 dist
node dev-frontend-remote.js             # 连远程服务器（默认 152.136.254.127）
API_HOST=1.2.3.4 node dev-frontend-remote.js
```

可用环境变量：`DEV_PORT`（默认 8080）、`FRONTEND_ROOT`、`DIST=1`、`API_HOST`、`BOOKING_PORT`、`MSG_HOST`、`MSG_PORT`、`NO_PROBE=1`。

启动成功后访问 **http://localhost:8080/**：

- 业务端：`/index.html`（登录）、`/student.html`、`/teacher.html`、`/booking.html`
- 租户管理端：`/admin.html`（数据维护 → 后台信息）
- 平台管理端：`/platform_admin.html`（系统维护 → 后台信息）

### 2.3 一键自检（本地全绿才算搭好）

```bash
# 1) 三个端口都在监听
ss -ltn | grep -E '8080|8081|8090'      # Windows: netstat -ano | findstr "8080 8081 8090"

# 2) 页面（经 8080 代理）
for p in index.html admin.html platform_admin.html student.html teacher.html booking.html; do
  printf '%-24s %s\n' "$p" "$(curl -s -o /dev/null -w '%{http_code}' http://localhost:8080/$p)"
done
# 全部应为 200

# 3) 接口分流（两个 info 应分别返回 booking / message-service 的服务名）
curl -s http://localhost:8080/api/v1/system/info          | head -c 150; echo
curl -s http://localhost:8080/api/v1/message/system/info  | head -c 150; echo
```

### 2.4 ⚠️ 密钥域铁律（本地联调最常见的 401 根因）

> token 只能被**与其同源密钥**的服务校验。`JwtAuthenticationFilter` 只验签名、不查 session。

| 拓扑 | 是否可用 | 前提 |
|------|---------|------|
| 全本地（本地 booking 8081 + 本地 message 8090） | ✅ | 两端都用源码 `application.properties` 的 `jwt.secret`，同源 |
| 全远程（远程 booking + 远程 message-service） | ✅ | 远程两端同为系统密钥；需远程 8090 放行 |
| **混合**（本地 message + 远程 booking，或反向） | ❌ **必 401** | 密钥不同源，无解，只能改成上面两种之一 |

典型症状：消息列表/收件人加载报 `{"code":401,"message":"未登录或登录已过期"}`。
另外要注意：`/api/v1/message/system/info` 返回 booking 的 401 文案，说明**请求根本没路由到 8090**（分流问题），不是权限问题。

### 2.5 本地常见故障

| 症状 | 原因 | 处理 |
|------|------|------|
| 页面空白但接口有数据 | 前端对**已解包**的响应又取了一次 `.data` | 页面必须走 `unwrapPayload` / `unwrapBackendPayload`；详见姊妹篇 10.2 |
| `Address already in use` | 端口被占用 | `netstat -ano \| findstr :8081` 找 PID 后结束，或换 `--server.port` |
| 报数据库连接失败 | MySQL 未启动 / 库未建 / 密码不对 | 按 1.2 重新导库；确认 `root/123456` |
| 排期时间差 8 小时 | `serverTimezone=UTC`（源码默认） | 本地覆盖配置里改 `Asia/Shanghai` |
| 改了 js 刷新没变化 | 伺服的是 dist 不是源码 | 改用 `dev-frontend-local-src.js`，或 `Ctrl+F5` |
| 启动后立刻绑到别的端口 | 环境变量 `SERVER_PORT`/`SERVER__PORT` 被宽松绑定 | 启动命令显式带 `--server.port=8081` |

### 3.0 一图看懂全流程

```
本地：构建三份产物（2 个 jar + frontend/dist）
   │  scp / rsync
   ▼
```

#### 3.4.1 向服务器复制文件与文件夹：命令速查

> 本节是所有 `scp` / `rsync` 用法的**集中出处**。3.4、3.5 以及后续章节里的上传命令，写法都来自这里。

**① 一条铁律：结尾的 `/` 决定"传目录本身"还是"传目录里的内容"**

```bash
scp -r frontend/dist  $SERVER:/var/www/frontend/    # ❌ 传的是【目录本身】
                                                     #    → /var/www/frontend/dist/index.html
scp -r frontend/dist/ $SERVER:/var/www/frontend/    # ✅ 传的是【目录里的内容】
                                                     #    → /var/www/frontend/index.html
```

Nginx `root /var/www/frontend` 找的是**同一层**的 `index.html`，传错层 → 首页 403/404。这条是本项目最容易翻车的一处。

**② 复制单个文件 / 多个文件**

```bash
# 单个文件
scp booking_api-2.0.1.jar $SERVER:/opt/lesson/

# 上传时就改名（目标写完整文件名）
scp booking_api-2.0.1.jar $SERVER:/opt/lesson/booking_api.jar

# 一次传多个文件（最后一个参数才是目标目录）
scp a.jar b.jar c.sql $SERVER:/opt/lesson/

# 源用通配符（不想写死版本号时）
scp api/target/booking_api-*.jar                  $SERVER:/opt/lesson/booking_api.jar
scp api/message-service/target/message-service-*.jar $SERVER:/opt/lesson/message-service.jar
```

**③ 复制整个文件夹（递归，必须带 `-r`）**

```bash
# 前端产物：传内容到站点根（注意结尾 /）
scp -r frontend/dist/ $SERVER:/var/www/frontend/

# 配置模板：先传到临时目录，因为 /etc 下需要 root
scp -r deploy/nginx/  $SERVER:/tmp/nginx-conf/

# SQL 目录
scp -r api/beforeRun/sql/ $SERVER:/opt/lesson/sql/
```

**④ 文件夹同步优先用 `rsync`（能续传、能删除多余文件）**

```bash
# -a 保留权限时间，-v 显示过程，--delete 删掉服务器上多出来的旧文件
rsync -av --delete frontend/dist/ $SERVER:/var/www/frontend/
rsync -av api/beforeRun/sql/      $SERVER:/opt/lesson/sql/

# 服务器没装 rsync 时先装： apt install -y rsync
# 或退回 scp： scp -r frontend/dist/* $SERVER:/var/www/frontend/
```

> **`--delete` 要小心**：它会把目标目录里"本地没有的文件"删掉。所以**目标目录必须只放这个东西**（`/var/www/frontend/` 里不要混放手工文件）。

**⑤ 从服务器复制回本地（下载）**

```bash
# 下载单个文件（注意最后一个是本地路径，. 表示当前目录）
scp $SERVER:/opt/lesson/booking.log ./

# 下载整个文件夹
scp -r $SERVER:/var/log/nginx/ ./nginx-logs/

# 只增量拉取（比 scp 快，且不会重复下载）
rsync -av $SERVER:/var/log/nginx/ ./nginx-logs/
```

**⑥ 非常规端口 / 指定密钥**

```bash
scp -P 2222 -i ~/.ssh/id_rsa  file  $SERVER:/opt/lesson/     # 注意是大写 -P（rsync 里是 -e "ssh -p 2222"）
rsync -av -e "ssh -p 2222 -i ~/.ssh/id_rsa"  frontend/dist/  $SERVER:/var/www/frontend/
```

**⑦ 目标是 `/etc/**` 这类系统目录：不要直接 scp 进去**

普通用户对 `/etc/lesson`、`/etc/nginx` 没有写权限，直接传会报 `Permission denied`。**先传 `/tmp`，再在服务器上 `sudo mv`**：

```bash
# 本地
scp deploy/nginx/booking.conf $SERVER:/tmp/
scp api/beforeRun/booking.env.template $SERVER:/tmp/

# 服务器
sudo mv /tmp/booking.conf /etc/nginx/sites-available/booking
sudo mv /tmp/booking.env.template /etc/lesson/booking.env
sudo nginx -t && sudo systemctl reload nginx
```

**⑧ 传完必须验证（不要只看 scp 没报错）**

```bash
ssh $SERVER 'ls -l /opt/lesson/*.jar'
ssh $SERVER 'ls /var/www/frontend/*.html'
# 期望：/var/www/frontend 下直接就是 index.html / platform_admin.html ...（不是 dist/index.html）
```

**⑨ 本项目"哪个文件 → 哪个目录"对照**

| 本地路径 | 服务器路径 | 复制命令 |
|---|---|---|
| `api/target/booking_api-*.jar` | `/opt/lesson/booking_api.jar` | `scp api/target/booking_api-*.jar $SERVER:/opt/lesson/booking_api.jar` |
| `api/message-service/target/message-service-*.jar` | `/opt/lesson/message-service.jar` | `scp ... $SERVER:/opt/lesson/message-service.jar` |
| `frontend/dist/`（内容） | `/var/www/frontend/` | `rsync -av --delete frontend/dist/ $SERVER:/var/www/frontend/` |
| `api/beforeRun/*.sql` | `/opt/lesson/sql/` | `scp api/beforeRun/*.sql $SERVER:/opt/lesson/sql/` |
| `deploy/nginx/*.conf` | `/etc/nginx/sites-available/` | 经 `/tmp` 中转 + `sudo mv`（见 ⑦） |
| `booking.env.template` → `booking.env` | `/etc/lesson/booking.env` | 经 `/tmp` 中转 + `sudo mv`（见 ⑦、3.5.2） |
| `message.env.template` → `message.env` | `/etc/lesson/message.env` | 同上 |
| `deploy/backup.sh` | `/opt/lesson/backup.sh` | `scp deploy/backup.sh $SERVER:/opt/lesson/ && ssh $SERVER 'chmod +x /opt/lesson/backup.sh'` |

> `api/target` 下的 jar 文件名带版本号（如 `booking_api-2.0.1.jar`），**以 `ls api/target/*.jar` 看到的为准**，脚本/手册里都用通配符 `booking_api-*.jar` 避免版本号漂移。

**⑩ 仓库自带的一键上传脚本**

```bash
SERVER=root@1.2.3.4 bash deploy/upload-to-server.sh
```

脚本内部就是上面这些命令的组合（jar + dist + 配置文件），适合"一次全传"。单独发版时仍建议按 ⑨ 逐项手动执行，便于核对。

**⑪ Windows 本机注意事项**

- **Git Bash**：命令与上面完全一致（`scp` 来自 Windows 自带 OpenSSH）。
- **PowerShell**：变量写法不同——用 `$env:SERVER`，或直接把 `root@1.2.3.4` 写在命令行里；路径分隔符用 `/`。
- 路径含空格要加引号；**中文文件名经 scp 偶发乱码**，上传前先改成英文名（本项目产物都是英文名，正常不会遇到）。
- 不想用命令行：**WinSCP / MobaXterm** 拖拽即可。首次连接确认主机指纹；拖文件夹时同样要注意"拖的是文件夹还是文件夹里的内容"。

### 3.5 配置文件逐份落地（★ 本章核心）

> 下面每个文件都给出「部署路径 + 完整内容」。可以在本地建好、改成自己的值，再按 **3.4.1 ⑦**（传 `/tmp` 再 `sudo mv`）上传。

#### 3.5.0 先生成三个密钥（本地生成即可）

**Windows PowerShell**：

```powershell
# JWT：64 字节随机串（Base64）
[Convert]::ToBase64String((1..64 | ForEach-Object { Get-Random -Maximum 256 }))
# AES / HMAC：各 32 字节（Base64，44 字符，结尾带 =）
[Convert]::ToBase64String((1..32 | ForEach-Object { Get-Random -Maximum 256 }))
```

**Linux / macOS / Git Bash**：

```bash
openssl rand -base64 64    # JWT_SECRET
openssl rand -base64 32    # CRYPTO_AESKEY
openssl rand -base64 32    # CRYPTO_HMACKEY
```

约束：

- `JWT_SECRET`：≥64 字符；
- `CRYPTO_AESKEY` / `CRYPTO_HMACKEY`：Base64 解码后**必须正好 32 字节**（44 字符、结尾 `=`）；
- **booking 与 message-service 的三个值必须逐字符相同**，否则消息服务 401、跨服务解密失败；
- 前端（dist）**不持有任何密钥**。

#### 3.5.3 文件 `/etc/systemd/system/booking.service`

> **`$JAVA_OPTS` 必须写在 `ExecStart` 里**：`EnvironmentFile` 只是把变量放进进程环境，JVM **不会自动读取** `JAVA_OPTS`（JVM 只自动读 `JAVA_TOOL_OPTIONS` / `JDK_JAVA_OPTIONS`）。漏写会导致 `-Xms/-Xmx` 失效；若里面还塞了别的参数，甚至会启动即崩、被 systemd 判定 `Start request repeated too quickly`。

```ini
[Unit]
Description=Lesson Booking Service
After=network.target
Wants=network.target
StartLimitIntervalSec=600
StartLimitBurst=3

[Service]
Type=simple
User=lesson
Group=lesson
WorkingDirectory=/opt/lesson
EnvironmentFile=/etc/lesson/booking.env
# $JAVA_OPTS 必须写在这里；jar 用固定名（升级时直接覆盖文件即可）
ExecStart=/usr/bin/java $JAVA_OPTS -jar /opt/lesson/booking_api.jar
Restart=on-failure
RestartSec=10s

StandardOutput=append:/var/log/lesson/booking.log
StandardError=append:/var/log/lesson/booking.log

[Install]
WantedBy=multi-user.target
```

#### 3.5.5 文件 `/etc/nginx/sites-available/booking`（有域名 + HTTPS）

仓库模板：`deploy/nginx/booking.conf`（把 `booking.example.com` 换成你的域名）。

```nginx
server {
    listen 80;
    server_name booking.example.com;
    location /.well-known/acme-challenge/ { root /var/www/html; }
    location / { return 301 https://$host$request_uri; }
}

server {
    listen 443 ssl http2;
    server_name booking.example.com;

    ssl_certificate     /etc/letsencrypt/live/booking.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/booking.example.com/privkey.pem;
    ssl_protocols       TLSv1.2 TLSv1.3;

    client_max_body_size 20m;

    # 前端静态资源（dist 的内容）
    root /var/www/frontend;
    index index.html;
    location / {
        try_files $uri $uri/ /index.html;      # SPA 兜底
    }
    # platform_admin.html 就在这份 dist 里，不需要任何反代

    # /api/v1 分流：消息类 → 8090，其余 → 8081（顺序不能乱）
    location /api/v1/message {
        proxy_pass http://127.0.0.1:8090;
        include /etc/nginx/proxy_params;
    }
    location /api/v1/sse {
        proxy_pass http://127.0.0.1:8090;
        include /etc/nginx/proxy_params;
        proxy_buffering off;          # SSE 必须关缓冲
        proxy_cache off;
        proxy_read_timeout 3600s;
        proxy_http_version 1.1;
        chunked_transfer_encoding on;
    }
    location /api/v1/users/ {
        proxy_pass http://127.0.0.1:8090;
        include /etc/nginx/proxy_params;
    }
    location /api/v1/ {
        proxy_pass http://127.0.0.1:8081;
        include /etc/nginx/proxy_params;
        proxy_read_timeout 120s;
    }
}
```

> `include /etc/nginx/proxy_params;` 已含 `Host` / `X-Real-IP` / `X-Forwarded-For` / `X-Forwarded-Proto`。
> 发行版若无此文件，改成显式四行：
> ```nginx
> proxy_set_header Host $host;
> proxy_set_header X-Real-IP $remote_addr;
> proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
> proxy_set_header X-Forwarded-Proto $scheme;
> ```

**证书**：

```bash

sudo certbot --nginx -d booking.example.com      # 自动续期
```

```bash
#!/bin/bash
set -e
DATE=$(date +%Y%m%d_%H%M%S)
KEEP_DAYS=14
BAK_DIR=/opt/backup
mkdir -p "$BAK_DIR"

mysqldump --login-path=backup --single-transaction --routines --set-gtid-purged=OFF \
  lesson_appointment | gzip > "$BAK_DIR/lesson_appointment_${DATE}.sql.gz"
mysqldump --login-path=backup --single-transaction --routines --set-gtid-purged=OFF \
  message_center | gzip > "$BAK_DIR/message_center_${DATE}.sql.gz"

find "$BAK_DIR" -name "*.sql.gz" -mtime +${KEEP_DAYS} -delete
echo "[$(date '+%F %T')] backup done"
```

### 3.7 防火墙 / 安全组

腾讯云控制台 → 防火墙，**只放行**：

| 端口 | 来源 | 用途 |
|------|------|------|
| 22 | 你的常用 IP（建议） | SSH |
| 80 | 0.0.0.0/0 | HTTP（跳转 HTTPS） |
| 443 | 0.0.0.0/0 | HTTPS |

**不开放**：8081、8090（Nginx 内部转发）、3306（MySQL 只本机）。

```bash
sudo ufw allow 22,80,443/tcp && sudo ufw enable
```

> **⚠️ 上线后务必自查**：若 `http://服务器IP:8081` 从外网能直接打开，说明后端端口对外暴露了。
> 除在安全组删掉 8081/8090 规则外，还应让 jar **只监听本机回环**（纵深防御）：
>
> ```bash
> echo 'SERVER_ADDRESS=127.0.0.1' | sudo tee -a /etc/lesson/booking.env
> echo 'SERVER_ADDRESS=127.0.0.1' | sudo tee -a /etc/lesson/message.env
> sudo systemctl restart booking message-service
> ss -lntp | grep -E '8081|8090'      # 应显示 127.0.0.1:8081 / 127.0.0.1:8090
> ```
>
> （`SERVER_ADDRESS` 经 Spring Boot 宽松绑定映射为 `server.address`。）

### 5.1.1 服务起不来时，如何看到真正的错误

systemd 只会给 `Failed with result 'exit-code'`，**真实原因在 Java 输出里**。按下面的顺序查：

```bash
# ① 看退出码（先看这个，能直接分大类）
systemctl show booking -p ExecMainStatus -p ExecMainCode

# ② 抓 Java 报错关键字
journalctl -u booking -n 200 --no-pager | grep -iE "status=|Unable to access|Failed to load environment|Caused by|Exception|Port .* was already in use" | head -30

# ③ 前台直接跑（最准，报错会打在当前终端，Ctrl+C 退出）
cd /opt/lesson
sudo -u lesson bash -c 'set -a; . /etc/lesson/booking.env; set +a; /usr/bin/java $JAVA_OPTS -jar /opt/lesson/booking_api.jar'
```

**退出码 / 报错 → 原因对照**：

| 看到 | 含义 | 修复 |
|---|---|---|
| `status=203/EXEC` | `java` 路径不对，或 jar 不存在/无权限 | `which java` 核对路径；`ls -l /opt/lesson/*.jar`；`chmod 644` |
| `status=217/USER` | `User=lesson` 不存在 | `sudo useradd -r -s /bin/false lesson` |
| `Failed to load environment files` | `/etc/lesson/booking.env` 不存在 | 按 3.5.1 建 env |
| `Unable to access jarfile` | `ExecStart` 里的 jar 名与实际不符 | 按 `ls /opt/lesson/*.jar` 的真实名改，或建软链 |
| `Communications link failure` / `Access denied for user` | 数据库连不上 | 查库是否存在、`lesson` 账号授权、env 里密码 |
| `Port 8081 was already in use` | 端口被占（旧进程） | `sudo fuser -k 8081/tcp` 后重启 |
| `Illegal base64` / 密钥长度相关异常 | `CRYPTO_AESKEY`/`HMAC` 不是 32 字节，或 `JWT_SECRET` 太短 | 按 3.5.0 重新生成 |
| `Start request repeated too quickly` | 连续失败触发了启动限流（不是新毛病） | 修完根因后先 `sudo systemctl reset-failed booking` 再 start |

> 触发限流后 systemd 会拒绝再次启动，**必须**先 `systemctl reset-failed booking`，否则会一直看到同样的提示。

## 第 6 章 故障速查表

### 6.0 首页显示 "Welcome to nginx!"（第一坑，先查这里）

> **这句话的含义**：Nginx 在跑、也在响应，但**请求落到了 Nginx 自带的默认 server**（Ubuntu 默认页 `/var/www/html/index.nginx-debian.html`）。
> 即：**我们的站点配置没被用上**，与后端 jar、前端 dist 都无关。

**第一步：一条命令看清 Nginx 实际加载了什么**

```bash
sudo nginx -T | grep -nE "server_name|^ *root |listen |include .*conf"   # 全部生效配置
ls -l /etc/nginx/sites-enabled/                                          # 启用了哪些站点
grep -rn "index.nginx-debian\|/var/www/html" /etc/nginx/sites-enabled/   # 谁在提供这个默认页
```

**第二步：对照定位**

| 现象（`ls -l /etc/nginx/sites-enabled/`） | 根因 | 修复 |
|---|---|---|
| 只有 `default`，没有 `booking` / `booking-ip` | 站点**没启用**（只写了 sites-available，忘了软链） | `sudo ln -s /etc/nginx/sites-available/booking-ip /etc/nginx/sites-enabled/` |
| `default` 与 `booking` **同时存在** | `default` 带 `default_server`，抢先接管 | `sudo rm -f /etc/nginx/sites-enabled/default` |
| 启用的是 `booking`（域名 + 443），却用 **IP + 80** 访问 | server_name 不匹配 + 只监听 443 → 落到默认 server | 改用 `booking-ip.conf`（80 + `server_name _`），或改用域名访问 |
| 系统**没有 sites-enabled 目录**（CentOS/Rocky/Alma） | 这些发行版只 include `/etc/nginx/conf.d/*.conf` | 把配置放到 `/etc/nginx/conf.d/booking.conf` |
| 配置看着对但没生效 | 改完没 reload | `sudo nginx -t && sudo systemctl reload nginx` |
| `nginx -t` 报错 | 语法错误（漏分号、括号不匹配最常见） | 按报错行号修，再 `nginx -t` |
| `nginx -t` 报 `open() "/etc/nginx/sites-enabled/xxx" failed (2: No such file or directory)` | **悬空软链**：只建了软链，`sites-available/` 里没有源文件（漏上传） | 在 `sites-available/` 建真实文件（内容见 3.5.5 / 3.5.6），或先 `rm /etc/nginx/sites-enabled/xxx` 再重建 |
| 软链已建、`default` 已删，外网**仍是**欢迎页 | 没 reload（改配置后 Nginx 仍用旧配置跑着）；或软链指向的文件内容不对 | `sudo nginx -t && sudo systemctl reload nginx`（reload 即可，不必 restart）；再 `grep -nE "root|server_name" /etc/nginx/sites-available/booking-ip` 核对内容 |
| 没有 `sites-enabled`，但 `/etc/nginx/conf.d/` 里有别的 `.conf` | 默认站点藏在 `conf.d`（Ubuntu 主配置两个 include 都生效） | `grep -rn "index.nginx-debian" /etc/nginx/conf.d/`，找到就 `rm` 或改 `server_name` |

**第三步：一键修复（无域名 / 按 IP 访问的场景）**

```bash
sudo rm -f /etc/nginx/sites-enabled/default
sudo ln -sf /etc/nginx/sites-available/booking-ip /etc/nginx/sites-enabled/booking-ip
sudo nginx -t && sudo systemctl reload nginx
```

**第四步：验证（用来区分"Nginx 没生效"还是"dist 没上传"）**

```bash
ls -l /var/www/frontend/index.html                          # 必须存在，否则是 dist 没上传
ss -lntp | grep ':80'                                       # Nginx 是否在听 80
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1/  # 服务器内自测
curl -s http://127.0.0.1/ | head -3                         # 应看到我们自己的 HTML
curl -s http://127.0.0.1/api/v1/system/info | head -c 120; echo
```

- 自测 200 且是我们自己的页面 → 已生效（外网还看旧页就清缓存 / 换无痕窗口）
- 自测也是 Welcome → 回到第二步
- 自测 403/404 → `root` 路径错（常见：多了一层 `dist`，正确是 `/var/www/frontend`）
- 页面 OK 但接口 502/404 → 后端没起或分流没配（见 6.1）

### 6.1 其他故障

| 症状 | 排查命令 | 常见原因与解法 |
|------|---------|---------------|
| 首页显示 "Welcome to nginx!" | `ls -l /etc/nginx/sites-enabled/`；`nginx -T \| grep server_name` | 站点没启用 / `default` 没删 / 用 IP 访问了只监听 443 的域名站点 → 见 **6.0** |
| 网页打不开 | `systemctl status booking`；`nginx -t` | 服务挂了 → restart；Nginx 配置错 → 看 `nginx -t` 输出 |
| 页面 200 但接口 502 | `ss -lntp \| grep -E '8081\|8090'` | 后端没监听；检查 jar 是否启动成功 |
| **页面能开、所有 `/api/v1` 都 502** | `systemctl is-active booking message-service`；`ls -l /opt/lesson/*.jar /etc/lesson/*.env` | 后端整体没起：jar 未上传 / `ExecStart` 路径与实际文件名不符 / env 缺失 / DB 连不上 / 没装 JDK → 按 3.6 启动，看 `journalctl -u booking -n 50` |
| 软链 `/opt/lesson/*.jar` 指向 `/root/...`，服务起不来 | `/root` 默认 700，运行用户 `lesson` **进不去**，读不到 jar | 把真身复制到 `/opt/lesson/`（chown lesson、chmod 644）再软链；**不要** `chmod 777 /root`、也不要改成 `User=root`。诊断：`namei -l /opt/lesson/booking_api.jar`、`sudo -u lesson test -r /opt/lesson/booking_api.jar` |
| `Start request repeated too quickly` | `journalctl -u booking -n 50` | **ExecStart 漏写 `$JAVA_OPTS`** / 端口冲突 / DB 连不上 |
| 消息接口 401 | 对比两 env 的 `JWT_SECRET` | 两端密钥不一致；或分流没到 8090 |
| 排期时间差 8 小时 | 检查 `SPRING_DATASOURCE_URL` 的 `serverTimezone` | 应为 `Asia/Shanghai` |
| 平台管理端跳到缺省页 | 检查 `/var/www/frontend/platform_admin.html` 是否存在 | dist 是旧包（管理端曾在 jar 内）→ 重新构建上传 |
| 改了前端没生效 | `curl -I` 看 `Last-Modified` | 浏览器缓存 / 静态资源缓存策略 → Ctrl+F5；或 rsync 时漏了 `--delete` |
| 上传图片失败 | Nginx `error.log` | `client_max_body_size` 太小（已配 20m） |
| 磁盘满 | `df -h` + `du -sh /var/log/lesson/*` | 日志暴涨：加 logrotate 或清旧日志 |
| 数据库连不上 | `systemctl status mysql`；查 env 里密码 | MySQL 没起 / 密码错 / 账号没授权 |
| 服务器整体卡死 | 控制台 VNC 登录 | 内存耗尽：`free -h`，调小 `-Xmx` 或升配 |

**万能三板斧**（按顺序，解决 80% 问题）：

```bash
sudo systemctl restart mysql
sudo systemctl restart booking message-service
sudo nginx -t && sudo systemctl reload nginx
```

验证期采用"每客户一实例"时：

- 每个客户一个数据库（`lesson_appointment_a`、`lesson_appointment_b`…）+ 一对 jar 实例（8081/8090、8082/8091…端口错开）
- Nginx 用子域名区分：`firm-a.example.com → 8081/8090`，`firm-b.example.com → 8082/8091`
- systemd 服务名错开：`booking-a.service`、`message-a.service`，env 也分开：`/etc/lesson/booking-a.env`
- 备份脚本循环导出所有库
- 前端 dist 可以共用一份（同版本），也可按客户子域各放一份目录
- 客户数超过 15 家后走多租户改造，把新客户收进共享池
