# 电子课堂：管理员应急建课与临场加人（可行方案）

> 版本：2026-11-19
> 场景：临时要开一节课 / 临时把某个学生塞进已有课堂。**应急优先，流程可以糙，但不能把账（课时、出勤）搞乱。**
> 全部结论均已对照代码核实，标注为 `文件:行号`。

---

## 0. 结论速览

> **2026-11-19 更新**：B1~B4、C1/C2 已落地。运营台「实时监控」页现在有「临时建课」「给指定课堂加学员」两个表单，
> 课堂列表每行有「复制学生链接 / 加学员 / 结束」，学生未登录点直链登录后会自动回跳课堂。
> 下文 §2、§4 的报文模板仍保留——它是接口内部的等价物，排障时对照用。

课堂服务**没有"新建课堂"的 REST 接口**，课堂只能由排期事件生成。但管理员有一条现成的旁路：

| 需求 | 手段 | 是否改代码 | 耗时 | 副作用 |
|---|---|---|---|---|
| 临时开一个教室（系统里没有这节排期） | 运营台 → 契约联调 → **重放 `created` 报文** | 否 | 2~3 分钟 | 不结算课时、不进学情报表、学生"我的课堂"看不到 |
| 课前给这个教室加学生 | 同页**重放 `updated` 报文**（带 `students`） | 否 | 1 分钟 | 同上；且**必须在开课前** |
| 上课中加学生（有正常排期） | 排期页 →「候补 / 指定学生」→「指定学生」 | 否 | 1 分钟 | 生成 booking，**会正常结算课时**、学生"我的课堂"可见 |
| 上课中加学生（临时教室，无排期） | 只能 SQL 插 `classroom_membership` + `classroom_attendance` | 否 | 3 分钟 | 无审计留痕；不结算 |
| 要让师生从菜单点进去、要扣课时、要出学情 | **只能走正常排期建课**（方案 B） | 否 | 5~10 分钟 | 无 |

一句话：**"开个房间应急"和"记一笔正式课程"是两件事，选错会丢账。**

## 1. 机制事实（决定了能怎么做）

### 1.1 课堂实例的唯一写入方是排期事件

`classroom` 表只有一个 insert 点：

```
api/classroom-service/.../event/ScheduleEventConsumer.java:77  handleCreated()
  :80  String classroomId = ClassroomKey.of(event.getScheduleId(), event.getClassIndex());
  :82  已存在 → log.info("课堂已存在，跳过创建"); return;   ← 不做 upsert
  :95  status = "SCHEDULED"; autoStart = true;
  :101 tenantId = event.getTenantId() != null ? ... : 0L;
  :104 classroomMapper.insert(c);
  :113 逐个 students → classroom_membership(role=student, OFFLINE)
  :123 teacher → classroom_membership(role=teacher)
  :129 attendanceService.initRoster(...)   → classroom_attendance 全员 ABSENT
```

事件类型只有三种（`:50-55`）：`created` / `updated` / `cancelled`，没有 `rescheduled`。

> `ClassroomService.create()` 无任何调用方——**别再指望用 REST 建课堂，现在没有这个口子。**

### 1.2 管理员旁路：重放接口（本次方案的核心）

```
/api/v1/admin/contract/replay        AdminContractController.java:80-111
  权限：AuthContext.isManager()（admin / platform_admin），不走 HMAC
  逻辑：idempotentGuard.release(eventId) → eventConsumer.consume(req) → log.warn 留痕
```

前端入口：`classroom-ops.html:98` 页签「契约联调」→ `:209` 面板「重放排期事件（粘贴预约侧原始报文）」→ `:212` 按钮「重放」。
调用：`js/classroom/ops.js:661-674`。

**这是目前唯一"不改代码、不碰预约侧"就能凭空造出一节课的通道。**

### 1.3 谁能进课堂（三重判定）

```
POST /api/v1/classrooms/{scheduleId}/enter     ClassroomController.java:68
  :73  用户维度限流（enterPerMinute）
  :77  accessGuard.assertAccess(scheduleId, userId, role)
  :79  membershipService.join(...)       ← 名单没行就地补建
  :80  学生 → attendanceService.checkIn(...)  ← 出勤没行就地补建
```

`ClassroomAccessGuard.assertAccess`（`security/ClassroomAccessGuard.java:65-114`）顺序：

| 序 | 判定 | 结果 |
|---|---|---|
| 1 | 课堂不存在 | `40401` |
| 2 | `isManager(role)`（admin / platform_admin） | **直接放行**（巡课靠这条） |
| 3 | `classroom.tenant_id` 与 token 租户不等 | `40402 无权访问该课堂` |
| 4 | `kicked=true` | `40301 已被移出课堂` |
| 5 | 教师：`teacherId` 本人或名单 role=teacher | 否则 `40302 仅本堂课教师可操作` |
| 6 | 学生：有 membership 行 **或** 主库有有效 booking | 否则 `你不在本课堂名单内` |

第 6 条是关键：`hasValidBooking()`（`:127-140`）**实时查** `lesson_appointment.booking`：

```sql
status NOT IN ('waiting','cancelled','canceled','rej-booking','frozen')
-- 注意：'booking'（待审核）不在排除列表里，也算有效
tenant_id 一致才命中（跨租户预约不放行），查询异常 fail-closed
```

**所以"临时加人"最轻的做法可以是"给这个学生加一条 booking"，不必先动课堂侧的表**——他进房时 membership 与 attendance 会自动补。

### 1.4 开课 / 下课是手动的

```
api/classroom-service/src/main/resources/application.properties:82  classroom.state-manual-only=true
                                                     :84  classroom.auto-start=false
scheduler/ClassroomScheduler.java:200  scanAutoStart 手动模式整轮 return
                              :233  scanAutoEnd 同样跳过
```

- 临时课建完是 `SCHEDULED`，**不会自己变 LIVE**，必须有人点「进行中」。
- 也不会自动下课——**必须有人点「下课」**，否则一直 LIVE、课时永不结算、出勤不归一。

开课/暂停/下课接口只需 `isTeacher() || isManager()`（`ClassroomController.java:98-104`），**管理员后端放行**；但前端按钮只给 `teacher` 渲染（`classroom-controls.js:57-62`）。

> 应急技巧：管理员打开 `classroom.html?scheduleId=X&role=teacher`，前端按 `role` 参数渲染出「进行中 / 暂停 / 下课」（`classroom-main.js:86`），服务端仍按 JWT 判 `isManager` 放行。**这样管理员可以替教师开课、下课。**

### 1.5 课堂开关是硬闸

`security/AuthInterceptor.java:63-72`：租户 `sys_tenant_eclassroom.enabled != 1` → 403「课堂未启用」。
平台管理员（tenantId=0/-1）与 `role=system` 豁免。
预约侧同样：`ClassroomEventPushService` 在未开通时**静默跳过推送**（`EclassroomService` 返回 null），课堂永远不会生成。

## 2. 方案 A：临时开一个教室（重放 `created`，零改代码）

### 2.1 前置检查

1. 目标租户已开通课堂（平台端「课堂实例」绑定 + 启用）；否则课堂页 403「课堂未启用」。
2. 知道**教师 userId**（不是姓名）——`teacher.userId` 必填，缺失会在 `:90` NPE，事件直接 FAILED。
3. 知道**学生 userId 列表**（可选，可后续用 updated 补）。

### 2.2 报文模板（可直接粘进运营台）

```json
{
  "eventId": "evt-tmp-20261119-1530-01",
  "eventType": "created",
  "scheduleId": "tmp202611191530aaaaaaaaaaaaaaaa",
  "tenantId": 6,
  "courseId": "tmp-course-20261119",
  "courseName": "临时课堂-11月19日答疑",
  "teacher": { "userId": "0dc6977b...", "name": "张老师" },
  "students": [
    { "userId": "stu-aaa", "name": "学生A" },
    { "userId": "stu-bbb", "name": "学生B" }
  ],
  "startTime": "2026-11-19T15:35:00",
  "endTime":   "2026-11-19T16:20:00",
  "duration": 45
}
```

字段规则（照抄，别省）：

| 字段 | 规则 |
|---|---|
| `eventId` | 全局唯一；重复会被幂等键挡掉（重放会先 release 再消费，所以同一 id 也能重放） |
| `eventType` | `created` |
| `scheduleId` | 自造 32 位十六进制即可，**千万不要带 `~N`**——`ClassroomKey` 会把 `sid~2` 当成同一排期的第 2 课次，后续取消会连带清理（`ClassroomKey:35,46-54`、`cancelOrphanInstances:253-269`） |
| `classIndex` | **留空**（默认 1 → 课堂 id 就是裸 `scheduleId`） |
| `classCount` | **不要填**。`null` 表示"不清理孤儿课次"，填错会触发批量取消 |
| `tenantId` | **必须与目标租户一致**。不填会落 0 → 租户管理员在监控列表看不到，学生跨租户被判 `40402` |
| `teacher.userId` / `teacher.name` | 必填；userId 要与实际登录账号一致，否则教师进不去（`40302 仅本堂课教师可操作`） |
| `startTime` / `endTime` | **本地时间，不要带 `Z`**：`JacksonConfig` 的宽松解析只认 `2026-11-19T15:35:00` 或 `2026-11-19 15:35:00`，带偏移会 400「请求体格式错误」 |
| `duration` | 不填默认 60（`:98`）；影响课时结算口径，建议填真实分钟 |

### 2.3 执行后生成的数据

| 表 | 内容 |
|---|---|
| `classroom` | 1 行，`status=SCHEDULED`、`auto_start=true`（但全局手动模式不生效）、`tenant_id` 按报文 |
| `classroom_membership` | 教师 1 行 + 每个学生 1 行（`OFFLINE`） |
| `classroom_attendance` | 每个学生 1 行（`ABSENT`，进房后升级 PRESENT/LATE） |

### 2.4 分发给师生

- 教师端 / 学生端链接：`classroom.html?scheduleId=<scheduleId>&tCode=<租户码>`
  （`tCode` 供未登录时登录页锁定租户，`api.js:resolveTenantCode:799-813` 优先读 URL 的 `tCode`）
- **必须先登录**：`WebMvcConfig.java:16-25` 白名单只有 `/api/v1/schedules/events`、`/api/v1/files/**` 等，课堂页所有接口都要 Bearer；没有邀请码 / 免登录 token。
- 学生能否在「我的课堂」列表里看到？**看不到**——该列表基于 booking 行（`student-myClassroom.js:117-184` 遍历 booking 的 `scheduleId`），临时课堂没有 booking。只能**直接发链接**。
- 管理员替开课：`classroom.html?scheduleId=X&role=teacher`（见 §1.4）。

#### 2.4.1 学生"找不到入口"的三个断点（逐一验证过）

| # | 断点 | 证据 | 表现 |
|---|---|---|---|
| 1 | 「我的课堂」只列 booking | `student-myClassroom.js:103-124` → `getBookingListPage` | 临时课堂整节课不出现 |
| 2 | 就算插了 booking，「课次 + 进入课堂」按钮也出不来 | `ScheduleController.java:339-354` 第一句 `selectById(scheduleId)`，排期不存在 → `404 排期不存在` | 列表有这一行，展开后没有课次、没有「进入课堂」 |
| 3 | 未登录点直链会被弹走，且**不带回跳** | `feature-flags.js:guardClassroom` → `pageUrl('login.html')`；`forceEntryLogin` 也只带 `tCode`，不带 `redirect` | 学生点链接 → 登录页 → 登录后落在学生首页，必须再点一次链接 |

> 第 2 条是"补 booking 也救不了"的原因：`/schedule/class-instances/{sid}` 是**排期驱动**的，
> 不是课堂驱动。临时课堂的 `scheduleId` 不在 `course_schedule` 里，永远拿不到课次行。

#### 2.4.2 四种"把入口送到学生手上"的方式

| 方式 | 成本 | 学生体验 | 副作用 / 限制 |
|---|---|---|---|
| ① 直链（`classroom.html?scheduleId=X&tCode=Y`） | 0 | 已登录：一步进课堂；未登录：被弹到登录页，登录后要再点一次 | 需自行拼链接；微信内可点 |
| ② 直链 + `login.html?redirect=classroom.html%3FscheduleId%3DX` | 0 | 未登录也能一次到位（登录后自动回课堂） | `login.html:1437-1466` 会校验同源 + `.html`，课堂页合规；但**这条链接不能从课堂页自动生成**，得手工拼 |
| ③ 走「指定学生」生成 booking | 1 分钟 | 「我的课堂」能看到并点进去 | 必须走正常排期建课（方案 B）；临时课堂用不了（断点 2） |
| ④ 消息中心发通知 | 1 分钟 | 站内信能收到；**C4 之后链接可点**（见 2.4.5） | 改造前 `messages-inbox.js` 用 `esc(content)` 转义正文，只能显示 URL 文本让学生复制 |

#### 2.4.3 入口改进（C1~C4 全部落地，2026-11-19）

| # | 改动 | 状态 | 位置 |
|---|---|---|---|
| C1 | `guardClassroom` 跳登录时带 `redirect=当前页`，未登录点直链也能一次到位 | ✅ 已实现 | `feature-flags.js:guardClassroom` |
| C2 | 运营台课堂列表每行加「复制学生链接」，自动带 `scheduleId + tCode`；建课结果区也直接给出两条链接 | ✅ 已实现 | `ops.js:_classroomLink / _copyText` |
| C3 | 学生端「加入课堂」：粘贴链接或输入课堂号 → 校验名单 → 进入课堂 | ✅ 已实现 | `student.html` 菜单 + `js/student-joinClassroom.js` |
| C4 | 运营台群发上课通知（发给名单学生，消息里「进入课堂」按钮可点） | ✅ 已实现 | `classroom-ops.html` + `ops.js:_sendNotice` + `messages-inbox.js:payloadJumpHtml` |

C1 的实现细节：只有**拿不到角色**（=未登录）时才带 `redirect`；已登录但租户未开通课堂时**不带**，
否则会变成「登录 → 被踢回首页 → 再点链接 → 再登录」的死循环。回跳参数由 `login.html:getUrlRedirectTarget`
做同源 + `.html` 校验，`classroom.html?scheduleId=...` 合规。

C3 才是根本解法（不依赖 booking、不依赖排期）：学生手上只要有课堂号或链接就能自己找进门，
不需要「我的课堂」里有这条记录。

#### 2.4.4 C3 实现：学生端「加入课堂」

| 环节 | 做法 | 为什么 |
|---|---|---|
| 入口 | `student.html` 侧边栏新增「加入课堂」（`key=join_classroom`，带 `data-module="classroom"` 跟随租户开关显隐）；「我的课堂」页头也放一个按钮跳过来 | 学生找课堂的自然位置就是这两个菜单；页头按钮覆盖「点进我的课堂发现是空的」那一刻 |
| 解析 | 同时接受完整 URL（`classroom.html?scheduleId=X&tCode=Y`）、相对链接、裸课堂号、多课次复合键 `xxx~2`；拒绝含 `/`、`.` 的输入 | 输入来自 IM 转发，会长会折行、会带首尾引号；`scheduleId` 要拼进 URL 路径，不能放行任意字符 |
| 校验 | `GET /api/v1/classrooms/{sid}/status`（经 `window.ClassroomAPI.getClassroomStatus`） | 见下方「为什么不用 POST /enter」 |
| 放行 | 通过后展示课程名 / 状态 / 时间 + 「进入课堂」按钮，跳 `classroom.html?scheduleId=X`（`pageUrl` 自动带 `tCode`） | 真正的 `enter`（写名单 + 签到 + 回调「已签到」）交给课堂页自己发 |
| 报错 | 按课堂服务错误码给可执行文案：`40401` 课堂号不存在 / `40402` 不在名单（附「让管理员在运营台加学员」的指引）/ `40301` 已被移出 / `42901` 太频繁 | 「你不在本课堂名单内」是临时课堂最常见的一次性失败，必须直接告诉学生找谁 |
| 跨租户 | 链接里的 `tCode` 与本地登录态不一致时当场提示换账号 | 否则点进去必然 40402，白撞一次 |

**为什么校验不用 `POST /enter`（与初版方案的偏离）**：`enter` 有副作用——`membershipService.join()`
补名单行、`attendanceService.checkIn()` 签到、`callbackService.sendJoinEvent()` 回调预约侧「已签到」。
把它放在「查找课堂」这一步，等于学生还没看到课堂页面就已经产生出勤记录；手滑点一下也洗不掉
（课末收尾按区间归一，不会因为「没真的上课」而抹掉签到）。`/status` 走同一个
`ClassroomAccessGuard`（课堂存在 → 租户一致 → 名单/有效预约 → 是否被移出），校验能力等价、零副作用。

#### 2.4.5 C4 实现：群发上课通知 + 让链接可点

| 环节 | 做法 | 位置 |
|---|---|---|
| 名单 | 运营台「发上课通知」面板 → `GET /classrooms/{sid}/members`（管理员在守卫里直接放行）→ 只挑 `role=student && !kicked` | `ops.js:_noticeTargets` |
| 发送 | `POST /api/v1/messages/send`（主站同源，网关按 `/api/v1/messages` 前缀分流到 message-service:8090），`recipientUserIds` = 名单学生 | `ops.js:_sendNotice` |
| 正文 | 留空自动生成：课程名 + 上课时间 + 课堂号 + 进入方式；标题默认「上课通知：课程名」 | 同上 |
| 跳转 | `payload = {type:'classroom_join', scheduleId, url: 带 tCode 的课堂链接}`；平台管理员代别家租户发时带 `targetTenantId` | 同上 |
| 可点 | 收件箱详情识别 `payload.url`，白名单校验（仅 `http(s)` 或本站 `.html` 相对页）后渲染「进入课堂」按钮 | `messages-inbox.js:payloadJumpHtml / safeJumpUrl` |
| 空名单 | 名单里没有学生时直接提示「先用『加学员』把人加进来」，不发空通知 | 发出去没人收到比不发更糟 |

改造前后对比（④ 的限制被解除）：

```text
改造前：正文「…进入方式：https://…/classroom.html?scheduleId=xxx&tCode=yyy…」
        → esc() 转义 → 屏幕上是一串不能点的文本 → 学生长按复制 → 粘到浏览器
改造后：正文照旧（可读）
        + payload.url → 详情里多一个「进入课堂」按钮 → 点一下就到（未登录由 C1 自动回跳）
```

**为什么群发落在运营台而不是管理端「今日课程（上课通知）」**：那一页是**排期驱动**的
（`admin-AppointmentNotes.js` 按 `course_schedule` 展开），临时课堂根本不在里面——放个按钮也点不到。
而 `admin.html → 课堂监控` 本来就是跳运营台（`admin.html:401`），管理员的课堂操作入口只有这一处，
C4 与 B1/B2 并列放在同一屏，应急时手不用换位置。


### 2.5 方案 A 的硬限制

| 限制 | 依据 |
|---|---|
| 不扣课时、不进学情报表 | 出勤回流到 booking 侧要查 `course_schedule`，临时 `scheduleId` 不存在 → `LessonAttendanceService` 抛「排期不存在，无法归户」→ 回调 404 → 判永久失败进 DLQ |
| 已存在的课堂**不能**靠重放 `created` 补人 | `handleCreated` 首行 `if (existing != null) { log.info("课堂已存在，跳过创建"); return; }` |
| 开课后不能改时间 | `handleUpdated:146-150`，LIVE/PAUSED/CLOSED/CANCELLED 一律忽略 |
| 运营台没有「加学员」「强制结束」按钮 | 后端有 `POST /api/v1/admin/classrooms/{sid}/end`（`AdminConsoleController.java:33`），`ops.js` 未接线 |

## 3. 方案 B：正式建课（推荐，账最干净）

适用于"这节课要算课时、要出学情、学生要从菜单点进去"。

1. 管理端 → 排期设置 → 新建排期（`POST /api/v1/schedule/create`，权限 `TEACHER_OR_ADMIN`），
   **重复类型 = 不重复**，时间设为当前/稍后 → 保存。
2. 保存后自动推 `created`（`CourseScheduleService:308-319` `pushAfterCommit(tenantId, Id, "created")`），课堂即刻生成，`scheduleId` 是系统生成的裸 id。
3. 加学生：排期页 → 页签「候补 / 指定学生」（`admin-schedule.js:385`）→「指定学生」→ 选学生 → `POST /api/v1/schedule/assign-student`。
   写入 `booking`（`status=booking→booked`）+ 生成 `appointment`（`CourseScheduleService.asgn_student:643-681`）。
4. 学生「我的课堂」立刻能看到这节课；课堂侧准入按 §1.3 第 6 条放行，进房自动补 membership/attendance。
5. 教师进课堂点「进行中」开课，讲完点「下课」（否则一直 LIVE、不结算）。

「指定学生」的两个前置（会直接报错，需要提前处理）：

- 排期必须存在：`lockScheduleAndAssertExists` 用 `selectByIdForUpdate` 查 `course_schedule`，查不到抛「排期ID不能为空/排期不存在」；
- 席位不能满：`assertSeatsAvailable` 在 `occupied >= available_sites` 时抛「该排期名额已满（总席位 N，已占 M）」——应急时得先把排期席位改大。

## 4. 给指定课堂加学生：三档对比

| 档 | 手段 | 适用时机 | 结算课时 | 学生"我的课堂" | 前置 |
|---|---|---|---|---|---|
| ① | 重放 `updated` 报文带 `students` | 仅 `SCHEDULED` / `READY` | 否（临时课堂）/ 是（正常排期） | 否 | 报文要给全量字段；`version` 不小于当前或不填 |
| ② | 排期页「指定学生」 | 课前课后都行 | **会** | **会** | 排期存在且席位未满 |
| ③ | SQL 插两张表 | 任意 | 否 | 否 | 控制台权限；无审计 |

### 4.1 为什么"重放 updated"能加人

```java
// ScheduleEventConsumer.handleUpdated:136-168
if (LIVE/PAUSED/CLOSED/CANCELLED) { log.warn("课堂已在进行或已结束，忽略改期事件"); return; }
... 更新 courseName/startTime/endTime/version ...
syncRoster(event);        // ← 只增不删：新学生补 membership + attendance(ABSENT)
cancelOrphanInstances(event);
```

`syncRoster`（`:172-198`）逐个比对 `students`，`membershipExists` 为 false 就 insert，然后 `initRoster(added)` 补出勤行。

**要点：只增不删**——被移出名单的人不会被删除（避免销毁账务证据）。

报文（在 created 报文基础上改三处）：

```json
{
  "eventId": "evt-tmp-20261119-1535-02",
  "eventType": "updated",
  "scheduleId": "tmp202611191530aaaaaaaaaaaaaaaa",
  "tenantId": 6,
  "courseId": "tmp-course-20261119",
  "courseName": "临时课堂-11月19日答疑",
  "teacher": { "userId": "0dc6977b...", "name": "张老师" },
  "students": [ {"userId":"stu-aaa","name":"学生A"}, {"userId":"stu-ccc","name":"迟到的C"} ],
  "startTime": "2026-11-19T15:35:00",
  "endTime":   "2026-11-19T16:20:00"
}
```

> ⚠️ `students` 要**给全量名单**还是只给新增？`syncRoster` 是"存在则跳过、不存在则插入"，所以**只给新增的也安全**（未列出的人不会被删）。但 `courseName/startTime/endTime` 会被整体覆盖，别写错。

### 4.2 上课中加人的唯一稳妥路径

课堂一旦 `LIVE`，`updated` 事件被直接忽略（日志 `课堂已在进行或已结束，忽略改期事件`，用户侧表现为"点了没反应"）。此时：

- **有排期** → 用「指定学生」（档 ②）。它写 booking，`hasValidBooking` 实时查库 → 学生立刻能进；进房 `join/checkIn` 自动补两表，出勤与课时都正常。
- **无排期（临时课堂）** → SQL 兜底（档 ③）：

```sql
-- 1) 成员行（PK: schedule_id + user_id）
INSERT INTO classroom.classroom_membership
  (schedule_id, user_id, role, display_name, online_state, kicked)
VALUES ('tmp2026...', 'stu-ddd', 'student', '学生D', 'OFFLINE', 0);

-- 2) 出勤行（PK: schedule_id + user_id），进房后自动升级 PRESENT/LATE
INSERT INTO classroom.classroom_attendance
  (schedule_id, user_id, attendance_status, effective_minutes, late, manual_adjust)
VALUES ('tmp2026...', 'stu-ddd', 'ABSENT', 0, 0, 0);
```

两张表都**没有外键约束**（`classroom-schema.sql` 无 `FOREIGN KEY`），插得进去；但 `tenant_id` 必须与 `classroom.tenant_id` 逻辑一致，否则 §1.3 第 3 条直接 `40402`。

> 插完别人看不到他——成员面板只在进页面时拉一次（`classroom-main.js:_refreshMembers`），其他人需要刷新页面。

## 5. 十个必踩的坑

1. **`created` 对已存在课堂直接跳过** → 想给已建课堂加人必须用 `updated`，用 `created` 只会看到"成功"但什么都没变。
2. **LIVE 后 `updated` 被忽略** → 上课中加人别指望重放。
3. **时间带 `Z` 会 400** → `JacksonConfig` 的宽松解析接 `LocalDateTime`，不接受偏移量。
4. **`scheduleId` 别手写 `~N`** → 会被当成同一排期的第 N 课次，取消/孤儿清理会连带处理。
5. **`tenantId` 漏填 = 0** → 租户管理员监控列表看不到，学生跨租户 `40402`。
6. **`teacher.userId` 漏填 → NPE → 事件 FAILED**（`:90`），课堂建不出来且只在日志里。
7. **临时课堂不结算** → 出勤回流查不到 `course_schedule`，回调 404 进 DLQ；课时不扣、学情报表没有。
8. **课堂开关有 5 分钟缓存**（`TenantEclassroomService`）→ 刚开通/解绑后可能仍 403，重试或等缓存过期。
9. **手动模式**：建完不点「进行中」就永远 SCHEDULED，不点「下课」就永远 LIVE；自动开/下课两条扫描器在手动模式下整轮 return。
10. **审计缺口**：重放只写 `log.warn` + `classroom_reconcile_log`，**不进 `audit_log`**；「指定学生」有 `@Audit(SCHEDULE_ASSIGN)`。等保口径下"临时建课"需要补审计。

## 6. 已落地：运营台应急按钮（B1~B4，2026-11-19）

原来要手写 JSON 才能建课，现在运营台「实时监控」页直接有表单。改动全部复用现有链路，
没有新增表、没有新增状态值。

| # | 实现 | 位置 |
|---|---|---|
| B1 | `POST /api/v1/admin/classrooms` 临时建课 | `AdminConsoleController.createTempClassroom` → `ClassroomAdminOpsService.createTempClassroom` |
| B2 | `POST /api/v1/admin/classrooms/{sid}/members` 临场加学员 | 同上 `addMembers` |
| B3 | 运营台三个入口：临时建课表单 / 加学员表单 / 行内「复制学生链接」「加学员」「结束」 | `classroom-ops.html` + `ops.js` |
| B4 | 审计留痕：`CLASSROOM/CREATE`、`CLASSROOM/ADD_MEMBER`（target_id 记被加的人）、`CLASSROOM/END` | `AuditService.logClassroomCreate/logMemberAdd/logClassroomEnd` |

### 6.1 B1 请求 / 响应

```http
POST /api/v1/admin/classrooms        （仅 admin / platform_admin）
{
  "courseName": "临时课堂",              // 空 → "临时课堂"
  "teacherId": "0dc6977b...",           // 必填
  "teacherName": "张老师",               // 空 → 回退 teacherId
  "students": [{"userId":"stu-a","name":"学生A"}],
  "startTime": "2026-11-19T16:00:00",   // 空 → 服务端 now（不带 Z！）
  "endTime":   "2026-11-19T17:00:00",   // 空 → start + duration
  "duration": 60,
  "tenantId": 6                          // 空 → 调用者租户；平台管理员必须显式传
}
→ { "scheduleId": "<32位>", "classroomId": "<同 scheduleId>", "status": "SCHEDULED",
    "startTime": "...", "endTime": "...", "studentCount": 1, ... }
```

内部做的事与手工重放**完全一致**：合成 `created` 事件 → `ScheduleEventConsumer.handleCreated`
→ 建 `classroom` + 教师/学生 `classroom_membership` + 全员 `classroom_attendance(ABSENT)`。
`eventId = "tmp-" + scheduleId`，`classIndex = 1`（→ 课堂 id 就是裸 scheduleId）。

### 6.2 B2 请求 / 响应

```http
POST /api/v1/admin/classrooms/{scheduleId}/members
{ "students": [{"userId":"stu-c","name":"学生C"}], "note": "学生临时加入" }
→ { "added": ["stu-c"], "skipped": [], "addedCount": 1, "skippedCount": 0 }
```

- 幂等：已在课堂的人进 `skipped`，不覆盖在线态、不重置出勤；
- 写 `membership(OFFLINE)` + `attendance(ABSENT)`，**不走** `MembershipService.join`
  （那会把 `online_state` 置 ONLINE，人没到却显示在线）；
- 跨租户防护：租户管理员只能动本租户课堂，平台管理员放行。

### 6.3 仍然做不到的

B1 不能绕开"临时课堂不结算"——结算依赖 `course_schedule` 与 booking，这里都没有。
要算课时/进学情，仍必须走正常排期（方案 B）。B1 的价值是"比手写 JSON 稳、少踩时间格式坑"。

## 7. 应急 SOP（贴墙上）

**场景 1：10 分钟内要开一节临时课（不计课时）**

1. 确认租户课堂已开通（平台端课堂实例 `enabled=1`）。
2. 拿到教师 userId + 学生 userId 清单。
3. 运营台 →「实时监控」→「临时建课（应急）」：填课程名 / 教师 userId / 学生 / 时间 →「创建临时课堂」。
   （等价旧做法：契约联调页粘 `created` 报文重放，见 §2.2）
4. 结果区直接给出两条链接：「学生链接」和「管理员代开课」——点「复制」发给师生。
   学生未登录也没关系：登录后会自动回跳这间课堂（C1）。
5. 教师进课堂点「进行中」；管理员用「管理员代开课」那条链接（自带 `role=teacher`）。
6. **讲完必须点「下课」**；课堂卡住不动时运营台列表行内「结束」可强制作废。

**场景 2：课前往临时课堂加人**

运营台「给指定课堂加学员」：粘课堂号 + 学生 userId（逗号分隔）→「加入」。
（等价旧做法：重放 `updated` 报文，`students` 带上新人，见 §4.1）

**场景 3：上课中往已有排期的课堂加人**

排期页 →「候补 / 指定学生」→「指定学生」（席位满了先改大 `available_sites`）。
学生刷新后即可进入，「我的课堂」也会出现这节课，课时正常结算。

**场景 4：上课中往临时课堂加人**

运营台「给指定课堂加学员」（同一入口，课中同样可用——它不依赖课堂状态）。
加完让本人刷新课堂页即可进入；其他人在「参与者」面板看到新人需要各自刷新。
（兜底才是 SQL 插两行，见 §4.2）
