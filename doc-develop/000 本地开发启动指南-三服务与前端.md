# 本地开发启动指南（三服务 + frontend）

> **适用**：本仓库当前形态 —— 三个后端（`booking` / `message-service` / `classroom-service`）+ `frontend` 前端。
> **最后核对**：2026-10-31 00:10，本机实测 8081 / 8090 / 8080 分流正常（`/api/v1/system/info` 回 `booking_api`，`/api/v1/message/system/info` 回 `message-service`）。
> **相关文档**：`000 腾讯云部署与维护手册-预约系统.md`（上线）、`前端部署与维护手册.md`（前端细节）。

---

## 0. 一分钟版

```bash
# ① 首次构建产物（已构建过就跳过，见第 4 章）
cd api               && mvn clean package -DskipTests && cd ..
cd api/message-service   && mvn clean package -DskipTests && cd ../..
cd api/classroom-service && mvn clean package -DskipTests && cd ../..

# ② 一条命令起全套（后端 + 前端代理）
bash deploy/local/run-all.sh          # Git Bash / Linux / macOS
deploy\local\run-all.cmd              # Windows：双击或在 cmd 里执行

# ③ 浏览器
http://localhost:8080/login.html

# 停 / 看状态
bash deploy/local/run-all.sh status
bash deploy/local/run-all.sh stop
```

前端是**源码直出**（不打包）：改完 `js` / `html` / `css` 直接刷新浏览器即生效，不需要 `npm run build`。

## 1. 架构与端口

```
浏览器 http://localhost:8080
   │
   ▼  node 前端代理（静态资源 + 接口分流）
   ├─ /api/v1/{message,sensitive,sse,users/*}            → 127.0.0.1:8090  message-service
   ├─ /api/v1/{classrooms,attendance,recordings,uploads,
   │           files,schedules,rtc,admin/classrooms|monitor|
   │           reports|reconcile|audit|contract|exports}
   │   + /ws/classrooms/*（WebSocket 升级）               → 127.0.0.1:8092  classroom-service
   └─ 其余 /api/v1/*                                     → 127.0.0.1:8081  booking_api
```

| 服务 | 端口 | 数据库 | 额外依赖 |
|------|------|--------|---------|
| `booking_api`（主系统） | **8081** | `lesson_appointment` | — |
| `message-service`（消息 + SSE） | **8090** | `message_center` | — |
| `classroom-service`（在线课堂） | **8092** | `classroom` | **Redis `localhost:6379` db2** |
| 前端开发代理 | **8080** | — | Node.js |

> ⚠️ **分流前缀清单必须与 Nginx 一致**（`deploy/nginx/booking.conf` 与 `doc-develop/nginx-代理远端API-样例.conf` 已核对含 `sensitive`）。
> 两个易错点：`/api/v1/schedules/`（**复数**，属课堂）vs `/api/v1/schedule`（单数，属主服务）；`/api/v1/admin/*` 不能整片划给课堂，必须逐个精确前缀。

## 2. 启动方式（两种，按需要选）

### 2.1 推荐：`run-all` 一条命令起全套

```bash
bash deploy/local/run-all.sh            # 起三后端(后台) + 前端代理(前台占当前终端)
bash deploy/local/run-all.sh stop       # 前后端全停
bash deploy/local/run-all.sh status     # 只看四个端口
```

它做的事：

1. 调 `start-backend-local.sh` 起后端（该脚本自带"端口已占用就跳过"，**可以重复执行**）；
2. 轮询探活 8081 / 8090（课堂在监听时探 8092），就绪后才继续 —— 免得前端启动时连通性检查全是 ❌，让人误以为后端没起来；
3. 前台跑 `node doc-develop/dev-frontend-local-src.js`（Ctrl+C 停前端，后端留在后台）。

常用环境变量（可组合）：

| 变量 | 作用 |
|------|------|
| `SKIP_CLASSROOM=1` | 不起课堂 8092（没有 Redis、只调预约与消息时） |
| `BACKEND_ONLY=1` | 只起后端，前端自己另开 |
| `FRONTEND_ONLY=1` | 只起前端（后端假定已在跑） |
| `DIST=1` | 前端改伺服 `frontend/dist` 构建产物（默认源码直出） |
| `DEV_PORT=8080` | 前端代理端口 |

```bash
# 例：不起课堂、只起后端
SKIP_CLASSROOM=1 BACKEND_ONLY=1 bash deploy/local/run-all.sh

# 例：验证构建产物（dist）而不是源码
DIST=1 bash deploy/local/run-all.sh
```

Windows：`deploy\local\run-all.cmd`，环境变量先用 `set` 设：

```cmd
set SKIP_CLASSROOM=1
deploy\local\run-all.cmd
```

### 2.2 分两步：后端一个窗口，前端一个窗口

```bash
# 窗口 1：后端
bash deploy/local/start-backend-local.sh          # 后台 + 日志 /tmp/{booking,message,classroom}.log
# 或 Windows：deploy\local\start-backend-local.cmd  → 三个独立窗口，能看到实时日志

# 窗口 2：前端代理
node doc-develop/dev-frontend-local-src.js
```

## 3. 脚本清单

### 3.1 后端（`deploy/local/`）

| 脚本 | 行为 | 用法 |
|------|------|------|
| `run-all.sh` / `run-all.cmd` | **全套**：三后端 + 前端代理 | `bash deploy/local/run-all.sh` / `deploy\local\run-all.cmd` |
| `start-backend-local.sh` | 只起后端，`nohup` 后台，日志 `/tmp/*.log` | `bash deploy/local/start-backend-local.sh`；`SKIP_CLASSROOM=1` 跳过课堂；`stop` 全停 |
| `start-backend-local.cmd` | 只起后端，**每个服务一个独立窗口** | 双击；`nopause` 参数供 `run-all.cmd` 内部复用 |

两个后端脚本都已做：**jar 名通配匹配**（版本号会变，写死必踩空）+ **端口占用预检查**（已占用就跳过，不产生"窗口一闪而过"的伪启动）。

### 3.2 前端（`doc-develop/`）

| 脚本 | 静态根 | 接口指向 | 什么时候用 |
|------|--------|---------|-----------|
| **`dev-frontend-local-src.js`** | `frontend/` 源码（**不打包**） | 本地 8081 + 8090 + 8092 | ⭐ **日常开发首选**，改完刷新即生效 |
| `dev-frontend-local.js` | 源码；`DIST=1` 切 `frontend/dist` | 本地 8081 + 8090 + 8092 | 验证构建产物是否正确 |
| `dev-frontend-remote.js` | 源码 / dist | 远程 `152.136.254.127:80` | 本地页面连线上接口排障 |
| `dev-frontend-remote-tcb.js` | 源码 | 云托管 `api-329614-...` | 验证云托管环境 |
| `dev-frontend.js`（旧） | 源码 | 远程 8081 / 8090 | 已被 `remote.js` 取代，一般不用 |

Windows 双击对应：`start-frontend-local-src.cmd` / `start-frontend-local.cmd` / `start-frontend-remote.cmd` / `start-frontend.cmd`。

### 3.3 构建

| 产物 | 命令 | 实际文件名 |
|------|------|-----------|
| booking jar | `cd api && mvn clean package -DskipTests` | `api/target/booking-api-2.2.0.jar` |
| message jar | `cd api/message-service && mvn clean package -DskipTests` | `api/message-service/target/message-service-1.1.0.jar` |
| classroom jar | `cd api/classroom-service && mvn clean package -DskipTests` | `api/classroom-service/target/classroom-service-1.0.0.jar` |
| 前端 dist | `cd frontend && npm run build`（= `node build.js`） | `frontend/dist/` |

> 本机 `mvn` 命令损坏时用 Maven Launcher JAR 直启（完整命令见《000 腾讯云部署与维护手册》1.4）。
> 构建 dist 时若被 safe-delete 闸拦住（`SAFE_DELETE_BULK_CONFIRM_REQUIRED`），用 `CODEBUDDY_SAFE_DELETE_ENABLED=0 node frontend/build.js`。
> **源码直出不需要构建 dist**，只有 `DIST=1` 模式才需要。

## 4. 手工启动（不用任何脚本）

```bash
# 三个后端，各开一个终端（jar 名带版本号，用通配避免写死）
java -jar api/target/booking-api-*.jar                          --server.port=8081
java -jar api/message-service/target/message-service-*.jar      --server.port=8090
java -jar api/classroom-service/target/classroom-service-*.jar  --server.port=8092

# 前端（第四个终端）
node doc-develop/dev-frontend-local-src.js        # 浏览器开 http://localhost:8080
```

> **`--server.port` 必须显式带**：环境里若存在 `SERVER__PORT` 之类的变量，Spring Boot 的宽松绑定会覆盖 jar 内配置，把服务绑到别的端口，表现为"起了但访问不通"。

## 5. 前置依赖

| 项 | 要求 | 检查命令 |
|----|------|---------|
| JDK | 编译目标 **17**，本机 JDK 21 运行亦可 | `java -version` |
| MySQL | 三个库都在：`lesson_appointment` / `message_center` / `classroom` | `mysql -uroot -p123456 -e "SHOW DATABASES;"` |
| Redis | **仅课堂需要**，`db2` | `redis-cli -n 2 ping` → `PONG` |
| Node.js | 前端代理 | `node -v` |

> **课堂 8092 起不来的唯一常见原因就是没 Redis**。它不影响预约与消息，只调这两个设 `SKIP_CLASSROOM=1`（后端）或 `CLASSROOM_PORT=0`（前端代理侧彻底关掉课堂路由，不探测不转发）。
> 三个库的建库/导入见《000 腾讯云部署与维护手册》1.2 —— 注意 `api/sql/schema/` 下的脚本**不带 `CREATE DATABASE`**，要先建库。

## 6. 验证

```bash
# 一次性看端口
bash deploy/local/run-all.sh status
# 期望：8080 / 8081 / 8090 都在监听；8092 与 6379 视是否需要课堂

# 分流是否落对服务（三条返回的服务名必须各不相同）
curl -s http://localhost:8080/api/v1/system/info          | head -c 120   # booking_api
curl -s http://localhost:8080/api/v1/message/system/info  | head -c 120   # message-service
curl -s http://localhost:8080/api/v1/rtc/providers        | head -c 120   # classroom（未起则 502）

# 页面
curl -s -o /dev/null -w 'login %{http_code}\n' http://localhost:8080/login.html
```

> 若三条返回**同一个服务名**，说明分流没生效：确认跑的是最新版代理脚本（两个本地脚本都已接 8092 + `/ws/classrooms/`）。

## 7. 常见问题

| 现象 | 原因 | 处理 |
|------|------|------|
| `Unable to access jarfile` | jar 名写死成旧版本 | 用通配 `booking-api-*.jar`；先 `ls api/target/*.jar` 看真实文件名 |
| `EADDRINUSE` / 端口被占 | 上一次没停干净，或已有实例在跑 | `bash deploy/local/run-all.sh status` 先看；`stop` 后重启，或改 `DEV_PORT` |
| 前端启动时连通性检查全 ❌ | 后端还没起完 | `run-all` 会等就绪；分两步启动时先等后端，或设 `NO_PROBE=1` 跳过检查 |
| 消息接口 401 | booking 与 message-service 的 `jwt.secret` 不同源 | **不要一端本地一端远程混连**；要么全本地、要么全远程 |
| 课堂页 401 / 404 | 课堂服务没起，请求被兜底到 8081 | 起 8092（需 Redis）；或 `CLASSROOM_PORT=0` 关掉课堂路由 |
| 课堂 8092 启动即退出 | 没有 Redis / `classroom` 库不存在 | 起 Redis；检查 `classroom` 库；看 `/tmp/classroom.log` |
| 改了前端代码没生效 | 跑的是 `DIST=1` 或旧进程 | 用 `dev-frontend-local-src.js`；确认浏览器没缓存（Ctrl+F5） |
| `target/` 里有多个版本 jar | 通配取到旧的 | 先 `mvn clean` 或手动删旧包 |
