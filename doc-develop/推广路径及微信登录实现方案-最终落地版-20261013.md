## 一、方案概述

### 1.1 两大能力

| 能力 | 场景 | 说明 |
|---|---|---|
| **推广路径** | 路径1：自助建租户 | 通过推广链接注册新租户，成为首管理员，免费体验 |
| | 路径2：指定租户注册 | 推广链接带 tenantCode，为本租户拉新用户 |
| **微信登录** | 场景A：静默登录 | 已绑定 openid 的用户免输入进系统 |
| | 场景B：已有账号绑定 | 密码登录成功后关联 openid |
| | 场景C：微信直接注册 | 以 openid 为账号自动创建 user + 关联 |

### 1.2 租户编码

- 注册租户时自动生成 **8 字符** tenantCode（替代 UUID，易传播/分享/输入）
- tenantCode 与创建者账号关联（`sys_tenant.creator_account`）
- 字符集去除易混淆字符（`0/O`、`1/I/l`）

### 1.3 设计原则

- **后端为单一事实源**：所有业务规则在后端事务内完成，前端只传参数
- **user 表零改动**：微信关联存独立表 `wx_userid`
- **推广者不新增角色**：任何已注册用户均可成为推广者，通过 `referral_code` 关联
- **静默降级**：微信登录任何环节失败都不影响密码登录主流程
- **openid 不落前端**：`wx.login()` 仅拿临时 code，openid 由后端 `code2Session` 换取

### 3.1 `wx_userid`

```sql
CREATE TABLE `wx_userid` (
  `id`          bigint       NOT NULL AUTO_INCREMENT COMMENT '自增主键',
  `wx_openid`   varchar(64)  NOT NULL COMMENT '微信 openid（全局唯一，不随租户隔离）',
  `user_id`     varchar(36)  NOT NULL COMMENT '关联 user.user_id',
  `tenant_id`   bigint       NOT NULL COMMENT '用户所属租户（冗余，便于按租户统计）',
  `bind_source` varchar(20)  NOT NULL DEFAULT 'manual' COMMENT 'manual=已有账号绑定 / auto_register=微信直接注册',

  KEY `idx_tenant_id` (`tenant_id`)

```

**租户隔离**：本表**有** `tenant_id` 列，但语义是冗余统计。隔离必须**显式跳过**（一个微信全局只绑一个账号，跨租户统一）。否则插件追加 `tenant_id = 当前租户`，平台管理员视角查不到绑定 → **静默失败**。

做法（推荐集中式）：`WxUseridMapper` 全类加 `@InterceptorIgnore(tenantLine = "true")`。

## 四、8 字符 tenantCode

### 4.1 生成器

```java
public class TenantCodeGenerator {
    // 去除易混淆字符：0/O、1/I/l
    private static final char[] CHARS =
        "23456789abcdefghjkmnpqrstuvwxyzABCDEFGHJKMNPQRSTUVWXYZ".toCharArray();
    private static final int DEFAULT_LENGTH = 8;
    private static final SecureRandom RANDOM = new SecureRandom();

    public static String generate() { return generate(DEFAULT_LENGTH); }

    public static String generate(int length) {
        StringBuilder sb = new StringBuilder(length);
        for (int i = 0; i < length; i++) sb.append(CHARS[RANDOM.nextInt(CHARS.length)]);
        return sb.toString();
    }
}
```

### 4.2 组合数（修正原稿）

库是 `utf8mb4_general_ci`（大小写不敏感），`K` 与 `k` 等价。
字符集 54 → 大小写等价后有效字符 = 8 数字 + 21 字母 = **29 个**

```
有效组合 = 29^8 ≈ 5.0×10^11      （原稿 54^8 ≈ 7.2×10^13 高估约 144 倍）
1 万租户碰撞概率 ≈ n²/(2N) ≈ 1×10^-4；重试 10 次后失败概率可忽略
```

### 4.3 唯一性 + 保留字

```java
private static final Set<String> RESERVED_TENANT_CODES = Set.of("platform", "default");

public String generateUniqueTenantCode() {
    int maxRetry = sysConfigService.getInt("tenant.code.max.retry", 10);
    for (int i = 0; i < maxRetry; i++) {
        String code = TenantCodeGenerator.generate();
        if (RESERVED_TENANT_CODES.contains(code.toLowerCase())) continue;  // 撞保留字则换
        if (getByCode(code) == null) return code;                          // 走 uk_tenant_code
    }
    throw new BusinessException("租户编码生成失败，请重试");
}
```

### 4.4 硬约束：`platform` 行不得改写

`UserService.fillOrgName` 依赖 **`tenant_code = 'platform'`** 定位平台自身行（真库 `id=11`），用于：

- 平台管理员的「所属公司」显示
- `/user/briefs` 回 `orgName` 时 `tenant_id <= 0` 的映射（**2026-10-13 刚落地的功能**）

**约束**：

1. `TenantCodeGenerator` **只用于新建租户**，不得对已存在行批量重编
2. 若将来必须重编历史数据，**显式排除 `tenant_code = 'platform'`**
3. 新建时用 `RESERVED_TENANT_CODES` 拦截（§4.3）

## 五、微信登录三场景

### 5.0 前置：解除屏蔽的正确姿势

原屏蔽说明要求「ALTER TABLE user 加 wx_openid 列」—— **本方案不这么做**（user 表零改动是核心优势）。

| 位置 | 动作 |
|---|---|
| `authController.java:234-273` | 删除块注释标记，端点代码保留 |
| `UserService.java:392-429`（`wechatLogin`） | 取消注释，**内部实现从「查 `user.wx_openid`」改为「查 `wx_userid` 表」** |
| `UserService.java:431-445`（`bindWechat`） | 同上，改为写 `wx_userid` |
| `User.wxOpenid` 字段 | **保持 `exist = false`，不要启用** |

### 5.1 场景 A：静默登录

```
小程序启动 / 进入登录页
  → 无本地会话 → wechatSilentLogin()
    ① wx.login() → 临时 code（静默，无弹窗）
    ② POST /auth/wechat-login { code }（不带 Bearer）
    ③ WeChatService.code2Session(code) → openid
    ④ WxUseridService.findByOpenid(openid)
       ├─ 命中 → 状态校验 → 生成 token → { token, role, tenantCode }
       │         → setSession → 直接进角色首页
       └─ 未命中 → Result.fail(1001, ...) → 前端降级（密码登录 / 微信注册）
```

> **必须用 1001 而非 401**：401 会触发小程序 `request.js` 的 `onAuthFail` 重定向把用户踢回登录页；此处只是"未绑定"，应静默降级。该约定在原屏蔽代码注释里已写明，**解除屏蔽时不要改**。

### 5.2 场景 B：已有账号绑定

```
密码登录成功 → 用户勾选"允许微信登录" → bindWechat()
  ① wx.login() → code
  ② POST /auth/bind-wechat { code }（带 Bearer）
  ③ code2Session → openid
  ④ 校验 openid 未被其他账号绑定
  ⑤ INSERT wx_userid { wxOpenid, userId, tenantId, bindSource:'manual' }
  → 下次启动即可走场景 A 静默登录
```

> 失败用 **400 而非 401**（401 会把已登录用户踢出），保留原注释约定。

### 5.3 场景 C：微信直接注册（新增）

```
用户扫码/分享链接进入（带 tenantCode）
  → wechatSilentLogin() 返回 1001（未绑定）
  → 检测到 tenantCode → 走微信直接注册
    ① wx.login() → code
    ② POST /auth/wechat-register { code, tenantCode, role? }（不带 Bearer）
    ③ code2Session → openid
    ④ 查 wx_userid 未命中（防重复注册）
    ⑤ getByCode(tenantCode) → tenant，校验 status 正常
    ⑥ 事务内：
       ├─ 创建 User { account: openid, password: 随机UUID密文, role: student, status: pending }
       ├─ TenantQuotaService.acquire(tenantId, USER)          ← 原稿笔误 acquire8 已修

       ├─ INSERT wx_userid { openid, userId, tenantId, bindSource:'auto_register' }
```

- `account = openid`：`uk_user_account_tenant` 含租户维度，openid 全局唯一 → 不冲突 ✅

- **不可密码登录**：password 为随机 UUID 密文，用户无从得知

## 八、归因契约（硬阻塞 B3 的修订）

### 8.1 冲突

| | 现有 `acquisition.js` | 原稿推广 |
|---|---|---|
| 抓取参数 | `inviter` / `source` / `scene` | `ref` |
| 落盘 | `{ inviter, source, firstTouchAt }` | — |
| 上报 | `{ inviter, source, role, tenantCode }` | `referralCode` |

**直接照原稿做，推广链接的 `ref` 不会被捕获 —— 归因全丢。**

### 8.2 统一契约

链接**同时带 `ref`（推广码）与 `inviter`（推广者 userId）**，两端都认：

```
?ref=ABC123&inviter=<userId>&path=1|2&tcode=<8字符>&source=share
```

### 8.3 `acquisition.js` 扩展（唯一前端改动）

```js
export function captureAttribution(options) {
  if (!options) return;
  const next = {};
  if (options.ref)     next.ref     = String(options.ref);      // 新增
  if (options.inviter) next.inviter = String(options.inviter);
  if (options.source)  next.source  = String(options.source);
  if (options.scene) {
    try {
      decodeURIComponent(options.scene).split('&').forEach((kv) => {
        const i = kv.indexOf('=');
        if (i < 0) return;
        const k = kv.slice(0, i), v = kv.slice(i + 1);
        if (k === 'ref' || k === 'inviter' || k === 'source') next[k] = v;   // 新增 ref
      });
    } catch (e) { /* scene 解析失败忽略 */ }
  }
  if (!next.ref && !next.inviter && !next.source) return;
  const prev = storage.get(ATTR_KEY) || {};
  storage.set(ATTR_KEY, {
    ref:          prev.ref          || next.ref          || '',
    inviter:      prev.inviter      || next.inviter      || '',
    source:       prev.source       || next.source       || '',
    firstTouchAt: prev.firstTouchAt || Date.now()
  });
}
```

上报体改为 `{ inviter, ref, source, role, tenantCode }`。

### 8.4 后端 `/api/v1/user/attribution` 归因优先级

1. **有 `ref`** → 直接按 `promo_referral.referral_code` 归因（唯一、无歧义）
2. **只有 `inviter`** → 用 `uk_promoter_scope(promoter_user_id, path_type, target_tenant_id)` 定位；优先取 `path_type=1 AND target_tenant_id IS NULL` 的默认码；仍多则取最早创建的一条
3. 二者皆无 → 只记 `source`，不计入推广业绩

```java
        record.setBindSource(source);

    }

        wxUseridMapper.deleteByUserId(userId);
    }
```

```java
// 微信直接注册
@Transactional(rollbackFor = Exception.class)
public Result<HashMap<String, Object>> wechatRegister(String openid, String tenantCode, String role) {
    if (wxUseridService.findByOpenid(openid) != null) {
        return Result.fail(409, "该微信已注册，请直接登录");
    }
    Tenant tenant = tenantService.getByCode(tenantCode);
    if (tenant == null || tenant.getStatus() != STATUS_NORMAL) {
        return Result.fail(403, "租户不存在或已停用");
    }
    String resolvedRole = (role != null) ? role : RoleConst.STUDENT;
    String userId = UUID.randomUUID().toString();
    User user = new User();
    user.setUserId(userId);
    user.setTenantId(tenant.getId());
    user.setAccount(openid);                                   // 以 openid 为账号
    user.setPassword(passwordEncoder.encode(UUID.randomUUID().toString()));  // 不可密码登录
    user.setRole(resolvedRole);
    user.setStatus("pending");
    tenantQuotaService.acquire(tenant.getId(), TenantQuotaService.USER);
    if (RoleConst.STUDENT.equals(resolvedRole)) {
        tenantQuotaService.acquire(tenant.getId(), TenantQuotaService.STUDENT);
    }
    userMapper.insert(user);
    wxUseridService.bind(openid, userId, tenant.getId(), "auto_register");
    // 生成 token + 返回
}
```

## 十三、安全要点

| 项 | 设计 |
|---|---|
| **openid 不落前端** | `wx.login()` 仅拿临时 code，openid 由后端 `code2Session` 换取 |
| **不获取用户隐私** | 不调 `wx.getUserProfile` / `wx.getUserInfo`，仅用 openid |
| **全局唯一绑定** | `wx_userid.uk_wx_openid` 唯一索引 |
| **跳过租户隔离** | `WxUseridMapper` 加 `@InterceptorIgnore(tenantLine="true")`；promo 三表加入 `IGNORE_TABLES` |
| **公开接口无 Bearer** | `/auth/wechat-login`、`/auth/wechat-register`、`/promo/register-tenant`、`/promo/register-user` 在 permitAll 白名单 |
| **appid + secret 保护** | 环境变量注入（`wechat.miniapp.appid` / `wechat.miniapp.secret`），不进版本库 |
| **微信注册不可密码登录** | password 随机 UUID 密文 |
| **微信注册禁止解绑** | `bind_source='auto_register'` 拒绝解绑，防僵尸账号 |
| **防重复注册** | 注册前先查 `wx_userid`，`uk_wx_openid` 兜底并发 |
| **推广码防篡改** | 后端校验 `promo_referral.target_tenant_id` 与请求 `tcode` 匹配 |
| **重复归因** | `promo_conversion.uk_conversion_invitee`（`invitee_user_id` NOT NULL，去重真正生效） |
| **tenantCode 碰撞** | 生成后查 `uk_tenant_code` 校验，最多重试 10 次，并排除保留字 |
| **tenantCode 与账号关联** | `sys_tenant.creator_account`；反查接口限「本人或管理员」 |
| **业绩刷量** | `stage='registered'` 仅在 `userMapper.insert` 成功后写入（同事务） |
| **自助建租户防刷** | ① 同 IP 每小时 ≤ `promotion.register.period.limit` ② 手机号校验与次数限制 ③ 全局试用租户 ≤ `promotion.trial.global.limit` |
