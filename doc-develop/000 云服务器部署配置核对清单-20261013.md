# 云服务器部署配置核对清单（2026-10-13）

> 背景：本地 8080 开发代理伺服 `frontend/` 源码，从未暴露问题；一旦部署到云服务器
> （尤其国内），所有走境外 CDN 的前端依赖全部加载失败，表现为「auth.js 依赖
> utility_request.js，请先引入 utility_request.js」（axios 未定义 → utility_request.js
> 崩溃 → window.request 没挂上）以及 `index.global.min.css` 失败等。
>
> **根因**：前端 4 类库此前全部走 CDN（jsdelivivr / cdnjs / bootcdn），云服务器
> 访问境外 CDN 不稳定/被墙。本次已将全部依赖本地化（vendor 自托管），并修正构建脚本。

---

## 一、本次已完成的修复（源码侧，已提交）

| 项 | 改动 | 说明 |
|---|---|---|
| 前端依赖本地化 | 新增 `frontend/js/public/vendor/` | axios / fullcalendar / html2canvas / font-awesome(含 webfonts) 全部本地自托管，不再依赖任何 CDN |
| 12+ 个 HTML | `https://cdn...` → `js/public/vendor/...` | 全部外链改为相对路径；fullcalendar 独立 CSS 链接已删除（v6 样式由 JS 注入，独立 CSS 多余） |
| `frontend/build.js` | `copyAssets` 增加 vendor CSS 原样复制 | 原 `buildCss` 只扫 `frontend/css/`，vendor 下的 font-awesome CSS 两头都不处理 → 漏进 dist。已修 |
| `frontend/tools/check-origin.js` | `SKIP_REL` 跳过规则修正 | 原正则 `^js/vendor/` 漏掉实际路径 `js/public/vendor/`，导致 axios 内部 `http://localhost` 被误报。已改为匹配任意层级 `/vendor/` |

**部署前必须重新构建**：`cd frontend && node build.js`（已跑通，dist 内含完整 vendor 资源，含 8 个字体文件）。

## 三、建议部署顺序

1. **数据库**：先导入 schema + 行业基础数据（否则后端行业端点/下拉报错）。
2. **后端**：`mvn package` → 上传 jar → 重启 8081。
3. **前端**：`node build.js` → rsync dist → `/var/www/frontend`（**重点确认 vendor/ 一并上传**）。
4. **前端**：`node build.js` → rsync dist → `/var/www/frontend`（**重点确认 vendor/ 一并上传**）。
5. **课堂服务（如启用电子课堂）**：先装 Redis → 导 `classroom` 库 schema + patch → 配 `classroom.env`（三密钥同源）→ 放 `classroom.service` → `enable --now classroom` → 同步 nginx 课堂分流 → 从开发仓库重建并上传含 4 个课堂页面的 dist。
6. **nginx**：基本无需改；确认 root 指向 dist；`nginx -t && systemctl reload nginx`。
7. **环境变量**：注入 `JWT_SECRET` / `WECHAT_SECRET` / `DB_*`（+ `classroom.env` 的 `AES_KEY`/`HMAC_KEY`/`RTC_*`）。
8. **冒烟**（见下）。

## 五、电子课堂服务速查（部署/维护时直接抄）

```bash
# 构建（开发仓库，不是 H 盘部署副本）
cd api/classroom-service && mvn clean package -DskipTests && cd ../..

# 上传
scp api/classroom-service/target/classroom-service-1.0.0.jar  root@SERVER:/opt/lesson/classroom-service.jar
scp api/beforeRun/classroom.env.template  root@SERVER:/tmp/classroom.env.template
scp api/beforeRun/classroom.service       root@SERVER:/tmp/classroom.service
scp -r api/classroom-service/sql/         root@SERVER:/opt/lesson/sql/classroom/

# 服务器：库 + patch
mysql -uroot -p < /opt/lesson/sql/classroom/classroom-schema.sql
for f in /opt/lesson/sql/classroom/patch/*.sql; do mysql -uroot -p classroom < "$f"; done

# 服务器：目录 + 服务
sudo mkdir -p /var/log/lesson/classroom /opt/lesson/data/oss
sudo chown -R lesson:lesson /var/log/lesson /opt/lesson/data/oss
sudo mv /tmp/classroom.env.template /etc/lesson/classroom.env   # 再填真实值
sudo chmod 600 /etc/lesson/classroom.env && sudo chown lesson:lesson /etc/lesson/classroom.env
sudo mv /tmp/classroom.service /etc/systemd/system/classroom.service
# 日志滚动规则：本地先 scp deploy/logrotate/lesson root@SERVER:/tmp/lesson-logrotate，再：
sudo cp /tmp/lesson-logrotate /etc/logrotate.d/lesson
sudo systemctl daemon-reload && sudo systemctl enable --now classroom redis-server

# 验证
systemctl status classroom --no-pager
ss -lntp | grep -E '8092|6379'
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8092/actuator/health/readiness
```
