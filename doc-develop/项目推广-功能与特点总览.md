# 一套面向"预约型服务业"的多租户 SaaS 平台 —— 功能与特点总览（推广版）

> 文档用途：产品推广 / 销售沟通 / 落地页文案素材 / 合作方介绍
> 编制时间：2026-10-21
> 说明：本文所有功能点均对应当前系统已实现的模块（管理端、平台端、教师端、学生端、微信小程序），
> 未列入"规划中"的内容一律不写，避免对外承诺超出实际。

## 一、一句话定位

**一套开箱即用的多行业预约 SaaS：一家门店/机构/事务所，一个独立租户空间；同一套代码，换个词表就是另一个行业。**

不是"通用排课工具"，而是把 **预约 → 排期 → 上课/服务 → 通知 → 退改 → 结算统计** 的整条链路
做成了可多租户复制的标准产品。

---

## 二、面向谁：四类典型客户

| 客户类型 | 典型场景 | 当前已适配词表 |
| --- | --- | --- |
| 教育培训 / 语言教学 | 1对1、小班课、试听课排期与签到 | 课程 / 教师 / 学生 / 上课 |
| 律师事务所 / 法律咨询 | 律师咨询时段预约、材料预审、改期 | 咨询话题 / 律师 / 客户 / 咨询 |
| 心理咨询 / 情感咨询 | 咨询师档期、单次/疗程包、请假改期 | 咨询 / 咨询师 / 来访者 |
| 健身 / 私教陪练 | 教练排期、名额释放候补、次卡核销 | 训练项目 / 教练 / 学员 / 训练 |

**关键差异**：行业差异不是靠"配置文件改个字"，而是靠一套 **三级术语体系**（平台词 → 行业词 → 租户词）
在运行时渲染。同一个租户想改称"客户"为"学员"，自己改词表即可，不用等厂商发版。

## 三、功能地图（四端 + 一个小程序）

```
平台端（平台方运营）    租户管理 / 套餐模板 / 行业与词表 / 全平台监控 / 推广统计
      │
      ├── 管理端（每租户独立）  课程 · 排期 · 预订 · 用户 · 通知 · 退改 · 消息 · 审计 · 推广
      │        ├── 教师端        课程与排期管理 · 学生名单 · 预约处理
      │        └── 学生端        浏览师资 · 选时段 · 预约/候补 · 我的课表 · 退改
      │
      └── 微信小程序          登录/注册 · 师资列表 · 预约 · 我的预约 · 推广落地页
```

### 3.1 平台方（SaaS 运营者）能做什么

| 能力 | 说明 |
| --- | --- |
| 租户全生命周期 | 开通 / 编辑 / 停用 / 删除 / 恢复 / 续费（含租期到期预警） |
| 套餐与限额 | 套餐模板统一配置"课程数、排期数、教师数、学生数、发布数"上限；一租户一套实例，改套餐实时生效 |
| 行业与词表 | 新增行业、维护行业词库、从平台词一键复制到行业（冷启动工具） |
| 平台级监控 | 运营总览、租户趋势、在线统计、接口健康、性能采样与趋势 |
| 全平台推广统计 | 推广者排行、合计漏斗、Top20、最近转化 |
| 协议与政策 | 平台级协议/隐私政策维护，租户可覆盖本租户版本，签署留痕 |

### 3.2 租户管理端（商家日常使用的后台）

按真实菜单，一共 **7 组 20+ 模块**：

- **系统概览**：数据总览（今日/未来 1·3·7 天预约、状态分布、班级维度统计）
- **课程管理**：课程模板（批量开课的"母版"）+ 课程列表（具体在售课程）
- **排期与预订**：课程排期（批量生成课次）、预订审核（确认/驳回）、预约检视（按课次看名单与状态）
- **上课通知**：多档位自动提醒（首次预告 → 再次提醒 → 即将开始 → 最后提示）+ 手动补发
- **用户管理**：教师管理、学生管理（审批、冻结、批量导入）
- **消息中心**：站内消息收发、消息管理（含接收台账、撤回、全局删除）、消息分类管理
- **系统维护**：租户信息、数据维护、审计日志、系统配置、敏感词管理、退改规则、通知规则、协议与政策
- **我的推广 / 推广统计**：双推广码、业绩漏斗、转化明细

### 3.3 教师端

- 课程与排期管理（建课、生成课次、改期、取消）
- 预约处理（确认/驳回学生预约、候补递补）
- 学生名单与课次状态
- 个人资料发布页（对外展示执业信息、擅长领域、可预约时段）

### 3.4 学生端

- 公开师资落地页（免登录可浏览、支持按行业词切换，可做投放落地页）
- 选课程 → 选排期 → 提交预约；**名额满可排队候补**，名额释放自动递补
- 我的预约 / 我的课表 / 预约详情
- 请假、取消预约、撤回取消、重新申请（状态机五条自助转移路径）
- 站内消息（收件箱 / 收藏 / 回收站，实时红点）

### 3.5 微信小程序

- 微信登录 / 注册（独立的微信身份表，不与主账号体系耦合）
- 师资列表 / 师资详情 / 预约 / 我的预约 / 我的课表
- 推广落地页与自助开租户入口（分享即注册）

## 四、十个可以拿出去讲的卖点

### 1. 真多租户，不是"多开几个账号"

每个租户是数据层面隔离的独立空间：租户 A 的课程、排期、用户、消息，租户 B 一条也看不到。
**隔离做在数据访问层**（ORM 层统一注入租户条件），不是靠每个接口手写 `where tenant_id = ?`——
后者只要漏写一处就是数据泄露事故。

### 2. 套餐限额真的会拦人，不只是展示

课程数、排期数、教师数、学生数达到套餐上限时，系统在创建动作上**原子占用额度并拒绝超额**，
并发提交也不会冲破上限。平台方改套餐、续费、降级都有真实约束与提示。

### 3. 一套系统四套行业话术，可自助切换

平台词 → 行业词 → 租户词三级覆盖。律所看到的是"咨询话题/律师/客户/改期"，
培训机构看到的是"课程/教师/学生/请假"。
**租户自己改自己的词，不影响别人，也不用厂商发版。**

### 4. 号满不是"到此为止"，而是自动排队

名额满时学生可加入候补队列；有人取消，系统按队列顺序自动递补并推送通知（含第一节课时间）。
这是教培、私教、咨询行业最刚需、也最容易被低价产品忽略的一环。

### 5. 通知不是群发刷屏，是分档位、去重、可追溯

上课提醒按"3 天 / 1 天 / 30 分钟"等档位自动触发，每个课次每位收件人每档只发一次
（数据库唯一键兜底幂等，定时任务重跑也不会重复轰炸）。
每一次发送都落流水，可查"发了没、成没成功"。

### 6. 站内消息是真的能用的消息系统

- 三级分类（发起角色维度 + 业务场景维度），可按场景筛选
- 模板化发送、群发/广播、投递追踪（未投/已投/已确认/失败）
- 实时到达（服务端长连接推送，未读红点自动更新，不用刷新页面）
- 敏感词过滤（拒绝或掩码两种策略，可分组分租户配置）
- 管理员可撤回、可全局删除；平台方有"接收台账"看消息落到了哪些公司

### 7. 内置推广体系，分享即获客

- **平台推广码**：好友打开即自助开通新租户（免费试用期，无需销售介入）
- **租户推广码**：好友打开直接申请加入本租户（待审批）
- 每个推广者可查看完整漏斗：点击 → 注册 → 审批通过 → 成功缴费 → 促成新租户，
  外加微信注册数与转化率，附二维码一键分享
- 有防刷设计（同 IP、同手机号、试用租户上限三重闸门），点击只计数不注册

### 8. 微信生态打通，从朋友圈到预约只差一次点击

小程序登录/注册、师资展示、预约全流程可用；推广链接可直接在微信内打开落地页，
扫码即注册。**获客路径短到不需要用户下 App。**

### 9. 退改规则可配置，不用和客户扯皮

按课程 + 时间计算可退金额的规则可配置，学生下单前可看到退改条件提示，
管理员操作留痕。规则变化不用改代码。

### 10. 运营可视 + 可审计，出问题查得到

- 平台级：接口健康、性能趋势、在线统计、租户到期预警
- 租户级：预约/课次/注册多维统计（按天、按月、按状态）
- 全量审计日志（谁、什么时候、对哪个对象、做了什么）
- 服务器日志在线检索（管理员专用）

## 五、技术特点（给技术决策人看的部分）

不是"我们用了什么框架"，而是"这些选择给你的业务带来了什么"。

| 技术特点 | 对客户意味着什么 |
| --- | --- |
| 单库多租户 + 数据访问层统一隔离 | 一套部署服务所有客户，运维成本低；隔离由框架保证而非人工纪律 |
| 独立消息服务（独立进程 + 独立库） | 消息模块挂了不影响预约主流程；未来可单独扩容 |
| 长连接实时推送（SSE，非轮询） | 红点与消息秒级到达，服务端无轮询压力 |
| 敏感字段加密存储（手机号、邮箱、姓名） | 数据库被拖走也拿不到明文；支持按手机号精确检索（盲索引） |
| 全链路时间统一（UTC 存储 + 按排期时区渲染） | 跨时区连锁机构不会出现"预约时间差 8 小时"的事故 |
| 双令牌登录 + 单设备在线 + 可强制下线 | 账号被盗可立即踢下线；换设备登录有管控 |
| 契约守卫 + 自动化校验（构建期拦截） | 新增接口漏配权限/漏配白名单，在提交代码时就被拦下，而不是上线后出事 |
| 前后端共用一套领域模型（Web + 小程序同源） | 两端行为一致，改一处两端同时生效，不会"网页改了小程序没改" |
| 多语言词表（当前支持中文，英语/法语词条可配置） | 有外籍客户/涉外业务的机构可直接扩展 |

### 7.3 卖点清单版（落地页 / 一页纸）

2. 多行业词表：教培 / 法律 / 心理咨询 / 健身

4. 名额满自动候补，释放即递补并通知

## 八、常见提问怎么答（销售/客服口径）

| 客户会问 | 建议回答 |
| --- | --- |
| 我们是律所，不是培训机构，能用吗？ | 能。系统内置法律咨询行业词表，"课程/教师/学生/请假"会显示成"咨询话题/律师/客户/改期"，也可以自己再改。 |
| 数据会不会和别的机构混在一起？ | 不会。每个租户是数据隔离的独立空间，隔离在数据访问层统一做，不是靠人工记着加条件。 |
| 我们人少，套餐会不会太贵/太大？ | 套餐按课程数、排期数、教师数、学生数分档，可以先从最小档试用，规模上来再升级，平台侧改套餐实时生效。 |
| 老师不会用电脑怎么办？ | 教师端只有三件事：看排期、处理预约、看名单；学生端可以只用微信小程序。 |
| 名额满了学生一直问怎么办？ | 让学生加候补。有人取消系统自动递补，并给他发通知带第一节课时间。 |
| 能不能看到推广到底带来了多少客户？ | 能。每个推广码的点击、注册、审批通过、缴费、促成新租户都是分开统计的，还有转化率。 |
| 消息会不会发重复、半夜发？ | 提醒按档位触发，每课次每人每档只发一次（数据库唯一键兜底），档位时间可在通知规则里配。 |
| 我们的客户信息安全吗？ | 手机号、邮箱、姓名加密存储，日志有审计，接口有权限校验，账号可强制下线。 |

## 九、推广路径建议（谁适合先推）

按"需求刚性 × 决策链短"排序：

1. **单店/小机构（教培、私教）**：决策快、立刻要排课和名单，试用即见效
2. **个人执业者（律师、心理咨询师）**：只需展示页 + 预约 + 提醒，轻量需求最容易转化
3. **连锁/多品牌**：多租户 + 套餐 + 平台统计是刚需，但决策链长，适合做标杆案例
4. **行业服务商/代运营**：可以直接用"平台推广码"做二级分销，把开租户当成自己的产品卖

**最佳切入口**：把"教师/咨询师对外展示页 + 学生自助预约"当成免费引流工具先送出去——
客户先有一个能发朋友圈的链接，用起来之后再谈排期、通知、套餐。

## 十、边界说明（对外沟通要注意）

为避免过度承诺，以下几点需要如实说明：

- **当前多语言词条以中文为主**，英语/法语等词条可按需配置，但界面文案的完整多语言尚未全量覆盖。
- **消息实时推送为单实例内存长连接**，多实例水平扩展需配套改造（不影响当前使用）。
- **未内置在线支付/结算**：缴费状态由管理员确认，支付通道需按客户实际对接。
- **短信/邮件通道未内置**：当前通知以站内消息 + 小程序/网页推送为主，短信需另接服务商。
- **套餐模板当前以"限额"维度定义**（课程/排期/教师/学生），价格体系由运营方自行定价。
