# 课堂屏幕共享功能变更说明（2026-11-27）

## 一、需求与拍板

在线课堂增加「屏幕共享」：采集指定屏幕区域与主机声音输出并实时分享给课堂内其他人。

用户拍板的两个方向：

| 决策点 | 采用 | 否决/放弃 |
|---|---|---|
| 画面呈现 | **独立共享画面，与摄像头并存** | 替换本地摄像头轨（会顶掉人像画面） |
| 范围选择 | **浏览器原生选择器** | 自定义框选 + `canvas.captureStream` 裁剪（代码量大、有性能开销） |

## 二、技术事实（决定实现边界）

1. `getDisplayMedia` 的 `video.displaySurface` 只是**提示**，Chrome 出于隐私不允许代码强制指定范围；实际可选整屏/窗口/标签页由浏览器 picker 决定，UI 三选项只作为提示传给浏览器。
2. 系统声音：`getDisplayMedia({audio:true})` 在 Windows Chrome 共享**标签页**时可带系统音频；共享整屏/窗口通常要用户在 picker 里勾「分享系统音频」，且并非所有平台支持。代码只负责「请求」，不保证拿到。
3. 后端信令白名单 `ClassroomSignalService.KNOWN` 只含 hand/cam-state 等；未知 `type`（`screen-state`）走 `default → broadcastSignalExcept` 房间透传，**无需改后端**。若加进 KNOWN 反而触发服务端路由与事件落库，属不必要改动。
4. 发布门禁：`ClassroomPublishGuard.allows` 对未知 type 在 LIVE 时放行；已建立的媒体轨不走信令闸，必须前端在暂停/下课时主动停轨。

## 三、实现（新增 1 个模块 + 6 个文件接线）

### 核心模块 `frontend/js/classroom/classroom-screenshare.js`

- 独立 IIFE，对外 `window.ClassroomScreenShare`；
- `start()` 同步发起 `getDisplayMedia`（必须用户手势直接触发，不能在异步回调里调），范围三选映射 `displaySurface`：`desktop→monitor` / `window→window` / `region→browser`；系统声音由开关决定 `audio` 参数；
- **独立共享轨**：共享流是一份独立 `MediaStream`，通过 `pc.addTrack(track, screenStream)` 进入每个已建立的 peer connection，摄像头 `localStream` 完全不动；
- **重协商**照抄 `engine-mesh.js` 的 `_restorePublishing`：字典序大的一方 `createOffer`，小的一方发 `rtc-peer-join{rejoin:true}` 让对方重建后再发，避免 glare；
- **三重流识别**（任一命中即分流到独立格子）：`stream.id` 前缀 `screen-` / 轨 `label` 前缀 / `screen-state` 信令维护的 `screenPeers` 映射；并用 `cameraStreamIds` 排除摄像头流，防止信令先到时误判；
- `screen-state` 信令广播 `{on,userId,displayName,withAudio}`，对端建/拆独立格子；
- 轨 `ended`（浏览器原生「停止共享」）自动收尾；`stop()` 走 `removeTrack` + 重协商 + 停流 + 广播；
- SFU/SDK 引擎降级提示「当前模式不支持独立屏幕共享」。

### 接线改动

| 文件 | 改动 |
|---|---|
| `classroom-controls.js` | 教师/学生控制条加 `ctrl-share` 按钮（渲染时按 `supported()` 隐藏）；加入 `applyGate` 发布类清单；门禁关闭时主动 `stop(true)` 停轨；按钮点击：共享中=停止，未共享=弹配置面板 |
| `classroom.html` | 新增 `#screen-share-modal`（范围三选 + 系统声音开关 + 提示 + 开始/停止）；脚本区引入 `classroom-screenshare.js`（早于 controls） |

| `rtc/engine-mesh.js` | `ontrack` 每条流先问屏幕共享模块；返回 true=已按屏幕流接管，false=摄像头流（模块顺手记录其 stream.id 作排除项） |

## 六、SDK/SFU 支持与 maxPeers 优先级（2026-11-27 12:20 补做）

用户要求「三个都做」的第 2、3 项已一并收掉：

### 6.1 SFU 引擎支持（不再只是降级提示）

`engine-sdk.js` 新增 `startScreenShare(withAudio)` / `stopScreenShare()`，按 `sdkType` 分派：

| 服务商 | 发布 | 停止 |
|---|---|---|
| LiveKit | `localParticipant.setScreenShareEnabled(true, {audio})` | `setScreenShareEnabled(false)` |
| Agora | `createScreenVideoTrack({withAudio})` + `client.publish()`（兼容 6.x 返回的 `[video,audio]` 数组） | `client.unpublish()` + `close()` |
| TRTC | `startScreenShare({view, systemAudio})` | `stopScreenShare()` |

`leave()` 里补 `stopScreenShare()`，避免 leaving 后屏幕采集指示灯常亮。

`classroom-screenshare.js` 的能力检查从「仅 mesh」改为 `_engineReady()`：mesh 走 addTrack+重协商，
SDK 走各家 API（**不重复调 getDisplayMedia**，SDK 自己采集）；对端识别仍统一靠 `screen-state`
信令 + 独立格子，两种拓扑共用一套渲染逻辑。

### 6.2 maxPeers 优先级调度

达到 `maxPeers` 发布上限时，屏幕共享比摄像头更值钱：开始共享前检测
`_publishedCount() >= maxPeers`，若摄像头开着则**临时关闭摄像头轨给屏幕让路**，
停止共享后按 `ClassroomRTC.camEnabled` 恢复原开关状态。避免两路视频互挤导致都卡。
