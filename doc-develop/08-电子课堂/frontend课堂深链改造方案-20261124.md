# frontend 侧课堂链接深链化改造方案（v3 终版 · 2026-11-24）

> **定位**：frontend 保留「入口 + 管理面」，课堂本体归 classroom-app。本文回答「frontend 一侧的代码怎么调」。
> **事实基线**：`classroom-app/scripts/{sync,patch,build}.js`、`classroom-app/config/environments.js`、`classroom-app/src/core/role-router.js`、`frontend/js/**`（行号为当前工作区实测）。
> **来源**：系统架构师《深链契约与迁移边界裁定 v1.4（冻结，C1~C13）》+ 前端体验工程师《实现清单 v3》+ 主理人裁决。所有冲突点已定论。

---

## 0. 边界与结论

**边界一句话**：**迁走的是「上课」，留下的是「管理」**——课堂本体（RTC / 白板 / 媒体 / 课堂内录制控制 / 聊天）归 classroom-app；**课堂资料上传与管理、录制列表与回放、消息中心（含课堂侧读写）永久留 frontend**（裁决 15/16/17）。这条边界决定了 P3 的删减白名单，也决定了 `my-classroom-core.js` 是一个必须"半改半留"的混合职责文件。

**App 定位（已确认）**：App 只做「**上课 + 消息查看**」。资料与录制的**管理**在 web 端；App 内资料**只读**（上传/删除/整期入口隐藏）、回放**出壳**到浏览器、消息中心**完整读写**。所以 App 缺的不是"管理功能"，而是"消息服务的第四套地址"（`messageApiOrigin`，见附录 C.1）。

**本次改造的实质不是"把地址换成 classroom-app"，而是把散落 15 处、参数口径 5 套的课堂跳转，收敛进 `js/public/api.js` 里的一个构造器**（`window.ClassroomLink`），并遵循两条结构性不变式：`href()` 恒相对（不可能出壳）、`shareUrl()` 恒绝对且无有效基址时 fail-closed。因为同域同路径，`href()` 输出与今天逐字一致，**P0 零行为变化、零 HTML 改动、可零风险灰度**。

## 1. 关键裁决（17 条，全部定论）

### 裁决 1 · 深链形态：同域同根路径 https + App Links / Universal Link

深链恒为 `https://{公开站点}/{page}.html?scheduleId={key}&tCode={code}`，host 与路径本阶段不变。

| 场景 | 行为 |
|---|---|
| 纯浏览器 | 落 web 课堂页，功能完整（**产品底线**：不允许"没装 App 就进不去教室"） |
| 已装 App | Android App Links（`assetlinks.json` + `intent-filter autoVerify`）/ iOS Universal Links（AASA + Associated Domains）唤起 |
| 未装 App | 同一 URL 直接上课，**降级天然免费**——这是选它而非独立子域的根本原因 |

**由消息中心白名单反推的硬约束**：深链路径必须是根目录下**单段 `[A-Za-z0-9_-]+\.html`**。`/classroom/index.html` 这类多段路径会让"进入课堂"按钮渲染不出来。

**否决**：独立子域（跨域 localStorage 不共享 → 重登或 token 塞 URL；历史链接全失效）；纯自定义 scheme（未装 App 全废 + 被白名单拦）。

### 裁决 2 · 构造器落位：并入 `js/public/api.js`，不新建文件（架构师 v1.3 返工，采纳）

原方案要新建 `frontend/js/public/classroom-link.js`。**改为并入 `api.js`**，理由（架构师核对 `sync.js` 后发现，成立）：

1. 新文件**不在 `sync.js` 的 `PUBLIC_JS` 白名单** → local 模式（真正打包上真机那个）里 `student.html`/`teacher.html` 引不到 → `window.ClassroomLink` 为 `undefined` → 入口按钮全报错。而浏览器与 server 模式完全正常，属最难提前发现的事故。
2. 就算补白名单，还得在 4 个页面各加一行 `<script>` 且必须排在入口 JS 之前，漏一处就是空指针。

并入后：**白名单天然覆盖**（api.js 是 `PUBLIC_JS` 第一项）、**加载顺序天然正确**、**零 HTML 改动**。代价只是 api.js 增约 60 行，与 `pageUrl`/`resolveTenantCode` 同属一个职责域。

**⚠️ 并入方式的关键约束（已实测，写错会触发守卫）**：`api.js` 实测是**扁平脚本、没有 IIFE 包裹**——顶层直接暴露 `window.ADMIN_ORIGIN = ...`、`var STORE = ...`、`function pageUrl(...)`。因此**新增段必须自带 IIFE 包裹**：

```js
(function () { /* 构造器 */ })();
```

否则新增的顶层 `var`/`function` 声明会与全站其他文件的同名声明冲突，`npm run check:global-collide` 直接红。

**C12 双向约束（缺一不可）**：

| 方向 | 要求 | 违反后果 |
|---|---|---|
| 正向 | 新增段必须整段包在 `(function () { 'use strict'; … })();` 内 | 顶层同名声明撞车 → **解析期 SyntaxError，api.js 全部函数不注册，全站 40+ 文件失效** |
| **反向** | **严禁把整个 `api.js` 包 IIFE** | api.js 全局函数被 40+ 文件直接调用（`platform-admin-dataMaintain.js` 40 处、`teacherInfo-publish.js` 36 处），整体包裹 = 一次性打断全部调用方 |

**块标记（守卫按标记取区间，不靠缩进猜）**：

```js
  // [CLS-LINK-BEGIN] 课堂深链构造器（C1~C13）—— 本区间必须整体位于 IIFE 内（C12）
  (function () {
    'use strict';
    …
  })();
  // [CLS-LINK-END]
```

`pageUrl` / `resolveTenantCode` 在 api.js 顶层作用域已声明，内层 IIFE 可通过闭包直接调用，无需 `window.` 前缀。

| 适配点 | 独立文件版 | 并入 api.js 后 |
|---|---|---|
| 作用域 | 自身 IIFE | **必须新起 IIFE 包裹**（api.js 顶层是扁平的） |
| `href()` 委托 | `typeof window.pageUrl === 'function' ? window.pageUrl(...)` | 直调 `pageUrl(file, params)`（同作用域，仍建议保留 `typeof` 防御以兼容旧构建） |
| tCode 兜底 | `typeof window.resolveTenantCode === 'function' ? …` | 直调 `resolveTenantCode()` |
| 挂载 | `window.ClassroomLink = {...}` | 同（必须显式挂 window，因 IIFE 封闭） |

### 裁决 3 · 取消「可配基址」概念

不引入 `CLASSROOM_APP_ORIGIN` 这类"深链目标域"字段。server 模式下 `server.url` 加载的就是线上前端，存在第二个 origin 必然跨源加载、课堂 API 的同源假设直接破裂。**不是"允许配但校验"，是根本不提供这个字段。**

### 裁决 4 ·「不出壳」改为结构性保证

否决"运行时环境检测决定 URL 形态"：server 模式下 WebView 加载远端页，页面里没有 `app-config.js`，`APP_CONFIG` 判断大概率失真，Capacitor 桥是否注入未实测——不能把跳转正确性押在未验证的检测上。

| 不变式 | 含义 |
|---|---|
| `href()` **恒相对** | `'./classroom.html?…'`，结构上不可能出壳 |
| `shareUrl()` **恒绝对** | 复制 / 通知 payload / 只读输入框展示 |
| `isInApp()` **只控按钮显隐** | 决定"要不要显示「用 App 打开」"，**绝不参与地址构造** |

判断失真的代价从"用户被踢到浏览器"降到"少一个按钮"。

### 裁决 5 · `shareUrl` 双函数：字符串版 + fail-closed 版

前端主张 `shareUrl()` 恒返回字符串；架构师要求返回 `{url, insecure}` 供落库通道校验。**裁定为双函数，两者都要**：

| 函数 | 返回 | 允许用于 |
|---|---|---|
| `shareUrl(spec)` | 字符串（无基址时 `''`） | **即时 UI**：渲染到页面、写进只读 input 让用户手动复制 |
| `shareUrlSafe(spec)` | `{ url, insecure }` | **凡提交/发送/落库的值必须走它**并检查 `insecure` |

`insecure` 判据三条件取或（C10）：① 目标非 https；② 目标 host 为 localhost / 回环 / 私网；③ **来源页自身非 https**。
**无有效基址时 `shareUrl()` 必须返回空串 + 禁用复制按钮（C11）**，禁止静默降级为相对路径——相对值被复制出去或写进 payload 就是不可召回的坏链，比"按钮不可用"难排查十倍。

> 我原口径是"无基址宁可退回相对"，此条按 C11 修正。相对路径只适用于 `href()`（页面跳转），`shareUrl()` 语义天然要求绝对。

### 裁决 6 · `replay.html` 是唯一合法的「出壳」例外（终局）

**回放永久留 frontend 同源，不进 classroom-app 白名单。** 回放是点播，不需要相机/麦克风/屏幕共享/WS，进 App 无收益；进白名单要补 JS 白名单 + 全屏/画中画回归。代价：local 模式下 App 内点回放会 404 → **用 `@capacitor/browser` 打开绝对地址**（`openReplay()` 内建此分支 + `window.open` 兜底）。

插件实例写法：`window.Capacitor.Plugins.Browser`（**不是**裸 `Capacitor.Plugins.Browser`），依据是本工程既有写法 `classroom-app/src/core/app-bridge.js:125/132` 用 `caps.Plugins.App`。前提：`@capacitor/browser` 已在 dependencies（已确认 `^6.0.0`）且跑过 `npm run cap:sync`。`Browser.open()` 返回 Promise，必须 `.catch` 兜底，否则 Android 上插件缺失会变成未捕获 rejection（静默不跳转）。

### 裁决 7 · `classroom-ops.html` 留 frontend 到 P2，`js/classroom/*` 禁止目录级删除

App 内 `ops.html` 是轻运营版，巡课/强结/链接分发能力与 `classroom-ops.html` 不等价。删减顺序**强制**：删页面 → Grep 确认零引用 → 再删 JS，逐个文件来。**P3 可删的页面只有 `classroom.html` 与 `classroom-prep.html` 两个。**

### 裁决 8 · `ops.js` 属入口层，P0 可改

`ops.js` 承载链接分发 + 入口跳转，不做 RTC/WS/媒体控制；且**不在 `sync.js` 白名单**（App 用自有 `ops-lite.js`），改了不波及 www，回归面仅限 frontend 运营台。所以 `role:'teacher'` 的假分流清理放 P0。

### 裁决 9 · 过渡期课堂页「能力与结构」一字不改 ⚠️

已核实 `classroom-app/scripts/build.js:134`：server 模式 `capacitor.config.json` 的 `server.url = frontendOrigin`，WebView 加载**线上 frontend 原页**，`www/` 里的 FP-001~FP-008 补丁只对 local 模式生效。**删页 = App 白屏。**

准确口径：**不改的是课堂能力与页面结构；入口链接构造与链接分发展示，本来就是本次改造对象。**
P0 明确不动：`classroom-prep.js:376`、`classroom-main.js:774/834`、`admin.html:399-404`。

### 裁决 10 · `role` 参数禁止入链，且 UI 残留必须清理

FP-001 已把课堂页 role 收敛为只认登录态。`ops.js:511-512` 仍生成"教师链接"、`:516-522` 渲染两个按钮——**只删参数不够，两个按钮必须合并为一个「复制课堂链接」**，否则运营台继续以为分了角色。

### 裁决 11 · 单行 `publicWebOrigin` 变量名统一为 `window.PUBLIC_WEB_ORIGIN`

候选链四项：`window.PUBLIC_WEB_ORIGIN → APP_CONFIG.publicWebOrigin → FRONTEND_ORIGIN → location.origin`。**app-config 生成时只产出一个名字**（`window.PUBLIC_WEB_ORIGIN`），候选链保留其余三项仅为兼容与兜底，不得多源并存。

### 裁决 12 · dev 内网段放行 http，但禁止落库外发

`publicWebOrigin()` 允许 `localhost / 127.0.0.1 / 10.x / 192.168.x / 172.16-31.x` 走 http（否则本地根本验不了复制链接）；但 `insecure` 为真时，**落库/外发通道必须拒绝**（见裁决 5）。dev 跑得通、生产不漏发坏链。

### 裁决 13 · 构造器归属：不改 shared，改用断言锁

架构师主张给 `shared/domain/classroom.js:256` 的 `classroomLink` 加 `options` 扩展。**裁定不改 shared**：

1. 两者输入域不同——shared 服务"小程序把链接发出去"，只需四段拼接；web 端还要 `parse`、壳判定、分享原址回退、白名单化参数、`shareUrlSafe`。
2. 四步同步成本不对称：`gen-shared-bridge` 是 2580+ 行全量重生成，diff 噪音淹没真实改动。
3. **断言必须按"参数集合等价"比对，不能比字符串**（这条实现必踩）：`shared.classroomLink` 顺序是 `scheduleId → tCode → extra`；`pageUrl` 是 `extra → tCode`（`api.js:837-840` 最后 set）。正确做法：固定样例集（无 extra / 带 mode / 多课次 `S1~2` / 无 tCode），两边过 `new URL()` 比较 `origin+pathname` 相等且 `searchParams` 排序序列化相等，不等则构建失败。

### 裁决 14 · 课堂侧没有二维码，别为此预留闸门

全仓 `QRCode` 只在 `login.html`（微信登录码）与 `js/public/promo.js`（推广码）。`ops.js:731` 是**通知结果回显输入框**，不是生成。前端 v1 的"二维码(:731)"表述有误，已更正；C10 措辞同步修正。

### 裁决 15 · 课堂资料上传与管理**永久留 frontend**，不迁 classroom-app

归属代码：`js/public/my-classroom-core.js` 的 `listMaterials`(:126) / `uploadMaterial`(:139) / `deleteMaterial`(:156) + 课次资料面板渲染(:546-630) + 排期级「整期资料」入口(:387 / :505-519)。宿主是 `teacher.html` / `student.html` 的「我的课堂」页签。

- **教师端**可上传 / 删除；**学生端只读**（按 role 渲染，无上传按钮）。
- **禁止**把资料管理搬进 classroom-app：App 的 `my-classroom.html` 是轻量入口，不承担「整期资料 + 多课次资料面板」这种批量管理能力。
- **由此得出一条硬约束**：`my-classroom-core.js` 是**混合职责文件**，P0 只允许改其中 4 个跳转函数（`enterClassroom`/`openPrep`/`openStudentPrep`/`openReplay`），**资料与回放取数的 4 个函数原文不动**；P3 也不得删除该文件。
- **App 内落地（口径已定：管理在 web）**：资料面板在 `ClassroomLink.isInApp()` 为真时**隐藏**「上传资料」「删除」「整期资料」三个入口；文件列表可只读展示或整体不渲染（建议只读，便于上课前确认讲稿已传）。
  ⚠️ 这与裁决 4 不冲突：裁决 4 禁止的是 `isInApp()` 参与**地址构造**（判错会把用户踢出壳），此处只用它控**按钮显隐**（判错最多多/少一个按钮）——正是裁决 4 明确允许的用途。

### 裁决 16 · 课堂录制管理**永久留 frontend**（强化裁决 6）

录制管理有两侧，归属不同，不能一刀切：

| 侧 | 代码 | 端点 | 归属 |
|---|---|---|---|
| **录制文件查看与管理** | `replay.html` + `js/classroom/replay.js`（415 行，调 `getRecordings` 拉**列表**、多录制切换、签名 URL 播放） | `GET /api/v1/recordings/{scheduleId}`、`/playback` | **永久留 frontend**（同裁决 6） |
| 课堂内录制控制（教师侧 MediaRecorder 起停 + OSS 上传） | `js/classroom/classroom-record.js` | `POST /classrooms/{sid}/recording/start`、`/state`、`/{recordingId}/stop` | 随 `classroom.html` 走，属课堂能力 |

所以 `replay.html` 不只是"回放点播"，它是**录制列表管理页**——这是它必须留在 frontend 的新增依据（原裁决 6 的理由是"点播无需设备权限"，现在多一条：`getRecordings` 的列表管理不该塞进课堂 App）。

**App 内落地（口径已定：管理在 web）**：「回放」入口**保留**（属查看行为），点击走 `openReplay()` 出壳到 web 的 `replay.html`；**不**在 App 内重做录制列表页、**不**提供录制删除/管理入口。

### 裁决 17 · 消息中心**整体留 frontend**，课堂侧读写不能断

- 宿主 5 个页面：`student.html:704`、`teacher.html:559`、`admin.html:621`、`platform_admin.html`、`classroom-ops.html`。
- **写**：运营台/管理端对课堂发通知（`ops.js` `MSG_SEND`，`payload.type='classroom_join'`）。
- **读**：消息列表 + `payload` 渲染「进入课堂」按钮（`messages-inbox.js:85`）+ `safeJumpUrl` 校验。
- ⚠️ **别混淆**：课堂内聊天（`classroom-chat.js`）走 **WS signal 广播**（`{type:'chat',from,name,text,ts}`），**不经过消息中心**。消息中心是站内信，两者不是一条通道。
- ⚠️ **新发现缺口（必须补，否则 App 内消息中心读写全废）**：`messages-inbox.js:23` 的 `MSG_BASE = window.MESSAGE_API_BASE_URL || window.API_BASE_URL || ''`，而 classroom-app 的 `build.js` 注入的 `runtimeConfig` 只有 `apiOrigin / classroomApiOrigin / classroomWsOrigin / wsOrigin` **四套里没有 message**，`build.js:46` 的 local 必填校验也只查三套。local 模式下消息请求会打到 booking 8081（无 message 路由）→ 列表空、发消息 404。**必须新增第四套 `messageApiOrigin`**（见附录 C 跨工程配套）。

## 4. 构造器设计（并入 `js/public/api.js`）

**落位**：`api.js:846` `window.pageUrl = pageUrl;` 之后，同一 IIFE 内。

**职责边界**：只构造/解析地址。**不判权限、不管显隐、不弹 toast**（显隐归 `hasClassroom()`/`applyMenuVisibility()`；能否进入归目标页 `guardClassroom()` 与 App 侧 `app-entry-guard`）。

**API**（挂 `window.ClassroomLink`）：

| API | 返回 | 用途 |
|---|---|---|
| `href(spec)` | 相对字符串 | 站内跳转（恒不出壳） |
| `shareUrl(spec)` | 绝对字符串 / `''` | 即时 UI 展示、只读 input |
| `shareUrlSafe(spec)` | `{url, insecure}` | **落库/外发通道专用** |
| `open(spec)` | 跳转 | 按钮回调 |
| `openReplay(key)` | Promise | 回放（唯一出壳例外） |
| `parse(raw)` | `{key, target, tCode, error}` | 加入课堂粘贴 |
| `publicWebOrigin()` / `isInApp()` / `enabled()` | — | 排障 / 按钮显隐 / 开关透出 |

`spec` 形状（**无 role 字段**）：`{ target: 'classroom'|'prep'|'entry'|'replay', key, mode?, intent?, src?, meta?{start,end,state,idx,total} }`。`paramsOf()` 白名单化，`role / token / tenantId / userId` 一律丢弃。

**核心不变式**（实现见附录 A 代码）：

```js
function href(spec)        // 恒 './x.html?…'，不碰 origin
function shareUrl(spec)    // publicWebOrigin() 为空 → ''（C11 fail-closed）
function shareUrlSafe(spec)// { url: shareUrl(spec), insecure: isInsecure(origin) }
function isInsecure(origin)// 非 https || 私网 host || 来源页非 https
```

## 12. 决策与权衡（被否决方案）

| 被否决 | 原因 |
|---|---|
| 独立子域 `classroom.{domain}` | 跨域 localStorage 不共享 → 重登或 token 塞 URL（安全红线）；历史链接全失效 |
| 纯自定义 scheme | 未装 App 全废；被 `safeJumpUrl` 拦下，为它放宽等于削弱消息中心安全边界 |
| 同源**子路径** `/classroom/index.html` | 被单段 `.html` 正则挡下，消息中心按钮渲染不出来 |
| 新建 `classroom-link.js` 独立文件 | 不在 `sync.js` 白名单 → local 模式空指针，且需 4 个页面加 script；改并入 `api.js`（裁决 2） |
| 改 `shared/domain/classroom.js` 加 `options` | web API 面远大于小程序需要；四步同步 + 2580 行 bridge 全量重生成，成本不对称 → 改断言锁（裁决 13） |
| 改 `safeJumpUrl` 放行 scheme | 要同改 `shared/domain/message.js:232`，小程序复用同一函数却打不开 scheme |
| 引入 `CLASSROOM_APP_ORIGIN` 可配基址 | server 模式下第二 origin 必跨源，课堂 API 同源假设破裂（裁决 3） |
| 用 `isInApp()` 决定 URL 形态 | 运行时检测在 server 模式大概率失真 → 改结构性保证（裁决 4） |
| `shareUrl()` 单函数兼顾两种语义 | 落库通道无法 fail-closed → 拆双函数（裁决 5） |
| 无基址时 `shareUrl()` 降级相对路径 | 复制出去即不可召回的坏链 → C11 fail-closed |
| 把 `replay.html` 迁进 classroom-app | 点播无需设备权限/WS，进白名单要补 JS 与全屏回归，收益为零（裁决 6） |
| P0 删 frontend 课堂页 | server 模式 App 加载线上原页，删即白屏（裁决 9） |
| 只删 `role:'teacher'` 参数、保留两个按钮 | 运营台会继续以为链接分了角色（裁决 10） |
| **把资料管理 / 录制管理 / 消息中心一并迁入 classroom-app** | 三者都是「管理面」而非「上课面」：资料要支持整期 + 多课次批量操作、录制要列表管理、消息中心是跨课堂的站内信通道。App 内 `my-classroom.html` 是轻量入口，迁过去等于让教师失去批量管理能力，且消息中心一旦搬走，学生收不到课堂通知就进不了门（裁决 15/16/17） |
| **App 内也提供资料/录制管理入口**（口径：管理在 web） | 当前资料面板是表格 + 多按钮结构，小屏适配成本高且与 App「上课」定位冲突；管理集中在 web 端还能保证只有一个真源，避免两端上传行为分叉 |

### C.1 `messageApiOrigin` 落地细节（与 api 8081 对齐，含一处必须区别对待）

**对齐的部分（照抄 api 那套）**

| 环节 | api 8081 现状 | message 照此办理 |
|---|---|---|
| 前端基址 | `api.js:58-67`：`API_SERVER_HOST/PORT` 留空 → `API_BASE_URL=''` → 同源；有值才拼绝对地址；末尾 `window.API_BASE_URL = API_BASE_URL` 导出 | `messages-inbox.js:23` 已是 `MSG_BASE = window.MESSAGE_API_BASE_URL \|\| window.API_BASE_URL \|\| ''`，**前端文件不用改**，天然支持"留空即同源" |
| 配置字段 | `environments.js.apiOrigin` → `build.js` 的 `runtimeConfig.apiOrigin` → `app-config.js` 的 `APP_CONFIG.apiOrigin` | 同样加一条 `messageApiOrigin` 到这三处 |
| local 必填校验 | `build.js:46` `missing = ['apiOrigin','classroomApiOrigin','classroomWsOrigin']` | 扩成 4 项，缺 messageApiOrigin 也要 `exit=1` |
| 桥接覆盖 | `app-bridge.js` 的 `patchNormalize()` 改写 `ApiPaths.normalizeUrl`，给 `/xxx` 前缀 `API_ORIGIN` | message 这边**不是**改 `ApiPaths`（消息走独立 axios 实例），而是把 `messageApiOrigin` 写成 `window.MESSAGE_API_BASE_URL` |

**⚠️ 必须区别对待的一处：注入时机**

- api 走 `ApiPaths.normalizeUrl`，**每次请求时**才拼接 → 桥接层可以在运行时任意时机 patch。
- message 的 `MSG_BASE` 是**模块顶层 `const`，只在 `messages-inbox.js` 执行那一刻读一次**（`:23`）→ 一旦读成 `''`，后面再 patch `window.MESSAGE_API_BASE_URL` 也不会生效，请求照样打向 `capacitor://localhost`。

所以落地必须满足：**`messageApiOrigin` 在 `app-config.js` 里就写进 `window.MESSAGE_API_BASE_URL`**（`app-config.js` 由 `build.js` 生成、在页面最前面加载），保证早于 `messages-inbox.js`。不要指望桥接层在 `DOMContentLoaded` 时补——那时 axios 实例的 `baseURL` 已固化。

**验收判据**：App local 模式打开消息中心，`mreq.defaults.baseURL` 应等于 `messageApiOrigin` 而非空串；发一条消息成功（200），列表能拉到。
