# 视频画面独立移动/缩放可行性分析

- 日期：2026-11-17
- 问题：学生和老师的视频目前"绑在一个区域上缩放平移"，能否相对独立、分别移动和缩放？
- 结论一句话：**能，现状是所有 tile 共享一个 `#video-grid`、外层 `#video-panel` 整体被拖动缩放；每个视频块本身是独立 DOM 且有稳定 id，具备单独定位的技术前提。只是当前没有任何 per-tile 的位置/变换逻辑。**

---

## 1. 现状：为什么现在是"绑在一起动"

三层结构（自外向内）：

```
#video-panel  (cl-panel, 可拖动/缩放的单元)      ← 拖动/缩放作用在这一层
  ├─ .cl-panel-bar  (data-cl-drag 拖动条 + 复位按钮)
  ├─ #video-grid    (CSS Grid: repeat(auto-fit, minmax(220px,1fr)))
  │    ├─ #vt-local        .video-tile  ← 教师/自己（本地摄像头）
  │    ├─ #vt-{userId}     .video-tile  ← 某个学生/对端
  │    └─ ...
  └─ .cl-panel-resize (data-cl-resize 缩放手柄)
```

关键事实：

| 项 | 现状 | 依据 |
|---|---|---|
| 谁被拖动/缩放 | **整个 `#video-panel`**，里面所有视频一起动 | `classroom-panels.js:44-49` `panelEl('video')` 返回 `#video-panel`；拖动/缩放/复位都作用在它身上 |
| tile 怎么排布 | CSS Grid 自动均分，`minmax(220px,1fr)`，等宽流式 | `classroom.css:158-166` |
| 单个 tile 能独立定位吗 | **不能**——`.video-tile` 只有 `position:relative` + flex 居中，无任何 left/top/transform | `classroom.css:167-182` |
| tile 是独立 DOM 吗 | **是**——每个有稳定 id（`vt-local` / `vt-{peerId}`），创建/移除由 `RtcTiles` 管 | `rtc-engine.js:53-88` |
| tile 会不会被整体重建 | 不会——`RtcTiles.local/remote` 有幂等判断（已存在就 return），进房 append、离房 remove，单个 tile 增删 | `rtc-engine.js:56-88` |
| 位置有没有记忆 | 只有 `#video-panel` 级别的（`localStorage['classroom.panelLayout.v1']`），无 per-tile 记忆 | `classroom-panels.js:27,164-167` |

一句话：**现在的拖动缩放是"面板级"而不是"格子级"，所以给人的感觉是所有人的画面绑在一个框里整体平移缩放。**

---

## 2. 技术上能不能独立

**能，而且改造边界很干净**——有三点现成基础：

1. **每个 tile 是独立 DOM、id 稳定**：`vt-local` / `vt-{userId}`，可直接挂 pointer 事件与内联定位，不需要碰 RTC 引擎的流绑定逻辑。
2. **tile 增删可控**：进房 append、离房 remove（`rtc-engine.js`），且幂等，不会整体 `innerHTML` 重建把位置状态冲掉——这意味着位置状态能稳定按 userId 保存。
3. **已有可复用的交互范式**：`classroom-panels.js` 已经实现了"按需脱层"（动过才从 flow 切 fixed）、拖动 rAF 节流、夹紧、localStorage 记忆、复位、层级管理、缩放后补 resize 事件。这套逻辑可以下沉复用到每个 tile。

没有技术阻断，纯前端工作量，不动流媒体、不动服务端。

---

## 3. 但要先分清两种"独立"

"分别移动缩放"有两种语义，成本差一个数量级，必须先定：

### 方案甲：本地独立视图（各人看各人的）

每个观看者自己决定把教师/学生画面放在哪、多大，**只影响自己屏幕**，靠 localStorage 记忆。

- 做法：给每个 `.video-tile` 加拖动手柄 + 缩放手柄，位置/尺寸按 `userId` 存 `localStorage['classroom.videoTiles.v1']`；`RtcTiles.remote/local` 创建 tile 时按 id 恢复；面板复位时分别清单块。
- 优点：零服务端改动、零权限问题、互不干扰；复用现有 `classroom-panels.js` 范式。
- 难点：tile 是动态增删的，要处理"新成员进来用什么默认位"和"成员离开后记忆留不留"（建议保留一段时间，重进恢复）。
- 与现有面板的关系：视频 tile 的独立定位要在 `#video-panel` 内部，若面板本身也被拖成浮窗，需要明确坐标系（建议 tile 相对 panel 定位，panel 整体移动时 tile 跟着走）。

### 方案乙：教师导播式（全局同步）

教师调整布局后**广播给全班**，所有学生端画面位置跟着变（类似"导播切位"）。

- 做法：走 WS signal 新增 `layout:tile` 类型，携带 `{userId, left, top, width, height}`；服务端 `ClassroomSignalHandler` 路由（需在 `ClassroomPublishGuard` 登记控制类权限，仅教师/管理员可发）；各端 `onSignal` 应用；可能还要落教学流水与快照。
- 优点：全班视角一致，适合"教师主讲、统一呈现"的授课形态。
- 难点：新增信令类型要动服务端门禁（`CONTROL_TYPES`）、`ClassroomSignalService.KNOWN`、前端 `apiPaths`/守卫多处；要定权限（谁能改、学生能不能改自己的）；要处理迟到者布局恢复（类似 `pushInitialState`）。工作量和回归面明显大。

---

## 4. 建议

1. **若诉求是"我自己看着方便"**（例如把教师的画面拖小放角落、把某个学生放大）——走**方案甲**，纯前端、可快速落地，且和 2026-11-16 已做的面板拖动缩放一脉相承。
2. **若诉求是"教师统一控制全班看到什么布局"**——才值得走方案乙，且建议**先做甲、再在甲的存储层上加广播**，不要一开始就铺服务端信令。
3. 无论哪种，都要守住两点：
   - **tile 的增删幂等与位置记忆的生命周期**：避免成员重进后位置错乱、避免 localStorage 无限积累已离开成员。
   - **`object-fit: cover` 下的缩放语义**：现在视频是裁切填满（`classroom.css:180`），"缩放"要明确是缩放整个 tile 框（连带画面一起变大变小）还是调整画面在框内的裁切比例——两者体验不同，建议按前者（缩放 tile 框）实现，语义最直观。

## 5. 新增特性分析：点击放大（焦点模式 / Spotlight）

> 需求：多个视频源时，点击其中一个画面将其放大，其余画面缩到一列；关闭放大后整个网格恢复默认均分布局。**仅分析，未改代码。**

### 5.1 结论

**完全可行，而且比方案甲/乙都简单**——因为它不需要 per-tile 的自由定位，也不需要服务端广播：本质是给 `#video-grid` 加一个"焦点态" class，用 CSS Grid 把被点中的 tile 撑满主区、其余 tile 挤到一列即可。关掉时移除 class，浏览器自动回到 `repeat(auto-fit, minmax(220px,1fr))` 的均分布局——**"恢复默认"是免费的，不用记录原位置**。

### 5.2 现状基础（为什么容易做）

| 有利条件 | 依据 |
|---|---|
| 网格是纯 CSS Grid，布局规则集中在一处 | `classroom.css:158-166` |
| tile 是独立 DOM、id 稳定（`vt-local` / `vt-{peerId}`） | `rtc-engine.js:53-88` |
| `#video-grid` 上已有 `data-topology` 属性可区分引擎 | `classroom-rtc.js:79-80` |
| 目前 tile 上**没有任何 click 绑定**，不存在与现有点击行为冲突 | 全量 grep `classroom/` 无 tile click 监听 |
| 目前**没有**任何 spotlight/focus/放大实现，是全新功能、无历史包袱 | grep `spotlight|focus|放大|pin|maximize` 无命中 |

### 5.3 推荐做法（本地焦点，纯前端）

1. **状态**：在 `#video-grid` 上维护一个焦点 id（如 `data-spotlight="vt-{userId}"` 或 `vt-local`），存在 JS 变量里；这个状态**不进 localStorage**——焦点是临时观看行为，刷新后回默认更自然（若产品要求记忆再加）。
2. **交互**：
   - 给每个 tile 绑 click（在 `RtcTiles.local/remote` 创建时绑，或在 grid 上做事件委托更省事）；点一下 = 设焦点，再点一下同一个 = 取消。
   - 焦点 tile 上放一个明显的"关闭放大"按钮（× / 缩放图标），或支持 Esc 退出——**必须有明确的退出入口**，不能只靠"再点一次"让用户猜。
   - 与 11-16 面板拖动的关系：焦点态作用在 `#video-grid` 内部，与外层 `#video-panel` 的自由定位互不干扰；但要注意 `classroom-panels.js` 在 tile 区域有"捕获阶段置顶"的 pointerdown（`classroom-panels.js:349`），点击 tile 会先把视频面板抬到最上层——这与焦点模式不冲突，反而符合"点谁谁到前面"的直觉。
3. **布局（核心，纯 CSS）**：给 `#video-grid[data-spotlight]` 加一套规则，用 `:has()` 或按 id 选中焦点 tile：
   - 方案之一（grid 区域法）：焦点态改 `grid-template-columns: 1fr 200px`（主区 + 侧栏），焦点 tile `grid-column:1; grid-row:1;` 撑满主区，其余 tile `grid-column:2;` 并让它们按行排列形成一列（配合 `grid-auto-flow:row`、固定小高度如 90~110px）。
   - 方案之二（顺序法）：把焦点 tile 用 CSS `order` 提到最前并 `grid-column:1/-1` 占满首行，其余 tile 落到第二行——但这样是"一行大图 + 下面横排小图"，不是用户要的"一列"，故选方案一。
   - 兼容性：`grid-template` + `:has()` 在现代 Chrome/Edge 都支持；若要兼容旧内核，退路是 JS 给焦点 tile 加 `.is-spotlight` class、其余加 `.is-thumb`，用属性选择器代替 `:has()`，效果一样。
4. **动态成员安全**：tile 增删（进房/离房）时焦点 id 可能指向已离开的成员——必须处理：
   - 焦点成员离开 → 自动清除焦点态、回默认网格（`RtcTiles.remove` 里判断，或监听 DOM 移除）。
   - 新成员进来时若已有焦点 → 新 tile 自动归入侧栏小列，不用特殊处理（CSS 规则按"非焦点即侧栏"设计，天然覆盖）。
5. **"关闭放大恢复默认"**：移除焦点 class/属性即可，`#video-grid` 回到原 CSS Grid 均分；不需要保存/还原任何坐标——这是焦点模式比"独立移动缩放"省事的根本原因。

### 5.4 与方案甲/乙的对比

| 维度 | 焦点放大（本节） | 方案甲 本地独立移动缩放 | 方案乙 教师导播全局 |
|---|---|---|---|
| 解决的问题 | "想把某个人看清楚/主讲突出" | "想把画面摆到任意位置" | "全班看同一布局" |
| 服务端改动 | 无 | 无 | 有（WS 信令 + 门禁） |
| 恢复默认 | 移除 class，自动 | 需清 localStorage 与内联样式 | 需广播复位 |
| 动态成员处理 | 焦点者离开则自动退出 | 位置记忆的增删管理 | 还要同步给全班 |
| 工作量 | 小（CSS + 少量 JS） | 中（复用 panels 范式） | 大 |

**三者不冲突，可叠加**：焦点放大是网格内的"观看模式"，独立移动缩放是"摆放偏好"，导播是"全局同步"。建议实现顺序：焦点放大（最快见效、最贴近"看清主讲"诉求）→ 方案甲 → 必要时方案乙。

### 5.5 需要注意的点
- **单人课堂**：只有 1 个视频源时点击放大的意义不大，建议 `tile 数 < 2` 时不启用焦点交互（避免点了没反应或放大后一片空白）。
- **本地画面（vt-local）**：点自己放大通常没意义，可允许但不默认推荐；焦点侧栏至少要留一个名额，别让"其余画面"为零。
- **侧栏可读性**：缩到一列后每个 tile 很小，姓名字条（`.vt-label`）可能被挤没，建议 CSS 里给缩略 tile 缩小字号或只显示头像。
- **与录制/回放的关系**：焦点是纯本地观看态，不影响 11-17 分析的录制流（录的是教师上行流），回放里不会出现"被放大"的效果——这是合理的，回放是另一套呈现。
- **`data-topology`**：焦点 CSS 若要区分 mesh/SDK 两种引擎的画面（比如 SDK 模式布局略有差异），可用 `#video-grid[data-topology]` 属性选择器精确限定。
