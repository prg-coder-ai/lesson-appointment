| `my-classroom-core.js:184` | **IIFE 内局部函数**，经 `window.MyClassroomCore` / `window.ClassroomEntry` 暴露 | depth 2 | **不删**，只改函数体（属"改 4 个跳转函数"之一） |

⚠️ 注意第 2 和第 4 行的**赋值语句行号远小于函数体行号**（`:12` vs `:382`、`:293` vs `:592`）。这是本工程最危险的删除姿势，见 §1.5。

### 1.3 中间态谁生效（按实际 script 加载顺序）

4 处待删函数体**逐字等价**（同 3 行：`if(!scheduleId) alert` + `pageUrl('classroom.html',{scheduleId})` + 相对兜底），所以无论谁生效，产物与行为都一样。

| 页面 | 中间态生效者 | 说明 |
|---|---|---|
| `admin.html` | `admin-booking`（:626 最后加载） | 等价 |
| `teacher.html` | `student-bookingBrowserCards`（:556，**教师端也加载它**） | 等价 |
| `student.html` | `student-bookingBrowserCards`（:696） | 等价 |
| `classroom-ops.html` | **`api.js`**（本页无业务定义点） | **提前受益**：原先该页 `enterClassroom` 未定义 |
| `platform_admin.html` | **`api.js`**（原先完全未定义） | **提前受益** |

→ **结论：拆开安全**，没有页面会丢入口、不会 ReferenceError。C1 可单独上线。

⚠️ 但中间态会"**假绿**"：点击正常，走的却是旧实现。所以 C1 的自检**不许看点按钮的行为**，只能看静态指纹（§3）。

### 1.4 `keyOf()` 收紧是否会造成回退 —— 已实测排除

构造器 `keyOf()` 要求 `^[A-Za-z0-9_-]{4,64}(~\d{1,2})?$`，旧实现只判非空。

实测（`lesson_appointment.course_schedule`，`schedule_id varchar(36)`）：
- 实际值全为 **32 位无连字符 hex**（如 `20c84f569f654a9898cfc6f129a5f5bd`）
- 按上述正则全表校验：**不合规 0 条**

→ 现有数据无风险。纪律保留：上线前抽 20 条看一眼，防未来脏数据。

### 1.5 最危险的删除姿势（务必看懂这一条）

`admin-booking.js:12` 是 `window.enterClassroom = enterClassroom;`，函数体在 `:382`。**若只删 `:382` 保留 `:12`**：

- `enterClassroom` 裸标识符 → 解析到全局 `window.enterClassroom`；api.js 已加载则自赋值、无害
- **但 api.js 未加载、或构造段只在 IIFE 内声明没挂 window** → `ReferenceError` 在 **第 12 行**抛出
- **后果：该文件从第 12 行起停止执行**，其后的 `window.renderBookingCards` / `cancelBooking` / `validBooking` / `deleteBookingByFrozen` **全部不再注册** → 管理端预定审核整块消失

这比"链接不对"严重一个量级，且 `node --check` 抓不到（语法合法）。**四个文件都有这个配对关系**：`admin-schedule:2635↔2641`、`admin-booking:382↔12`、`teacher-course:457↔463`、`student-booking:592↔293`。

**铁律：函数体与赋值语句必须同文件、同 commit 成对删除。**

### C1 · 新增构造器 + 守卫脚本（**三者必须同一个 commit**）

| 文件 | 动作 |
|---|---|
| `frontend/js/public/api.js` | 在 `:846` `window.pageUrl = pageUrl;` **之后**插入 `// [CLS-LINK-BEGIN]` … `// [CLS-LINK-END]` 包裹的 IIFE（内含 `window.ClassroomLink` + `window.enterClassroom`） |

```

grep -c "CLS-LINK-" frontend/js/public/api.js                    # = 2
git diff --stat                                                  # 恰 3 个文件
```

**红线**
- 新增段**必须**自带 IIFE（api.js 是扁平脚本，顶层 35 条声明全带缩进也是 depth 0）
- **严禁整体 IIFE 化 api.js**（40+ 文件直接调其全局函数，症状是全站 `getToken is not defined`）
- `window.enterClassroom = function(key){...}` 用**属性赋值**，不要在顶层写 `function enterClassroom`（会与 4 个业务文件构成静默覆盖）

## 4. 施工序列的两处纪律

**① 顺序不可反（D1）**：C1 → C2/C3/C4/C5/C6 → C7。
反向（先删后加）会让 `classroom-ops.html` / `platform_admin.html` 短暂进入"`enterClassroom` 无定义"状态。

**② C2~C6 可并行开发，但建议串行合并**：每步的 `--check` + grep 指纹都是秒级，串行合并换来的二分定位能力远值这个成本。

**③ 如果只允许交付最小可上线子集**：保留 **C1 + C2 + C3 + C4**，砍 C5、C6，守卫只启用 block 版。
- 覆盖三角色"进入课堂"的全部主路径（工作台卡片、我的课堂、课前准备、回放）
- 砍 C5 代价≈0：旧链接格式在同域下依然可用，只是不认未来新格式
- 砍 C6 要接受一个后果：`insecure` 闸门缺席，"http 内网打开运营台 → 生成私网链接发进通知"的口子仍在（存量缺陷，非本次引入）

## 7. 回滚

| 场景 | 动作 |
|---|---|
| 运营台出问题 | `git revert <C6>`（影响仅 `classroom-ops.html`） |
| 入口跳转出问题 | `git revert C2 C3 C4`（保留 C1 构造器，它是纯新增、无调用方不算坏） |
| 构造器本身有问题 | `git revert C1`，注意**必须同时退 C2~C6**，否则那些文件调用了不存在的 API |
| App 侧出问题 | 先确认是否跑过 `sync.js`：跑过则回滚 frontend 后**必须重跑 sync+build**，否则 www 留新副本与源码分叉 |
| 不做的事 | 不用 `dist` 双版本切换（`dist` 被 gitignore，切版本要动 nginx，成本远高于 revert） |

**灰度**：不做。纯静态资源无租户级灰度手段；唯一可行的角色开关会违背"只收敛入口、不改行为"的目标并留下长期分叉。失败模式本也是降级的（链接不对 / 按钮失效），不会白屏或 500。
