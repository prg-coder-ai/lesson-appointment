## 二、本轮落地（全部已通过守卫验证）

### 1. 预约状态文案：参数化，而不是"统一"

这是本轮**最需要判断力**的一处。两端文案确实不同：

| 状态 | 小程序（default 档案） | Web（web 档案） |
|---|---|---|
| `booking` | 待确认 | **预定待确认** |
| `booked` | 已确认 | **预定已确认** |
| `rej-booking` | 已拒绝 | **已拒绝预订** |
| `ended` | 已失效 | **已删除** |
| `waiting` / `canceling` / `cancelled` / `completed` / `rej-canceling` | 候补 / 取消待确认 / 已取消 / 已完成 / 已拒绝取消 | 同左 |

Web「预定」用字是 2026-10-06 拍板保留的（小程序内统一用「预订」，Web/API 维持「预定」）。
**若按字面意思"消除重复"把两端合成一套，就是把已拍板的差异单方面回退——用户可见的回退。**

因此做法是 `shared/domain/bookingState.js` 引入双档案 + 参数化：

```js
const STATUS_TEXT_PROFILES = {
  default: { booking: '待确认',    booked: '已确认',    rejBooking: '已拒绝',   ended: '已失效', ... },
  web:     { booking: '预定待确认', booked: '预定已确认', rejBooking: '已拒绝预订', ended: '已删除', ... }
};
export function bookingStatusText(status, opts) {
  const profile = (opts && opts.profile === 'web') ? STATUS_TEXT_PROFILES.web : STATUS_TEXT_PROFILES.default;
  ...
}
```

Web 侧 `checkStatus_booking(status)` 改为 `bookingStatusText(status, { profile: 'web' })` + 内联降级快照。
**两端界面文案逐字不变**，重复的是代码而不是产品口径。

## 四、新建的守卫（防回归）

新增 `tools/check-endpoints-refs.mjs`，三项检查：

| 检查 | 内容 |
|---|---|
| ① 引用完整性 | 两端所有 `ENDPOINTS.X` / 本地别名 `EP.X` 引用都必须在权威源中定义（未定义 → `undefined` 拼进 URL → 畸形请求） |
| ② 硬编码防回归 | 代码里不得再出现引号紧邻的 `/api/v1/...` 字面量（注释里的说明不误报） |

守卫全绿只有在守卫被证明会红时才有意义；否则它可能只是恰好没扫到。

`package.json` 新增：`npm run check:endpoints` / `npm run test:endpoints-guard`。

## 五、三个必须记住的坑（本轮亲身踩到）

### 坑 1：`path.join` 在 Windows 产反斜杠 → 守卫**空跑假通过**

守卫里用 `path.join('frontend','js','x.js')` 造路径清单，与 `relPath`（正斜杠）比对恒 `false`。
后果是**两件事同时静默失效**：生成产物没被跳过、③ 号检查压根没执行却报"✅ 一致"。

修法：清单**一律写 POSIX 正斜杠**，并加一道"必须真校验过 N 份"的断言——否则这类失效永远无声。

### 坑 2：守卫的**诊断顺序**会误导根因

快照漂移时忘了计数，报告写成"只校验了 1/2 份（属脚本路径问题）"而不是"快照不一致"。
退出码是对的，**但归因错会把人引向错误方向**。报告顺序改为：业务可解释的问题（文件缺失/内容不一致）优先，工具自身问题（计数不足）最后。

### 坑 3：vm 源码切片测试会被"外层新增声明"打断

`msg-category-combo-test.js` 从 `messages-inbox.js` 第 914 行起切片，而本轮在第 30 行新增了 `const EP = ...`。
切片内引用 `EP` 但切片不含声明 → VM 里是未声明标识符 → ReferenceError → 该用例变红。

修法不是"把声明挪进切片"（试过：切片从第 27 行起会把 900 行无关顶层语句卷进来，触发新的 DOM 垫片缺失），
而是**把源码里那一行原样补在切片前 + 断言该行仍存在**（形状变了就 `exit 2`，不静默降级）。

顺带把该测试原先 `mreq.get(url)` **完全忽略 url** 的盲点，改成**字面量 URL 护栏**（断言请求命中的正是 `/api/v1/message-categories/tree`）。

## 六、另外发现并修复：仓库卫生

`tests/miniprogram-itest/_sut_login/` 是 `login-flow.mjs` 每次运行用 `cpSync` 从 `miniprogram/{core,shared}`
重新生成的"被测系统"暂存目录，**却有 26 个文件被提交进 git**。

证据链：
- `login-flow.mjs:14-15` 用 `cpSync` 生成 `_sut_login`
- `logic.mjs:13-14` 用同样方式生成 `_sut`，而 **`.gitignore:90` 已忽略 `_sut`** —— 说明项目本就认同这类目录不该入库
- 只有后加的 `_sut_login` 漏配 → 每次跑测试产生 26 个文件的 diff 噪声（本次工作就撞到了）

处理：`.gitignore` 的 `_sut` 改为 **`_sut*`**（避免以后再出 `_sut_xxx` 变体重演），
并 `git rm -r --cached` 移除索引中的 26 个文件（**工作区文件保留**，测试每次会重新生成；实测 `login-flow` 仍 12/12 通过）。
