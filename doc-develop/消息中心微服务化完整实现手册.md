# 消息中心微服务化完整实现手册

> 本文档整合消息中心独立微服务的架构设计、交互流程、接口规范、可复用代码、部署方案与落地步骤，单文档一站式查阅，基于 Spring Boot \+ Spring Cloud 技术栈实现。

## 一、架构总览与职责边界

### 1\.1 核心定位

消息中心作为全校统一的独立消息中台（Notification Service），与课表预约、教学管理、学生管理等业务系统完全解耦，独立部署、独立扩缩容、独立迭代，负责全渠道消息投递与全生命周期管理。

### 1\.2 职责划分

|角色|职责范围|
|---|---|
|**消息中心微服务**|全渠道消息投递（WebSocket站内推送、离线补偿、批量广播）；消息全生命周期管理（存储、分类、已读/收藏/删除、归档）；推送通道运维（连接管理、流量控制、优先级调度、投递追踪）；基础能力（模板、敏感词过滤、AES加密存储、统计审计）；对外提供标准化接口|
|**上游业务系统**|业务规则判断（触发时机、接收对象、内容组装）；按约定格式组装消息参数；调用消息中心接口或投递业务事件；接收消息状态回调并更新自身业务单据|

> 边界原则：业务系统不感知推送技术细节，消息中心不感知业务逻辑。

## 二、四种核心交互模式

### 2\.1 同步API调用模式

- **适用场景**：单条精准发送、高可靠业务通知（如预约成功、请假提交回执）

- **交互流程**：业务系统在业务流程节点同步调用消息中心发送接口 → 消息中心接收后立即落库 → 异步执行推送 → 同步返回消息ID

- **特点**：调用后立即返回，投递异步执行，业务线程不阻塞

### 2\.2 异步事件驱动模式

- **适用场景**：全年级批量通知、高并发触发场景（如排期更新、作业发布）

- **交互流程**：业务系统发布业务事件到消息队列 → 消息中心订阅事件 → 自动转换成消息投递

- **特点**：完全解耦，削峰填谷，支持批量消费，业务系统发完事件即可继续执行

### 2\.3 状态回调模式

- **适用场景**：需要确认用户已读的重要通知、请假审批已读回执、作业查看追踪

- **交互流程**：消息中心状态变更（投递成功/失败、用户已读、用户点击）→ 异步调用业务系统回调地址 → 业务系统更新业务单据状态

- **特点**：异步非阻塞，支持失败重试、幂等校验

### 2\.4 前端直连模式

- **适用场景**：实时消息接收、未读数实时更新、多端状态同步

- **交互流程**：前端浏览器直接通过网关与消息中心建立WebSocket连接 → 接收实时推送、同步消息状态

- **特点**：消息流不占用业务系统资源，业务系统无感知

## 三、标准化接口协议

### 3\.1 消息发送接口（消息中心提供）

- **接口地址**：`POST /api/internal/v1/messages/send`

- **鉴权方式**：服务间内部API密钥 \+ 请求签名

- **请求体格式**：

```JSON
{
  "bizCode": "APPOINTMENT_CONFIRM",
  "receiverType": "USER_ID",
  "receiverIds": ["1001", "1002"],
  "messageType": "SYSTEM_NOTICE",
  "priority": "NORMAL",
  "title": "预约成功通知",
  "content": "您的课程预约已确认，请准时参加。",
  "jumpUrl": "/appointment/detail/12345",
  "bizId": "appointment_12345",
  "sender": "课程预约系统",
  "callbackUrl": "https://appointment-service/api/callback/message-status"
}
```

### 3\.2 批量发送接口

- **接口地址**：`POST /api/internal/v1/messages/batch`

- **扩展参数**：支持按用户角色、年级、班级等维度群发，`receiverType` 可选 `ROLE` / `GRADE` / `ALL`

### 3\.3 事件驱动契约（队列交互）

标准事件格式，所有业务系统遵循同一规范：

```JSON
{
  "eventId": "evt_8f3a2c1e",
  "eventType": "APPOINTMENT_BOOKED",
  "source": "appointment-service",
  "timestamp": 1710000000000,
  "data": {
    "userId": "1001",
    "bizId": "appointment_12345",
    "title": "预约成功通知",
    "content": "您的课程预约已确认，请准时参加。",
    "jumpUrl": "/appointment/detail/12345"
  }
}
```

### 3\.4 状态回调协议（消息中心 → 业务系统）

- **回调时机**：投递成功、投递失败、用户已读、用户点击跳转

- **重试策略**：失败后指数退避重试，最多3次

- **回调格式**：

```JSON
{
  "messageId": "msg_7d2e9f0a",
  "bizId": "appointment_12345",
  "bizCode": "APPOINTMENT_CONFIRM",
  "status": "READ",
  "userId": "1001",
  "timestamp": 1710000500000
}
```

#### 4\.1\.3 消息发送核心Service

```Java
package com.notification.service;

import com.notification.dto.MessageSendDTO;
import com.notification.entity.Message;
import com.notification.entity.UserMessageInbox;
import com.notification.mapper.MessageMapper;
import com.notification.mapper.UserMessageInboxMapper;
import com.notification.util.AesGcmCryptoUtil;
import lombok.RequiredArgsConstructor;
import org.springframework.data.redis.core.StringRedisTemplate;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

import java.time.LocalDateTime;
import java.util.List;
import java.util.UUID;

@Service
@RequiredArgsConstructor
public class MessageService {

    private final MessageMapper messageMapper;
    private final UserMessageInboxMapper inboxMapper;
    private final StringRedisTemplate redisTemplate;
    private final WebSocketPushService webSocketPushService;

    @Value("${app.aes-gcm.secret}")
    private String aesSecret;

    @Transactional(rollbackFor = Exception.class)
    public String sendMessage(MessageSendDTO dto) {
        // 1. 消息持久化（内容加密存储）
        Message message = new Message();
        String messageId = "msg_" + UUID.randomUUID().toString().replace("-", "").substring(0, 16);
        message.setMessageId(messageId);
        message.setBizCode(dto.getBizCode());
        message.setBizId(dto.getBizId());
        message.setSender(dto.getSender());
        message.setMessageType(dto.getMessageType());
        message.setPriority(dto.getPriority());
        message.setTitle(AesGcmCryptoUtil.encrypt(dto.getTitle(), aesSecret));
        message.setContent(AesGcmCryptoUtil.encrypt(dto.getContent(), aesSecret));
        message.setJumpUrl(dto.getJumpUrl());
        message.setCallbackUrl(dto.getCallbackUrl());
        message.setIsBroadcast(0);
        message.setSendTime(LocalDateTime.now());
        message.setCreateTime(LocalDateTime.now());
        message.setUpdateTime(LocalDateTime.now());
        messageMapper.insert(message);

        // 2. 写入用户收件箱索引
        List<String> receiverIds = dto.getReceiverIds();
        for (String userId : receiverIds) {
            UserMessageInbox inbox = new UserMessageInbox();
            inbox.setUserId(userId);
            inbox.setMessageId(messageId);
            inbox.setIsRead(0);
            inbox.setIsStarred(0);
            inbox.setIsDeleted(0);
            inbox.setCreatedAt(LocalDateTime.now());
            inboxMapper.insert(inbox);

            // 3. 未读数+1
            redisTemplate.opsForValue().increment("unread:count:" + userId);
        }

        // 4. 异步WebSocket推送
        webSocketPushService.pushToUsers(receiverIds, message);

        return messageId;
    }
}
```

```Java
package com.notification.service;

import lombok.RequiredArgsConstructor;
import org.springframework.messaging.simp.SimpMessagingTemplate;
import org.springframework.stereotype.Service;

import java.util.List;

@Service
@RequiredArgsConstructor
public class WebSocketPushService {

    private final SimpMessagingTemplate messagingTemplate;

    public void pushToUsers(List<String> userIds, Object message) {
        for (String userId : userIds) {
            messagingTemplate.convertAndSendToUser(userId, "/queue/notifications", message);

    }

    public void broadcast(Object message) {
        messagingTemplate.convertAndSend("/topic/notifications", message);
    }
```

```Java
package com.notification.consumer;

import com.alibaba.fastjson.JSON;
import com.notification.dto.MessageSendDTO;
import com.notification.event.BusinessEvent;

import org.springframework.stereotype.Component;

import java.util.Collections;

@Component
@RequiredArgsConstructor
public class BusinessEventConsumer implements StreamListener<String, ObjectRecord<String, String>> {

    private final MessageService messageService;

    @Override
    public void onMessage(ObjectRecord<String, String> record) {
        String value = record.getValue();
        BusinessEvent event = JSON.parseObject(value, BusinessEvent.class);
        
        // 事件转消息
        MessageSendDTO dto = new MessageSendDTO();
        dto.setBizCode(event.getEventType());
        dto.setReceiverType("USER_ID");
        dto.setReceiverIds(Collections.singletonList(event.getData().getUserId()));
        dto.setMessageType("SYSTEM_NOTICE");
        dto.setPriority("NORMAL");
        dto.setTitle(event.getData().getTitle());
        dto.setContent(event.getData().getContent());
        dto.setJumpUrl(event.getData().getJumpUrl());
        dto.setBizId(event.getData().getBizId());
        dto.setSender(event.getSource());
        
        messageService.sendMessage(dto);
    }
}
```

```JavaScript
// 建立WebSocket连接
export function connectNotification(userId, token) {
    const socket = new SockJS('/ws/notification');
    stompClient = Stomp.over(socket);

            unreadCount = parseInt(message.body);

        });
    });
}
```

## 六、平滑演进落地步骤

### 第一步：接口抽象与抽取

1. 将现有消息中心模块从业务代码中抽离为独立Maven模块，定义标准接口

2. 业务系统通过接口调用，不直接依赖内部实现，为拆分做准备

3. 梳理所有消息触发点，统一收口到接口层

### 第二步：独立部署，双轨运行

1. 将消息模块打包为独立Spring Boot应用，独立部署

2. 业务系统同时保留本地调用和远程调用两种方式，通过配置切换

3. 先将非核心消息切到独立服务，验证稳定性后逐步全量切换

4. 验证数据一致性、推送可靠性、接口兼容性

### 第三步：完整解耦，事件驱动

1. 下线业务系统本地消息模块，全部切换为远程调用

2. 引入事件总线，将高并发、批量场景切换为事件驱动模式

3. 完善监控、告警、链路追踪，完成完整微服务治理

4. 接入更多业务系统，沉淀统一消息中台能力

## 七、生产级注意事项

1. **幂等性保障**：所有发送接口、回调接口都必须实现幂等，通过消息ID、业务ID去重，避免重复发送、重复回调

2. **一致性保证**：消息发送与业务提交保持最终一致，采用“业务事务提交后再发消息”\+“失败重试”模式，避免业务回滚但消息已发

3. **限流与熔断**：对每个业务系统设置发送量阈值，避免单一业务突增流量打垮消息中心；调用端配置熔断降级，消息中心不可用时不影响主业务流程

4. **安全隔离**：内部接口不对外网开放，服务间调用采用内部鉴权；敏感消息内容加密传输，密钥独立管理

5. **链路追踪**：接入SkyWalking等链路追踪工具，透传traceId，实现从业务触发到消息投递的全链路可追踪

6. **性能优化**：用户收件箱按用户ID分表，热点未读数缓存到Redis；批量消息采用分片异步处理，避免长事务

7. **高可用部署**：消息中心多节点部署，无状态水平扩展；Redis集群、MySQL主从保证数据层高可用
