## 一、架构概述

### 1.1 服务定位

**classroom-service** 是独立部署的课堂业务域微服务，与预约系统（booking-api）数据库完全隔离，通过契约接口对接。定位与 `message-service` 一致：独立 Spring Boot 应用、独立端口、独立 schema、共享 JWT 密钥域。

```
┌─────────────────────────────────────────────────────────┐
│                    微信云托管                            │
│                                                         │
│  ┌──────────┐     MQ/REST      ┌──────────────────┐    │
│  │ booking  │ ──────────────▶  │ classroom-service │    │
│  │   -api   │ ◀──────────────  │  (port 8092)      │    │
│  │(port 8081)│   回调(attendance) │  schema: classroom  │    │
│  └──────────┘                  └──────────────────┘    │
│       │                              │                   │
│       │                              │ Redis(在线状态)    │
│       │                              │ OSS(讲稿/作品/录制) │
│       │                              │ WebSocket(信令)    │
│       │                              │ 第三方RTC(媒体)    │
│  ┌──────────┐                                           │
│  │ message  │  (port 8090, schema: message_center)     │
│  │ -service │                                           │
│  └──────────┘                                           │
└─────────────────────────────────────────────────────────┘
```

### 1.2 与 message-service 的架构对比

| 维度 | message-service | classroom-service |
|------|----------------|-------------------|
| 包名 | `com.messagecenter` | `com.classroom` |
| 端口 | 8090 | **8092** |
| schema | `message_center` | `classroom` |
| 共享密钥 | JWT_SECRET / AES_KEY / HMAC_KEY | 同左 |
| 鉴权方式 | MessageAuthInterceptor（Bearer JWT） | 同模式 |
| 部署 | `cloudBased/message-service/` | `cloudBased/classroom-service/` |
| MQ | 无 | **有**（消费排期事件） |
| WebSocket | SSE（单向推送） | **WS**（双向信令：白板/心跳/点名） |
| Redis | 无 | **有**（在线状态/房间路由/幂等去重） |
| 对象存储 | 无 | **有**（讲稿/作品/录制文件） |
| 定时任务 | 无 | **有**（对账/自动开课/录制清理） |
| 回调主系统 | 无 | **有**（出勤/告警/对账回调） |

### 1.3 技术选型

| 组件 | 选型 | 说明 |
|------|------|------|
| 服务框架 | Spring Boot 3.3.5 + **Java 17** | 与 booking-api/message-service 一致（需求文档建议 Java 21，但对齐项目实际用 17，降低联调成本） |
| ORM | MyBatis Plus 3.5.7 | 与既有服务一致 |
| 数据库 | MySQL 8.x | 独立 schema `classroom` |
| 缓存 | Redis | 在线状态、房间路由、幂等去重、排期快照缓存 |
| 消息队列 | RabbitMQ（主通道）/ REST（降级） | 排期事件消费；云托管无 MQ 时降级为 REST 同步推送 |
| 实时通信 | WebSocket（Spring WebSocket） | 白板信令、心跳、点名广播、成员状态 |
| 对象存储 | OSS/COS | 讲稿、学生作品、录制文件 |
| 媒体层 | 第三方 RTC（默认） | 经媒体抽象层接入，可切换自建 SFU |
| 安全 | JWT（共享密钥）+ HMAC（服务间） | 与 message-service 同模式 |
| API 文档 | SpringDoc OpenAPI 2.6.0 | 与既有服务一致 |

## 四、核心状态机

### 4.1 课堂生命周期（需求 6.2）

```
SCHEDULED ──(距startTime≤10min)──▶ READY ──(开始上课)──▶ LIVE ──(下课/到点)──▶ CLOSED
    │                                  │           │
    └────────(cancelled事件)──────────▶└──────────▶└──▶ CANCELLED
```

实现：`ClassroomService.transitionStatus(scheduleId, from, to)`，带状态守卫（LIVE 不接受改期）。

### 4.2 签到状态机（需求 6.3）

```
ABSENT ──(首次进入)──▶ PRESENT/LATE ──(离开)──▶ LEFT ──(重连)──▶ REJOINED
```

迟到判定：`checkInAt > startTime + 5min`（可配置 `classroom.late-grace-minutes=5`）。

### 4.3 成员在线状态机（需求 6.4）

```
ONLINE ──(心跳丢失15-60s)──▶ IDLE ──(丢失>60s/主动断开)──▶ OFFLINE
```

实现：`OnlineStateManager`（Redis），心跳间隔 15 秒，IDLE 宽限 15-60 秒，>60 秒判 OFFLINE。

## 六、对接契约实现

### 6.1 事件消费链路

```
预约系统 ──(MQ/REST)──▶ ScheduleEventController
                            │
                            ▼
                   EventIdempotentGuard (Redis SETNX eventId, TTL 7天)
                            │ 幂等通过
                            ▼
                   ScheduleEventConsumer
                            │
                   ┌────────┼────────┐
                   ▼        ▼        ▼
              created   updated   cancelled
                   │        │        │
                   ▼        ▼        ▼
           ClassroomService.create / update / cancel
                            │
                            ▼
                   ReconcileLog 写入（SUCCESS/SKIPPED/FAILED）
```

### 6.2 降级策略

| 场景 | 主方案 | 降级方案 |
|------|--------|---------|
| MQ 不可用 | ScheduleEventConsumer 消费 MQ | 预约系统直接 POST `/api/v1/schedules/events`（REST） |
| Redis 不可用 | EventIdempotentGuard 用 Redis 去重 | 降级用 DB 唯一索引（reconcile_log.event_id）去重 |
| 预约系统不可用 | CallbackService 回调 | 写入待发送队列，恢复后补偿发送 |
| 第三方 RTC 故障 | MediaService 走 RTC | 切换备用厂商或标记降级（仅音频+白板） |

### 6.3 对账闭环

```
每日 01:00 ──▶ DailyReconcileTask
                  │
                  ▼

                  │
          ┌───────┼───────┐
          ▼       ▼       ▼
      拉取近7日  比对两侧  生成差异
      排期状态   课堂状态  补偿任务
                  │
```

## 九、关键实现要点

### 9.1 幂等去重

`EventIdempotentGuard`：
```java
public boolean tryAcquire(String eventId) {
    // Redis SETNX eventId 1 EX 604800 (7天TTL)
    return redisTemplate.opsForValue().setIfAbsent(
        "idem:" + eventId, "1", Duration.ofDays(7));
}
```
降级：`reconcile_log` 表 `event_id` 唯一索引插入冲突即重复。

### 9.2 课堂状态守卫

```java
public void transitionStatus(String scheduleId, ClassroomStatus from, ClassroomStatus to) {
    int affected = classroomMapper.updateStatus(scheduleId, from.name(), to.name());
    if (affected == 0) {
        throw new ClassroomBizException(40901, "状态冲突：当前状态非 " + from);
    }
}
```

### 9.3 有效时长核算

```java
// 签到时记录 checkInAt，离开时记录 checkOutAt
// 有效时长 = sum(各段在线时长) - 抖动重连(60秒内不计)
// 封顶 = 课时时长 duration
int effective = Math.min(
    onlineSegments.stream().mapToInt(Segment::minutes).sum(),
    classroom.getDuration()
);
```
