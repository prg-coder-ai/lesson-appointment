## 修复：登录后不跳转 + 仍有 wechat-login 调用
- 现象（开发者工具）：密码登录成功却没跳到对应首页，且登录页网络里持续出现 `/auth/wechat-login` 请求。
- 根因：
  1. `request.js` 对 `tokenOnly`（公开/匿名接口）请求遇 401 仍 `clearSession()`+`onAuthFail()` 跳登录页；`login()` 成功后立即 `await loadTermMap()`（term/map），若后端 term/map 返回 401（未部署我们之前 401 修复的旧后端），会把刚写好的登录态清掉并 reLaunch 回登录页 → "登录后没跳转/跳回登录"。
  2. `login()` 把术语加载 `await` 在主流程且无 try/catch，任一接口失败即中断整个登录。
  3. `login.js onLoad` 调 `tryWechatAutoLogin()` → `wechatSilentLogin()` → `/auth/wechat-login`，而用户明确暂不处理微信登录。
- 修复（4 处）：
  1. `core/request.js`：tokenOnly 请求遇 401 不再清登录态/不跳登录页（`if (status === 401 && !opts.tokenOnly)`），仅非 tokenOnly 的真实鉴权 401 才踢人。
  2. `core/auth.js login()`：loadTermMap / syncIndustryFromTenant 包独立 try/catch 静默，失败绝不阻断登录成功与跳转。
  3. `core/term.js`：term/map 保留 `tokenOnly`（公开接口，由修复1免疫 401）；tenant/industry 去掉 tokenOnly（带 Bearer，需租户上下文）。
  4. `pages/login/login.js`：移除 onLoad 的 `tryWechatAutoLogin()` 自动调用与 onLogin 里的 `bindWechat()` 调用；`login.wxml` 用 `wx:if="{{false}}"` 临时隐藏"允许微信登录"勾选框（恢复只需删该条件）。
- 验证：新增 `tests/miniprogram-itest/login-flow.mjs`（12/0 PASS），覆盖 term/map 200 与 401 两种场景——均确认 login 成功、登录态保留、goHome→/package-student/home/home、不发 wechat-login；重跑 `logic.mjs` 41/0 无回归。
- 结论：无论后端 term/map 是否已部署 401 修复，前端这版都不再被 401 踢回登录页（双保险）。仍建议在开发者工具对"已部署新后端"联调确认 term/map 免登录 200 与首页渲染。
