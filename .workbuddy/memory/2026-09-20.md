## admin.html「系统配置」菜单不显示 —— 根因与修复

**症状**：租户管理员 admin.html 侧栏里，上次新增的「系统配置」菜单组（含退改规则 / 通知规则）在页面上看不见。

**排除项（都有证据）**
- 菜单是**静态 HTML**：`<div class="menu-item" key="refund_rule">` 直接写在 `admin.html:152-162`，切换靠 `loadAdminPageContent(key)` 的 `switch`；全仓 grep 无任何 JS 按角色/配置隐藏菜单（唯一被 JS 操的只有 `menu-test-data`）。
- 15 个 `key` 与 15 个 `case` 分支**一一对应**，`refund_rule` / `notify_rule` / `sensitive_words` 分支都在。
- `dist/admin.html` 与 `dist/css/admin.css` 都含该菜单，CSS 规则与源文件一致（dist 是压缩版，非旧版）。
→ 与 JS、权限、构建产物全部无关。

**根因（CSS 裁切，不是"没渲染"）**
- `.layout-container { height: calc(100vh - 60px); overflow: hidden }`（admin.css:60，header 正好 60px）
- `.sidebar { width:220px; height:100%; flex-shrink:0 }` —— **没有 `overflow-y`**
- 于是侧栏高度 = 容器高度，菜单内容超出部分**直接溢出到容器外被裁掉，且无处可滚**（右侧 `.content-wrapper` 有 `overflow:auto`，侧栏没有，容易被忽略）。
- 量化：菜单总高 ≈ 1040px（组标题 38 + 项 41 + 组间距 20，6 组标题 / 15 项）。视口 CSS 高度低于 ~1100px 就开始裁；1080p + 125% 缩放（视口 864px）、1366×768 更矮时，「系统配置」整组（181px）必然消失 —— 正好是最后新增的那组。

**修复**
- `frontend/css/admin.css`：`.sidebar` 加 `overflow-y: auto; overscroll-behavior: contain;`（桌面端）。
- 移动端断点 `@media (max-width:768px)` 内 `.sidebar` 补 `overflow-y: hidden`，还原「横向平铺滑动」语义（桌面端那条是全局的，会漏进去）。
- **顺带修两处结构问题**（用一次性 node 脚本按锚点替换，每步带匹配次数断言，避免多次 Edit 静默丢改动）：
  1. `admin.html` 的「课程管理」组漏了 `</div>`，导致「系统维护」被嵌套进「课程管理」（多一层缩进 + 多 20px 边距）；
  2. 「敏感词管理」仍在「消息中心」组下 —— 上一轮只加了退改/通知两个入口，这一项没搬，现移到「系统配置」组首位（组内顺序：敏感词管理 / 退改规则 / 通知规则）。

**验证**
- aside 内 div 开合 **29/29 配平**；dist 内逐组解析归属正确（`系统配置 -> [sensitive_words, refund_rule, notify_rule]`）。
- `dist/css/admin.css` 压缩形态含 `overflow-y:auto`；dist 已重建。
- 后端未改，未跑编译。

**待用户拍板**：`student.css:93` / `teacher.css:55` 是**同样的写法**（`overflow:hidden` + `.sidebar` 无滚动），目前菜单项少（6~8 项）没溢出，但属同一隐患，是否一并加保险。

## 退改规则「新增」弹窗课程下拉补全（12:15）

**需求**：新增课程退改规则时，课程下拉要列出**所有课程**，且**第一项为「适用全部课程的缺省设置」**。

**现状问题（全在前端 `admin-refund-rule.js`，后端无问题）**
- 后端 `RefundRuleService.listCourseOptions()` 已用 `requireTenantContext()` 返回**当前租户全部课程**（按 createTime 倒序），前端 `refundRuleCourseOptions` 拿到的已是全量。
- 但前端两处挡住了：
  1. 下拉生成（原 279-285 行）把已配置课程 `configuredIds` 过滤掉 → 列表不全；且**缺第一项**「适用全部课程」。
  2. `collectRefundRuleForm` 里 `if (!courseId)` 对空串报「请选择要配置的课程」——而「适用全部课程」正是空串（`courseId=''` = 租户默认规则），会被误拦。

**修复**
- 下拉生成：第一项 `<option value="">适用全部课程（缺省设置）</option>`，之后 `refundRuleCourseOptions` **全量**列出（去掉 `configuredIds` 过滤）。
- 校验：移除 `courseId` 必填拦截（空串合法 = 租户默认；选具体课程 = 课程覆盖，两者均合法）。
- 语义：从「新增课程规则」入口选第一项保存即 upsert 租户默认规则，与列表里「编辑租户默认」入口并存、不冲突。

**验证**：`node --check` 通过；dist 已重建；dist 内「适用全部课程（缺省设置）」=1、`configuredIds`/「所有课程都已单独配置」/「请选择要配置的课程」均 =0。后端未改。
