# 2026-11-16 工作日志

## 08:50 教师开摄像学生无画面 → 根因 P2P 未建连，按 A+C 修订
- **报障**：教师端打开摄像后学生端没有教师图像。取证结论：**不是摄像头问题**，是 mesh P2P 没建起来（默认 provider=native-mesh，`application.properties:106`），学生连教师轨道都没收到。
- **根因四条（代码级）**：① `engine-mesh.js#_onPeerJoin` offer 只由「收到对方 join 且 userId 字典序更大」一方发起，双方须都收到对方 join；② `rtc-peer-join` 不在 `ClassroomPublishGuard.CONTROL_TYPES`，课前学生发的 join 被服务端门禁丢弃（教师是 staff 不受限）；③ `classroom-main.js#setClassStatus` 旧条件 `!wasAllowed && canPublish() && role==='student'` —— 教师课前 canPublish() 就已为 true，`!wasAllowed` 永不成立 → 教师**从不**重发 join；④ 进房时序 `_initModules`（采集+广播 join）排在 `_connectWS` 之前，`sendSignal` 在 WS 未 OPEN 时**静默丢弃**（classroom-ws.js 无队列）。→ 教师字典序较小时双方都不发 offer，永久无画面。
- **排除的误判**：门面发 `cam-state`、main 收 `cam:state` 看似 bug，实为服务端 `ClassroomSignalService:117` 权威转换（收 cam-state → 广播 cam:state），且只影响成员图标/toast，**不控制画面**，勿改。
- **A 落地**（`classroom-main.js#setClassStatus`）：判定改为「状态进入 LIVE」（`s==='LIVE' && prev!=='LIVE'`）而非「能否发布」：学生走 `rejoin()`（课前 join/offer 被门禁丢、轨道被关过，重建最干净）；教师/管理员走 `broadcastJoin()` 只补发 join 不重建引擎（避免重采集打断本地画面），引擎未就绪返回 false 时退回 rejoin。旧「PAUSED 恢复」分支保留兜底。
- **C 落地**：① `_connectWS(ctx)` 提到 `_initModules(ctx)` 之前（main.js `_boot`）；② WS 三通道 onOpen 回调里调 `ClassroomRTC.broadcastJoin()` 补发；③ `classroom-ws.js#sendSignal` 改为**返回 boolean**（未 OPEN 返回 false），供调用方判断是否需要补发。
- **新增机制（A/C 的闭环补丁，防再次死锁）**：`engine-mesh.js` 新增 `broadcastJoin()`；join 消息带 `reply`（对端 join 的应答，防无限回环）与 `rejoin`（我重建过会话，请无条件重建）两个标记；`rejoin` 标记跨补发保留在 `_rejoinMark`（WS 未就绪时补发仍带）；`leave(silent)` —— rejoin 时旧引擎**不广播** `rtc-peer-leave`（否则晚到会把新连接拆掉）；`_buildEngine(cfg, isRejoin)` 透传，`rejoin()` / SDK 回落 `_fallbackToMesh` 都传 true。
- **幂等/竞态加固**：`_onPeerJoin` 对重复 join 判 rejoin/dead(failed|closed|disconnected)/idle(new+stable 且非在途) 才 `_closePeer` 重建，否则忽略；`_createOffer` 加 `_offering[peerId]` 在途锁 + `signalingState!=='stable'` 早退，`_closePeer` 清锁；idle 判定排除 negotiating（createOffer 途中 PC 恰为 new+stable，否则会把在途协商拆掉——这坑是我自己第一版引入的）。
