## student-landing.html?tCode=TENANT_A 不再被踢到 login.html

### 需求
登录链路调通后，用户要求 landing 页正常展示，加载时不得跳到 login.html。

### 根因（代码级证据）
`frontend/js/public/api.js` 是**顶层脚本（无 IIFE 包裹）**，第 61 行 `InitUserInfo();` **解析即执行**；未登录时（第 90-92 行）执行 `window.location.href = pageUrl('login.html')`。而 `student-landing.html` 第 90 行引入了 api.js → 公开落地页一打开就被踢回登录页。
注：与 `utility_request.js` 的 401 守卫（`__PUBLIC_LANDING__`）是**两条独立链路**，前者已修好但仍会漏这条顶层跳转。

### 修复
`api.js` `InitUserInfo()` 内加公开页守卫：
```js
const isPublicPage = !!window.__PUBLIC_LANDING__ || !!window.__PUBLIC_PAGE__;
if (!isPublicPage && !window.location.pathname.endsWith('login.html')) {
  window.location.href = pageUrl('login.html');
}
```
（`student-landing.html` 已在 api.js 之前置 `window.__PUBLIC_LANDING__ = true`，顺序不变即可生效。）

### 踩坑（复查价值高）
`api.js` 第 695-716 行**自带一份 `pageUrl`** 并 `window.pageUrl = pageUrl` **覆盖** `utility_request.js` 的同名全局实现；而 `InitUserInfo` 调用的是本文件 IIFE 内提升的那一份。→ 测试若用「hook `window.pageUrl`」判断是否跳转会**恒假通过**（calls 恒为空）。必须改用 jsdom 真实导航错误 `Not implemented: navigation` 作判据，并加反向用例自证测试有效。

### 验证

1. `type="number"` 必须改 `text`：number 会**静默丢弃**非数字文本，写「满额」直接显示空白；
2. 显示文案进 `value`、数值另存 `data-remaining`，回读优先 `data-remaining`；否则 `Number('满额')` = NaN → `isFinite(NaN)` false → 判「未满」→ **满员时候补按钮反而不出现**（老缺陷换形态）；
3. 口径收敛成顶层三个纯函数并导出：`formatRemainingSites()` / `applyRemainingSitesDisplay(el,n)` / `readRemainingSitesFromDom()`；`renderSchedule`、`isScheduleFull`、`resetScheduleInfoPanel`（切换课程/未选排期时清数值载体与样式，防残留误弹候补）三处统一调用。
4. 「未知」（null/''/非有限数）返回空串而非 0 —— 未选排期时不伪装成真值，也不误阻断预定。
