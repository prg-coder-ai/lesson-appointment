## 审计日志页顶栏"语言"下拉与主界面布局不一致 —— 根因与修复
- 现象：审计日志页顶端的"用户名 / 返回 / 语言"三元素布局与主界面(admin.html)不一致：用户名+返回被挤到中间、语言甩到最右分离。
- 根因：语言切换下拉是"全局自注入"组件 `injectLangSwitch()`（`js/public/termsFunction.js`）。其放置优先级：① 命中 `.fa-sign-out-alt`(退出按钮) → 语言下拉插进 `.header-actions` 内；② 否则 `header.appendChild` 追加成 `.header` 第三个 flex 子元素。主界面有退出按钮(命中①)故正常；审计日志"返回"按钮用 `fa-arrow-left` 而非 `fa-sign-out-alt`，落入②分支 → `.header` 变 3 子元素，`justify-content:space-between` 把右侧操作区分散。非刻意，是无意布局 bug。
- 改动（frontend，已重建 dist）：在 `injectLangSwitch` 的 fallback 增加一级——存在 `.header-actions` 时优先 `headerActions.appendChild(wrap)`（放进右侧操作区），再退 `.header`、再退悬浮。主界面①分支不变；审计日志现变为 `[用户名][返回][语言▼]` 与角色页右侧分组一致。
- 验证：build.js 重建 exit=0；dist/js/public/termsFunction.js 含两处 `querySelector(".header-actions")`（①分支 fallback + ②分支）与 `fa-sign-out-alt`，逻辑就位（局部变量 headerActions 被 terser 重命名，grep 字符串字面量确认）。
- 影响面：共享函数，所有页面复用，低风险；对已有主界面零影响。

## 编辑页"满额"出现 2 个字符串 —— 根因与修复
- 现象：进入"职业信息"编辑（修订）页，同一满额排期行出现两个"满额"。
- 根因（双写）：① 进入编辑时 `enterEditMode → fillEditForm → appendAvailableTimes → renderTimeRow(t)`，若快照 `t.full` 为真则直接渲染一个"满额" `<span>`（**无 `full-badge` 类**）；② `enterEditMode` 末尾又调 `enrichTimeRowsWithFull(teacherId)`，异步拉 `/schedule/listByTeacher` 后对每个满额行 `if(... && !row.querySelector('.full-badge'))` 再追加一个"满额" `<span class="full-badge">`。
  - 关键：`t.full` 之所以为真，是因为视图页 `enrichOriginalDataFull` 已把 `full` 写回 `originalData.availableTimes`，进入编辑时快照就带 `full` → 路径①已渲染；而①的 span 不带 `full-badge` 类，路径②的 `!row.querySelector('.full-badge')` 守卫漏检 → 重复追加。
- 修复（frontend/js/teacherInfo-edit.js，已重建 dist）：给 `renderTimeRow` 的 `fullHtml` span 加上 `class="full-badge"`（并补 `margin-left:6px` 与 enrich 的 span 视觉一致）。两路径徽章同源同类，`enrich` 守卫检测到已存在即跳过 → 单一"满额"。
- 验证：node --check OK；dist/js/teacherInfo-edit.js 含 3 处 `full-badge`（守卫、enrich 追加 span、renderTimeRow span），逻辑去重就位。
