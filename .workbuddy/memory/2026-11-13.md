## 13:40 讲稿 iframe 报 X-Frame-Options DENY

**根因**：`classroom-service` 的 `SecurityConfig` 只配了 `csrf.disable / permitAll`，**没碰 Spring Security 默认的响应头** → 所有 8092 响应都带 `X-Frame-Options: DENY`。而讲稿 PDF 是靠 `<iframe src>` 加载签名 URL 的（`FileAccessController` 注释明确写了「iframe/video/img 带不了 Authorization，所以用 exp+HMAC 短时签名 URL」），浏览器必然拒绝内联显示。8080 前端反代只是透传这个头。

**取证**：`GET /api/v1/classrooms/d8965e…/materials/current` → `url: /api/v1/files/<base64key>?exp=…&sig=…`（`STORAGE_PUBLIC_BASE_URL` 默认空 → 相对路径）；该 URL 经 8080 与直连 8092 都是 **HTTP 200 / application/pdf / 600257 bytes**，但响应头 `X-Frame-Options: DENY`。8080 根本身没有这个头 → 排除前端静态服务器。

**修法**：`SecurityConfig` 拆两条链 —— `@Order(1)` `securityMatcher("/api/v1/files/**")` 只对该前缀 `headers.frameOptions(frame -> frame.disable())`，其余配置（csrf/cors/STATELESS/permitAll）与默认链保持一致；`@Order(2)` 原链不动。只放开签名文件端点，其它端点仍 DENY（不返回 HTML 表单、无登录态，且有 2h 签名保护）。

**验证**：compile BUILD SUCCESS；按上一轮流程停 8092（PID 5892）→ `package -DskipTests`（fat jar 55MB）→ `unset SERVER__PORT` + `--server.port=8092` 重启（新 PID 22124）；签名 URL 经 8080 / 直连 8092 均 **无 X-Frame-Options**，`/api/v1/system/info` 仍 `DENY`。**刷新页面即可**，前端不用改。

**★生产云托管的两个待办（本次未改，等用户拍板）**：`cloudBased/frontend/default.conf.template` ① server 级 `add_header X-Frame-Options "DENY" always`（等保 P0-2 六头之一）对所有 location 生效，模板注释自己写明「location 里只要出现任意一条 add_header，server 级 6 条就全不下发」→ 需要为 files 新增专用 location 并复制其余 5 条头、去掉 X-Frame-Options（或改 SAMEORIGIN）；② 模板的 location 列表里**没有 `/api/v1/files/`**，`/api/v1/files/...` 会落到通用 `location /api/v1/` → `proxy_pass $api_upstream`（booking 8081）而不是 `$classroom_upstream`（8092），生产讲稿/回放文件会直接 404。本地 `doc-develop/dev-proxy.js` 有 files 前缀（第 81 行）所以本地正常。
