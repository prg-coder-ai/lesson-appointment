## 同日第三次迭代：今日课程列表的课堂入口（课程准备 / 进入课程 / 课程回看）

**判定口径（关键决策）**：**不用 `appointment.status` 判"已完成"**——它是课堂下课回调回流才变 completed，课堂服务没跑时永远 active，会出现「课上完还显示进入课程」。改为「原始 UTC 上课时间 + 课时」：`now >= start+duration → past`、`now >= start → live`、否则 upcoming。
- `appointment.appointmentDatetime` 是 **UTC 裸串**（渲染时才 utcToZoned，兜底文案拼 "(-UTC)"）→ `parseUtcLoose` 对裸串按 `Date.UTC()` 解析，否则东八区整体偏 8 小时。
- `processOne` 补出 `rawDatetime`（原始串，别用格式化串二次解析）+ `classDuration`（排期课时，缺失 60）。

**按钮矩阵**：upcoming → 学生「进入课程」/ 教师「课程准备+进入课程」；live → 双方「进入课程」；past → 双方「课程回看」。取消/拒绝/删除/候补态、admin 角色、时间缺失、课堂未开通 → 都不出按钮。

**实现**：逻辑集中在 `my-classroom-core.js`（`classroomKeyOf`/`classroomPhase`/`buildEntryButtons` + `window.ClassroomEntry.{enter,replay,prep}`），`appointmentNotes.js` 只提供 `classroomButtonsFor(cardInfo, role)` 并在 `formAppointmentTr`（学生/管理员行）与 `formAppointmentGroupTr`（教师聚合行，取 `pickEntryItem(items)`）两处挂上。行内 onclick 用 `window.ClassroomEntry.xxx('key')`，不声明同名全局函数（避内联覆盖）。

**新增 `classroom-prep.html` + `js/classroom/classroom-prep.js`**：教师课前页（讲稿上传复用 core.renderMaterialPanel、成员名单 `getMembers`、同步课堂、进入课堂）。课堂状态枚举 `SCHEDULED/READY/LIVE/CLOSED/CANCELLED`；Membership 名字字段是 **displayName** 不是 userName。

**重要前提**：`POST /classrooms/{key}/enter` 第一步就 `assertAccess`，非名单成员 40301；名单是推送 created 事件时按 students 预建的，enter 自己不会建行 → 课堂没同步则学生点「进入课程」必 40301，靠教师的「课程准备→同步课堂」补。

**测试**：`tests/check_today_course_classroom_buttons.js` 38 断言全绿；回归 myClassroom 46/46、appointmentNotes 14/14、studentBookingBrowser 14/14；endpoints/global-collide/inline-js 全过；build 成功 128 文件。
