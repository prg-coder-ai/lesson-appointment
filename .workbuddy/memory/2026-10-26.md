## 数据维护页「预约」删除拿不到有效主键（delFunc 形参错位）
- 现象：admin.html「数据维护 → 预约」勾选行点「删除」，没有取到有效的预约 id。
- 根因（两处，均前端）：

  2. 即便补齐参数也会假失败：`deleteAppointmentsById` 删完调 `viewMyReservationDetail(bookingid)`，

     （记录其实已删，界面报"失败"）。
- 修复：`admin-dataMaintainPage.js` 新增 `maintainDeleteAppointment(appId)`，**按后端契约直连**

  不复用学生端两参函数；`delFuncMap.appointment` 改指它，`loadMaintainTableData` 的 cfg.delFunc 同步改名（加注释禁止再接两参函数）。
- 附加防线：`batchDeleteMaintain` 收集 ids 时显式过滤 `''/undefined/null`，全空则不发请求并明确提示；confirm 文案改用**有效条数**
  （原本用 checks.length，遇缺主键行会虚报），有跳过行时附加提示。
- 顺带修同链路另一个硬伤：`js/public/datamaintain_delete.js` 的预约列表补充循环里，`browserTimeZone` 是 try 块内 const，

## 数据维护页删「预定」报错 viewMyReservationDetail is not defined（同一类根因的第二次暴露）
- 现象：admin.html「数据维护 → 预定」勾选删除 → `ReferenceError: viewMyReservationDetail is not defined at deleteAppointmentsByBookingId (appointmentNotes.js:1182) ← deleteBooking (datamaintain_delete.js:172)`。
- 根因（跨页面复用 UI 副作用）：`viewMyReservationDetail` 定义在 `student-bookingBrowserCards.js`
  （student.html 另有内联同名版），**admin.html 不加载**。而 appointmentNotes.js 里多处「删/改」函数在
  **业务请求之后**直接裸调它做详情刷新 → 在 admin 上下文抛错 → 外层 `deleteBooking` 的 catch 吞掉并返回
  undefined → 不但误报「删除失败」，连后面的预定本体删除都没执行（await 已中断）。
- 修复（治本，不再逐处打补丁）：appointmentNotes.js 新增 **`safeRefreshReservationDetail(bookingId)`** 统一替身 ——
  typeof 存在性判定（两种形态：裸全局 / window 挂载）+ try/catch；**只负责尽力刷新 UI，绝不参与删除结果判定**。
  四处裸调用全部替换：`setApointmentStatusAndReload`、`updateAppointmentsStatusByBookingId`、
  `deleteAppointmentsByBookingId`、`deleteAppointmentsById`。
- 附带修复：`deleteBooking` 里 `if (checkAppointmentExistsBookingId(id))` **缺 await** —— 该 async 函数返回 Promise，
  不 await 恒为 true → 无条件走级联删除（正是落入本次崩溃的入口）。已补 `await`（函数内部出错本身也返回 true，保守级联）。
- **纪律（重要）**：被 admin / student / 数据维护多页面复用的 `js/public/*.js` 函数，
  **禁止裸调某页面专属的 UI 渲染/刷新函数**；一律经 `safeXxx` 守卫（typeof + try/catch），
  且守卫失败必须静默降级，**不得影响业务判定**。这是继「删函数形参错位」之后同一类"跨页面契约"问题的第二次出现。
- 验证：无头测试两组，均全绿 ——
  ① appointmentNotes 单源 7/7（admin 环境不崩、请求照发、详情函数崩溃不传染、URL 正确）；
  ② 三件套（appointmentNotes + admin-booking + datamaintain_delete）端到端 6/6（复现 admin 无 ViewMyReservationDetail，
  deleteBooking 不抛错、无课次时不走级联、预定本体删除请求正常发出）。
