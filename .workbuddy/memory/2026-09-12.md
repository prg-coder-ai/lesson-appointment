# 2026-09-12 工作日志

## 远端 logback NoClassDefFoundError 诊断
- **现象**：远端运行实例报 `java.lang.NoClassDefFoundError: ch/qos/logback/classic/spi/ThrowableProxy`（发生在 JwtAuthenticationFilter 记"Token 校验失败"经 JUL→SLF4J 桥接写日志时，崩 Tomcat 工作线程）。
- **根因**：logback-core 与 logback-classic **版本错配**（或 classic 包被截断/外部旧 logback 覆盖）。本地 8081 跑的是我打的 `api/target/booking_api-2.0.1.jar`，内嵌 `logback-classic-1.5.11` + `logback-core-1.5.11` 配对且各仅一份、`ThrowableProxy.class` 存在 → 本地正常；远端跑的是另一份（旧构建/异环境/外部 classpath 覆盖）→ 崩溃。
- **不是**多租户或业务代码问题；`Token 校验失败` 只是诱因（无效 token 触发 Tomcat 经桥接记日志）。
- **修复**：把本地这份配对 jar 部署到远端并重启（带 `--server.port=8081`，jar 默认 11166）；远端自检 `unzip -l ...jar | grep logback-` 看版本是否一致、classic 内 `ThrowableProxy` 是否在。若仍崩则查启动 classpath 是否挂外部旧 logback。
- **可选加固**：api/pom.xml 显式钉死 logback-classic/logback-core=1.5.11（目前靠 Spring Boot 托管已一致，防御性）。

## logback 钉版本 + 重打包（已完成）
- 已做：api/pom.xml 加 `<dependencyManagement>` 钉死 logback-classic/logback-core=1.5.11；加 `<build><finalName>booking-api-2.0.1</finalName>` 锁定产物名（artifactId 本就是 booking-api，连字符）。
- `mvn package -DskipTests` → BUILD SUCCESS，产物 `api/target/booking-api-2.0.1.jar`（41.6MB）；校验 logback-classic-1.5.11 + logback-core-1.5.11 配对、`ThrowableProxy.class` 存在。
- **产物名由旧遗留的 `booking_api-2.0.1.jar`（下划线）统一为 `booking-api-2.0.1.jar`（连字符）**。远端/本地重启均用新名：`java -jar booking-api-2.0.1.jar --server.port=8081`。target 内旧的 `booking_api-2.0.1.jar`（可能仍被旧实例占用）为废弃产物，应停旧实例后用新名 jar。
