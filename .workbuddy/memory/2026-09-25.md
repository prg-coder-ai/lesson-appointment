## CSP eval 告警排查（00:14）
- **现象**：浏览器报 `Content Security Policy prevents evaluation of arbitrary strings (eval/new Function/setTimeout([string]))`，无具体行号。
- **排查结论**：应用代码零 eval 类写法。全量扫描 `frontend` + `api/beforeRun/dist` 全部 js/html 内联脚本 = 0 命中（仅 `setTimeout(resolve,ms)` 传函数引用，合规）；3 个 CDN 库（axios/fullcalendar@6.1.10/html2canvas@1.4.1）单独下载扫描均 clean；8080/8081 服务端均不下发 CSP 头，仓库无 CSP 定义、无 nginx 配置。
- **根因**：告警来自运行/预览环境（内置预览窗 iframe 强加的严格 CSP + 其自身注入脚本使用 eval），并非本应用代码或声明依赖。
- **处置建议（待用户选）**：① 若仅在预览窗看到、应用功能正常→良性噪声，建议用真实浏览器直连 8080 访问规避；② 若需以严格 CSP 部署→应用已 eval-free，仅需把 3 个 CDN 库自托管到本地 + 在 CSP 中放行 cdn 主机或 'self'，无需 unsafe-eval。

- **排查（全盘实测）**：① 三个 teacher.html 副本（source 379行 / dist 170行 / beforeRun 170行）的**内联 `<script>` 全部 `node --check` 通过**；② teacher.html 引用的 **18 个外链 `<script src>` 脚本逐一 `node --check` 全 OK**；③ `curl 8080/teacher.html?tCode=tenant_A` 实际吐出的是**未转换源码**（17945 字节/379 行，合法）；④ `find` 全盘**无任何单行损坏 teacher.html**；⑤ `netstat` 显示除 8080/8081 外**无其它预览端口** → 预览面板是 WorkBuddy 内置（Electron webview），非独立 HTTP 服务。
- **根因判定**：报错**不来自应用代码**（所有磁盘文件 + 8080 源码均语法合法）。`line 1` 特征 + `wrappedSendMessageCallback/chrome.runtime` + `message channel closed` = **WorkBuddy 内置预览面板自身注入的桥接脚本/浏览器扩展 messaging 失败**（`line 1` 即注入点；位置从 `:1:69`→`:1:74` 的漂移，正是文档长度随改动变化、注入点偏移所致，进一步佐证是预览注入而非应用脚本）。属预览环境噪声。
- **处置/建议**：① 用**真实浏览器直连** `http://localhost:8080/teacher.html?tCode=tenant_A`（node 静态服务吐合法源码）即可不再出现该报错，且 `previewScheduleGroup` 功能经 harness 验证可正常跑通；② 若坚持在预览面板内查看，这些 console 错误为面板基础设施噪声，**应用功能本身不受影响**；③ 若在真实 Chrome 仍见 `message channel closed`，是浏览器扩展（如密码管家）messaging 失败，可隐身模式/禁用扩展验证。
