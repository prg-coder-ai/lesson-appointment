## 12:00 修复注册时审计日志 tenant_id 为 NULL 报错
- 根因（两条叠加）：
  1. MP 的 TenantLineInnerInterceptor **不负责 INSERT 赋值**：processInsert 先调 ignoreInsert(columns, tenantIdColumn)，列清单已含 tenant_id 就跳过，绝不覆盖。实体 tenantId 为 null → 显式插入 NULL → 违反 NOT NULL
  2. AuditAspect 的 setTenantId 写在 if(token != null) 内，注册接口在白名单无 Token → 从未赋值
- 修复1 AuditAspect：抽 resolveTenantId(request)，Token → TenantContext → 兜底 0L，在 buildBaseLog 开头赋值（必须在主线程，saveAsync 异步取不到 ThreadLocal）
- 修复2 新增 config/TenantMetaObjectHandler（MetaObjectHandler）：所有含 tenantId 的实体 insert 且为空时自动填充当前租户，无上下文填 0；已显式赋值不覆盖
- ★ 连带发现（反编译 mybatis-plus-extension-3.5.7 证实）：buildTableExpression 无条件 `new EqualsTo(column, getTenantId())`，**无任何 null/NullValue 判断**。
  MyBatisPlusConfig 中平台管理员返回 `new NullValue()` 会拼成 `tenant_id = NULL`，SQL 语义下恒为 UNKNOWN → **平台管理员查询所有隔离表都返回 0 条**。
  正确解法：在 ignoreTable() 里判断 TenantContext，平台身份(0/null)直接 return true 跳过拼接（buildTableExpression 对 ignoreTable 有短路 return null）
- 编译 BUILD SUCCESS（未启动运行）
- 排查手法：反编译 jar 定位依赖行为——`mvn dependency:build-classpath` 拿 jar 路径 → unzip → javap -c
