## 01:00 补充修复：briefs 字段白名单静默丢弃新字段

**现象**：用户反馈「重新编译后平台管理员已发列表仍无租户名」。查证 jar(00:49) 与 dist(00:46) 均已含新代码 → 不是没部署。

**根因（真 bug）**：`frontend/js/messages-inbox.js:779`
```js
recState.briefs[b.userId] = { name: b.name || '', account: b.account || '' };
```
把后端 briefs 的返回**按字段白名单重建**，后端新增的 `orgName` 在这一层被丢弃 → 前端 `b.orgName` 恒 undefined → 不渲染，**且无任何报错**。

**修法**：改为整体存 `recState.briefs[b.userId] = b;`（小程序端 `detail.js:192` 本就是整体存，不受影响）。理由写进注释：**白名单式转发 = 后端加字段会被前端静默吞掉**，该接口字段已由服务端按角色收敛，整体存不引入越权。
`renderRecipients` 侧天然安全：`b.name` 缺失回退 userId、`b.account`/`b.orgName` 缺失则不渲染该节。

**同类隐患（已排查，无第二处）**：全仓 `briefs[...] =` 只有 web 这一处白名单；小程序 `this._recBriefs[id] = briefs[id]` 是整体存。
