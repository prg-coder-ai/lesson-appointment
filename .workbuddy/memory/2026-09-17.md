# 2026-09-17 工作记录

## 小程序登录页「标题在、正文无」根因定位与修复
- 现象（续 09-16 空白排查）：登录页导航栏标题"登录"正常显示，但输入框/角色选择/按钮整块不渲染。
- 深查：login.wxml/wxss/js/json 均无 BOM、合法 UTF-8；app.wxss 全局样式无隐藏正文规则；WXML 语法合法；import 链无模块级 throw；login.json 正常（故标题显示）。
- 真因定位：`pages/login/login.js` 第 6 行在**模块顶层裸调** `const app = getApp();`，而 project.config.json 开了 `"enhance": true`（glass-easel）。全代码库仅此一处未加守卫，core/request.js、core/auth.js 均用安全写法 `(typeof getApp === 'function') ? getApp() : null`。增强模式下页面模块求值期 getApp 可能未就绪，顶层裸调若抛错 → Page() 不注册 → 正文不渲染、标题（来自 login.json 独立加载）照常。
- 修复：删除顶层 `const app = getApp()`；onLoad 内改为 `const app = (typeof getApp === 'function') ? getApp() : null;` 并 `if (app && app.globalData)` 守卫；clearBinding 内 app2 同样改为安全守卫。与 core/* 风格统一。
- 验证：`node --check`（拷为 .mjs）SYNTAX_OK。
- 仍有残留风险：① 目录重构后开发者工具编译缓存脏数据（工具→清除缓存→全部清除→重编）；② 若修复+清缓存后仍空白，需用户提供调试器 Console 具体报错文本（看 WXML 编译错误 / Component not found / JS 运行时错误）再精确定位。
- 建议：其余页面/home/booking 等均无顶层 getApp 裸调（grep 全仓仅 login.js 有），不必改；但后续新增页面遵循「getApp 仅在 onLoad 内、且用 typeof 守卫」约定。

## 官方优化：启用按需注入 + 用时注入（lazyCodeLoading）
- 依据微信官方「小程序启动性能」提示，在 `miniprogram/app.json` 加 `"lazyCodeLoading": "requiredComponents"`（基础库 2.11.1+ 按需注入；2.11.2+ 用时注入生效）。
- 组件声明审计（官方注意事项要求移除未使用声明）：grep 全仓 9 处 `role-tabbar` 声明（mine/student-home/teacher-home/courses/profile/my-booking/booking/admin-home/dashboard）在各自 WXML 均真实使用 `<role-tabbar>` 标签，**无"声明未用"可删**；app.json 无全局 usingComponents（无"全局低使用率组件"问题）。审计通过，无需改任何页面 JSON。
- 影响：login 页纯原生 form、无自定义组件，不受该配置影响；role-tabbar 为各 tab 页高使用组件，注入效果良好。
- 说明：「用时注入」需额外为组件配 占位组件 才生效，本次未配置（按需注入已满足优化目标），未来若要进一步延迟注入再单独加。
