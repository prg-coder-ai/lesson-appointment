## 修复：租户登录后 admin 页报 testData.js 找不到
- 根因：`frontend/admin.html`（源 + `dist`）的 `window.onload` 有一行 `window.makeTestPage = makeTestPage;//test`，
  而 `makeTestPage` 定义在 `js/test/testData.js`。该文件是开发测试工具（"测试-批量创建数据"批量建用户），
  构建产物 `dist` 不含它（build.js 排除 `js/test/`，且 L1 清理本就计划删除），导致 `makeTestPage` 未定义、
  `onload` 抛 `ReferenceError: makeTestPage is not defined`，租户 admin 页初始化中断。
- 修复：从 `frontend/admin.html` 与 `frontend/dist/admin.html` 移除 ①菜单项"测试-批量创建数据" ②`case "test_data"` 分支
  ③`onload` 里的 `window.makeTestPage = makeTestPage;//test` ④`<script src="js/test/testData.js">` 引用；
  并删除 `frontend/js/test/testData.js`（符合 L1 清理意图，消除死代码）。
- 验证：`grep` 两 admin.html 已无 testData/makeTestPage/test_data 残留引用。
- 部署提示：Nginx 以 `frontend/dist` 为 root 直接伺服业务前端，改动即时生效，浏览器硬刷新即可；
  api jar 不伺服 `admin.html`（只伺服平台管理端 platform-admin.html），重打 jar 时 build-platform.js 会把 dist 重新拷入 static，保持一致。

## 修订：保留批量工具，但发行版不显示菜单项
- 用户要求：保留 `js/test/testData.js`（开发批量建数据工具），但发行版（dist）不显示菜单项 `key="test_data"`。
- `git restore` 恢复此前删除的 `frontend/js/test/testData.js`（git 提交 00ace80 仍跟踪）。
- 根因呼应：build.js 第30/105行本就把 `js/test/` 排除出生产构建（"测试目录不进生产构建"），故 dist 天然不含该脚本。
- 方案（运行时判定，零构建改动）：`admin.html` 的 `window.onload` 改为 `if (typeof makeTestPage === 'function')` 才挂
  `window.makeTestPage` 并显示 `#menu-test-data`，否则隐藏该菜单项；`case "test_data"` 也加 `typeof` 保护。
  - 源 `frontend/admin.html`：保留 `<script src="js/test/testData.js">` + 菜单 → 开发态前端直接可用。
  - 部署版 `frontend/dist/admin.html`：菜单加 id 但**不**加脚本标签（避免 404），运行时 `makeTestPage` 未定义 → 菜单自动隐藏、不再报错。
- 验证：`grep` 两文件均无裸 `window.makeTestPage = makeTestPage;//test`，源有脚本标签、dist 无。
- 说明：发行版(dist)按现有设计不打包 testData.js，故该工具仅在开发态（源前端）可用；若需在生产部署版也可用，
  需改 build.js 放行 `js/test/` 并加 `?dev=1` 之类的菜单显隐开关——已向用户提此选项。

## 文档：三个密钥在前端/api/信息中心的配对关系（写入部署手册 6.2）
- 代码核对结论：
  - 前端（dist）**零密钥**：`grep` frontend 无 `JWT_SECRET`/`CRYPTO_*` 引用；前端只存 token、请求头转发，不签发/验签/加解密。
  - `JWT_SECRET` → `jwt.secret`：`JwtUtil` 按 UTF-8 字节读、长度≥64（HS512/HS256）。api 签发+校验；message-service 仅校验（共享密钥域，见 `MessageAuthInterceptor`）。**booking 与 message 必须相同**。
  - `CRYPTO_AESKEY` → `crypto.aes-key`：`CryptoUtil` Base64 解码须正好 32 字节（AES-256-GCM）。
  - `CRYPTO_HMACKEY` → `crypto.hmac-key`：32 字节 HMAC-SHA256 搜索索引。
  - AES/HMAC 两服务复制同一 `CryptoUtil`、共用 `message_center` 库，跨服务解密依赖密钥相同。
- 重要安全发现：`api/src/main/resources/application.properties` 与 `message-service/.../application.properties` **当前已明文写死且生效**三个密钥（AES/HMAC 值与用户示例一致，JWT_SECRET 两处相同）。属"已入库"，生产须用 env 覆盖并建议轮换。
