## 租户管理端「用户管理」新增"管理员"菜单（管理员角色账号管理）

需求：admin.html「用户管理」组下加"管理员"菜单，按"教师管理"同样的页面管理 role=admin 的账号。

实现（复用，新增零后端端点）：
- `frontend/admin.html`：<div class="menu-item" key="admin"> 管理员管理（fa-user-shield），switch 新增 `case "admin": renderTeacherCards("admin")`。
- `frontend/js/admin-user.js`：同一函数 `renderTeacherCards(role)` 扩展支持第三角色。
  - 新增 `window.adminUserRoleText / adminUserRoleLabelHtml / adminUserRoleIcon`（挂 window 属性而非顶层 function/const：本文件未包 IIFE，顶层声明会进全局作用域触发 check-global-collide）。
  - 标题/按钮"添加XX"/添加弹窗/编辑弹窗标题全部改为按 role 取词；教师学生仍走 termText 行业词表，管理员字面量（职能角色不进词表）。
  - 管理员列表加"当前账号"自锁保护：`isSelf` 行不渲染禁用/删除（管理员自冻结会导致本租户无人可审批，只能找平台管理员救场），账号列显示"（当前账号）"。
- `miniprogram/package-admin/home/home.js`：用户管理组加"管理员管理"入口 `?role=admin`。
- `miniprogram/package-admin/user-list/user-list.js`：onLoad 角色解析扩为 teacher/student/admin（未知回落 teacher），roleText 同步。

后端零改动（已具备）：`/user/page?role=admin` 走 TenantLineInnerInterceptor 天然限本租户；AuthzRules 里 `/user/page`、`/user/add`、`/user/updateStatus|updateInfo` 均为 PLATFORM_OR_TENANT_ADMIN；`UserService.Register(approvedByAdmin=true)` 对 admin 直接 active，且 doRegister 只对 teacher/student 占角色配额（admin 仅占 USER 总数）。

守卫：check-global-collide / check-endpoints-refs / check-miniprogram-shared-sync 全绿；admin-user.js 与两个小程序文件 --check 通过。

## ★构建陷阱复现：frontend/build.js 被 safe-delete 闸拦下
`node frontend/build.js` 会先 `rmSync(dist)`（93 个文件 > 50 阈值）→ `SAFE_DELETE_BULK_CONFIRM_REQUIRED` 直接抛错，dist 未被破坏但构建不动。
本次做法：临时脚本（仓库根，用完即删）只用 terser(compress+mangle,module:false) 与 html-minifier(collapseWhitespace/removeComments/minifyCSS/minifyJS:false/caseSensitive/keepClosingSlash) 重生成 **改动到的** `dist/admin.html` + `dist/js/admin-user.js`，与 build.js 参数逐项对齐。dist 已被 frontend/.gitignore 忽略，属部署产物。
