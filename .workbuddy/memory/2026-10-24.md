## pending 状态禁止登录（用户拍板：禁止 / 微信注册仍 pending 不发 token / 存量保持 pending）

### 决策前的证据（三条链路三种口径）
| 入口 | 原行为 |
|---|---|
| `UserService.login:412` | 只拦 frozen/inactive，**pending 放行** |
| `wechatLogin` | `!"active"` 全拦（pending 被拒） |
| `wechatRegister` | 建号 pending 却签发 token，前端 `setSession` → 注册即登录；下次静默登录又被拒 |
| `doRegister`（含 /user/register 自助注册） | **无条件发 token**，web 注册页把 token 写进 localStorage → 挡登录口也能从注册侧门进 |

产品侧承诺与实现矛盾：`promo.js` 文案"审批通过后即可登录"、`login.html` 注释"注册需审核"。
危害实证：`JwtAuthenticationFilter` 只验签、业务接口不查 `user.status` → pending 用户拿 token 后全功能可用，审核纯装饰。

### 改动
后端（`UserService` + `AuthzRules`）
- `login`：改为**白名单失败关闭**（`!"active".equals(status)` 即拒），文案按 frozen/pending/其它 三档；补 `log.warn` 记 accountHmac（不打明文）。
- `wechatLogin`：加 pending 专用文案，与 login 同构。

- `AuthzRules` 注释更新（原写"pending 用户能登录"，已腐烂）。

小程序

## 核查：管理员/平台管理员自助注册的 active/pending 判定（只分析，未改码）

代码确认按"首管理员自动 active，否则 pending"实现，唯一判定点 `UserService.applyRoleAdmission`（Register 内、写库前、同事务）：
- `admin`：`countByTenantAndRoleForUpdate(regTenantId,'admin')==0 && regTenantId>0` → active，否则 pending（按租户，非全局）。
- `platform_admin`：`countByRoleGlobalForUpdate('platform_admin')==0` → active，否则 pending（全局唯一、不可再生）。
- 两处计数都 `@InterceptorIgnore(tenantLine)` + SQL 显式写 tenant_id，`FOR UPDATE` 提供并发互斥。
- 不走此规则：`/user/add`（approvedByAdmin=true 恒 active，由调用者角色限权）、`wechatRegister`（硬编码 pending，且只允许 student/teacher）、`PromoService.registerTenant`（新租户无 admin → 自然 active）。

发现的瑕疵（未修，待拍板）：
1. P1 判据含 frozen/pending —— 唯一 platform_admin 若被冻结，后续自助注册永远 pending，只能改库救场；租户管理员同理。
2. P1 保留字 `platform` 在注册链路未拦：`UserService:194` 注释称"sys_tenant 中没有 platform 记录"，**实测有 id=11、status=1**。role=admin + tenantCode=platform 会解析到租户 11；当前仅因该租户无 sys_tenant_package → 配额 acquire 失败 403 才被挡住（靠运气非校验）。
3. P2 `JwtAuthenticationFilter.WHITELIST_PATHS` 无 `/user/register`，只有不存在的 `/user/admin|teacher|student/register` —— 与"四处同步"约定不符；过滤器本身不拒（无 token 直接放行），故匿名注册当前可用，带过期 token 时仅多一条 warn。
4. P2 `tests/` 无任何 applyRoleAdmission 用例，并发正确性只靠代码注释里的 FOR UPDATE 实测记录。
5. P3 实测数据：platform_admin 13 条全 active → 自助注册平台管理员必为 pending；无 admin 的租户 = 4(TENANT_C)、10(ORG05)、11(platform,空租户) → 拿到其租户码者可抢首个 admin 直通 active。
