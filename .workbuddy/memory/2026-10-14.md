## 微信登录与绑定实现路径方案（分析，无代码改动）

- 新需求：frontend 加微信登录（已登录绑 openid / 自助注册微信建号关联 userid）+ 小程序微信绑定未调通。产出《微信登录与绑定实现路径方案.md》（仓库根）。
- **现状证据**：后端五端点已就绪（authController:245/261/288/303/322，wechat-login/register 四白名单齐、AuthzRules:221-223）；小程序 core/auth.js 五封装 + login.js 静默登录/勾选绑定 + mine.js 三态文案；web api.js:501 注释明示「Web 拿不到 wx.login code，只能查/解」。
- **小程序绑定未调通根因排序**：R1（最可能）`wechat.miniapp.secret` 占位 `REPLACE_WITH_REAL_APPSECRET`（application.properties:119，env template 也是 CHANGE_ME；2026-09-17.md 早有预判）→ code2Session errcode≠0 → 1001/400 被 customErrorMsg:false 静默吞；R2 request 合法域名；R3 code 一次性；R4 bind 未带 Bearer（概率低）；R5 appid 不一致（当前不成立）。附带瑕疵：119 行嵌套默认值 `${WECHAT_SECRET:${WECHAT_SECRET:...}}` 冗余。
- **核心架构结论**：openid 三分裂（小程序/网站应用/公众号各不相同），**unionid 是唯一跨端公共键**，但 `wx_userid` 表无 unionid 列 → 浏览器与小程序无法互通。方案：加 `wx_unionid` 列 + uk，匹配顺序 unionid→openid。
- **浏览器链路**：PC 扫码登录（开放平台网站应用，qr/qr-status/pc-callback 三端点 + state 表）+ H5 OAuth（公众号，可选）；已登录绑定 = 扫码确认绑（state 带 userId）；自助注册关联 = web 注册成功页出绑定二维码（注册与绑微信解耦两步）。
- **待用户提供数据**：小程序 AppSecret（立即）、开放平台账号+小程序绑定、网站应用 AppID/Secret/回调域、服务器出口 IP、生产 HTTPS 域名。P0=注入 secret 修小程序；P1=unionid 列；P2=PC 扫码；P3=PC 绑定；P4=H5；P5=注册关联。
- **守卫注意**：新免登录端点需四处白名单双形态；新增 secret 属性登记 check-secret-env-guard.mjs:46-47 同款清单；禁硬编码 /api/v1 字面量（endpoints 守卫）。
