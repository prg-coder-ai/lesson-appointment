## 小程序 login-flow 测试 4 FAIL 实为产品 bug（非单纯断言过时，13:30 闭环）
- 现象：上一轮修 storage 漏导出后 login-flow.mjs 仍 8 PASS/4 FAIL（A 场景 term/map auth 断言 + B 场景"401 不清 session/不跳登录"三连败）。
- **关键判断**：这 4 个 FAIL 不是单纯"断言该把 false 改 true"，而是**产品 bug 复现**。A 场景那条（term/map 不带 Bearer）才是真正过时的断言；B 场景"401 不应踢登录"的设计意图是对的——它失败说明产品行为错了。
- 根因链（读源码确认）：`auth.js:18-21` 注释记录历史 bug「loadTermMap 调 term/map 若 401 会清登录态并弹回登录页，现已在 request 层对 tokenOnly 401 免疫」。但 `term/map` 已改为**带 Bearer**（拉租户自定义词，logic.mjs:110 已断言），于是 401 免疫失效：`request.js:102/135` 对「非 tokenOnly」的 401 先 `doRefresh`、刷新失败则 `clearSession()+onAuthFail()`——login 成功后 loadTermMap 的 401 把刚建立的会话清掉（catch 拦不住清 session 副作用），复现"登录成功被弹回"。
- 修复（根因修复，非改测试掩盖）：
  1. `core/request.js` 新增 `enhance`（增强请求）标记：401/403 时只 `throw`、不清 session、不 `onAuthFail`、不 `showError`；同时第 102 行 refresh 判断与第 135 行踢人判断都加 `&& !opts.enhance`。
  2. `core/term.js` 的 `loadTermMap`、`syncIndustryFromTenant` 两处增强拉取请求带 `enhance:true`（它们是登录后的增强数据，失败绝不可阻断登录/跳转，退回本地兜底词表即可）。
- 测试对齐：`login-flow.mjs:66` 真正过时的断言 `term/map 用 tokenOnly(不带 Bearer)→auth===false` 改为 `term/map 带 Bearer(拉取租户自定义词)→auth===true`；场景 B 断言保持原意（设计正确），修 bug 后自然全 PASS。
- 验证：`logic.mjs` 41 PASS/0 FAIL（无回归，term/map 带 Bearer 断言不受影响）；`login-flow.mjs` 由 8/4 转为 **12 PASS/0 FAIL**。已 cpSync `miniprogram/core` → `_sut_login/core` 保持 SUT 副本最新。
- 铁律：小程序端"增强型请求"（词表/行业/静默拉取等非关键数据）必须带 `enhance:true`，否则其 401/403 会被当鉴权失败踢人，引发"登录成功弹回"。新增任何"登录后增强拉取"务必同理加 `enhance`，不要只靠调用方 try/catch（catch 拦不住 request 层清 session 的副作用）。
