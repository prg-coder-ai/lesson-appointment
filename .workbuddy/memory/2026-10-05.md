## 微信小程序编译报"主包内不应存在未使用的js文件"（11:14 排查）
- 现象：开发者工具编译期报错主包有未使用 js。
- 根因（依赖图分析确认）：miniprogram/ 主包 59 个 js 中，10 个在依赖图不可达：
  1. **Node 工程脚本（真·未使用）**：`sync-shared.js`（`#!/usr/bin/env node`，npm run sync 拷贝 ../shared）、`scripts/upload.js`（miniprogram-ci 上传）。二者本就不该进小程序代码包，被依赖分析判为未使用。
  2. **shared 全量镜像的暂未接入模块**：`shared/index.js`（聚合出口无人 import → 其 re-export 的子树全不可达）、`shared/format.js`、`shared/domain/mask.js`（经 format re-export）、`domain/refundRule.js`、`domain/term.js`、`shared/adapters/index.js`+`router.js`、`utils/index.js`。本质是 sync 全量镜像共享源、但小程序端 P1 领域层还没消费完。
- 修复（已验证）：
  - `project.config.json` 的 `packOptions.ignore` 增加 `{type:file,value:sync-shared.js}` 与 `{type:folder,value:scripts}`，排除两个 Node 脚本（标准做法，不影响 npm run sync/upload 本地执行）。
  - `shared/index.js` 补 `export * from './domain/term.js'` 与 `export * from './adapters/index.js'`（mask 经 format 已覆盖，refundRule 已 export）。
  - `app.js` 顶部加副作用引入 `import './shared/index.js';` + `import './utils/index.js';`，使整棵共享树进入依赖图。
  - 重跑依赖图脚本（已修：解析 `export ... from` re-export）确认可达 57/59，仅剩 2 个 Node 脚本孤儿（靠 ignore 排除）。
- 注意：微信"未使用 js"检查基于 packOptions 后的依赖图；`export * from` 也算依赖（开发者工具识别），故让共享 barrel 被 app.js import 即可消除告警，不要去 ignore 共享模块（否则未来运行时 import 会找不到）。
- 备选：若某微信版本 ignore 对该检查不生效，再把 sync-shared.js / scripts/ 移出 miniprogram/ 目录（改 package.json script 路径与 sync-shared 的 ROOT 推算）。

## 跨端对齐：小程序消息收件箱 `box.list`→`box.rows`（11:38 排查）
- 背景：近期 frontend 修正 message-service 分页接口字段口径——`PageResult` 返回 `rows`+`total`（前端 `messages-inbox.js:322` 用 `data.rows`；敏感词 `sensitiveWords.js` 也改 `pr.list`→`pr.rows`）。

## 小程序镜像 vs 根 shared/ md5 不一致（11:47 排查 + 处理）
- 现象：`tools/check-miniprogram-shared-sync.js`（md5 守卫）报 `小程序镜像与根 shared/ md5 不一致：index.js`，`guard_exit=1`；`git status` 显示 `M miniprogram/shared/index.js`（mp 镜像被改且已纳入版本管理），根 `shared/index.js` 干净。
- 根因：修"主包未使用 js"时（11:14 那轮），我给 **mp 镜像**的 `miniprogram/shared/index.js` 补了 `domain/term.js` + `adapters/index.js` 两条聚合导出，但**漏把同样的改动回流到权威源根 `shared/index.js`**——这正是 md5 守卫要拦的"在镜像侧改逻辑、根源没动"的漂移。
- 处理（遵循"根 shared 是唯一权威源"红线，正确流向 = 根→mp，绝不反向）：
  1. 把两条聚合导出（含注释）**回流**到根 `shared/index.js`；
  2. `node tools/sync-miniprogram-shared.js` 逐字节镜像回 `miniprogram/shared/`（覆盖 mp 旧 index.js）；
  3. 重跑守卫 → `[shared-sync] OK: 小程序 shared/ 镜像与根 shared/ 一致（17 文件）`，`guard_exit=0`。
- 铁律固化（防复发）：**任何对小程序里 `miniprogram/shared/*` 的"逻辑"改动，都必须先在根 `shared/*` 改、再 sync 下来；绝不直接手改 mp 镜像**。在 mp 里改 shared 逻辑且没回流根 → md5 守卫必拦。改完根 shared 后一律跑一次 sync + 守卫确认。
- 守卫只会单向检查（根→镜像的缺失/不一致）；镜像里若多出根没有的文件，守卫不报，需靠 sync 前人工确认（本次无多余文件）。
