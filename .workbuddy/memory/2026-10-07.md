### 五条系统性根因（报告主线，非逐条罗列缺陷）
- **A 授权模型缺失**：`SecurityConfig` 只有 `.anyRequest().authenticated()`，全仓 0 处 hasRole/hasAuthority/@PreAuthorize。

  收敛方式：改声明式、未匹配默认拒绝。改完可连带消掉 P0-1/2/4 + P1-1~P1-7 约 80%。
- **B 业务正确性外包给前端**：课次生成（Web 浏览器现算+逐条 POST 且 forEach 未 await）、级联取消（前端两次 HTTP 非原子，
  小程序只调一次→两端行为不一致）、状态机合法性（全靠前端按钮）。解释了"Web 与小程序结果不一致"是架构必然而非 bug。
- **C 数据库定义无单一事实源**：唯一完整 DDL `api/beforeRun/sql/lesson_appointment_schema_fixed.sql` 被 .gitignore 排除、
  停在 2026-09-06，比现网少 4 表；`uk_booking_schedule_student` 与 `course_schedule_chk_sites` 只存在于手工补丁
  `seat-oversell-hardening-20260918.sql`。**重建库 = 拆掉防超卖防线**，且不报错。
- **D 密钥管理缺失（原罪）**：jwt.secret / crypto.aes-key / crypto.hmac-key / DB 密码明文入库且被 git 跟踪
  （`application.properties:55,102,117,119`），message-service 逐字符复用同一套。**AES 密钥泄露无法靠轮换补救**，
  需换密钥 + 历史数据重加密迁移。
- **E 可观测性与测试真空**：无 Actuator/健康检查/指标/告警/traceId/日志轮转/连接池配置；`api/src/test` 不存在。
