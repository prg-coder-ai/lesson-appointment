## 11:08 新增「入口登录态守卫」（tcode/tenantCode/角色一致性校验）
- 需求：程序进入受保护页时，比较 URL 的 tcode 与本地(localStorage.currentUser.tenantCode) 上次登录租户是否一致；
  角色与 tenantCode 必须匹配（platform_admin↔platform；租户角色 admin/teacher/student 的 tenantCode 必须非空且≠platform）；
  URL 带 tcode 但与本地不一致、或页面要求角色与上次登录角色不一致 → 强制跳 index.html 登录（URL 带 tcode 时 ?tCode= 作为登录页预填/锁定参数）。
- 实现：在 js/public/api.js 增加全局函数 getUrlParam / isRoleTenantCodeMatch / forceEntryLogin / guardEntryPage(requiredRole)，
  并在 admin('admin')、platform_admin('platform_admin')、teacher('teacher')、student('student')、booking(无 requiredRole) 的 window.onload 最前调用，
  guard 返回 false 即 return（已跳转）。InitUserInfo 跳登录时也改为保留 URL tCode。
- 关键坑1：后端 /auth/login 响应 map 不含 tenantCode（只有 userId/account/name/role/token/refreshToken），
  故 index.html 登录提交处原 `tenantCode: user.tenantCode||''` 恒为 ''，守卫对租户角色永远判定不匹配。
  已改为用登录时确定的租户编码：`loginRole==='platform_admin'?'platform':loginTenantCode`。
- 关键坑2：index.html 内联脚本已 `const PLATFORM_TENANT_CODE='platform'`，classic 脚本共享同一全局词法环境，
  api.js 若再声明同名 const 会 SyntaxError；故 api.js 守卫内用字面量 'platform'。
- 验证：node --check api.js 通过；Node 真理表测试 16 个场景（无登录态/角色租户不匹配/URL tcode 不一致/角色不一致→登录；正常→放行）全 PASS；
  重启 8081 后 curl 确认各页面与 api.js 已含 guardEntryPage 调用。
- 新增受保护页时只需在 window.onload 最前加 `if(window.guardEntryPage && !window.guardEntryPage('<role>')) return;`
