## 【11:47~12:05】修复自签 HTTPS 下音视频不可用（Permissions-Policy 空 allowlist）

### 用户报的三个现象
1. 自签证书云服务器发布的前端，浏览器仍提示「不安全」
2. 浏览器已允许摄像头/麦克风，「课前准备」页仍调不动设备
3. 原来的 localhost 调试可以音视频

### 诊断结论：是两个独立病因，不是一条因果链
- **① 「不安全」提示 = 自签证书必然结果**，属提示不属故障。**它不影响音视频**：
  用户点过「继续前往」后 `window.isSecureContext === true`，getUserMedia 按设计放行
  （权威依据：Chromium Issue 40090684 官方回复「This is working as designed —— the user has vouched for the validity of the certificate」）。
- **② 音视频真凶 = nginx 的 `Permissions-Policy: geolocation=(), microphone=(), camera=()`**。
  空括号 `()` = **空 allowlist**，语义「任何来源都不许用」，**连页面自身也禁**。
  它是**文档级策略，优先级高于浏览器站点设置** → 用户在 chrome://settings/content/camera 点「允许」完全压不过它。
- **③ localhost 能用 = 对照证据**：`doc-develop/dev-frontend-local.js` 一个响应头都不发，
  走 `camera` 指令默认值 `self`。（grep 无任何 setHeader）

**教训（写进脑子里）**：`Permissions-Policy` 是这类"权限都给了、按钮没反应"的第一嫌疑，先查它再查证书。

### 反向测试第一版抓到守卫两个真 bug（价值体现）
1. **正则只认双引号** → nginx 里 header 值含空格要整体加引号、而 allowlist 的 origin 本身带双引号，
   正确写法是**外层单引号**：`add_header Permissions-Policy 'geolocation=(), camera=(self "https://a.com")' always;`
   只认双引号会在内层第一个 `"` 处截断 → 把合法配置误判成「没声明 camera」。已改为三形态兼容 `(?:"([^"]*)"|'([^']*)'|([^\s;]+))`。
2. 我自己的测试也构造了**非法 nginx 写法**（值里直接嵌双引号）+ 一条断言方向写错（只删一个文件的头不会触发「均未声明」note）。

## 【12:01~12:20】补 ca.crt 下载入口（客户端导入受信任根用）

### 放哪里
`/var/www/frontend/ca.crt` —— 就是 nginx 的站点根（`root /var/www/frontend;`），文件名必须**正好是 ca.crt**。
`gen-selfsigned-cert.sh` 第 4 步本来就会 `install -m 644 $CA_CRT $WEBROOT/ca.crt`，
但原来是 `if [ -d "$WEBROOT" ]` 静默跳过（跳过就变 404 且没人知道为什么）→ 已改成明确警告 + 给出手动命令。

### nginx 怎么配（5 份 conf 共 6 处，双栈文件的两个 server 段都要）
```nginx
location = /ca.crt {
    default_type application/x-x509-ca-cert;
}
```
三个设计理由，别被"简化"掉：
1. **不能靠 `location /`**：它 `try_files` 兜底 `/login.html` —— ca.crt 没放进来时会"成功下载"一个登录页 HTML，看起来像证书损坏。精确匹配 = 文件不在就是干净 404。
2. **`default_type` 必须显式**：nginx 官方 mime.types 确实有 `application/x-x509-ca-cert der pem crt`，但精简镜像若没 `include mime.types`，`.crt` 会落成 `text/plain` → Chrome 把证书**文本摊在页面里显示**而不是下载。
3. **刻意不写 `add_header`**：写了就不再继承 server 级 6 个安全头（想要 Content-Disposition 也得整套重发，不值当）。

### 验证
`curl -skI https://152.136.254.127/ca.crt | grep -iE "^HTTP|content-type"` → 应 200 + `application/x-x509-ca-cert`。
若 200 但 `text/html`：命中了 `location /` 兜底，实际发的是 login.html = 文件没放对地方。

### 安全边界与形态差异
- `ca.crt` 是**根证书公钥，可公开**；`ca.key` 私钥只在 `/etc/nginx/ssl/selfsigned/`（600 root），**绝不进站点目录**。
- **微信内置浏览器既不能下载也不能导入 CA** → 移动端必须用系统浏览器（Safari / Chrome）。
- 双栈形态推荐用 `http://IP/ca.crt` 下载：明文段免「继续前往」，避免"为了拿证书先绕过证书警告"的鸡生蛋。
- iOS 与 Android 不同：光装描述文件不算信任，必须再去「关于本机 → 证书信任设置」打开「完全信任」。
