## 【课堂入口 404 根因与修复，2026-11-26 12:2x】

- **现象**：教师端「近日课程 / 我的课程(课次列表) / 我的课堂 / 排期详情」点「进入课堂」全 404；「课堂准备」页的进入课堂当时已好。
- **根因（单一）**：frontend 侧所有入口已收敛到 `ClassroomLink.open({target:'entry'})` → 相对地址 `./launch.html?scheduleId=…`。launch.html **只存在于 classroom-app/www**，`frontend/` 下没有同名页。dev-proxy 的接管开关 `--app-www` 默认关闭，且 `dev-frontend-local.js` 调 `startProxy()` 时**从未传 appWww** → `/launch.html` 落到 frontend 静态根 → 404。上午修的 `toAppWww` 提前 return bug 只解决了课堂页内 `app-*.js` 资源（所以 prep 通了），入口页仍缺开关。实测证据：8080 现有实例 `/launch.html` → 404。
- **修复**：`doc-develop/90-tools/dev-frontend-local.js` 中新增 APP_WWW 解析（默认 `../../classroom-app/www`，`APP_WWW=0|off` 可关），显式传给 `startProxy({appWww})`。
- **验证（8089 临时实例）**：launch/classroom/classroom-prep/my-classroom → 全部 200 且 md5 与 www 逐字节一致；index/login/teacher/student → 仍是 frontend 版（符合同名页排除设计）；三个课堂页的全部 src/href 依赖逐个探测 0 个非 200。
- **生产 nginx 隐患（更隐蔽，未改）**：`deploy/nginx/booking-https.conf` 是 `root /var/www/frontend` + `try_files $uri $uri/ /login.html`。所以线上访问 `/launch.html` **不报 404，而是返回 login.html 内容（200）**，参数全丢，用户只会看到登录页。上线前必须补 www 的 location（launch/classroom/classroom-prep/my-classroom + app-*.js/role-router.js/app.css + /js/classroom/），并保留「www 缺文件回落 frontend」语义。5 个 conf 需逐条同步（check:proxy 会比对）。

## 【课堂 App 静态承接三处闭环 —— nginx 五份 + 部署脚本，2026-11-26 12:2x】

- **一个 URL 契约牵出三处配置，只改一处看不出效果**：①dev 工具（APP_WWW 默认接管，47f3f6b8）②生产 nginx（本次）③部署脚本（本次，www 从未被 rsync）。
- **nginx 规则（6 处插入点：booking / booking-ip / booking-https / booking-ip-https 各 1 处 + booking-ip-dual 的 80 与 443 两个 server 各 1 处）**：

  - `location ~ ^/(app-[a-z-]+\.js|role-router\.js|ops-lite\.js|verify\.js|app\.css)$`
  - `location ^~ /js/classroom/`、`location = /css/classroom.css`
  - `location @fe_static { root /var/www/frontend; try_files $uri =404; }`

## 【classroom-app 三端打包能力，2026-11-26 13:3x】

- **三端不是一套工具**：Android=Capacitor+Gradle（本机可出包）；iOS=Capacitor+Xcode（**编译只能在 macOS**，本机只生成 ios/App/App.xcworkspace）；Windows 桌面=**Electron**（Capacitor 无桌面 target）。
- **Android 实测出包 5.8MB**（`android/app/build/outputs/apk/debug/app-debug.apk`）。三个坑已固化进 `scripts/build-native.cjs`：
  1. Capacitor 6 要 compileSdk 34/build-tools 34，本机 SDK 只到 30 → 装法必须 `sdkmanager --package_file=pkgs.txt`（命令行直接带分号会被 cmd 吃掉，报"此时不应有 android-34"）。
  2. Capacitor 生成 Gradle 8.2.1 **不支持 JDK 21**（本机无 JDK 17）→ 脚本检测 JDK≥21 且 wrapper<8.5 时**自动改写为 8.7**。
  3. 腾讯镜像的 gradle-8.7-bin.zip 下到一半截断（zip END header not found）→ 脚本用**阿里镜像**自行下载 + 校验 EOCD 签名后再交给 gradlew。
- **Gradle 缓存目录名 = base36(md5(distributionUrl))**，与 PathAssembler 一致（已实算比对 af3un6e4ivqgjcdo5lfa5efog）。所以预置 URL 必须与 wrapper 完全一致，否则下到别的目录白费。
- **桌面 Electron 关键设计：内置本地同源 server（desktop/server.js），不 loadFile**。理由：file:// 不是安全上下文 → mediaDevices undefined → 采集不了设备；同源则后端无需开 CORS；裸相对路径解析与 Web 一致。server.js 抽成纯 Node 模块可脱壳单测：分流判定 15/15、静态 200、404 不兜登录页、目录穿越 403、API 分支 502。
- Tauri 被否：要 Rust + WebView2 碎片化，RTC 兼容风险高、WS 代理要另写。
- **沙箱 safe-delete 会拦 cap sync**（`SAFE_DELETE_BULK_CONFIRM_REQUIRED`），需 `CODEBUDDY_SAFE_DELETE_ENABLED=0`（与 frontend/build.js 同源问题）。用户本机无此限制。
- classroom-app/.gitignore 仍忽略 android/ ios/，故其中手工修正必须由脚本保证，不能靠"记得改"。
