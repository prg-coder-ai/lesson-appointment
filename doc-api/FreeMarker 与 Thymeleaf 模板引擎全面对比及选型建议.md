# FreeMarker 与 Thymeleaf 模板引擎全面对比及选型建议

FreeMarker 和 Thymeleaf 都是 Java 生态主流的**服务端模板引擎**，核心作用都是将后端数据与模板结合生成 HTML，但二者的**设计理念、语法风格、使用场景、兼容性**差异极大，Thymeleaf 更偏向**自然模板（前端友好）**，FreeMarker 更偏向**高性能模板（后端友好）**。

下面从**核心差异、语法、使用场景、优缺点**等维度做**清晰对比**，同时给出**选型建议**，看完就能直接决定用哪个。

# 一、核心差异速览（最关键的8点）

|对比维度|FreeMarker|Thymeleaf|
|---|---|---|
|**设计理念**|纯后端模板引擎，专注**高性能渲染**，模板是「后端专属」|自然模板引擎，主打**前后端兼容**，模板本身是**标准可运行的HTML**|
|**模板兼容性**|.ftl 不是标准HTML，浏览器双击打开会显示`${}`/`<#if>`等未解析指令，前端无法直接预览|.html 是**完整标准HTML**，浏览器可直接打开预览，前端开发无需依赖后端环境|
|**语法风格**|自定义指令（`<#if>`/`<#list>`），语法简洁紧凑，偏向后端思维|基于HTML**自定义属性**（`th:text`/`th:each`），融入HTML结构，前端易上手|
|**运行依赖**|必须由后端引擎解析，无模板引擎则完全无法使用|支持**无引擎静态运行**（属性会被浏览器忽略，不影响页面展示）|
|**渲染性能**|渲染速度快，内存占用低，适合**高并发、大数据量**场景|渲染性能稍弱（解析HTML属性耗时），对大数据量循环渲染不如FreeMarker|
|**前后端协作**|协作成本高（前端无法独立预览模板）|协作成本低（前端直接写HTML，后端加Thymeleaf属性即可）|
|**功能丰富度**|内置指令/函数极丰富（日期、数字、集合处理），支持宏定义、自定义指令|功能够用但偏轻量化，高级功能需自定义工具类，宏定义能力较弱|
|**Spring 集成**|需手动引依赖，配置简单，Spring 对其支持偏基础|**Spring 官方推荐**，自动配置、集成度极高，Thymeleaf3+完美适配Spring Boot|
# 二、语法直观对比（同一个需求，两种写法）

以**变量渲染、条件判断、列表循环**这3个最常用的需求为例，直观感受二者的语法差异，**模板文件后缀均为.html（Thymeleaf）/ .ftl（FreeMarker）**。

### 1. 变量渲染

#### FreeMarker

```Plain Text

<!-- 直接用${}，支持默认值! -->
<h1>你好，${username!"游客"}</h1>
<p>年龄：${age}</p>
```

#### Thymeleaf

```HTML

<!-- 用th:text替换标签内容，原生HTML写默认值，浏览器可直接显示 -->
<h1 th:text="|你好，${username}|">你好，游客</h1>
<p th:text="${age}">年龄：未知</p>
```

### 2. 条件判断

#### FreeMarker

```Plain Text

<#if age >= 18>
    <p>已成年</p>
<#else>
    <p>未成年</p>
</#if>
```

#### Thymeleaf

```HTML

<!-- 基于HTML属性，不影响原生HTML展示 -->
<p th:if="${age >= 18}">已成年</p>
<p th:unless="${age >= 18}">未成年</p>
<!-- 或用th:switch -->
<div th:switch="${age >= 18}">
    <p th:case="true">已成年</p>
    <p th:case="false">未成年</p>
</div>
```

### 3. 列表循环

#### FreeMarker

```Plain Text

<ul>
<#list hobbies as h>
    <!-- ${h_index}是循环索引，默认从0开始 -->
    <li>${h_index + 1}、${h}</li>
</#list>
</ul>
```

#### Thymeleaf

```HTML

<ul>
    <!-- th:each循环，${stat}是状态对象，包含索引、是否第一个/最后一个等 -->
    <li th:each="h,stat : ${hobbies}" th:text="|${stat.index + 1}、${h}|">
        1、默认爱好
    </li>
</ul>
```

# 三、核心特点详解

## 1. FreeMarker 核心特点

### ✅ 优点

- **高性能**：作为老牌模板引擎，经过多年优化，渲染速度和内存效率远高于Thymeleaf，适合**大数据量循环、高并发访问**的系统（如电商、后台管理系统）。

- **语法强大**：内置超丰富的指令和函数（日期格式化`${date?string('yyyy-MM-dd')}`、数字保留小数`${num?string('#.00')}`、集合过滤等），无需手动写工具类，后端开发效率高。

- **灵活性高**：支持**宏定义**（类似HTML组件复用）、自定义指令、模板继承，适合复杂页面的封装。

- **轻量**：核心包体积小，无额外依赖，除了Java外不依赖任何框架。

### ❌ 缺点

- **前后端协作差**：.ftl 不是标准HTML，前端工程师无法独立预览页面效果，必须依赖后端引擎解析，联调成本高。

- **模板不可静态运行**：浏览器直接打开.ftl文件会显示未解析的指令（如`${username}`），页面混乱，前端无法单独开发模板。

- **Spring 集成度一般**：虽支持Spring Boot，但并非官方推荐，部分高级特性（如动态模板）需手动配置。

## 2. Thymeleaf 核心特点

### ✅ 优点

- **自然模板，前端友好**：**最大优势**，模板是标准HTML，Thymeleaf的所有指令都是HTML自定义属性，浏览器会自动忽略这些属性，直接显示原生HTML内容，**前端可独立开发、预览，后端只需在原有HTML上添加Thymeleaf属性**，前后端协作无缝。

- **Spring 官方推荐**：与Spring Boot、Spring MVC深度集成，自动配置，无需手动写额外代码，开箱即用，是Spring生态的**默认模板引擎选择**。

- **学习成本低**：前端工程师无需学习新的指令语法，只需掌握少量`th:*`属性，即可快速上手，门槛远低于FreeMarker。

- **支持多模板格式**：除了HTML，还支持XML、JSON、TEXT、JavaScript等，适配多种场景。

### ❌ 缺点

- **渲染性能稍弱**：解析HTML属性的过程比FreeMarker的自定义指令更耗时，在**大数据量循环（如1000条以上数据）** 时，性能差距会明显体现。

- **功能偏轻量化**：内置函数和指令不如FreeMarker丰富，比如复杂的日期/数字处理、集合过滤，需要手动编写工具类或使用Spring EL表达式补充。

- **宏定义能力弱**：虽支持模板片段（`th:fragment`）复用，但灵活性和功能不如FreeMarker的宏定义，复杂组件封装稍显繁琐。

# 四、适用场景（选型关键，别瞎选）

### 👉 优先用 FreeMarker 的场景

1. **高并发、大数据量的后端系统**：如电商平台、秒杀系统、大型后台管理系统，对渲染性能要求高，需要处理大量列表循环。

2. **后端主导开发的项目**：项目前后端分工不明确，主要由后端工程师开发页面，追求后端开发效率和功能丰富度。

3. **需要复杂模板封装的场景**：页面有大量可复用的组件，需要强大的宏定义、模板继承能力。

4. **非Spring生态的Java项目**：如纯Java SE项目、SSM框架（非Spring Boot）项目，FreeMarker轻量、无强依赖，适配性更好。

### 👉 优先用 Thymeleaf 的场景

1. **Spring Boot/Spring Cloud 微服务项目**：Spring官方推荐，集成度最高，开箱即用，开发效率高。

2. **前后端协作开发的项目**：有专门的前端工程师开发页面，需要前端独立预览、开发模板，降低联调成本。

3. **中小型项目、快速迭代项目**：项目规模小，数据量不大，对性能要求不高，追求开发速度和学习成本低。

4. **需要静态页面和动态页面无缝切换的场景**：比如官网、博客，既可以静态部署，也可以通过后端渲染动态内容。

# 五、版本与生态

1. **FreeMarker**：最新稳定版`2.3.32+`，更新频率低（成熟稳定），生态完善，有大量的教程和工具类，支持所有Java版本。

2. **Thymeleaf**：最新稳定版`3.1.x+`，更新频率高，与Spring Boot版本严格适配（如Spring Boot 3.x 对应 Thymeleaf 3.1.x），生态围绕Spring展开，非Spring项目使用成本稍高。

# 六、超精简总结 + 选型建议

### 核心总结

- **FreeMarker**：**后端工程师的模板引擎**，高性能、功能强，适合后端主导、高并发的项目，缺点是前后端协作差。

- **Thymeleaf**：**前后端友好的模板引擎**，自然模板、易上手，Spring官方推荐，适合中小型Spring Boot项目、前后端协作开发，缺点是性能稍弱。

### 选型建议

1. **如果是 Spring Boot 项目，且有前端协作**：**无脑选 Thymeleaf**，这是最贴合Spring生态、协作成本最低的选择。

2. **如果是高并发、大数据量的后端系统（无论是否Spring）**：**选 FreeMarker**，性能和功能优势能体现得淋漓尽致。

3. **如果是纯后端开发的小项目**：两者皆可，追求快用Thymeleaf，追求功能强用FreeMarker。

4. **如果需要前端独立开发模板**：**必须选 Thymeleaf**，FreeMarker无法满足此需求。

# 七、补充：能否混用？

**不建议混用**，二者的模板引擎配置、语法完全不同，混用会增加项目复杂度，且Spring Boot默认只能配置一个主模板引擎，另一个需要手动复杂配置，性价比极低。

如果项目中既有静态预览需求，又有高性能需求，建议**核心高并发页面用FreeMarker，普通页面用Thymeleaf**，但需做好引擎隔离，仅适用于大型项目。
