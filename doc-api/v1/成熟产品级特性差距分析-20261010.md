## 二、本报告新增发现（旧报告未覆盖）

### 2.1 已成体系的"超前项"（成熟度高于旧报告预期）
- **质量基建**：15 道 pre-commit 守卫（授权/级联/DDL/时区/密钥/契约/跨端状态/itest 同步等）+ 反向变异测试 + 小程序集成测试（41+12 用例）+ 37 单测。同类项目罕见。
- **契约治理**：Result.code 契约（29-b HTTP 映射）、JSON 日期契约（UTC+Z）、跨端状态契约登记表、错误码白名单。
- **安全治理**：密钥全量 `${ENV:兜底}` 注入、SecurityConfig 兜底 denyAll、182 端点全量声明式授权 + 31 端点方法级校验、敏感词库（message-service）。
- **幂等设计前置**：余额存根注释已写明幂等键/行锁/降级三要素（StudentBalanceServiceStub），课次生成幂等、通知派发 uk_dispatch_once——**支付实现的"地基纪律"已经铺好**。

### 2.2 新暴露的成熟度前提
- **单机架构假设**：排期行锁+CAS 防超卖只在单实例下成立；上多实例前必须引入分布式锁或把扣位改数据库原子操作。这是 P3 演进的硬前置。
- **schema 演进靠手工**：patch 7 个、无 Flyway（已挂账），SaaS 批量建租户库前必须解决。

## 三、缺失特性清单（按优先级，全部带实测证据）

### P0 —— 商业化闭环（不补则无法收费运营）

#### 3.1 学生余额/课时账户（最优先，且地基已铺好）
| 项 | 现状 | 改动面 |
|---|---|---|
| `student_balance` + `student_balance_flow` 两表 | **不存在**，StudentBalanceServiceStub 只记日志不写库 | 建表 + 把 Stub 替换为真实实现（调用方依赖接口，**零改动**——Stub 注释已写明接管方案） |
| 充值入口 | 无 | 管理员人工充值先行（对账可控），在线支付后补 |
| 请假/退改的余额结算 | LeaveRefundSettleService 已调用 adjustId 幂等接口，存根只落日志 | 真实实现后自动生效 |

> 建议路径：**先做"管理员手工充值+余额扣减"闭环**（1 张流水表就能跑通请假/退改的课时增减），在线支付网关作为第二步。这把旧报告里最大的 🔴致命项拆成了两个可独立交付的里程碑。

#### 3.2 支付网关与订单
| 项 | 说明 | 改动面 |
|---|---|---|
| payment_order 表 + 订单状态机 | pending→paid→refunded→failed | 新表 + 状态流转日志 |
| 微信支付（小程序端已有入口形态） | JSAPI/小程序支付 | `integration/payment` 包 + 回调接口（幂等：requestId + 唯一约束） |
| 对账 | 日对账单 | 复用 MetricHourly 模式 |

#### 3.3 签到/评价/反馈（表已建、API 空缺，性价比最高）
- CourseCheckIn：扫码/手动签到，迟到/请假态联动 LeaveRefundSettleService
- CourseEvaluation：1-5 星 + 文字，过 message-service 敏感词库（**敏感词过滤能力已存在，直接复用**），均分进教师主页
- CourseFeedback：分类 + 管理端处理流

### P1 —— 规模化运营

| 项 | 说明 | 备注 |
|---|---|---|
| 教师/课程搜索 | 学科/语言/价格/评分筛选 | MySQL FULLTEXT 起步即可，勿先上 ES |
| 外部通知通道 | 短信（阿里云/腾讯云 SMS）、邮件（spring-boot-starter-mail）、微信订阅消息 | message-service 已有模板+投递追踪骨架，**只差 channel adapter**；密码找回自助流程依赖它 |

### P2 —— 合规与加固

| 项 | 说明 | 备注 |
|---|---|---|
| 登录限流/防爆破 | login_attempt + Caffeine 本地限流（单机够用） | 密码找回开放前必须先做 |
| 数据脱敏 | 手机/邮箱打星；logback Converter | 日志已集中（logController 体系），改造成本低 |
| PIPL：数据导出/注销 | /user/export + /user/delete（软删+余额清算） | 对外运营合规硬要求 |
| Flyway | patch 手工执行已 7 个 | SaaS 批量建租户库前必须（已挂账） |
| 审计补充 | 登录成功/失败也入 audit_log（当前偏业务操作） | 小改动 |

### P3 —— 长期演进（维持旧报告判断）
IM、实时教室（WebRTC/ZEGO）、回放、作业/考试、AI 学习报告、原生 App。**前置条件**：分布式锁（多实例）、Flyway、支付体系。
