## 二、缺陷清单与修复记录（开发工程师修订）

> 原则：不在缺少证据时断言根因，所有修复均附运行时日志/DB 证据。

### 🔴 Defect-1（代码缺陷）课程模板插入 500 — `description` 列 NOT NULL
- **现象**：`POST /course/template/insert` 空 description 时返回 500。
- **根因**：`course_template.description` 列 `NOT NULL`，API 将 description 建模为可选字段（未传），插入绑定 `NULL` → `Column 'description' cannot be null`。
- **证据**：`DataIntegrityViolationException: Column 'description' cannot be null`（spring-boot-app.log）。
- **修复**：`CourseTemplateMapper` insert/update 使用 `COALESCE(#{description},'')`（`api/src/main/java/.../mapper/CourseTemplateMapper.java`，仅改 `src`）。
- **关联用例**：TC-S-05。

### 🔴 Defect-2（代码缺陷）排期创建 500 — `status` 列 NOT NULL
- **现象**：`POST /schedule/create` 返回 500，级联导致预约（TC-S-03）失败。
- **根因**：`course_schedule.status` 列 `NOT NULL`（枚举 pending/active/inactive/frozen），`ScheduleCreateDTO.status` 可选且 harness 未传 → `CreateDtoToObject` 设置 `NULL` → `Column 'status' cannot be null`。
- **证据**：`DataIntegrityViolationException: Column 'status' cannot be null`（courseScheduleMapper.xml）。
- **修复**：`CourseScheduleService.CreateDtoToObject` 兜底 `cs.setStatus(dto.getStatus() == null ? "active" : dto.getStatus())`（仅改 `src`）。
- **关联用例**：TC-S-02、TC-S-03。

### 🔴 Defect-3（Schema / 多租户隔离缺陷）课程模板唯一索引未含 `tenant_id`
- **现象**：租户 B 创建「英语-初级」模板返回 `400 数据已存在`，级联导致 TC-S-18、TC-K-05 失败。
- **根因**：`course_template` 上存在 DB 唯一键 `uk_lang_level(language_type, difficulty_level)`，**不含 `tenant_id`**。租户 A 已占用「英语-初级」组合后，租户 B 无法再建同名组合 → **打破多租户隔离**。
- **证据**：`DuplicateKeyException: Duplicate entry '英语-初级' for key 'course_template.uk_lang_level'`（spring-boot-app.log）。
- **修复（Schema 迁移）**：
  ```sql
  ALTER TABLE course_template
    DROP INDEX uk_lang_level,
    ADD UNIQUE KEY uk_tenant_lang_level (tenant_id, language_type, difficulty_level);
  ```
  改为「按租户隔离」的唯一约束，保留「每租户内 (语言,难度) 唯一」业务规则，同时允许跨租户复用。
- **关联用例**：TC-S-05、TC-S-17/TC-S-18、TC-K-05。

### 🟡 Defect-4（代码缺陷，上一轮已修）教师可自发布本人资料
- **修复**：`teacher/published/save` 鉴权由仅 admin 改为 `checkTeacherSelfOrAdmin`（仅改 `src`）。
- **关联用例**：TC-S-07b（TC-J-05）。

### 🟡 测试脚本缺口（非代码缺陷，为使回归可跑而修正 harness）
| 项 | 说明 | 影响用例 |
|---|---|---|

| 平台共享模板跨租户不可见 | 改为每租户独立模板 `TPL_A`/`TPL_B` | TC-S-17/18/K-05 |

## 三、多租户隔离专项核查（顺带扫描全局唯一键）

为确认 SaaS 隔离完整性，扫描了全部非主键唯一索引：

| 表 | 唯一键 | 是否含 tenant_id | 结论 |
|---|---|---|---|
| course_template | uk_tenant_lang_level | ✅ 已修复含 tenant_id | 合规 |
| sys_tenant | uk_tenant_code | 全局（租户编码本应全局唯一） | 合规（设计如此） |
| sys_tenant_package | uk_tenant_id | ✅ tenant_id | 合规 |
| sys_tenant_stats_monthly | uk_tenant_month | ✅ (tenant_id,stat_month) | 合规 |
| sys_term | uk_scope_key | ✅ (term_key,industry_id,tenant_id) | 合规 |
| audit_log / sys_user_session | uk_log_id / uk_session | UUID 列，实际唯一 | 合规 |
| sys_industry / sys_package_template / sys_system_config / sys_metric_hourly | 各 code/key | 平台级引用表（单租户） | 合规（设计如此） |
| **user** | **uk_email / uk_phone** | ❌ 全局唯一 | ⚠️ 设计观察项（见第四节） |
| teacher_professional | uk_teacher_id | ❌ 不含 tenant_id（UUID 实际唯一） | 低风险 |

**核心隔离缺陷（Defect-3）已修复；其余唯一键均属合理设计或 UUID 实际唯一。**

## 四、遗留 / 设计观察项（建议创建后续事项）

1. **⚠️ `user.uk_email` / `user.uk_phone` 全局唯一**：多租户下同一邮箱/手机号无法在不同租户重复注册。若业务允许跨租户同邮箱，需改为 `(tenant_id, email)` / `(tenant_id, phone)` 唯一键；若要求全局唯一（统一登录），则维持现状。需产品确认。
2. **教师发布接口权限模型不完整**：`/teacher/published/list`、`/get`、`/update`、`/delete` 仍仅 admin 可访问，未同步改为 `checkTeacherSelfOrAdmin`。TC-S-07b 仅修了 `save`。建议补齐其余四个接口的本人/管理员鉴权。
3. **平台模板跨租户复用设计待定**：当前实现按租户隔离模板（Defect-3 修复后）。若产品希望「平台下发的标准模板可被所有租户复用」，需新增平台模板 + 租户实例化机制，而非简单放宽唯一键。
4. **TC-E-02 规格分歧**：测试规格期望「租户管理员访问租户列表 → 403」，实现返回「仅本租户数据（200）」。属合理非越权设计，但**与规格不一致**，需产品/测试负责人确认规格是否应修订为「返回本租户数据」。
