## 2. 部署方法

### 2.1 前置条件

- Nginx 1.27.4（本机安装目录 `C:/Temp/nginx-1.27.4`；生产可装任意路径）
- 后端 API 服务可达：本地 `127.0.0.1:8081`（运行 `api/run.sh`）或远端 `152.136.254.127:8081`
- 操作系统：Windows（本手册命令均 Windows 原生）；**Ubuntu/Linux 服务器部署见第 6 节**

### 2.2 部署步骤

1. **同步前端目录**：将 `frontend/` 整体拷贝到目标 Web 根（本机即上述路径；服务器上可放 `/var/www/frontend` 或任意目录，只需与 nginx `root` 一致）。
2. **准备 nginx 配置**：复制/维护 `conf/nginx.conf`（见第 5 节附录），确认 `root` 指向 Web 根、`proxy_pass` 指向实际后端地址。
3. **启动 Nginx**（见 2.4）。
4. **健康检查**（见 4.1）。

### 2.3 Nginx 配置要点

- `listen 8080;` —— 前端统一端口
- `root <frontend 绝对路径>;` `index index.html;`
- `location /api/v1/ { proxy_pass http://<后端host>:8081; ... }` —— 同源反代，**浏览器侧无跨域**
- `location / { try_files $uri $uri/ /index.html; }` —— 未知路径 SPA 兜底到 `index.html`
- **Windows 路径坑**：必须使用 Windows 原生 `C:/` 路径；启动务必带 `-p <nginx前缀目录> -c <配置文件>`，否则 Nginx 会去「当前工作目录/conf/nginx.conf」找配置而失败。

### 2.4 启动 / 停止 / 重载（Windows）

```bash
# 校验配置（改配置后必做）
C:/Temp/nginx-1.27.4/nginx.exe -t -p C:/Temp/nginx-1.27.4 -c C:/Temp/nginx-1.27.4/conf/nginx.conf

# 启动（daemon 化，后台常驻）
C:/Temp/nginx-1.27.4/nginx.exe -p C:/Temp/nginx-1.27.4 -c C:/Temp/nginx-1.27.4/conf/nginx.conf

# 热重载（改配置后不中断服务）
C:/Temp/nginx-1.27.4/nginx.exe -s reload -p C:/Temp/nginx-1.27.4

# 停止
C:/Temp/nginx-1.27.4/nginx.exe -s stop -p C:/Temp/nginx-1.27.4
```

> 日志：`C:/Temp/nginx-1.27.4/logs/access.log`、`error.log`。`logs/` 目录需存在，否则 Nginx 启动报「could not open error log file」。

### 2.5 跨源导航模型（最终态）

| 角色       | 页面所在       | 访问地址                                                    |
| -------- | ---------- | ------------------------------------------------------- |
| 平台管理员    | 后端 `:8081` | `http://<host>:8081/platform_admin.html?tCode=platform` |
| 租户管理员    | 前端 `:8080` | `http://<host>:8080/admin.html?tCode=<tenantCode>`      |
| 学生/教师/预约 | 前端 `:8080` | `http://<host>:8080/{student,teacher,booking}.html`     |
| 所有 API   | 统一前缀       | `/api/v1/*`（由 Nginx `:8080` 反代或直连 `:8081`）              |

两个全局变量在 `js/public/api.js` 中定义（前端与后端各一份，须同步）：

```js
window.ADMIN_ORIGIN    = window.ADMIN_ORIGIN    || ('http://' + location.hostname + ':8081');
window.FRONTEND_ORIGIN = window.FRONTEND_ORIGIN || ('http://' + location.hostname + ':8080');
```

登录分发改写：`platform_admin` 角色 → `ADMIN_ORIGIN + '/platform_admin.html?tCode=platform'`；`admin` 角色 → `FRONTEND_ORIGIN + '/admin.html?tCode=' + tenantCode`。

## 3. 维护方法

### 3.1 日常运维

- **健康检查**：
  ```bash
  curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1:8080/admin.html        # 期望 200
  curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1:8080/api/v1/sys/config/list  # 期望 401（鉴权门正常）
  ```
- **静态文件改动无需重启 Nginx**：直接覆盖 `frontend/` 下文件即生效（注意浏览器缓存，必要时强刷或加版本查询串）。
- **日志排查**：访问异常先看 `logs/access.log`（状态码）、`logs/error.log`（Nginx/反代错误，如 `connect() failed` 表示后端不可达）。

### 3.2 增加 / 修改页面

1. 在 `frontend/` 下新增 `xxx.html`，资源用**相对路径**引用（如 `css/xxx.css`、`js/xxx.js`、`images/xxx.jpg`）。
2. 复用公共依赖：`js/public/*` 已含请求封装、鉴权、术语等，勿重复造轮子。
3. 跨源跳转一律用 `ADMIN_ORIGIN` / `FRONTEND_ORIGIN` 变量，**禁止硬编码 `:8081`/`:8080` 或后端 IP**，否则换环境即失效。
4. 新页面若需调 API，走 `utility_request.js` 封装（自动补 `/api/v1` 前缀），不要手写完整 URL。

### 3.3 请求层约定（务必遵守）

- 所有 API 调用经 `js/public/utility_request.js` 的 `normalizeUrl(url)`，统一收敛到 `/api/v1`。
- 规则：绝对 http(s) 原样；`/api/v1` 开头原样；`/api/` 开头 → 替换为 `/api/v1`；`/` 开头 → 补 `/api/v1`；其余原样。
- **原因**：axios 对以 `/` 开头的 url 会忽略 `baseURL`，因此只能改 url 字符串、不能靠设 `API_BASE_URL`。改这一处即全站适配，勿在业务 JS 里逐个拼接前缀。

### 3.4 双份 `api.js` 同步（易错点）

`frontend/js/public/api.js` 与 `api/src/main/resources/static/js/public/api.js` 是**两份独立副本**，登录分发 / 跨源变量改动必须**两边同步**，否则前后端行为不一致。

- 改完用下方命令核对两文件关键行一致：
  ```bash
  grep -nE "ADMIN_ORIGIN|FRONTEND_ORIGIN|platform_admin.html|admin.html" frontend/js/public/api.js api/src/main/resources/static/js/public/api.js
  ```


### 3.5 前端与后端静态一致性

- `platform_admin.html` 套件仍在后端；若后端修改了 `js/public/*`，**前端副本须同步更新**（反之亦然），避免逻辑分叉。
- 后端经「Phase 2」清理后仅保留 28 个静态文件，前端**不含** `platform-admin-*.js`、`js/admin-*.js`（前端的是 `admin-*.js` 租户管理端，非平台端）。

### 3.6 常见问题排查

| 现象                           | 可能原因                                  | 处理                                                                |
| ---------------------------- | ------------------------------------- | ----------------------------------------------------------------- |
| 页面 404                       | 文件未同步到 `frontend/` 或相对路径写错            | 核对文件存在 + 引用路径；检查 Nginx `root`                                     |
| `/api/v1/*` 返回 502           | 后端未启动 / 被回收 / `proxy_pass` 指错         | 重启后端 `api/run.sh`；核对 `proxy_pass` 地址                              |
| 登录后跳到错误端口                    | `ADMIN_ORIGIN`/`FRONTEND_ORIGIN` 变量异常 | 检查 `api.js` 两副本；`platform_admin` 须落在 `:8081`                      |
| Nginx 启动报找不到配置               | 未带 `-p`/`-c`，或路径用了 `/c/` 格式           | 用 `C:/` 原生路径 + `-p <前缀> -c <配置>`                                  |
| 报 `could not open error log` | `logs/` 目录不存在                         | 在 nginx 前缀目录下建 `logs/`                                            |
| 改了静态文件不生效                    | 浏览器缓存                                 | 强刷 / 加版本串 `?v=1`                                                  |
| 跨域报错（未来 L2 独立域名时）            | `CorsConfig` 白名单未含新域名                 | 扩 `allowedOriginPattern`（当前仅 localhost/127.0.0.1/152.136.254.127） |

### 3.7 备份与回滚

- `frontend/` 与 `nginx.conf` 均纳入 Git 版本管理。 
- 回滚：`git checkout <版本> -- frontend nginx.conf` → `nginx -s reload`。
- 生产发布建议：先备份当前 `frontend/` 快照，再覆盖；异常即还原并重载。

## 4. 本地联调一键参考

```bash
# 1) 后端（编译 + 起 :8081）
cd api && bash run.sh

# 2) 前端 + Nginx（起 :8080，proxy_pass 默认指向本地 127.0.0.1:8081）
cd C:/Temp/nginx-1.27.4
./nginx.exe -p C:/Temp/nginx-1.27.4 -c C:/Temp/nginx-1.27.4/conf/nginx.conf

# 访问
#   租户管理：http://localhost:8080/admin.html
#   业务前端：http://localhost:8080/        （学生/教师/预约）
#   平台管理：http://localhost:8081/platform_admin.html
```

> 沙箱注意：本环境 Bash 调用结束会回收后台 Java 进程（Nginx daemon 化可存活）。若本地后端被回收导致 `/api/v1` 502，可临时把 `nginx.conf` 的 `proxy_pass` 取消注释指向远端 `152.136.254.127:8081` 做前端联调（改完 `nginx -s reload`）。

## 5. 附录：nginx.conf（当前生效版）

```nginx
worker_processes  1;

events {
    worker_connections 1024;
}

http {
    include       mime.types;
    default_type  application/octet-stream;
    sendfile       on;
    keepalive_timeout 65;

    server {
        listen       8080;
        server_name  localhost;

        root  C:/Users/Administrator/WorkBuddy/2026-08-30-17-19-24/frontend;
        index index.html;

        location /api/v1/ {
            # 本地后端（标准联调）：后端 run.sh 起在 127.0.0.1:8081
            proxy_pass http://127.0.0.1:8081;
            # 测试期可临时指向远端 API 服务器（本地沙箱后台 Java 会被回收，无法持久运行）
            # proxy_pass http://152.136.254.127:8081;
            proxy_set_header Host $host;
            proxy_set_header X-Real-IP $remote_addr;
            proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
            proxy_set_header X-Forwarded-Proto $scheme;
        }

        location / {
            try_files $uri $uri/ /index.html;
        }
    }
}
```
