1. 系统架构与部署拓扑

系统由两个相互独立的 Spring Boot 应用构成，各自拥有独立进程、端口与数据库 schema：

应用主类端口数据库 schema职责
api（主应用）com.reservation.SpringBootMergeApplication8081lesson_appointment认证、RBAC、租户隔离、业务 CRUD、运营监控；调用消息中心
message-service（消息中心）com.messagecenter.MessageCenterApplication8090message_center消息发送/收件箱/撤回/删除/SSE/分类/模板
两应用并非 Maven <modules> 聚合子模块，而是各自独立工程（父 pom 未声明 module），须分别构建、分别启动。二者仅通过共享 JWT/AES 密钥域与 HTTP 互通，数据库物理隔离为两个 schema。

前端静态资源（HTML/JS/CSS）随 api 应用托管于 8081，消息中心由前端通过同源路径直连。

3. 配置说明

两个应用各有一份 application.properties，位于：

  • api：api/src/main/resources/application.properties
  • message-service：api/message-service/src/main/resources/application.properties

3.1 关键配置项

配置键说明示例 / 默认值
server.port监听端口api=8081 / ms=8090
spring.datasource.url数据库连接api→lesson_appointment；ms→message_center（含 createDatabaseIfNotExist=true）
spring.datasource.username/password数据库账号（支持 ${DB_USERNAME:root} 环境变量覆盖）root / 123456
jwt.secretHS512 密钥（≥64 字节），两应用必须完全相同共享值（不对外明文）
jwt.expiration访问令牌有效期（毫秒）360000000（≈100h）
crypto.aes-key / crypto.hmac-key字段加密 / 索引密钥，两应用必须相同共享 Base64 32 字节
message.service.base-urlapi 调用消息中心的地址（仅 api 侧 @Value 默认值，ms 不直接使用）http://localhost:8090
mybatis-plus.*Mapper 路径、驼峰映射、主键策略（ms 用 assign_id 雪花）见各自 properties
spring.devtools.restart.enabled开发热重启（生产可关）api=true
密钥一致性是跨服务调用的硬前提：若 api 与 message-service 的 jwt.secret 不一致，消息中心拦截器将拒绝 api 自签的 Token，导致自动通知与用户收发消息全部静默失败（仅记录告警日志）。修改任一密钥须两应用同步修改。

4. 构建与部署

4.1 源码结构

# 项目根
api/
├─ pom.xml                      # 主应用（artifactId=booking）
├─ src/main/java/com/reservation/...
├─ src/main/resources/          # application.properties + static(前端)
├─ message-service/             # 独立子工程（artifactId=message-service）
│  ├─ pom.xml
│  └─ src/main/java/com/messagecenter/...
├─ sql/schema.sql               # 消息中心建库脚本
├─ migration-20260901-tenant-industry.sql
├─ migration-20260902-term.sql / -term-lang.sql
├─ migration-20260904-user-account-unique.sql
├─ run.sh / start-debug.bat     # 启动脚本
└─ package.json                 # 仅用于拷贝前端 lib（axios/fullcalendar）

4.2 编译

两个应用分别编译（以 Windows + 指定 Maven 家目录与本地仓库为例）：

# 主应用
cd api
mvn -f pom.xml compile

# 消息中心
cd api/message-service
mvn -f pom.xml compile

本项目实测可用的 Maven 启动方式（绕过受限仓库/IDE 锁）：以 java -cp "<maven_home>/lib/*;plexus-classworlds.jar" org.apache.maven.cli.MavenCli compile 显式指定 maven.home / maven.repo.local / maven.multiModuleProjectDirectory，可稳定完成注解处理与 Java 编译。

5. 启动与重启流程

5.1 标准启动

# 消息中心（先启动，api 依赖它）
java -cp "<ms-classpath>" -Dserver.port=8090 com.messagecenter.MessageCenterApplication

# 主应用
java -cp "<api-classpath>" -Dserver.port=8081 -Dfile.encoding=UTF-8 com.reservation.SpringBootMergeApplication

也可用 mvn spring-boot:run 或 java -jar target/*.jar（需先 mvn package）。本项目运行时采用扁平 classpath + java -cp 启动（无 devtools 自动重载，改 Java 后须重启，改静态文件后须拷贝至 target/classes/static）。

5.2 重启主应用（含端口冲突处理）

已知坑：端口占用导致新实例启动失败。重启前必须确认 8081 未被旧进程占用，否则新进程会在 Tomcat 绑定端口时报错退出，而旧进程仍在以旧 class运行（新代码未生效）。

推荐重启步骤（Windows PowerShell + Bash 混合）：

# 1) 查出占用 8081 的进程并确认身份
Get-NetTCPConnection -LocalPort 8081 -State Listen | Select-Object OwningProcess
Get-CimInstance Win32_Process | Where-Object { $_.CommandLine -like '*SpringBootMergeApplication*' } |
  Select-Object ProcessId, CreationDate, CommandLine

# 2) 停止旧 api 进程（保留 message-service）
Stop-Process -Id <旧api_PID> -Force
Start-Sleep -Seconds 2

# 3) 用原 classpath 重新拉起单一 api
java -cp "<原api-classpath>" -Dserver.port=8081 -Dfile.encoding=UTF-8 com.reservation.SpringBootMergeApplication > api.log 2>&1 &

# 4) 校验：仅一个 api 进程且持有 8081，日志出现 "Started SpringBootMergeApplication"
Get-NetTCPConnection -LocalPort 8081 -State Listen
Select-String -Path api.log -Pattern "Started SpringBootMergeApplication"
正常状态：恰好一个 api 进程持有 8081；若启用了 devtools，会多一个父进程（LiveReload 35729），属正常父子双进程，并非重复实例。

5.3 前端静态资源热更新

修改 src/main/resources/static/** 后，须将文件拷贝到 target/classes/static/ 对应路径，浏览器刷新即可生效（无需重启）：

cp src/main/resources/static/js/messages-inbox.js target/classes/static/js/
cp src/main/resources/static/admin.html        target/classes/static/

  • 运营仪表盘 /dashboard：租户用量、趋势、在线、到期预警。

8. 故障排查

现象可能原因处理
api 启动报 "Port 8081 already in use"旧 api 进程未释放端口按 5.2 杀旧进程后重启；确认仅一个 api 持端口
新代码未生效（但进程在跑）端口被旧实例占用，新实例启动失败核对 CreationDate，杀旧拉新
自动通知 / 收发消息全部失败且无报错api 与 ms 的 jwt.secret 不一致比对两 properties 的 jwt.secret，保持一致后重启
前端提示"离线暂存"、消息发不出message-service(:8090) 不可达检查 ms 进程/端口；恢复后刷新页面触发自动重发（最多 10 条）
跨租户数据串扰 / 隔离失效误将平台级表加入租户隔离，或 @InterceptorIgnore 误用检查 IGNORE_TABLES 与 Mapper 上的 @InterceptorIgnore(tenantLine="true")
登录/注册 401白名单路径与真实映射不一致核对 SecurityConfig 白名单（/user/register、/user/account/exist 等）
加密字段模糊搜索失效phone/email/name 为 AES+ HMAC，须走内存解密后匹配确认列表/分页逻辑在内存层解密再匹配

9. 安全维护

  • 密钥管理：jwt.secret、crypto.aes-key、crypto.hmac-key 为系统安全根基，禁止明文提交到仓库；生产环境建议用环境变量（${DB_USERNAME} 同机制）或配置中心注入，且两应用保持完全一致。
  • 账号唯一：user.account 在租户内唯一（见 migration-20260904）；注册/代建时系统查重。
  • 密码与敏感字段：密码 BCrypt 不可逆；phone/email/name 加密存储，运维人员不应明文读取。
  • 租户停用/删除：sys_tenant 用 status + deleted 软删；TenantInterceptor 会拦截已停用/删除租户的访问（403）。
  • 遗留引用：IGNORE_TABLES 中的 sys_platform_admin、sys_dict 暂无实体/Mapper，属历史遗留，排查隔离问题时勿误判。
