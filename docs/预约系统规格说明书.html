1. 引言

1.1 目的

本文档定义预约系统的功能边界、角色权限、数据模型、接口契约与非功能要求，作为需求评审、开发实现、测试验收与运维交付的统一基线。本文档与《软件操作数据手册》《系统维护手册》配套使用。

1.2 范围

系统由 主应用（api，端口 8081） 与 消息中心微服务（message-service，端口 8090） 两个独立 Spring Boot 应用组成，物理上各自拥有独立数据库 schema（lesson_appointment 与 message_center），通过共享 JWT / AES 密钥域实现跨服务可信互通。本文档覆盖：认证与用户、课程/排期/模板、预约与课次（含请假）、教师信息与发布页、租户与套餐、行业与词汇、监控审计日志、以及四角色消息收发。

1.3 术语

术语说明
租户（Tenant）一个使用本系统的组织机构（如某培训机构），拥有独立的数据隔离域；tenant_id=0 为平台级哨兵值（非真实租户）。
平台管理员（platform_admin）运营方人员，tenant_id=0，可跨租户管理租户、套餐、行业、监控与审计。
租户管理员（admin）某租户内的管理者，仅管理本租户下的课程、用户、排期与套餐额度。
教师（teacher）/ 学生（student）业务角色，归属某一租户，进行约课、请假、收发消息。
预约（Booking）学生对教师某排期（schedule）的预约订单，状态贯穿 booked → bookProved → completed/canceled。
课次 / 请假（Appointment）预约下的具体上课时间单元；学生发起请假作用于课次。
scope（接收人范围）消息发送时不指定具体接收者、而由系统按角色+租户解析出的接收者集合，如 tenant_admin、my_teachers。

2. 系统概述与总体架构

2.1 业务目标

为多行业（教育 / 法律咨询等）提供统一的多租户在线预约能力：学生可浏览教师与课程、预约上课、提交请假；教师管理自己的排期与课表；租户管理员运营本机构；平台管理员统一运营多租户。系统内置消息中心，实现四角色间互通与业务事件自动通知。

2.2 逻辑架构

前端（静态资源，随 api 一同服务）：student.html / teacher.html / admin.html / platform_admin.html / booking.html（公开） 等，通过 axios 调用后端 REST。

主应用 api（:8081，com.reservation）：认证授权、RBAC、租户隔离（TenantLineInnerInterceptor）、业务 CRUD、运营监控；并通过 MessageNotifyService 以共享密钥自签 JWT 调用消息中心。

消息中心 message-service（:8090，com.messagecenter）：消息发送/收件箱/已发/撤回/删除/SSE 推送/分类/模板；以共享 jwt.secret 校验跨服务请求。

存储层：MySQL 8.4 — 业务库 lesson_appointment 与消息库 message_center 物理隔离，仅通过密钥域互通。

3. 角色与权限模型

3.1 角色定义

角色（role 值）tenantId数据可见范围典型权限
platform_admin0跨全部租户（绕过租户隔离）租户管理、套餐模板、行业/词汇、监控、审计、系统配置
admin（租户管理员）本租户仅本租户本租户课程/排期/用户/套餐额度、消息管理
teacher本租户仅本租户 + 本人数据查看本人课表、审批请假、收发消息
student本租户仅本租户 + 本人数据浏览/预约课程、请假、收发消息

3.2 权限校验

  • 认证：JwtAuthenticationFilter 解析 Authorization: Bearer → 写入 SecurityContext（ROLE_<role>）。
  • 租户上下文：TenantInterceptor 解析 token 中 tenantId，写入 TenantContext 并校验租户状态（停用/删除→403）。
  • 细粒度 RBAC：业务层通过 PermissionCheck 显式校验（checkAdmin / checkPlatformAdmin / checkTeacher / checkStudent / checkTeacherSelfOrAdmin / checkStudentOwner 等），无权限抛 NoPermissionException。
  • 白名单：/auth/login、/user/register、/user/account/exist、/booking、/teacherPublishedProfile/** 等公开接口免认证。

3.3 四角色互通关系

  • 平台管理员 ⇄ 租户管理员（互发）
  • 租户管理员 ⇄ 教师 / 学生（互发）
  • 教师 ⇄ 学生（仅限已预约该教师课程的学生，即 my_students / my_teachers）
注：教师、学生发往管理员时可选择「一个管理员 / 所有管理员」，系统自动解析本租户管理员；租户管理员发往平台管理员同理自动解析平台管理员，均不要求指定具体接收者。

5. 消息中心专项规格

5.1 总体

消息中心为独立微服务（message-service，:8090），主系统通过 MessageNotifyService 调用其 POST /api/v1/messages/send 完成发送；用户侧收件箱/已发/撤回/删除/SSE 推送由前端直连消息中心（同源经 api 静态资源托管）。

5.2 接收人范围（scope）

角色可发范围（scope）说明
platform_adminplatform_admin（全部平台管理员）跨租户；可系统广播
adminplatform_admin、teachers、students本租户下行；可选一个/所有
teachertenant_admin、my_students本租户；仅已约课学生
studenttenant_admin、my_teachers本租户；不可广播

接收人解析入口：GET /user/message-recipients?scope=&tenantId=（仅平台管理员可传 tenantId 跨租户；其余锁定本租户）。

5.3 消息操作

  • 发送：支持指定接收者群发与按 scope 广播；标题必填。
  • 删除接收消息：用户可删除自己接收的消息（移入回收站，可恢复）。
  • 收回已发消息：仅当接收方未读时可收回（recallable 标志）。
  • 已读 / 收藏 / 未读计数：收件箱支持已读标记、星标、未读数。
  • 实时推送：SSE GET /api/v1/sse/connect 推送新消息与撤回事件。

5.4 系统自动发送场景

触发事件通知对象分类码
学生预订课程（booking created）对应教师 + 本租户管理员BOOKING_CREATED
学生提交请假（leave created）对应教师 + 本租户管理员LEAVE_CREATED
管理员确认预订 / 请假该学生BOOKING_CONFIRMED
平台管理员修改租户套餐配额该租户管理员TENANT_PACKAGE_CHANGED
可靠性：自动通知为 best-effort —— MessageNotifyService 自签共享密钥 JWT、超时 2s 连接 / 3s 读取，调用失败仅记录告警日志，不阻断主业务流程。

5.5 离线暂存

当消息中心不可达（连接拒绝/超时，即无 HTTP 响应）时，前端将最初 10 条未发送消息写入本地 localStorage（msg_offline_queue，FIFO 上限 10）；待服务恢复（SSE ready / 页面刷新）时自动 flushOfflineQueue 重发，业务错误（4xx/5xx）不入离线队列。

7. 接口规格（API）

7.1 通用约定

  • 基础路径：业务接口以 /auth、/user、/course、/course/booking、/course/appointment、/schedule、/tenant 等分组；消息中心以 /api/v1 分组。
  • 认证：Authorization: Bearer <accessToken>；SSE 允许 ?access_token=。
  • 统一返回：{ code, msg, data }，code===200 为成功；401 未认证 / 403 无权限 / 400 参数错误。

7.2 主应用关键端点（节选）

方法 / 路径说明
POST /auth/login登录，返回双 Token
POST /user/register、POST /user/add注册 / 代建用户
GET /user/message-recipients?scope=&tenantId=消息接收人范围解析
POST /course/booking/create、POST /course/booking/updateStatus预约下单 / 状态变更（触发通知）
POST /course/appointment/add、PUT /course/appointment/updateStatusById请假提交 / 审批（触发通知）
POST /tenant/package/insert|update|create-from-template|{tenantId}/switch-template套餐变更（触发通知）
GET /dashboard/overview、GET /monitor/overview、GET /api/audit-logs运营 / 监控 / 审计

7.3 消息中心端点（/api/v1）

8. 非功能需求

维度要求 / 实现
安全 — 认证JJWT HS512 访问令牌（≈100h）+ HS256 刷新令牌（7d）；密钥 jwt.secret 跨两应用共享（≥64 字节）。
安全 — 加密密码 BCrypt；phone/email/name 等敏感字段 AES-GCM 加密 + HMAC 索引，两应用共享 crypto.aes-key / crypto.hmac-key。
多租户隔离TenantLineInnerInterceptor 注入 tenant_id；平台角色全表忽略；平台级表入 ignoreTable；特定跨租户查询以 @InterceptorIgnore(tenantLine="true") 显式绕过。
可用性消息中心不可达时前端离线暂存（10 条）+ 自动重发；自动通知 best-effort 不阻断主流程。
可观测审计日志、应用日志浏览、监控指标（CPU/内存/JVM/磁盘/线程/GC/在线）、运营仪表盘。
可维护两个应用独立构建/启动；共享密钥域；迁移脚本集中管理（见维护手册）。
