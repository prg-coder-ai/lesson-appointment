1. 系统入口与角色说明

系统通过浏览器访问，统一入口为 http://<服务器IP>:8081/。各角色登录后进入对应工作台：

角色工作台页面说明
学生studentstudent.html我的预约、课表、请假、消息
教师teacherteacher.html课程与排期、学生课表、审批、消息
租户管理员adminadmin.html课程/排期/用户/套餐/数据维护/消息
平台管理员platform_adminplatform_admin.html租户/套餐/行业/监控/审计/消息
公开访客booking.html、teacherPublishedProfile.html浏览课程/教师、教师对外发布页（免登录）

2. 通用操作

登录：在登录页选择角色 → 输入账号、密码及（非平台角色）租户代码 tenantCode → 点击登录；平台管理员 tenantCode 固定填 platform。
登出：点击右上角账户菜单的"退出登录"。
修改密码：账户菜单 → 修改密码（POST /user/account/changePassword）。
导航：左侧/顶部菜单按模块切换；消息中心入口通常为铃铛图标或"消息"菜单项。
说明：admin / platform_admin 注册后状态直接为 active；教师 / 学生注册后状态为 pending，需由对应管理员审核激活后方可正常使用。

3. 学生操作

3.1 注册与资料

  • 注册：登录页"注册" → 选择角色 student、填写账号/密码/姓名/手机号/学习目标等 → 提交后等待管理员审核。
  • 资料：个人中心可维护学习目标、语言水平、资质等信息。

3.2 浏览与预约课程

浏览：公开页 booking.html 或直接进入学生工作台，按教师 / 课程 / 时间筛选可约排期。
预约：选择某教师的排期 → 点击"预约" → 系统创建 booking（status=booked）并自动向该教师及本租户管理员发送通知。

3.3 请假

提交请假：在"我的课表/课次"中选择某课次 → 提交请假 → 系统自动通知教师与本租户管理员。

3.4 收发消息（见第 7 节）

4. 教师操作

4.1 资料与排期

  • 维护职业信息、证书、可预约时段（/teacher/professional）。
  • 创建/调整课程排期，冲突检测（/schedule/checkConflict）。
  • 对外发布页（teacherPublishedProfile.html，公开可访问）。

4.2 课表与审批

查看预约：工作台查看本人被预约的课表与学生列表。
审批请假：收到请假通知后，在课次管理中批准/驳回；审批结果会自动通知该学生。

4.3 收发消息（见第 7 节）

5. 租户管理员操作

5.1 课程与排期运营

  • 管理本租户课程模板、课程、排期（admin-course.js / admin-schedule.js / admin-template.js）。
  • 确认学生预订（booking → bookProved），向学生发送确认通知。

5.2 用户管理

教师 / 学生列表：在用户管理页查看本租户教师、学生；每行提供"发消息"按钮（window.openComposeToUser），可快捷向该用户发送消息。

5.3 套餐额度

  • 查看本租户套餐额度（课程/排期/用户/教师/学生/发布数上限与已用）。
  • 额度由平台管理员在 sys_tenant_package 中设定，变更时平台会通知本租户管理员。

5.4 数据维护与消息（见第 7 节）

6. 平台管理员操作

6.1 租户管理

  • 租户分页、详情、新增/编辑、停用/恢复/续期、绑定套餐（/tenant）。
  • 跨租户用户管理（/user/platformPage）、修改用户所属公司名（/user/updateCompany）。

6.2 套餐与行业

  • 套餐模板定义（/package/template）：设定各类配额规格。
  • 为租户创建/更新套餐、从模板创建、切换模板（/tenant/package）；任一变更自动通知该租户管理员。
  • 行业字典（/industry）、行业词汇三级作用域维护（/term，支持多语言）。

6.3 监控与审计

  • 运营仪表盘：租户用量、总览、趋势、在线、到期预警（/dashboard）。
  • 系统监控：资源指标、趋势、小时聚合、API 健康（/monitor）。
  • 审计日志（/api/audit-logs）、应用日志浏览（/api/logs）。

6.4 用户列表发消息

平台管理员在用户管理（platform-admin-user.js）中，每行"发消息"按钮可快捷向指定用户发送消息；向租户管理员群发时系统自动解析目标租户管理员。

7. 消息中心通用操作

7.1 进入消息中心

各角色工作台点击"消息"图标进入收件箱，包含 收件箱 / 已发 / 星标 / 回收站 等视图，并通过 SSE 实时接收新消息与撤回事件。

7.2 发送消息（免指定接收者）

打开发送：点击"发消息"或列表页"发消息"按钮（window.openComposeToUser）。
选择范围：按角色给出范围（scope）：
  • 学生 / 教师：可选"本租户管理员"或"我的教师 / 我的学生"。
  • 租户管理员：可选"平台管理员 / 本租户教师 / 本租户学生"，并可选择"一个"或"所有"。
  • 平台管理员：可选"平台管理员 / 某租户管理员 / 教师 / 学生"。
系统按所选范围自动查询接收者，无需手动输入具体账号。
填写并发送：填写标题（必填）与内容 → 点击发送；支持勾选多名接收者。

7.3 删除与收回

操作对象条件
删除自己接收的消息可单条或批量删除，移入回收站，支持恢复
收回自己已发、接收方未读的消息仅"已发"列表中 recallable=true 的可收回

7.4 离线暂存

当消息服务暂时不可达（断网/服务宕机），系统自动把最初 10 条未发送消息存入浏览器本地（msg_offline_queue）；服务恢复后页面刷新或 SSE 重连时自动重发，并提示重发条数。业务报错（如标题为空）不会进入离线队列。

8. 数据字典（核心表字段）

说明：以下为业务关键表的字段释义，供运营与运维查阅。tenant_id 为租户隔离列，平台级表为 0 或忽略隔离。

8.1 user（用户表）

字段类型/约束含义
user_idUUID，PK用户唯一标识
tenant_idbigint所属租户（0=平台）
account明文，租户内唯一登录账号
passwordBCrypt登录密码（不可逆）
roleenumstudent/teacher/admin/platform_admin
statusenumpending/active/inactive/frozen
phone / email / nameAES-GCM + HMAC 索引敏感信息加密存储
create_time / update_timedatetime创建/更新时间

8.2 booking（预约订单）

字段含义
booking_idUUID 主键
schedule_id关联排期
student_id / teacher_id学生 / 教师 user_id
statusbooked（已约）/ bookProved（已确认）/ cancelling / canceled / completed / overtime

8.3 appointment（课次 / 请假）

字段含义

statusactive / noted（已请假）/ cancelled / completed / changed 等

8.4 sys_tenant / sys_tenant_package（租户与套餐额度）

表关键字段含义

表关键字段含义

9. 常见问题

现象排查方向
注册后无法登录教师/学生需管理员审核（status=pending→active）；确认 tenantCode 正确
收不到自动通知检查消息中心(:8090)是否在线；确认 api 的 message.service.base-url 指向正确地址
发出消息未送达查看前端是否提示"离线暂存"；服务恢复后刷新页面触发重发
无法收回消息仅接收方未读（recallable=true）时可收回；已读则不可收回
跨租户数据看不到非平台角色仅见本租户数据；平台管理员 tenantCode=platform
