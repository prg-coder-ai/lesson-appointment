何时推 C 层（私有/内网部署）｜ 何时推 M1（私有化授权）

配套文件：卞现拍板事项清单（2026-10-07）· 系统售卖层方案（2026-09-15）｜ 适用：销售 / BD / 代理培训 ｜ 2026-10-12
两份"私有"产品最容易让客户和内部都搞混：C 层是"我们帮你运维的私有部署"，M1 是"你把部署权买回去自己运维"。本页给一线一个先问谁运维、再定档报价的判断标准，避免同一客户既报 C 又报 M1 的内部打架。价格已按拍板清单口径错开：C 层 ¥8k 起、M1 ¥20k 起。
①

核心区分表（一眼分清两档）

维度C 层 · 私有/内网部署M1 私有化授权
谁掌控 / 运维时约交付并托管/代运维（重信任）客户自运维（买部署权，不交源码）
建议价一次性 ¥8k–30k + 年服 ¥3k–10k一次性 ¥20k–40k（按坐席阶梯）+ 年维护 15–20%
交付物部署 + 运维 + 升级包年（含在我们人力内）部署包 + 授权 Key + 安装文档（不含持续运维）
客户最适合单店/小团队、无 IT、要省心快速上线多门店/集团、有 IT、要数据主权与自有资产
合规责任数据在客户环境，运维责任由我们承担一部分数据合规责任完全随部署转移给客户
我们的成本持续人力（运维/响应），靠年服回血一次性交付，无持续人力（维护另计）
为什么 M1 起价比 C 层高却仍合理
C 层的¥8k里含了我们的持续运维人力，是"服务价"；M1 的¥20k 是资产授权费——客户买走部署权与自主权、自己养团队，我们不再背运维。客户拿到的是"控制权"，不是"托管省心"。两档卖的不是同一个东西，错位在起价（8k vs 20k），重叠只在 20–30k 的中段，靠下方"谁运维"判断分流。
②

分流判断标准（先问一句话，再定档）

客户说"想用私有/不挂公网"→ 先问：系统的运维、备份、升级，你们自己有人管，还是希望我们托管？→ 按回答定档
推 C 层 ｜ 我们运维
触发信号（命中任一条即优先推 C）
  • 客户明确"你们帮我托管/我们没 IT 人员"
  • 单店或 ≤10 服务者、预算有限、要 1–2 周快速上线
  • 心理/法律类要求"数据本地"但不愿自建运维
  • 怕麻烦、要"出事找你们"的省心型老板
  • 运维成本我们吃得下（单店/轻量私有）
推 M1 ｜ 客户自运维
触发信号（命中任一条即优先推 M1）
  • 客户有 IT 团队、要"系统归我们、自己掌控"
  • 多门店/连锁/集团、体量较大、想沉淀为自有资产
  • 合规要求"数据完全自主、不能依赖外部"
  • 不愿被年服绑定、接受一次性买断部署权
  • 我们运维成本过高（重私有/多门店）→ 主动转 M1
红线：① 同一客户不双报 C 与 M1，先定档再报价；② 不凭"感觉"报价，先问"谁运维"；③ 我们运维成本算不过账的重私有，主动转 M1，不硬接 C；④ M1 只交部署包不交源码（沿用系统售卖层护栏）。
③

对外话术边界（怎么说不让客户混）

推 C 层时这样讲
"这是部署在您自己环境里的私有版本，运维、备份、升级都由我们托管，您只要用就行，出事找我们。适合想数据本地、但不想自己养技术团队的您。"——卖点是省心 + 数据本地。
推 M1 时这样讲
"这是一次买断的私有化授权，系统部署权归您，您自己掌控数据和运维，我们给部署包、授权 Key 和安装文档，年维护另算。适合有 IT 团队、想把系统沉淀成自有资产的您。"——卖点是控制权 + 资产归属。
合规口径（心理/法律类）
"辅助管理 + 数据本地"等对外表述归赵写（内容风格教练）把关，本页不代拟。M1 场景须明确"数据合规责任随部署转移给客户"，不在话术里替客户承诺"数据不出公共云"。
