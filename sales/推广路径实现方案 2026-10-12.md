# 推广路径实现方案

## 一、现状与设计前提

| 现状 | 说明 |
|------|------|
| 小程序已有归因机制 | `miniprogram/core/acquisition.js` 已埋点 `inviter`/`source`，上报到 `/api/v1/user/attribution`，**但后端未实现** |
| Web 端注册表单 | `login.html:207-260` 仅有 `tenantCode`，无推广码字段 |
| 租户创建 | `POST /tenant/insert` 仅 platform_admin 可调，`TenantService.insertTenant` 会校验 tenantCode 唯一 |
| 首管理员 bootstrap | `UserService.applyRoleAdmission:248-249` 已支持"本租户无 admin 时首管理员自动 active" |
| 套餐/配额 | `TenantQuotaService.acquire/release` 完备，`sys_package_template` + `sys_tenant_package` 可承载免费体验额度 |
| 角色体系 | 仅 4 种，无推广员角色 |

**设计原则**：推广者不新增角色，任何已注册用户（含 admin/teacher/student）均可成为推广者，通过 `referral_code` 关联。后端为单一事实源，前端只传推广码。

## 二、数据模型设计

### 2.1 新增表：`promo_referral`（推广关系表）

```sql
CREATE TABLE `promo_referral` (
  `id`              bigint       NOT NULL AUTO_INCREMENT,
  `referral_code`   varchar(32)  NOT NULL COMMENT '推广码（推广者生成，全局唯一）',
  `promoter_user_id` varchar(36) NOT NULL COMMENT '推广者 user_id',
  `promoter_tenant_id` bigint   NOT NULL COMMENT '推广者所属租户',
  `target_tenant_id` bigint     DEFAULT NULL COMMENT '路径2：指定目标租户（NULL=路径1自助建租户）',
  `path_type`       tinyint      NOT NULL COMMENT '1=自助建租户 2=指定租户注册',

  UNIQUE KEY `uk_referral_code` (`referral_code`),
```

## 四、核心流程设计

### 路径1：自助注册租户 + 首管理员

```
推广链接: https://domain/login.html?ref=ABC123&path=1
                                    └────── 推广码
```

```
┌─ 前端 login.html ─────────────────────────────────────────────┐
│  1. 解析 URL ?ref=ABC123&path=1                              │
│  2. GET /promo/referral/validate?code=ABC123                 │
│     → 返回 {valid, pathType:1, promoterName, trialDays}      │
│  3. 渲染"免费体验注册"表单（隐藏 ref/path）：                │
│     - 机构名称（新租户 orgName）                              │
│     - 行业选择                                                │
│     - 管理员账号/姓名/密码                                    │
│     - 联系电话                                                │
│  4. POST /promo/register-tenant {                             │
│       referralCode:"ABC123",                                 │
│       orgName:"XX工作室",                                    │
│       industryId:1,                                           │
│       account:"admin1", password:"...", name:"张三",         │
│       phone:"138xxxx"                                        │
│     }                                                        │
└──────────────────────────────────────────────────────────────┘
                              │
┌─ 后端 PromoController.registerTenant ───────────────────────┐
│  ① 校验推广码：promo_referral.status=active 且未过期         │
│  ② 生成 tenantCode（UUID）                                    │
│  ③ 事务内：                                                   │
│     ├─ TenantService.insertTenant(tenant)                    │
│     │   └ trial_status='trial', trial_expire_time=now+14天   │
│     │   └ referred_by=promoter_user_id                       │
│     ├─ 创建试用套餐：sys_tenant_package（试用额度）           │
│     ├─ UserService.Register(user{                            │
│     │     role:'admin', tenantCode, account, ...             │
│     │   }, approvedByAdmin=false)                            │
│     │   └ applyRoleAdmission: 本租户无admin → 自动active ✅  │
│     └─ PromoService.recordConversion(                        │
│         referralCode, inviteeUserId, inviteeTenantId,        │

│  ④ 返回 {token, userId, tenantCode, trialExpireTime}         │
└──────────────────────────────────────────────────────────────┘
```

**关键设计点**：
- 复用 `TenantService.insertTenant` 创建租户，注入试用配置
- 复用 `UserService.applyRoleAdmission` 的首管理员 bootstrap（已实现，`UserService:248-249`）
- 试用套餐通过 `sys_tenant_package` 写入限额（`promotion.trial.user.limit` 等）
- 试用到期后 `trial_status='expired'`，租户 `status` 改为停用，需缴费转正

```
│  ② 事务内：                                                   │
│     ├─ UserService.Register(user{                            │

│     │   └ student/teacher → status='pending'（需审批）       │
```

## 七、安全与一致性保障

| 风险 | 对策 |
|------|------|
| 推广码被篡改 | 后端校验 `promo_referral.target_tenant_id` 与请求 `tenantCode` 匹配；路径1 不接受 tenantCode |
| 重复归因 | `promo_conversion.uk_conversion_invitee` 唯一键，一个被邀请者只归因一次 |
| 推广码滥用 | 限频（同 IP 每分钟最多 5 次校验）；推广码可设过期时间 + status=disabled |
| 试用租户滥用 | 试用租户 `trial_status='trial'`，到期自动停用；同手机号全局唯一（`uk_phone`）防重复建租户 |
| 业绩刷量 | `stage='registered'` 仅在 `userMapper.insert` 成功后写入（同事务）；`stage='paid'` 仅在套餐变更事务提交后触发 |
| 并发首管理员 | 复用现有 `applyRoleAdmission` 的 `FOR UPDATE` 锁定读，已保证原子性 |
| 推广者越权看业绩 | `promo_achievement` 查询强制 `promoter_user_id = 当前token.userId` |
