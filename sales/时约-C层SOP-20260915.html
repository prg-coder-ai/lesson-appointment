时约 · C 层商业化 SOP（单必成 · Sales Coach 视角 × 卞现/梗王）

C 层（私有部署 / 大客户）高 touch BD SOP

对象：连锁健身 / 多校区教培 / 律所分所 / 心理机构 ｜ 模式：项目制 BD（长周期 1–3 月）｜ 套餐：私有/内网部署 项目制 ｜ 2026-09-15
C 层是"高客单、长周期、重信任"的项目制销售，不能用 A/B 层的自助逻辑。本 SOP 把 Sales Coach 的 MEDDPICC 资格认定、Mutual Evaluation Plan（共同评估计划）、Pipeline Review 与 丢单无责复盘 落到可执行步骤。没有 Economic Buyer 不进 POC，POC 没有成功标准就是浪费——这两条是红线。
①

SOP 总览

商机获取→ 需求沟通+资格认定→ 安全合规方案+POC→ 报价签约→ 部署交付→ 复盘
一句话目标
用"数据安全 + 合规 + 定制"拿下高客单私有部署，靠 POC 建信任、合同+部署交付闭环，并沉淀可复用的行业案例。
硬指标
签约客单价 + POC→签约转化率。单笔金额大，质量（资格）比数量重要。
商机→POC 转化
目标 ≥40%
POC→签约 转化
目标 ≥50%
客单价
私有 ¥15k–30k / 内网 ¥25k+ （项目制）
交付周期
目标 ≤4 周（POC 另计）

阶段 1 · 商机获取（BD）

1.1 渠道与优先级
销售
  • 转介绍（最高优先级）：B 层客户长大 / 同行推荐——信任已前置，转化最快。
  • 定向 BD：律所、心理咨询机构、连锁健身/教培的协会、线下沙龙、定向拜访。
  • 行业活动：参展/演讲，讲"服务业数据本地化"而非硬广。
  • 优先级：律所（合规刚需）> 心理机构（隐私刚需）> 连锁健身/多校区教培（规模）。
1.2 商机来源登记
销售
  • 每条商机入"商机表"：渠道 / 行业 / 规模（门店·服务者数） / 联系人 / 阶段 / 风险。
  • 来源归因同 A/B：转介绍码、活动二维码，避免全算"自然"。
  • 红线：无联系人或无行业匹配的商机不占用 BD 精力。
④

阶段 2 · 需求沟通 + 资格认定（MEDDPICC）

2.1 MEDDPICC 诊断表（每次沟通后填）
销售
维度要回答的问题（发现式提问）
Metrics 量化收益现在多少门店/服务者？排期冲突/漏提醒造成的成本或损失怎么估？
Economic Buyer 经济决策者谁最终拍板采购？是老板、合伙人还是 IT/行政？我们能见到吗？
Decision Criteria 决策标准他们最看重什么：数据不出本地、合规、定制、价格、还是实施速度？
Decision Process 决策流程从意向到签约走几步？要招标/比价/内审吗？时间线？
Pain 痛点数据归属不清？合规风险？多门店统一管控难？用他们的话复述。
Champion 内部推动者谁在内部替我们推？他有推动力吗？
Competition 竞争在比自研、竞品 SaaS、还是继续用表格/微信？
Paper Process 采购流程合同/付款/发票流程？预算周期在哪一季度？
资格门槛（卡红线）
缺 Economic Buyer 或完全没有预算信号 → 养着，不进 POC。资格不全不是 CRM 卫生问题，是丢单风险。
2.2 发现式提问脚本（别一上来报价）
销售
开场（重构问题，不接需求）
"很多企业一开始想的是'做个预约页'，聊深了才发现真正卡的是数据归谁、合不合规。你们这边现在最担心的是哪头？"——先领着买方重新想问题，再给方案。
找 Economic Buyer
"这种涉及数据部署的采购，一般得合伙人/IT 一起看。能不能拉个会，我 20 分钟把部署和合规讲清楚？"
⑤

阶段 3 · 安全合规方案 + POC

3.1 方案文档结构（checklist）
赵写/销售
  • 背景与痛点（用买方原话）。
  • 部署形态建议：SaaS / 私有 / 内网，及各自适用边界（不夸大"点一下就行"）。
  • 安全合规要点：数据留存位置、出境、权限、审计。
  • 功能映射：买方需求 → 时约能力对照表。
  • 实施计划与报价区间（不写死最终价）。
3.2 POC + Mutual Evaluation Plan（共同评估计划）
销售+技术
  • 明确 POC 范围：功能边界、数据量、环境（内网/隔离）、时长（2–4 周）。
  • 双方共同写下成功标准（可量化）：如"内网环境跑通预约+提醒，数据不出本地，3 个角色权限正确"。
  • 约定步骤、标准、时间线 → 制造联合责任，减少 ghosting（玩消失）。
  • 红线：POC 没有书面成功标准 = 不做（否则验收必扯皮）。
共同评估计划模板（一句话）
"我们双方都同意：POC 在第 N 周结束，以【成功标准】为通过线；通过则进入报价签约，不通过我们免费出改进建议，不强行推单。"
⑥

阶段 4 · 报价与签约

4.1 报价单结构（项目制，不公开标价）
卞现
  • 一次性部署费（私有 ¥8k–30k / 内网 ¥15k 起，按规模·定制）。
  • 年服务费（私有 ¥3k–10k / 年，含升级·工单·支持）。
  • 可选：定制开发费、培训费（单独列）。
  • 付款节奏：首款（部署启动）+ 尾款（验收后），降低买方决策压力。
4.2 谈判与合同纪律
卞现/法务
  • 不公开统一标价，按项目单谈，避免被拿来做比价锚点。
  • 强调 TCO（含运维年服），别只拼一次性价格。
  • 合同条款：数据归属、SLA、保密、部署前置（服务器/网络自备，写清避免误会）。
  • 红线：不先开天价吓退；不承诺超出能力的功能（尤其合规表述）。
⑦

阶段 5 · 部署交付

5.1 交付流程（steps）
产品/技术
  • 环境确认（买方服务器/网络就绪）→ 部署 → 数据初始化 → 培训 → 验收 → 运维移交。
  • 培训：管理员 + 终端用户两场，留操作手册。
  • 验收：对照 POC 成功标准逐条核对，双方签字。
  • 年服：升级、工单、支持，明确响应时效。
5.2 验收与续约
产品/卞现
  • 验收即启动年服计时；到期前 60 天启动续约沟通。
  • 沉淀行业案例（脱敏）：用于下一单同行业 BD。
⑧

阶段 6 · 复盘（Sales Coach 工具）

8.1 Pipeline Review 框架（每周/双周）
单必成
商机价值阶段年龄关键问题风险
[客户][¥][阶段][天]"我们还不知道什么？"红/黄/绿
  • 每周过商机池，对每个问 6 句：变了什么 / 跟谁谈 / 业务理由 / 决策流程 / 最大风险 / 下一步（带日期· owner）。
  • 挑战"happy ears"：买方说"很喜欢"不算信号，问"他承诺了哪步具体动作"。
  • 超 30 天无进展的标红，强制决策：推、养、还是弃。
8.2 丢单无责复盘（Blameless Debrief）
单必成
  • 归类：资格（本不该进，早筛掉）/ 执行（该进但没做好）/ 竞争（做得好但对手更强）。
  • 三类对应不同干预：资格→收紧 MEDDPICC；执行→练话术/demo；竞争→重定位价值。
  • 问一句："哪一步我们本可以更早识别风险？"——把复盘变成下一次的提前量。
8.3 预测纪律（Forecast Discipline）
单必成
  • 分层：upside（努力可成）/ commit（有证据必成）/ closed（已签）。
  • commit 只认证据："买方做了什么（不是说了什么）证明这季能签？"
  • 把死单留在 commit 里掩盖问题 → 需教练；主动Pull单 → 鼓励（诚实）。

⑩

风险与边界

合规表述：心理/法律写"辅助管理工具 + 数据本地"，不写"帮你获客/合规"——合规承诺要可兑现，不能越界。

不夸大部署：说清前置（服务器/网络），别让人以为点一下就行；内网部署的边界写进合同。

不公开标价：对外不挂统一价，按项目单谈，避免比价。

资格红线：无 Economic Buyer、无预算信号不进 POC；POC 无书面成功标准不做。

数据安全承诺："数据留本地/不出公共云"必须靠部署形态真做到，否则是法律与信任双雷。
