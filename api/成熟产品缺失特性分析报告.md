## 二、成熟产品级缺失特性（按优先级分类）

### 2.1 P0（最高优先级，影响商业化落地）

#### 2.1.1 支付与订单系统

| 缺失项 | 说明 | 涉及改动 |
|--------|------|---------|
| 课时费计算 | 从 `CourseTemplate.classFee`（课程模板单价）× 预约课时数 → 生成订单金额 | 新增 `OrderService`，在 Booking 确认时计算价格 |
| 支付集成 | 支付宝 / 微信支付 / Stripe（海外） | 新增 `com.reservation.integration.payment` 包、`PaymentController`，对接支付 SDK |
| 订单状态机 | 状态：pending_payment → paid → refunded → failed | 新增 `payment_order` 表 + `order_status_change_log` 表 |
| 学生钱包 / 课时包 | 学生预充值套餐（5 节课包 10 节课包），预约时自动扣减 | `wallet_account` + `wallet_transaction` + `package_coupon` |
| 教师收入结算 | 平台抽成比例设置，课时完成后教师账户入账、月结提现 | `teacher_finance_account` + `withdraw_record` + `platform_profit_report` |
| 发票/收据 | 学生提交发票申请、开票记录 | `invoice_record` 表 + 发票开具接口 |

#### 2.1.2 通知与消息推送

| 缺失项 | 说明 | 涉及改动 |
|--------|------|---------|
| 站内信（In-App Notification） | 学生/教师/管理员三方消息中心，红点提示、已读未读 | `notification` 表（id/user_id/type/title/content/is_read/created_at） + `NotificationController` |
| 微信公众号/小程序推送 | 预约成功、预约取消、课程开始前 1 小时等关键节点模板消息 | 集成 WxJava SDK，TemplateService |
| 短信通知（SMS） | 手机号用户的关键事件推送（注册验证码、预约确认） | 集成阿里云短信 / 腾讯云 SMS，`SmsService` |
| 邮件通知 | 邮箱用户的重要通知 + 密码重置链接 | Spring Mail（`spring-boot-starter-mail`） |
| 日程日历同步（iCal） | 将已确认课程生成 .ics 文件，导入 Google/Outlook 日历 | BookingController 新增 `/booking/{id}/ics` |
| 消息模板管理 | 管理员后台配置各事件的模板内容 + 变量占位符 | `message_template` 表 + 模板管理页面 |

#### 2.1.3 签到与评价反馈（已有实体，补 API）

| 缺失项 | 对应空壳 Entity | 说明 |
|--------|----------------|------|
| 课程签到（学生端扫码/教师手动点到） | `CourseCheckIn` | 签到状态：已签到/未签到/迟到/请假；签到时间戳 |
| 课程评价（课后 1-5 星 + 文字） | `CourseEvaluation` | 学生对教师评分评价，评价平均分会展示到教师主页 |
| 课程反馈（学生+教师双方提交） | `CourseFeedback` | 内容反馈/服务反馈分类，管理员后台待处理/已处理流程 |
| 评价审核 | 无 | 管理员审核评价内容（敏感词过滤 + 人工审核） |

### 2.3 P2（中优先级，管理与合规）

#### 2.3.1 安全与合规

| 缺失项 | 说明 | 涉及改动 |
|--------|------|---------|
| 操作审计日志（Audit Log） | 所有关键操作（登录、预约、取消、删除、修改）入库，谁在什么时间做了什么 | `audit_log` 表：`id/user_id/role/action/resource_id/ip/ua/timestamp/detail_json`；AOP 切面 `@Audit` 自动采集 |
| 数据脱敏 | 日志输出、前端展示手机号/邮箱中间位打星（138****8888） | `SensitiveFilter` + logback 自定义 Converter |
| 登录限流（防暴力破解） | 同一账号/IP 多次失败后锁定，图形验证码 | `login_attempt` 表 + Redis 限流（或 Caffeine 本地缓存） |
| 敏感操作二次验证 | 管理员删除用户/踢人、教师提现 → 密码二次确认 |
| 个人信息保护（PIPL/GDPR） | 用户导出个人数据、注销账号删除数据 | `/user/export` + `/user/delete` |
| API 签名（接口防篡改） | 重要接口（支付/提现）增加 sign 参数 |
| 文件上传安全 | 教师上传证书图片：后缀白名单、病毒扫描、大小限制 |

#### 2.3.2 后台管理增强

| 缺失项 | 说明 |
|--------|------|
| 管理员操作日志浏览界面 | 基于 audit_log 的 Web 界面（时间/操作人/操作类型筛选） |
| 系统配置中心 | 网站名称、联系电话、协议文本、抽成比例等可动态配置（非硬编码） | `sys_config` 表 + `SystemConfigController` + 配置管理页面 |
| 用户拉黑 / 白名单 | 恶意学生/教师黑名单，登录拦截 |
| IP 黑名单 | 异常 IP 封禁 |
| 敏感词库 | 评价/反馈/聊天内容敏感词过滤 |
| 系统公告管理 | 管理员发布公告 → 全用户顶部横幅 | `system_notice` 表 |
| 多管理员 / 多角色（细粒度权限） | 当前只有 admin 单一角色，需要拆分：运营、财务、教务、客服 | 新增 `role` + `permission` 表，权限到 URL / 按钮级别 |

#### 2.3.3 可靠性

| 缺失项 | 说明 |
|--------|------|
| 数据库备份策略自动化 | 定时（每日凌晨）mysqldump 自动备份 + 保留周期 + 异地容灾 |
| 接口幂等性 | 支付接口、预约提交接口、回调接口加 `requestId` 防重复 |
| 分布式锁（预约场景） | 多实例部署时，同一排期最后一个席位可能被两人同时抢到 → Redisson 分布式锁 |
| 接口限流 / 防刷 | 单位时间单 IP/用户调用次数限制（限流 + 熔断） |
| 健康检查 & 监控 | `/actuator/health`、JVM/MySQL/Redis 指标 → Prometheus + Grafana |
| 慢查询监控 | SQL 执行 > 1s 自动记录，生成慢查询报告 |

## 四、缺失功能对业务的影响（风险评估）

| 风险 | 严重性 | 缺失功能 | 未引入的后果 |
|------|--------|---------|-------------|
| 无法收费 | 🔴 致命 | 支付系统 | 产品仅 Demo 级，无法商业化 |
| 消息丢失率高 | 🟠 高 | 通知推送 | 学生错过课程时间，教师错过预约，投诉率飙升 |
| 无售后闭环 | 🟠 高 | 评价 + 反馈 | 教师服务质量不可控，平台信任度低 |
| 无改期流程 | 🟠 高 | 改期 / 请假 | 学生临时有事只能取消，满意度低，课时流失 |
| 无法审计追责 | 🟠 高 | 审计日志 | 数据被误删无法定位操作人，出事故无法复盘 |
| 账号安全薄弱 | 🟡 中 | 限流 + 第三方登录 | 撞库攻击风险，密码登录流程繁琐 |
| 无法对账 | 🟡 中 | 财务管理 | 平台资金流不清，财务审计不通过 |
| 查找困难 | 🟡 中 | 搜索推荐 | 课程/教师数量增加后用户找不到目标 |
| 可靠性问题 | 🟡 中 | 幂等 + 分布式锁 | 高并发预约出现超卖，支付回调重复触发 |
| 竞争力不足 | 🟢 低 | P3 高级功能 | 与成熟竞品（飞书日历预约、Calendly、小鹅通）差距大 |
