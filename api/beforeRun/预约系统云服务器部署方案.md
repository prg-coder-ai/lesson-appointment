# 预约系统部署到云服务器：完整方法步骤

> 适用工程：`H:\2026\lesson-appointment`
> 技术栈：Spring Boot 3.3.5 + JDK 17 + MyBatis-Plus 3.5.7 + MySQL 8.x + Thymeleaf/静态页面
> 目标系统：Linux（Ubuntu 22.04 / CentOS 7+ / Debian 11+，2 核 4G 起步）

---

## 一、部署产物清单（先看清楚要部署什么）

| 服务 | 模块目录 | 打包产物 | 端口 | 数据库 | systemd 单元 |
|---|---|---|---|---|---|
| **booking**（预约主系统，含前端页面） | `api/` | `booking-<ver>.jar` | **8081** | `lesson_appointment` | `booking.service` |
| **message-service**（消息中心微服务） | `api/message-service/` | `message-service-1.0.0.jar` | **8090** | `message_center` | `message-service.service` |

关键事实（来自工程配置，部署时必须对得上）：

- `api/pom.xml`：`groupId=com.reservation`、`artifactId=booking`、**version=0.1.0**、主类 `com.reservation.SpringBootMergeApplication`
- `api/message-service/pom.xml`：`groupId=com.messagecenter`、**version=1.0.0**、主类 `com.messagecenter.MessageCenterApplication`
- 两个服务 **共享同一套 JWT / AES 密钥域**（`jwt.secret`、`crypto.aes-key`、`crypto.hmac-key` 两边必须一致，否则 Token 无法互认、加密字段无法互通）
- 数据库账号密码支持环境变量注入：`${DB_USERNAME:root}` / `${DB_PASSWORD:123456}` —— **生产务必用环境变量覆盖，不要改默认值后再提交代码**

> ⚠️ 版本号不一致提醒：`beforeRun/booking.service` 里写的是 `booking-0.2.0.jar`，而 `api/pom.xml` 当前版本是 `0.1.0`。部署前请二选一对齐：要么把 pom 版本改为 `0.2.0`，要么把 service 文件里的 jar 名改成实际产物名。**这是最容易导致 `systemctl start` 直接失败的点。**

## 二、服务器环境准备

### 2.1 安装 JDK 17

```bash
# Ubuntu / Debian
sudo apt update && sudo apt install -y openjdk-17-jdk
# CentOS / Rocky
sudo yum install -y java-17-openjdk-devel

java -version   # 必须显示 17.x
```

> 工程 `java.version=17`，服务端装 17 最省事；装 21 也能跑（高版本 JVM 可运行低版本字节码），但不要低于 17。

### 2.2 安装并初始化 MySQL 8.x

```bash
sudo apt install -y mysql-server          # Ubuntu
sudo systemctl enable --now mysql
sudo mysql_secure_installation            # 设置 root 密码、禁止匿名、禁止远程 root 登录
```

字符集核对（工程库用 `utf8mb4_unicode_ci`）：

```sql
SHOW VARIABLES LIKE 'character_set_server';   -- 应为 utf8mb4
SHOW VARIABLES LIKE 'collation_server';       -- 应为 utf8mb4_unicode_ci
```

若不符，参考工程自带的 `docker/mysql8/conf/my.cnf.txt` 配置 `[mysqld]`：

```ini
[mysqld]
character-set-server = utf8mb4
collation-server = utf8mb4_unicode_ci
default-storage-engine = InnoDB
max_connections = 1000
```

**时区提醒**：连接串写的是 `serverTimezone=UTC`，而业务字段多为 `DATETIME`，在 CST 服务器上会出现"存进去差 8 小时"。二选一处理：
- 方案 A（推荐）：连接串改为 `serverTimezone=Asia/Shanghai`；
- 方案 B：保持 UTC，MySQL 服务端也设 UTC，展示层再转本地时区。
两个服务要一致，避免跨服务时间错乱。

### 2.3 安装 Nginx（反向代理 + HTTPS）

```bash
sudo apt install -y nginx
sudo systemctl enable --now nginx
```

### 2.4 创建运行用户与目录

```bash
sudo useradd -r -s /bin/false lesson          # 非 root 运行，与 service 文件一致
sudo mkdir -p /opt/lesson /etc/lesson /var/log/lesson
sudo chown -R lesson:lesson /opt/lesson /var/log/lesson
```

目录用途：`/opt/lesson` 放 jar；`/etc/lesson` 放环境变量文件（不进版本库）；`/var/log/lesson` 放应用日志。

## 三、数据库初始化（严格按此顺序）

部署文件都在 `api/beforeRun/` 下：

| 文件 | 作用 | 是否生产可用 |
|---|---|---|
| `lesson_appointment_schema_fixed.sql` | 主库 `lesson_appointment` 全量表结构（含建库语句） | ✅ 首次部署执行 |
| `lesson_appointment_sys_seed.sql` | 平台基础数据：`sys_industry`、`sys_package_template`、`sys_system_config`、`sys_term`、`sys_tenant`、`sys_tenant_package`、`sys_tenant_stats_monthly` | ✅ 首次部署执行 |
| `messagecenter-schema.sql` | 独立库 `message_center` 结构与预置数据（msg_category / msg_template / msg_message 等） | ✅ 首次部署执行 |
| `lesson_appointment_cleanup.sql` | 清空主库全部业务数据（保留表结构） | ⚠️ **仅测试环境/重置演示数据用，生产禁止执行** |

### 3.1 上传 SQL 到服务器

```bash
scp api/beforeRun/*.sql root@<服务器IP>:/opt/lesson/sql/
```

### 3.2 执行顺序

```bash
# 1) 主库结构
mysql -uroot -p lesson_appointment < /opt/lesson/sql/lesson_appointment_schema_fixed.sql
# 说明：脚本自带 CREATE DATABASE + USE，无需提前建库

# 2) 平台基础数据（行业、套餐模板、系统配置、术语、租户）
mysql -uroot -p lesson_appointment < /opt/lesson/sql/lesson_appointment_sys_seed.sql

# 3) 消息中心独立库
mysql -uroot -p < /opt/lesson/sql/messagecenter-schema.sql
```

### 3.3 校验

```sql
USE lesson_appointment;
SHOW TABLES;                                  -- 应有 appointment/booking/course/user/sys_* 等
SELECT COUNT(*) FROM sys_industry;            -- 应 > 0（种子数据已导入）
SELECT COUNT(*) FROM sys_package_template;    -- 应 > 0

USE message_center;
SHOW TABLES;                                  -- msg_category/msg_template/msg_message/...
```

> 注意：`messagecenter-schema.sql` 内含 `DROP TABLE IF EXISTS`，**重复执行会清空消息数据**。生产环境二次执行前先备份。

### 3.4 创建应用专用数据库账号（不要直接用 root）

```sql
CREATE USER 'lesson'@'localhost' IDENTIFIED BY '强密码';
GRANT ALL PRIVILEGES ON lesson_appointment.* TO 'lesson'@'localhost';
GRANT ALL PRIVILEGES ON message_center.* TO 'lesson'@'localhost';
FLUSH PRIVILEGES;
```

```bash
JWT_SECRET=与本地一致的那串Base64密钥
CRYPTO_AESKEY=HVwcdqAh5A6nScL+0CRJYhKPLCI8y1FP9blj3BL9L4g=
CRYPTO_HMACKEY=Ip0fg8W0iUXc9Iuw/rcsL+DQ3UkJklcATNqjAtwZmMA=
JAVA_OPTS=-Xms256m -Xmx512m -Dfile.encoding=UTF-8
EOF

sudo tee /etc/lesson/message.env > /dev/null <<'EOF'
DB_USERNAME=lesson
DB_PASSWORD=强密码
SPRING_DATASOURCE_URL=jdbc:mysql://127.0.0.1:3306/message_center?useUnicode=true&characterEncoding=utf8&useSSL=false&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true

CRYPTO_AESKEY=必须与 booking 完全一致

sudo chmod 600 /etc/lesson/*.env
sudo chown lesson:lesson /etc/lesson/*.env
```

> 环境变量名采用 Spring Boot 的**宽松绑定规则**：`CRYPTO_AESKEY` → `crypto.aes-key`，`JWT_SECRET` → `jwt.secret`，可直接覆盖 `application.properties` 中的同名配置。

### 5.2 安装 systemd 单元

项目已提供 `api/beforeRun/booking.service` 与 `api/beforeRun/message-service.service`，原文件内容：

```ini
[Unit]
Description=Lesson Booking Service
After=network.target
Wants=network.target

[Service]
Type=simple
User=lesson
Group=lesson
WorkingDirectory=/opt/lesson
ExecStart=/usr/bin/java -jar /opt/lesson/booking-0.2.0.jar
Restart=on-failure
RestartSec=10s
StartLimitIntervalSec=600
StartLimitBurst=3

[Install]
WantedBy=multi-user.target
```

**建议在此基础上做三点生产化改造**（`EnvironmentFile` 注入密钥、`JAVA_OPTS` 限内存、日志落文件）：

```ini
[Unit]
Description=Lesson Booking Service
After=network.target mysql.service
Wants=network.target

[Service]
Type=simple
User=lesson
Group=lesson
WorkingDirectory=/opt/lesson
EnvironmentFile=/etc/lesson/booking.env
ExecStart=/usr/bin/java $JAVA_OPTS -jar /opt/lesson/booking-0.1.0.jar
Restart=on-failure
RestartSec=10s
StartLimitIntervalSec=600
StartLimitBurst=3
StandardOutput=append:/var/log/lesson/booking.log
StandardError=append:/var/log/lesson/booking.log

[Install]
WantedBy=multi-user.target
```

`message-service.service` 同理（`Description=Lesson Message Service`、`EnvironmentFile=/etc/lesson/message.env`、`ExecStart=.../message-service-1.0.0.jar`，日志 `/var/log/lesson/message.log`）。

安装与启动：

```bash
sudo cp booking.service message-service.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now booking
sudo systemctl enable --now message-service

systemctl status booking message-service --no-pager
journalctl -u booking -f                # 实时看启动日志
tail -f /var/log/lesson/booking.log
```

常用运维命令：

| 操作 | 命令 |
|---|---|
| 启动/停止/重启 | `sudo systemctl start|stop|restart booking` |
| 查看状态 | `systemctl status booking` |
| 开机自启 | `sudo systemctl enable booking` |
| 崩溃后重置限流 | `sudo systemctl reset-failed booking`（连续崩溃超过 3 次会进入 failed，需先 reset） |
| 平滑重载配置 | `sudo systemctl daemon-reload`（改了 service 文件后必须执行） |

## 六、Nginx 反向代理与 HTTPS

### 6.1 站点配置 `/etc/nginx/sites-available/lesson`

```nginx
upstream booking_backend {
    server 127.0.0.1:8081;
    # 蓝绿/滚动发布时追加第二实例：server 127.0.0.1:8082;
}

upstream message_backend {
    server 127.0.0.1:8090;
}

server {
    listen 80;
    server_name yourdomain.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name yourdomain.com;

    ssl_certificate     /etc/letsencrypt/live/yourdomain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/yourdomain.com/privkey.pem;

    client_max_body_size 20m;

    # ---------- 消息服务（含 SSE 实时推送，必须特殊配置）----------
    location /msg/ {
        proxy_pass http://message_backend/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # SSE 三要素：关闭缓冲、长超时、禁用 chunked 过滤
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 3600s;
        proxy_http_version 1.1;
        chunked_transfer_encoding on;
    }

    # ---------- 主系统：页面 + 接口 ----------
    location / {
        proxy_pass http://booking_backend;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 120s;
    }
}
```

```bash
sudo ln -s /etc/nginx/sites-available/lesson /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
```

### 6.2 申请免费证书

```bash
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d yourdomain.com
sudo certbot renew --dry-run      # 验证自动续期（certbot 已自带定时任务）
```

> SSE 提醒：消息服务是 SSE 单向推送，**Nginx 侧关闭 `proxy_buffering` 是硬性要求**，否则前端收不到实时消息（表现为一直等待、连接断开后才一次性收到）。

## 七、安全加固

| 项 | 做法 |
|---|---|
| 防火墙 | 只放行 22 / 80 / 443；8081、8090 **不对外暴露**（`ufw allow 22,80,443/tcp`） |
| 进程用户 | 已用 `User=lesson` 非 root 运行 |
| 数据库 | `bind-address = 127.0.0.1`；仅本地账号；生产务必改掉默认 `123456` |
| 密钥 | JWT / AES / HMAC 走 `EnvironmentFile`，文件权限 600，不进 Git |
| 服务间调用 | 8090 只允许本机访问；若跨机部署，用内网安全组限制来源 IP |
| 备份 | 见第十节 |

## 八、部署验证清单

```bash
# 1) 端口监听
ss -lntp | grep -E '8081|8090'

# 2) 主系统页面
curl -I http://127.0.0.1:8081/                 # 期望 200
curl -I https://yourdomain.com/                # 期望 200

# 3) 消息服务健康检查（需有 /actuator/health 或任意已知接口）
curl -I http://127.0.0.1:8090/

# 4) 数据库连接正常（日志中无 Access denied / Communications link failure）
grep -iE 'error|exception' /var/log/lesson/booking.log | head

# 5) 业务冒烟：登录 → 预约下单 → 消息中心收到通知
```

**容易踩的三个坑：**

1. **前端页面 404**：页面若放在 `src/main/resources/templates/` 且通过直链 `/xxx.html` 访问，需要在 `application.properties` 的 `spring.web.resources.static-locations` 中补上 `classpath:/templates/`（当前配置未包含该项），或改由 Controller 返回视图名。
2. **中文乱码**：启动参数必须带 `-Dfile.encoding=UTF-8`，且服务器 `LANG` 建议设为 `C.UTF-8` 或 `en_US.UTF-8`。
3. **消息服务 Token 校验失败**：两个服务的 `jwt.secret`、`crypto.aes-key`、`crypto.hmac-key` 必须逐字符一致；用环境变量注入时留意 Base64 中的 `+` `/` `=` 是否被 shell 转义。

## 九、零中断升级（滚动 / 蓝绿发布）

单实例发布必然中断，做法是**同一服务跑两个实例 + Nginx upstream 切换**：

```
/opt/lesson/
├── booking-0.1.0.jar      ← 当前版本（8081，运行中）
├── booking-0.2.0.jar      ← 新版本（8082，先启动）
└── booking@8081.service / booking@8082.service   ← systemd 模板单元
```

发布脚本示例 `deploy-booking.sh`：

```bash
#!/usr/bin/env bash
set -e
NEW_JAR=$1          # 例：booking-0.2.0.jar
NEW_PORT=$2         # 例：8082（与当前在跑的端口交替）

sudo cp "$NEW_JAR" /opt/lesson/
sudo chown lesson:lesson "/opt/lesson/$(basename $NEW_JAR)"

# 1) 启动新实例（新端口），等待健康检查通过
sudo systemctl start "booking@${NEW_PORT}"
for i in {1..30}; do
  curl -fsS "http://127.0.0.1:${NEW_PORT}/" >/dev/null && break
  sleep 2
done

# 2) 切 Nginx upstream（把新端口置顶、旧端口注释/摘除），reload
sudo sed -i "s/server 127.0.0.1:808[0-9];/server 127.0.0.1:${NEW_PORT};/" /etc/nginx/sites-available/lesson
sudo nginx -t && sudo systemctl reload nginx

# 3) 观察 30~60 秒无异常后，停掉旧实例
sleep 30
sudo systemctl stop "booking@旧端口"
```

配套要点：
- **数据库迁移必须向后兼容**：先加字段/新表 → 发新代码 → 下个版本再删旧字段，保证旧版本实例仍能运行，回滚无需回滚数据。
- **保留上一个版本 jar**，回滚 = 切 upstream 回旧实例（秒级）。

## 十、备份与回滚

```bash
# 每日备份脚本 /opt/lesson/backup.sh
#!/usr/bin/env bash
D=$(date +%F_%H%M)
mysqldump -ulesson -p'强密码' --single-transaction --routines \
  --databases lesson_appointment message_center | gzip > /data/backup/db_$D.sql.gz
find /data/backup -name 'db_*.sql.gz' -mtime +14 -delete
```

```bash
# crontab：每天 3:00 备份
0 3 * * * /opt/lesson/backup.sh >> /var/log/lesson/backup.log 2>&1
```

回滚矩阵：

| 故障 | 回滚动作 |
|---|---|
| 新版本功能异常 | Nginx upstream 切回旧实例（保留旧 jar 即可） |
| 数据被误改 | 用最近的 `db_*.sql.gz` 恢复到临时库，导出受影响表再回灌 |
| 消息库被 `DROP` | 同上；注意 `messagecenter-schema.sql` 含 DROP，二次执行前先备份 |

## 十一、故障速查表

| 现象 | 常见原因 | 排查 |
|---|---|---|
| `systemctl start` 立刻 failed，提示 No such file | jar 名与 service 里的版本号不一致 | `ls /opt/lesson/*.jar` 核对并改 service 文件 |
| 启动报 `Access denied for user` | 环境变量未注入 / 密码错 | `systemctl show booking -p Environment`；直接 `mysql -ulesson -p` 验证 |
| 启动后立刻退出、日志无内容 | JDK 版本低于 17 | `java -version`；`journalctl -u booking -n 50` |
| 页面能开，接口 404/500 | 上下文路径或被 Nginx location 截断 | 对比直连 `curl 127.0.0.1:8081/xxx` 与域名访问结果 |
| 消息推送不实时 | Nginx 缓冲未关 | 确认 `proxy_buffering off` 已配置并 reload |
| 时间显示差 8 小时 | `serverTimezone=UTC` 与本地时区不一致 | 改连接串为 `Asia/Shanghai` 并重启 |
| 崩溃后不再自动拉起 | 触发 `StartLimitBurst=3` 限流 | `systemctl reset-failed booking && systemctl start booking` |
