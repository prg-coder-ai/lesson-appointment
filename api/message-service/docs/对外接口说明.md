# message-service 对外接口说明

> 服务名：`message-service`（消息中心微服务）｜端口：`8090`｜上下文路径：`/`

---

## 1. 基础约定

- **Base URL**：`http://<host>:8090`
- **API 前缀**：`/api/v1`
- **鉴权**：所有业务接口需在请求头携带主系统登录签发的 JWT：
  ```
  Authorization: Bearer <token>
  ```
  （本服务与主系统共享 `jwt.secret`，token 可直接校验，无需重新登录。）
- **统一响应体**：
  ```json
  { "code": 0, "message": "ok", "data": { } }
  ```
  - `code = 0` 表示成功；非 0 为业务异常。
  - 鉴权/权限失败：`code = 401`（未登录）或 `403`（无权限），`message` 给出原因。
- **时间格式**：`yyyy-MM-dd HH:mm:ss`（UTC 存储，展示按客户端时区处理）。
- **内容类型**：`application/json;charset=UTF-8`。

## 2. 接口总览

| 分组 | 路径前缀 | 说明 |
|------|----------|------|
| 消息发送 | `/api/v1/messages` | 单发/群发/广播/系统通知 |
| 用户收件箱 | `/api/v1/users/{userId}` | 列表/详情/已读未读/收藏/删除恢复 |
| 分类管理 | `/api/v1/message-categories` | 三级分类 CRUD + 树 |
| 模板管理 | `/api/v1/message-templates` | 模板 CRUD + 基于模板发送 |
| 管理与追踪 | `/api/v1/messages`（管理端） | 历史/投递状态/批量任务/撤回/重推/ack |
| SSE 推送 | `/api/v1/sse` | 实时推送长连接 |

## 3. 接口明细

### 3.1 消息发送 `/api/v1/messages`

#### POST `/send` — 单发 / 群发
- 权限：已登录（学生仅可向指定用户上行；管理员/教师可下行）
- 请求体（`SendMessageReq`）：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| title | String | 是 | 消息标题（落库加密） |
| content | String | 否 | 消息正文（落库加密） |
| categoryCode | String | 否 | 业务分类编码（如 HOMEWORK_NOTICE） |
| priority | String | 否 | HIGH / MEDIUM / LOW，默认 MEDIUM |
| payload | Map | 否 | 附加元数据（如跳转地址，落库加密） |
| recipientUserIds | List<String> | 是* | 接收用户 ID 列表（单发/群发） |
| broadcast | Boolean | 否 | 是否广播，默认 false |
| targetRole | String | 否 | 广播目标角色 teacher/student/admin/all |
| targetTenantId | Long | 否 | 目标租户（平台管理员可指定，否则取当前租户） |

- 响应 `data`：`{ messageId, recipientCount, ... }`

#### POST `/broadcast` — 广播（按角色/全体）
- 权限：管理员 / 教师（`canSendDownstream`）
- 请求体：同上，`broadcast=true` + `targetRole`

#### POST `/system` — 系统通知
- 权限：system 角色 或 管理员
- 请求体：同上（无 recipientUserIds 时按 `targetRole`/`targetTenantId` 投递）

### 3.2 用户收件箱 `/api/v1/users/{userId}`

| 方法 | 路径 | 权限 | 说明 |
|------|------|------|------|
| GET | `/inbox` | 本人或管理员 | 分页列表，支持 `folder`/`keyword`/`unreadOnly`(int)/`categoryCode`/`priority`/`start`/`end` 过滤；`pageNum`(默认1)/`pageSize`(默认10) |
| GET | `/starred` | 本人或管理员 | 收藏列表 |
| GET | `/deleted` | 本人或管理员 | 回收站列表（folder=trash） |
| GET | `/inbox/unread-count` | 本人或管理员 | 未读总数（Long） |
| GET | `/messages/{messageId}` | 本人或管理员 | 详情（**解密**返回 title/content/payload） |
| POST | `/messages/{messageId}/read` | 本人 | 标记已读 |
| POST | `/messages/{messageId}/unread` | 本人 | 标记未读 |
| POST | `/messages/read/batch` | 本人 | 批量已读，body `{ "messageIds": [1,2] }` |
| POST | `/messages/{messageId}/star` | 本人 | 收藏 |
| POST | `/messages/{messageId}/unstar` | 本人 | 取消收藏 |
| DELETE | `/messages/{messageId}` | 本人 | 删除（软删进 trash） |
| DELETE | `/messages/batch` | 本人 | 批量删除，body `{ "messageIds": [1,2] }` |
| POST | `/messages/{messageId}/restore` | 本人 | 从回收站恢复 |
| GET | `/messages/ids` | 管理员 | 列出用户全部消息 id（`isDeleted` 可选） |

> 注：普通用户只能操作自己的 `userId`；管理员可代查代管。

### 3.3 分类管理 `/api/v1/message-categories`（仅管理员）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/` | 分页，`keyword`/`level`(1/2) 过滤 |
| GET | `/tree` | 完整层级树（List） |
| POST | `/` | 新增，`CategoryReq` |
| PUT | `/{categoryId}` | 更新 |
| DELETE | `/{categoryId}` | 删除 |

`CategoryReq`：

| 字段 | 类型 | 说明 |
|------|------|------|
| categoryCode | String | 编码（更新时为空则沿用原值） |
| categoryName | String | 名称（必填） |
| categoryLevel | Integer | 层级 1/2（有 parentId 自动为 2） |
| parentId | Long | 父级 ID（二级分类必填） |
| sort | Integer | 排序 |

### 3.4 模板管理 `/api/v1/message-templates`（CUD 仅管理员，发送需下行权限）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/` | 分页，`keyword`/`categoryCode` 过滤 |
| GET | `/enabled` | 全部启用模板列表 |
| GET | `/{id}` | 模板详情 |
| POST | `/` | 新增，`TemplateReq` |
| PUT | `/{id}` | 更新 |
| DELETE | `/{id}` | 删除 |
| POST | `/send` | 基于模板 + 参数发送 |

`TemplateReq`：

| 字段 | 类型 | 说明 |
|------|------|------|
| templateCode | String | 编码（必填） |
| templateName | String | 名称（必填） |
| categoryCode | String | 关联分类 |
| titleTemplate | String | 标题模板，支持 `{name}` 占位 |
| contentTemplate | String | 内容模板（落库加密） |
| senderType | String | 默认 admin |
| priority | String | 默认 MEDIUM |
| isEnabled | Integer | 默认 1 |

`TemplateSendReq`：

| 字段 | 类型 | 说明 |
|------|------|------|
| templateId | Long | 模板 ID |
| params | Map | 占位参数，如 `{ "name": "张三" }` |
| recipientUserIds | List<String> | 接收用户 |
| broadcast | Boolean | 是否广播 |
| targetRole | String | 广播角色 |
| targetTenantId | Long | 目标租户 |

### 3.5 管理与追踪 `/api/v1/messages`（管理端）

| 方法 | 路径 | 权限 | 说明 |
|------|------|------|------|
| GET | `/` | 管理员 | 发送历史分页，`tenantId`/`senderType`/`status` 过滤 |
| GET | `/{messageId}/delivery-status` | 管理员/发送者 | 单条投递追踪（含读/收藏/删除统计） |
| GET | `/batch/{taskId}` | 管理员/发送者 | 批量任务进度 |
| POST | `/{messageId}/withdraw` | 管理员/发送者 | 撤回消息 |
| POST | `/{messageId}/retry` | 管理员 | 对投递失败用户重推，返回 `{ "retried": n }` |
| POST | `/{messageId}/ack` | 已登录 | 接收回执（客户端收到推送后调用） |

---

### 3.6 SSE 实时推送 `/api/v1/sse`

#### GET `/connect` — 建立长连接
- 鉴权：通过 `Authorization` 头或 `access_token` 参数
- 响应类型：`text/event-stream`
- 连接成功立即推送一条 `ready` 事件：`{ "online": 3 }`
- 后续：服务端在消息发送成功时，向接收者在线连接推送新消息事件。

#### GET `/online-count` — 在线会话数（运维/测试）
- 响应：`{ "online": 3 }`

## 4. 错误码

| code | 含义 | 触发场景 |
|------|------|----------|
| 0 | 成功 | — |
| 401 | 未登录 / token 无效 | 缺 Authorization 头、签名失败、已过期 |
| 403 | 无权限 | 学生广播、非管理员操作分类/模板/历史等 |
| 其他 | 业务异常 | 参数校验失败、数据不存在等（见 `message`） |

## 5. 调用示例

### 步骤 1：主系统登录拿 token
```bash
# 主系统(api:8081)登录接口返回 JWT（具体字段随主系统而定）
TOKEN=$(curl -s -X POST http://localhost:8081/api/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"******"}' | jq -r '.data.token')
```

### 步骤 2：发送一条单发消息
```bash
curl -X POST http://localhost:8090/api/v1/messages/send \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{
    "title": "作业提醒",
    "content": "请于周五前提交实验报告。",
    "categoryCode": "HOMEWORK_NOTICE",
    "priority": "HIGH",
    "recipientUserIds": ["student_1001"]
  }'
```

### 步骤 3：接收者建立 SSE 连接（另开一个会话）
```bash
curl -N -H "Authorization: Bearer $TOKEN" \
  http://localhost:8090/api/v1/sse/connect
# 连接即收到：event:ready data:{"online":1}
# 消息到达时收到新消息推送事件
```

### 步骤 4：接收者查询收件箱
```bash
curl http://localhost:8090/api/v1/users/student_1001/inbox \
  -H "Authorization: Bearer $TOKEN"
```

### 步骤 5：管理员查看发送历史
```bash
curl http://localhost:8090/api/v1/messages \
  -H "Authorization: Bearer $TOKEN"
```
